# 规划角色与规划参考文本

## 目标
完成后，需求代理派出的 planner 按固定口径产出可执行的任务集：先骨架再正文、只改影响范围、内联原文、写验证约定、经固定检查通过。

## 业务规则（来源：spec）
- planning-preflight：派工前由需求代理核对需求确认、规划类型、受影响任务编辑状态、范围占用与验证条件；增量规划提供变化摘要、相关位置与已知限制，摘要不替代规划角色核实。
- planning-artifacts：同次运行先确定任务骨架（行为切片、文件归属、真实依赖、运行入口切换节点、验证边界），再生成自包含正文；增量从变化范围及直接依赖开始核实，未受影响任务逐字不变；使用固定机械检查入口，不临时编写检查器；关键前提未核实或提前删除现用入口时报告受影响任务与待验证条件，不宣布可执行。
- verification-contract：每任务写真实入口与契约、必须成立的行为、适用与不适用场景、模拟边界、三层验证责任；涉及状态控制、安全边界、宿主接入或不可重复副作用的任务，由需求代理在实施前核对方案。
- task-file-line-limit：任务文件扣除示例与成品代码块后最多 200 行，不限制代码改动量。
- role-catalog：planner 不得派出其他角色。

## 涉及文件

## 函数清单
`agents/planner.md` 必需段落：
| 段落 | 必须表达的规则 |
|---|---|
| 输入与边界 | 只读规范、需求文档与仓库代码；只写需求的任务目录与索引；不派出任何角色；不修改运行信息 |
| 骨架先行 | 同次运行先列出骨架：行为切片、文件归属（生产文件 ≤2 且互斥）、真实依赖、运行入口切换节点、验证边界；骨架成立后才写正文；骨架写进任务索引与任务协作说明，不另建长期报告，不增加确认轮次 |
| 增量规划 | 从变化摘要与直接依赖核实真实影响，未受影响任务逐字不变，不重写整套任务，不为未受影响任务重置运行状态 |
| 任务正文 | 按 spec-docs 格式；业务规则节逐字内联所引 AC 与其回指的 C；验证方式含验证约定五要点，涉及外部系统时核实所用版本、返回所代表的完成时机与事件或数据含义，不机械穷举组合；每份扣除示例与成品代码块后 ≤200 行 |
| 机械检查 | 交付前运行固定入口 `lint.sh --tasks`，失败即修正，不自行编写检查脚本、任务生成器或验收解析器 |
| 不可执行即报告 | 计划会提前删除现用入口或关键接口、环境、文件约束未核实时，报告受影响任务与待验证条件，不报告可执行；不以模拟通过、模型自觉遵守提示或既有测试数量替代证明 |

`references/planning-preflight.md`（需求代理派工前加载）必需内容：前检六项（需求已确认、规划类型、受影响任务编辑状态、范围占用、派工目录在本需求代理授权范围内且不借用其他目录授权、本轮规划所需验证入口与环境条件已知且未知技术前提明确列出）；受影响任务中已标记完成的待改任务须先核对原运行与成果、按获准变更解除完成状态限制后才可重规划；任一不满足即只说明具体阻塞、不派出规划角色、不改写旧运行结果、不伪造占用或授权；增量输入三件（变化摘要、相关位置、已知限制），摘要不替代规划角色核实，不为未受影响任务重置运行状态。
`references/planning-artifacts.md`（需求代理核对规划产物时加载）必需内容：只写需求代理核对产物的清单，不复述 `agents/planner.md` 与 spec-docs 已有的要素定义和模板——骨架五要素按名称逐项在场且落在任务索引与协作说明；高风险任务（状态控制、安全边界、宿主接入、不可重复副作用）在实施前由需求代理核对验证方案；验证条件无法确认时列出具体缺项、不判为实施就绪，模拟通过、模型自觉遵守提示、既有测试数量均不作为证明；产物中不得出现临时编写的检查脚本、任务生成器或验收解析器；验证入口必须可运行；模拟边界须把本次改动引入或修改的连接、鉴权与保护逻辑排除在模拟之外。
