# 原型外框柔和明暗配色和右上角方案切换

## 目标
`buildPrototypeFrame` 拼出的原型外框有明亮、暗黑两套柔和配色，跟系统外观、可手动切换；方案按钮在框上方右侧，切换栏只放页面和画面。

## 业务规则（来源：PRD soft-theme-scheme-switch）
- 外框四块：切换栏（左栏）、框上方一行、隔离框（iframe，放设计师交的页面）、说明区（隔离框下方）。切换栏、框上方一行、说明区用同一种底色，不再分深浅两层。
- 明亮主题色值：底色 `#d5dae1`；网格线 `rgba(71, 96, 127, .06)`，20 像素一格；正文 `#1d2633`；次要文字 `#4f5b6b`；标签边框和文字、切换栏右边缘虚线、隔离框外圈虚线、说明区顶边虚线 `#47607f`；普通按钮边框和分隔线 `#b7bfca`；选中按钮：1px 实线边框 `#47607f`、填充 `#c2cad5`、文字 `#1d2633`、加粗。
- 暗黑主题色值：底色 `#26282c`；网格线 `rgba(255, 255, 255, .03)`；正文 `#d4d4d4`；次要文字 `#8f949b`；标签和虚线 `#8e9aa8`；普通按钮边框和分隔线 `#3a3d43`；选中按钮：边框 `#8e9aa8`、填充 `#33363c`、文字 `#e6e6e6`。
- 没选中的按钮鼠标移上去时，边框变成该主题的虚线颜色（`--accent`）。
- 隔离框背景两种主题都是白色；切换主题只改根元素属性，不重新给 iframe 赋值，页面里输入的内容还在。
- 框上方一行最右端是「☀ 明亮」「☾ 暗黑」两个按钮，当前主题显示为选中（`aria-pressed="true"`）。打开时按 `prefers-color-scheme` 选；没点过按钮时系统外观变化就跟着变；点过以后不跟；不存进浏览器。`matchMedia` 不存在或它的结果没有 `addEventListener` 时，只按打开时的外观选，其余功能照常。
- 有方案清单时，框上方一行右侧从左到右：文字"方案"、每个方案一个按钮"方案 <字母>：<名称>"、明暗按钮；当前方案按钮选中。没有方案清单时"方案"和方案按钮都不显示。
- 切换栏从上到下：标签"设计说明 · 不属于页面"、原型名称、"第 N 版 · 这一栏上线后不存在"；有方案清单时接着两行"当前：方案 <字母>：<名称>"和"最后选哪个，在“确认原型”窗口里定"；最后"切换要看的内容"（页面组、当前页面的切换组，规则不变：只有一项可选的组不显示，组名没写显示"状态"）。切换栏里没有方案按钮，也没有"这份原型有 N 个方案，点这里切换对比"提示框。
- 框上方一行左侧："▼ 被设计的页面：只有这个框里的内容要实现"，后面是"页面名 · 画面名"（只有一项可选的组不写），不显示方案名；原来的方案标签（`option-pill`）去掉。
- 点方案按钮：隔离框重新载入这个方案的当前画面，页面、画面选中项不变，切换栏"当前："跟着变；不登记任何决定。
- 框上方一行放不下时折行：右侧按钮整组换到下一行靠右，明暗按钮始终在最后。6 个方案名各 20 字时，窗口宽 390、761、1440 像素都没有横向滚动条。
- 窗口宽度不超过 760 像素：从上到下切换栏、框上方一行、隔离框、说明区；切换栏右边缘虚线换成底边虚线（现有媒体查询保留）。
- 其余现有行为全部保持：标题、数据 JSON、textarea 里的页面、`<base href="about:srcdoc">`、说明区三块和三分之一高度上限、不引用外部文件、相同输入输出相同。

## 成品定义
外框样式里的颜色变量块，原样落盘（其余 CSS 按上面的规则改写，沿用现有类名风格）：

```css
:root{--bg:#d5dae1;--line:#b7bfca;--text:#1d2633;--muted:#4f5b6b;--accent:#47607f;--pick-bg:#c2cad5;--pick-text:#1d2633;--grid:rgba(71,96,127,.06)}
:root[data-theme=dark]{--bg:#26282c;--line:#3a3d43;--text:#d4d4d4;--muted:#8f949b;--accent:#8e9aa8;--pick-bg:#33363c;--pick-text:#e6e6e6;--grid:rgba(255,255,255,.03)}
```

## 函数清单
### src/modules/requirement/prototype-frame.ts
| 函数名 | 职责 |
|---|---|
| `FRAME`（模板常量） | 改样式：用上面的变量块，`body` 统一底色和网格；删去 `--rail`、`--stage`、`--label`、`--accent-ink`、`.option-box`、`.option-title`、`.option-foot`、`.option-pill`；新增框上方右侧按钮区、明暗按钮组和切换栏"当前："两行的样式；选中按钮改成细线框加浅填充 |
| `FRAME` 内脚本 `applyTheme` | 设置 `<html data-theme>` 并更新两个明暗按钮的 `aria-pressed` |
| `FRAME` 内脚本 `initTheme` | 按系统外观初始化，监听系统外观变化（没点过按钮时才跟），绑定两个按钮；不支持监听时跳过 |
| `FRAME` 内脚本 `render` | 方案按钮画到框上方右侧、明暗按钮左边；切换栏顶部画"当前："两行；框上方左侧只写页面 · 画面 |
| `buildPrototypeFrame` | 不改 |

## 协作关系
`submitDesign`（`requirement-prototypes.ts`）调 `buildPrototypeFrame` 拼文件，调用方不变。主题脚本放在渲染脚本之前，渲染出错时明暗仍能切。

## 验证方式
- 测试入口：`buildPrototypeFrame(input)` 的返回字符串（`tests/prototype-frame.test.ts`）；人工：exec 用 Playwright MCP 打开拼好的文件逐项看。
- 测试输入：带 4 个方案、2 个页面的输入；没有方案的输入；6 个 20 字方案名的输入。
- 预期结果：
- [ ] 输出含成品变量块里两套全部色值，含 `prefers-color-scheme`、`☀ 明亮`、`☾ 暗黑`、`data-theme`
- [ ] 输出不再含 `#0a2744`、`#6fd6ff`、`option-box`、`option-pill`、`这份原型有`、`点这里切换对比`
- [ ] 输出含 `当前：`、`最后选哪个，在“确认原型”窗口里定`、`方案`（右上角标签文字）
- [ ] 原有测试里的固定文字、转义、JSON、无外部引用、确定性、`<base>`、三分之一上限、`flex-wrap:wrap` 断言继续通过（"蓝图风格"那条改成新色值断言）
- [ ] Playwright 人工核对（截图放 `.bb-spec/.cache/ui-compare/`）：浅色系统打开选中明亮、深色系统选中暗黑；点暗黑后切系统外观不跟；4 个方案时右上角顺序为"方案"、A–D、明暗；点方案 C 后隔离框换内容、左栏"当前：方案 C"、页面画面选中项不变；切主题前在页面输入框里打的字切完还在；6 个长方案名在 390、761、1440 宽下 `document.documentElement.scrollWidth <= innerWidth`；390 宽下顺序为切换栏、框上方一行、隔离框、说明区
