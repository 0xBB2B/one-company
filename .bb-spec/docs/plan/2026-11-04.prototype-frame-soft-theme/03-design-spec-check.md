# DESIGN.md 内容检查

## 目标
有一个纯函数模块，能判定一份 DESIGN.md 全文合不合格（不合格时给出 PRD 规定的原因文字），能按十章顺序列出两份全文之间内容有变化的章。

## 业务规则（来源：PRD design-spec-file C-2 到 C-8）
- 读全文前先去掉开头的 BOM（`\uFEFF`），把 `\r\n` 统一成 `\n`；检查和按章比较都在统一后的文字上做。字节上限按交来的原文算。
- 全文最大 16384 字节（UTF-8）；超过时原因"DESIGN.md 有 <N> 字节，超过 16384 字节上限"。
- 十章，每章一个二级标题，文字一字不差，按这个顺序列名：风格、颜色、字体、间距、圆角与阴影、布局、组件、状态、无障碍、终端界面。章的正文是从 `## <章名>` 下一行到下一个 `## ` 之前；章名是 `## ` 后面去掉首尾空白的文字。十章是最低要求，可以另加别的二级标题章，程序不查新加章的内容。任何章名出现两次：原因"DESIGN.md 的「<章名>」章出现了两次，合成一章"（按出现顺序报第一个重复的）。缺章原因"DESIGN.md 缺少「<章名>」章"（多一字少一字都算缺；按十章顺序报第一个缺的）。
- 必填项每行写成 `- <项名>：<值>`，冒号可以是"："或":"，值去掉首尾空白。章里其他行不管。同一章（颜色章是同一节）里同一个必填项写了两行：原因"DESIGN.md「<章名>」的「<项名>」写了两次，只留一行"（颜色章的章名写成"颜色 · <节名>"），这一项先查重复再查缺项和格式。缺项原因"DESIGN.md「<章名>」缺少「<项名>」"；格式不对原因"DESIGN.md「<章名>」的「<项名>」要写成<格式说明>，如<例子>"。按章顺序、项顺序报第一个问题。
- 必填项与格式（格式说明 / 例子）：
  - 风格：主题（"明亮"、"暗黑"或"明亮、暗黑" / 明亮、暗黑）；参考设计体系（设计体系名称或"无" / Ant Design 5）
  - 颜色：按风格章主题分节，节是三级标题 `### 明亮`、`### 暗黑`，颜色章里同一个三级标题出现两次时原因"DESIGN.md「颜色」的「<节名>」一节出现了两次，合成一节"（先于缺节检查）；缺节原因"DESIGN.md「颜色」缺少「<节名>」一节"；每节项：主色、主色悬停、文字、次要文字、禁用文字、边框、背景、卡片背景、成功、警告、出错、提示（# 加 6 位十六进制 / #0f766e）。节内缺项、格式错的原因里章名写成"颜色 · <节名>"
  - 字体：字体（字体名，多个用英文逗号隔开 / Inter, PingFang SC）；标题 1 字号、标题 2 字号、标题 3 字号、正文字号、辅助文字字号（像素 / 14px）；正文行高（倍数 / 1.5）；常规字重、加粗字重（100 到 900 之间的整百数 / 400）
  - 间距：基本单位（像素 / 4px）；档位（一组像素值，用英文逗号或顿号隔开 / 4px、8px、16px）
  - 圆角与阴影：小圆角、大圆角（像素 / 4px）；卡片阴影、弹窗阴影（CSS 阴影值或"无" / 0 1px 2px rgba(0,0,0,.08)）
  - 布局：内容区最大宽度、页面边距、手机平板分界、平板桌面分界（像素 / 1200px）；侧栏宽度、顶栏高度（像素或"无" / 240px）
  - 组件：按钮高度、按钮左右内边距、输入框高度、表格行高、弹窗宽度、图标尺寸（像素 / 32px）
  - 状态：加载中出现时间、动画时长（毫秒 / 300ms）；提示条消失时间（毫秒或"不自动消失" / 3000ms）
  - 无障碍：正文最低对比度、图标和边框最低对比度（比值 / 4.5:1）；焦点框宽度（像素 / 2px）；最小点击区域（宽×高像素 / 44×44px，乘号"×"或"x"）
  - 终端界面：每行列数（正整数 / 80）；成功颜色、警告颜色、出错颜色、提示颜色（红、绿、黄、蓝、品红、青、白、灰之一 / 绿）。章正文去掉空行后只有一行"无"时，这章合格、不查必填项。
- 值的判定：像素 `^\d+(\.\d+)?px$`；毫秒 `^\d+ms$`；色值 `^#[0-9a-fA-F]{6}$`；比值 `^\d+(\.\d+)?:1$`；点击区域 `^\d+[×x]\d+px$`；行高 `^\d+(\.\d+)?$`；字重 100–900 的整百；其余"名称"类非空即可。
- 间距：档位每一项都是基本单位的整数倍，否则原因"DESIGN.md「间距」的档位 <值> 不是基本单位 <值> 的整数倍"。
- 无障碍下限：正文最低对比度不低于 4.5:1、图标和边框最低对比度不低于 3:1，否则原因"DESIGN.md「无障碍」的「<项名>」写的是 <写的值>，不能低于 <下限>"（下限写"4.5:1"或"3:1"）。
- 实算对比度（WCAG 2.1 相对亮度公式）：每节里文字和背景、次要文字和背景不低于正文最低对比度；主色和背景不低于图标和边框最低对比度；按文字、次要文字、主色顺序报第一个。原因"DESIGN.md「颜色 · <节名>」里<项名> <色值> 和背景 <色值> 的对比度是 <实算值保留两位小数>:1，低于「无障碍」写的<阈值项名> <写的值>"。实测：`#999999` 对 `#ffffff` 为 2.85，`#6b7280` 对 `#ffffff` 为 4.83，`#0f766e` 对 `#ffffff` 为 5.47。
- 检查顺序：字节数 → 重复章 → 缺章 → 各章必填项与格式（章顺序，颜色章先查重复节、缺节）→ 间距倍数 → 无障碍下限 → 实算对比度。
- 按章比较：两份全文都先统一（去 BOM、统一换行），再切成"开头"（第一个 `## ` 行之前的文字）和各章（从 `## ` 那一行起到下一个 `## ` 之前，连标题行一起，原样不去空白）。返回内容不同的章名：先按十章顺序列十章里不同的，再按新全文里的出现顺序列其他章里不同或新加的，再按旧全文里的顺序列被删掉的其他章，最后开头不同时加"开头的说明"。只调换章的顺序时返回空数组。以前的全文为空（文件不存在）时由调用方另行处理，不调用这个函数。

## 函数清单
### src/modules/requirement/design-spec.ts
| 函数名 | 职责 |
|---|---|
| `DESIGN_SPEC_FILE`、`DESIGN_SPEC_MAX_BYTES`、`DESIGN_CHAPTERS` | 常量：文件名 `DESIGN.md`、16384、十章名顺序 |
| `DesignSpecError` | 检查不合格时抛出，`message` 就是上面规定的原因文字 |
| `checkDesignSpec` | 按检查顺序判定全文，不合格抛 `DesignSpecError` |
| `normalizeDesignSpec` | 去掉开头 BOM，`\r\n` 统一成 `\n` |
| `designChapters` | 把统一后的全文按 `## ` 切成章名到正文的对应 |
| `changedChapters` | 按十章顺序列出两份全文里正文不同的章名 |
| `contrastRatio` | 按 WCAG 2.1 公式算两个色值的对比度 |

## 协作关系
本模块只依赖标准库，不读写文件、不碰数据库。`requirement-prototypes.ts` 交稿时调 `checkDesignSpec`，确认窗口算改动时调 `changedChapters`，P17 判定调 `checkDesignSpec`。

## 验证方式
- 测试入口：`checkDesignSpec`、`changedChapters`、`contrastRatio`（`tests/design-spec.test.ts`）。
- 测试输入：成品定义里的合格全文，及在它上面逐一删章、删项、改格式、改值的变体。
- 预期结果：
- [ ] 合格全文不抛错；把"："换成":"仍不抛错；主题只写"明亮"并删掉 `### 暗黑` 一节仍不抛错；终端界面章改成完整必填项仍不抛错
- [ ] 16384 字节（补空白行凑够）不抛错，16385 字节抛错，原因与规则一致
- [ ] 十章逐一删掉标题各抛错，原因写对章名；`## 颜色们` 算缺"颜色"
- [ ] 每个必填项逐一删掉各抛错，原因写对章名、节名和项名；每种格式各给一个错值各抛错，原因写对格式说明和例子
- [ ] 基本单位 4px、档位含 10px 抛"档位 10px 不是基本单位 4px 的整数倍"
- [ ] 正文最低对比度写 4:1、图标和边框最低对比度写 2.5:1 各抛错，原因写明写的值和下限
- [ ] 明亮一节次要文字改 `#999999` 抛错，原因含"2.85:1"和"正文最低对比度 4.5:1"；主色改 `#a7f3d0` 抛错，原因写图标和边框最低对比度 3:1；暗黑一节文字改 `#3f3f46` 抛错
- [ ] `contrastRatio("#999999","#ffffff")` 保留两位为 2.85，`#0f766e` 对白为 5.47
- [ ] 多加一章 `## 图表`（任意内容）不抛错；`## 颜色` 出现两次、`## 图表` 出现两次各抛"出现了两次，合成一章"；明亮一节"主色"写两行抛"写了两次，只留一行"；`### 明亮` 出现两次抛"一节出现了两次，合成一节"；带 BOM 且用 `\r\n` 换行的合格全文不抛错
- [ ] `changedChapters` 只改组件章时返回 `["组件"]`；改颜色和组件时返回 `["颜色","组件"]`；完全相同返回 `[]`；只把某章正文末尾多加一个空格也算这章变了；新加 `## 图表` 返回 `["图表"]`；删掉 `## 图表` 返回 `["图表"]`；只改第一行标题 `# 界面设计规范` 返回 `["开头的说明"]`；同样内容一份 `\r\n` 一份 `\n` 返回 `[]`；只调换两章顺序返回 `[]`
