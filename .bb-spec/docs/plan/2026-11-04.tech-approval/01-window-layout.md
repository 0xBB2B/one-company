# 问答窗口为技术清单补齐排版能力

## 目标
`src/core/host/question-window.ts` 能画出原型确认过的技术清单窗口：清单可滚动，确认问题和选项固定在下面，Esc 提示单独一行。

## 业务规则（来源：PRD 01-tech-list-window）
- 窗口外观沿用现有提问窗口：上下横线、灰色标题行、↑↓ 选择、回车确认、Esc 暂不回答。
- 排版（80 列）：灰色标题行“提问 · <需求名>（第 N 版）”，空一行，加粗“要引入的新技术（共 N 项）”；PM 上报打开时标题下多一行“PM 拆计划时发现需要 · 卡住的任务：<任务编号> <任务标题>”；空一行后逐项 4 行：第一行“<编号>. <名称>  <类别> · <来源>”，编号和名称加粗、来源黄色（主题色 warning），后三行缩进 4 格、灰色，依次“用途：”“为什么非它不可：”“备选为什么不选：”；项与项之间空一行。放不下时续行和本行文字起点对齐。
- 清单下面空一行，是加粗的确认问题“上面 N 项新技术，同意引入吗？”，再空一行是两个选项“1. 全部同意”“2. 写修改意见”，各带一行灰色说明，都不标“推荐”；光标默认在“全部同意”。
- “写修改意见”就是“其他”输入行：显示名改成“写修改意见”，下面要有一行灰色说明；光标在这里时出现输入框，Shift+Enter 换行，回车提交，空的不提交。
- 底部提示分两行：第一行是按键提示（普通时“↑↓ 选择 · 回车确认”，能滚动时末尾加“ · Shift+↑↓ 滚动内容”，输入时“直接输入 · 回车确认 · Shift+Enter 换行 · ↑↓ 选择”），第二行是“Esc 暂不回答（清单保留，之后在对话里回答也行）”。Esc 段单独占一行只用于这个窗口，其他窗口的提示不变。
- 放不下时只有标题和清单这部分滚动，顶部/底部显示“↑ 上面还有 N 行”“↓ 下面还有 N 行”；确认问题、选项、底部提示一直显示。终端 40 行高时窗口最多 24 行（沿用 HEIGHT_RATIO 0.6）。
- 按 Esc 返回 undefined（暂不回答）。

- `tests/question-window.test.ts` 修改

## 函数清单
### src/core/host/question-window.ts
| 函数名 | 职责 |
|---|---|
| `WindowLine`（类型） | 增加可选的分段写法：一行由多段组成，每段可单独指定颜色（沿用 LineTone）和是否加粗；增加可选的续行缩进，折行时续行按它缩进 |
| `WindowQuestion`（类型） | 增加三个可选字段：选项上方固定显示、不随内容滚动的加粗问题；“其他”行下面的灰色说明；Esc 提示单独占一行的开关 |
| `QuestionWindowView.render` | 按新字段排版：分段行着色、续行缩进；有固定问题时放在内容与选项之间；“其他”行在名称下显示说明；开关打开时底部提示把 Esc 段单独放第二行 |
| `QuestionWindowView.compose` | 计算高度时把固定问题算进不滚动的部分，只让内容部分滚动 |
| `techListWindow` | 新增导出：标准颜色、单个问题的窗口入口，供技术清单使用，返回 WindowAnswer 或 undefined；和 askWindow 一样经 showWindow 排队打开 |

## 协作关系
- `techListWindow` → `showWindow` → `openProgramWindow`（已有，窗口排队、上报“在等用户”状态）。
- 技术清单的内容由 interaction 模块拼成 WindowQuestion 后调用（见本主题 02、03），本文件不认识“技术”这个业务概念。
- 现有 askWindow、confirmWindow、chooseWindow、chooseOrWriteWindow 的渲染结果不变：已有测试 `tests/question-window.test.ts` 全部照常通过。

## 验证方式
- 测试入口：`QuestionWindowView`（`tests/question-window.test.ts` 里已有的 view() 帮助函数，主题函数把颜色写成 `<muted>…</>`、`<warning>…</>`、`<b>…</b>` 标记）。
- 测试输入：一个 WindowQuestion：caption“提问 · 图书馆借还系统（第 2 版）”、question“要引入的新技术（共 4 项）”、lines 为原型 4 项（分段：编号名称加粗、来源 warning；三行说明 muted、缩进 4）、固定问题“上面 4 项新技术，同意引入吗？”、choices [“全部同意”带说明]、allowOther 且显示名“写修改意见”带说明、escapeHint“Esc 暂不回答（清单保留，之后在对话里回答也行）”、Esc 单独一行开关打开。
- 预期结果：
  - [ ] 80 列宽渲染后去掉颜色标记的每一行，与原型“新项目：4 项”画面逐行一致（见本文件业务规则里的排版）；两个选项后面没有“推荐”。
  - [ ] 打开时光标在“全部同意”；按 ↓ 后“写修改意见”下出现输入框，底部第一行变成“直接输入 · 回车确认 · Shift+Enter 换行 · ↑↓ 选择”，第二行仍是 Esc 句；输入“后端换成 Java，数据库换成 MongoDB”回车，返回 `{ choices: [], other: "后端换成 Java，数据库换成 MongoDB" }`；输入框为空时回车不返回。
  - [ ] 终端 rows=40、6 项清单：渲染不超过 24 行，内容末尾“↓ 下面还有 22 行”，固定问题和两个选项完整可见，底部第一行末尾有“Shift+↑↓ 滚动内容”；滚到底后顶部出现“↑ 上面还有 22 行”。
  - [ ] 一项说明超过一行时，续行从缩进处开始，不回到第 1 列。
  - [ ] 按 Esc 返回 undefined。
  - [ ] 不设新字段时，现有全部窗口测试输出不变。
