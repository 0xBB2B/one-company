# 步骤窗口的边框和折行

## 目标
步骤窗口四边都有边框，所有文字放不下时折行显示完整；步骤区一次滚一行，"上面还有 N 步 / 下面还有 M 步"按每一步第一行的位置计数。

## 业务规则（来源：PRD 01-step-window-wrap）
- 边框占满终端宽度：第一行"╭" + "─"… + "╮"；标题与状态行下面、步骤区下面各一行"├" + "─"… + "┤"；最后一行"╰" + "─"… + "╯"。中间每行以"│ "开头、" │"结尾，右边"│"在最后一列（每行显示宽度正好等于 width）。
- 标题、状态行（含失败原因）、每一步文字、读不到步骤时的说明、底部提示：放不下就折行，一个字不少，不加"…"。
- 一步折行后，接着写的行开头空出"图标 + 空格"的宽度（2 列），和第一行文字对齐；codemode 下缩进两格的步骤，接着写的行空 4 列。
- 窗口总行数不超过终端高度减 1：步骤区可用行数 = 终端高度 − 1 − 其余行实际行数（4 行边框和分隔线 + 标题行数 + 状态行行数 + 提示行数），最少 3 行；标题、状态、提示各 1 行时等于现在的 rows − 8。
- 步骤区放不下时 ↑↓ 一次滚一行。上面有盖住的行时第一行写"↑ 上面还有 N 步"，下面有盖住的行时最后一行写"↓ 下面还有 M 步"（灰色）。N = 第一行在可见区上方的步数；M = 第一行在可见区下方的步数，"思考中"不算。可见区最上面可以是某一步的后半截（没有图标）。
- 打开时显示在最底下；在最底下时新步骤或某一步变长都自动滚到最后一行；翻上去后不跳动，只更新 M；翻回最底下恢复跟随。
- 终端宽度变了，下一次 render 按新宽度重新折行。
- 已有行为不变：标题、状态行、步骤的文字内容与颜色；读取中、读不到步骤、各状态图标；Esc 关闭；控制字符换成空格（`clean`）。

## 函数清单
### src/modules/panel/step-window.ts
| 函数名 | 职责 |
|---|---|
| `StepWindow.render` | 改：画四边框；标题、状态行、提示折行；按 C-4 算步骤区高度后调用 `visible` |
| `StepWindow.resize` | 改：只记终端行数，步骤区高度改在 render 里按实际折行结果算 |
| `StepWindow.handleInput` | 改：↑↓ 按行滚动，最大起点和跟随判断按折好的行数算 |
| `StepWindow.visible` | 改：把每一步折成多行（续行按缩进对齐），按行切出可见区，按每步第一行位置算 N、M |
| `StepWindow.stepLines` | 新增：按内容宽度把 `items()` 展开成行列表，每行带"属于第几步、是否第一行、是否思考中" |
| `StepWindow.maxStart` / `StepWindow.start` | 改：参数从步数改为行数 |

外部依赖：`@earendil-works/pi-tui` 的 `wrapTextWithAnsi`（项目已在用）、`visibleWidth`。折行时先折纯文字再上色，避免着色码被切开；`truncateToWidth` 在本文件里不再需要时删掉 import。

## 协作关系
`render(width)` → 内容宽度 = width − 4 → 折标题、状态行、提示 → 算步骤区高度 → `visible` → `stepLines` → `items()`。`handleInput` 需要最近一次 render 的宽度和步骤区高度来算行数，render 时记下这两个值。`openStepWindow` 不改。

## 验证方式
- 测试入口：`tests/step-window.test.ts` 里直接 `new StepWindow({ title, now, onClose })`，调用 `apply(view)`、`resize(columns, rows)`、`handleInput("\x1b[A" / "\x1b[B")`、`render(width)`，断言返回的字符串数组（不带 theme 时没有着色码）。
- 测试输入：标题 300 字；某一步 200 字符路径、110 字符命令；codemode 子步骤长文字；40 步其中 12 步各两行；失败原因 120 字；读不到步骤；宽度 80 和 60；行数 24 和 10。
- 预期结果：
  - [ ] 80 列下每行 `visibleWidth` 都是 80；首行"╭…╮"、两条"├…┤"、末行"╰…╯"，其余行首尾都是"│"（AC-1、AC-7 在 60 列同理）
  - [ ] 标题去掉边框和首尾空格后连起来等于原文；任何一行不以"…"结尾；200 字符路径那一步折成 3 行、连起来是"读 <完整路径>"；失败原因完整（AC-2）
  - [ ] 续行在"│ "之后空 2 列（codemode 子步骤空 4 列）（AC-3）
  - [ ] 24 行、标题 4 行时步骤区最多 13 行、窗口 ≤ 23 行；标题 1 行时步骤区 16 行；10 行终端标题 4 行时步骤区仍有 3 行（AC-4）
  - [ ] 40 步、步骤区 16 行，从底部按 ↑ 一次可见区整体下移一行；N + M + 可见区露出第一行的步数 = 40；可见区第一行是某步第二行时该步算进 N（AC-5）
  - [ ] 底部时新增两行的一步，最后两行是它；↑ 后新增一步内容不变、M 加 1；↓ 回底后新增一步最后一行是它（AC-6）
  - [ ] 原有测试里与截断无关的断言（图标、颜色、状态文字、读取中、读不到、Esc）照旧通过
