# 面板行保留尾部参数

## 目标
状态面板上带尾部参数的行，名字放不下时只截名字，尾部参数（轮数、耗时等）完整显示在行尾。

## 业务规则（来源：PRD 02-panel-keep-tail）
- 尾部参数：一行里名字后面表示用量的那串文字。截短时：行首前缀（树枝符号、图标）保留 + 名字截短并以"…"结尾 + 完整尾部参数。
- 各行的名字和尾部参数：
  - 需求行：名字 = 目标；尾部 = " · 任务 a/b"（有计划时）+ " · ↻N · K tool uses · X token (P%)"（无缓存率不写括号）+ " · 耗时"。
  - 执行行：名字 = "T3 执行 · <定义名>（第 N 次尝试）"；尾部 = "· ↻a/b · 耗时"（现有拼法 `runSuffix(...).trimStart()`）。
  - 审查代理行：名字 = 定义名和状态文字（如"✓ reviewer 通过""– vue-reviewer 2 次没交出结论，本轮结束后交你裁决"，含转圈或 ✓ ✗ – 图标）；尾部 = " · ↻a/b · 耗时"；"已关闭/已不存在，本轮未审"没有尾部。
  - PM 派出的检索行：名字 = "explore 检索"；尾部 = " · ↻a/b · 耗时"。
  - 原型设计行：名字 = "<原型名>（第 N 版）"；尾部 = "· <设计师定义名> · ↻a/b · 耗时"。
  - 主窗口检索行：名字 = "联网/本地 · <问题>"；尾部 = " · ↻a/b · 耗时"。
  - 已结束行：名字 = "<结果> · <标题>"；尾部 = " · ↻a/b · 耗时"，原来是原型设计时前面再加"· <设计师定义名>"；"读取中… · <标题>"没有轮数耗时，原型设计的仍保留"· <设计师定义名>"。
  - 没有上限时轮数写"↻N"。
- 整行放得下：和现在完全一样，不加"…"。
- 留给名字的宽度不到 2 列时：整行从行尾截断加"…"（现在的做法）。
- 没有尾部参数的行照旧从行尾截断：分组标题、⚑ 事项行、"在做什么"行、"T1 第 2 轮审查"任务行、按键提示。
- 每行显示宽度不超过终端宽度，不折行；选中行蓝底、各段颜色不变。
- 决策理由：从行尾截断时最先丢的是最有用的轮数和耗时（用户 2026-11-05 决定）。

## 涉及文件
- 修改 `src/modules/panel/pm-panel.ts`
- 修改 `tests/pm-panel.test.ts`（补长名字、窄终端用例；现有断言照旧通过）

## 函数清单
### src/modules/panel/pm-panel.ts
| 函数名 | 职责 |
|---|---|
| `PmPanel.fitTail` | 新增：给定前缀、名字、尾部参数和宽度，按上面规则输出一行（名字截短 / 整行截断 / 原样），文字先经现有 `fit` 的清洗 |
| `PmPanel.render` | 改：需求行、原型设计行、主窗口检索行、已结束行改用 `fitTail` |
| `PmPanel.taskLines` | 改：执行行、PM 派出的检索行按名字和尾部分开，交给 `fitTail`（选中时）或按段截断（未选中时） |
| `PmPanel.reviewerLine` | 改：名字和尾部分开，选中与未选中两种着色都保证尾部完整 |
| `PmPanel.segments` | 改或沿用：按段截断时最后一段（尾部）优先保留，前面的名字段让出宽度；颜色仍按段上色、着色码不被切开 |
| `prototypeTitle` / `ended` 行拼装 | 改：能分别拿到"<原型名>（第 N 版）"和"· <定义名>"，供原型设计行和已结束行拆名字与尾部；步骤窗口标题（`openSteps` 的 title）仍是完整的"<原型名>（第 N 版）· <定义名>" |

外部依赖：`@earendil-works/pi-tui` 的 `truncateToWidth`、`visibleWidth`（已在用）。

## 协作关系
`render` / `taskLines` / `reviewerLine` → `fitTail`（选中行，整体再 `mark` 上蓝底）或 `segments`（未选中、分段着色）。`Row.title`（传给步骤窗口的标题）内容不变。

## 验证方式
- 测试入口：`tests/pm-panel.test.ts` 现有方式——构造 `PmPanel`，`update` / `updateExplores` / `updatePrototypes` 喂概览数据，`focus()` 后 `render(width)` 取行；不带 theme 时没有着色码。
- 测试输入：300 字的主窗口检索问题（↻5/12、51.9s）；名字很长的原型设计（第 1 版、prototype、↻5/10、4m49s）；目标很长的需求（任务 2/5、↻9、30 tool uses、1.2M token、85%、3m5s）；定义名很长的执行行；名字很长的审查代理行（↻40/40、12m3s）；已结束行（含原型设计的）；100 字的 ⚑ 事项与"在做什么"；宽度 80 和 40。
- 预期结果：
  - [ ] 80 列：检索行以"· ↻5/12 · 51.9s"结尾，"· ↻"前紧挨"…"，宽度 ≤ 80（AC-1）
  - [ ] 80 列：原型设计行以"· prototype · ↻5/10 · 4m49s"结尾、不含"（第 1 版）"、"· prototype"前紧挨"…"（AC-2）
  - [ ] 80 列：需求行、执行行、审查代理行、已结束行（含原型设计的"· prototype · ↻12/12 · 2m3s"）以各自完整尾部结尾，名字以"…"结尾（AC-3）
  - [ ] 名字放得下时整行和改动前一模一样（AC-4）
  - [ ] 40 列：需求行整行以"…"结尾、宽度 ≤ 40；原型设计行等于"└─ ⠹ 桌面接…· prototype · ↻5/10 · 4m49s"（转圈帧为测试时的帧）（AC-5）
  - [ ] 80 列：100 字 ⚑ 事项行、"在做什么"行以"…"结尾（AC-6）
  - [ ] 80、40 列每行宽度 ≤ 终端宽度；选中行带 selectedBg（有 theme 时）（AC-7）
