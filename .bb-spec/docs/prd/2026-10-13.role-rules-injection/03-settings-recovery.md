# 设定栏：清除与出错

设定栏：/one:agents 分类栏最右边的一栏，管 PM、解释器、草稿核验器的模型和思考等级，分用户层和项目层（项目层优先，项目受信任才生效），存在 pi 设置文件的 one-company 字段下。问题栏：/one:agents 里列出写错、没生效的文件及原因的那一栏。

## 用户故事
### P0：作为改错了设定的用户，我想要一键恢复
**用例（主路径）**
- 场景：PM 那行的来源是"项目"。
- 操作：选中 PM 按 R。
- 预期：项目层的 PM 设定被删掉，改用用户层的；用户层也没有，就用内置默认值；底部写出现在用的值。

### P1：作为登录过期的用户，我想要一眼看出哪个设定用不了
**用例（异常）**
- 场景：解释器设定的模型已经没有可用凭据。
- 操作：打开设定栏。
- 预期：解释器那行的模型标红，写明"没有可用的凭据，批准需求时解读会失败；回车重新选"；批准需求时报错并说明原因，不会自动换成别的模型。

### P1：作为升级前同名复制过 PM 定义的用户，我想要知道旧文件已经没用了
**用例（边界）**
- 场景：用户层的角色定义目录里还留着一份 PM 定义文件。
- 操作：打开 /one:agents。
- 预期：问题栏里有这份文件，写明"已不再使用定义文件，请在设定栏修改"。

## 约束
- C-1：按 R 时，来源是用户层或项目层的，删掉那一层的这一项，改用下一层，并提示现在用的值；来源是内置的，提示"已经是内置默认值"，不做任何改动。
- C-2：某一层的某一项写错（模型写法不对、思考等级不认识、格式不对），或者整个设置文件不是合法的 JSON 时，写错的部分不生效，改用下一层；问题栏写明是哪个文件、哪一项、原因。
- C-3：设定的模型本机没有可用凭据时，设定栏那一行的模型标红，并写明后果；真正用到它时报错说明原因，不自动换成别的模型。
- C-4：用户层或项目层的角色定义目录里还有 PM、解释器、草稿核验器的定义文件时，这些文件不生效；问题栏写明"已不再使用定义文件，请在设定栏修改"。

## 验收
### AC-1 清除本层 ← C-1
- 触发：按 R
- Given：PM 来源为"项目"、用户层没有 PM 设定；解释器来源为"内置"
- When：分别在两行按 R
- Then：PM 改回内置默认值，项目设置文件里的这一项被删掉，文件里其他内容不变；解释器那行提示"已经是内置默认值"，两层文件都没变

### AC-2 清除后改用用户层 ← C-1
- 触发：按 R
- Given：PM 用户层设为 A、项目层设为 B
- When：在 PM 行按 R
- Then：来源变成"用户"，模型显示 A

### AC-3 写错不生效 ← C-2
- 触发：打开 /one:agents，或启动 PM
- Given：项目层 PM 的思考等级写成 "super"，用户层 PM 设为 A
- When：查看 PM 用的值和问题栏
- Then：PM 用 A；问题栏写明项目设置文件里 PM 的思考等级写错了

### AC-4 整个文件坏了 ← C-2
- 触发：打开 /one:agents
- Given：用户层设置文件不是合法的 JSON
- When：查看设定栏和问题栏
- Then：三行都用项目层的值或内置默认值；问题栏写明这个文件读不了

### AC-5 没凭据标红并报错 ← C-3
- 触发：打开设定栏，然后批准一个需求
- Given：解释器设定的模型没有可用凭据
- When：查看设定栏和批准结果
- Then：那行模型标红并写明后果；批准时报错，说明是哪个模型没有凭据，不会换成别的模型

### AC-6 旧定义文件提示 ← C-4
- 触发：打开 /one:agents
- Given：用户层的角色定义目录里有 PM 的定义文件，里面写了模型 C
- When：查看问题栏和 PM 用的值
- Then：问题栏写明"已不再使用定义文件，请在设定栏修改"；PM 用的不是 C，而是设定栏里的值

## 验证路径
1. 把 PM 存到项目层后按 R → 改回下一层（AC-1、AC-2）。
2. 把项目层设定写错、把用户层文件弄坏 → 问题栏各有一条，取值落到下一层（AC-3、AC-4）。
3. 退出模型服务登录 → 设定栏标红，批准需求时报错（AC-5）。
4. 放一份旧的 PM 定义文件 → 问题栏提示，不生效（AC-6）。
