# 项目设置文件受保护

项目设置文件：项目目录里给 pi 用的那份设置文件。pi 从它读取这个项目的扩展包等设置，设定栏的项目层设定也存在这里。用户层设置文件：用户目录下给 pi 用的那份设置文件，对所有项目生效，设定栏的用户层设定存在这里。

## 用户故事
### P0：作为用户，我想要子代理改不了 pi 的设置文件
**用例（主路径）**
- 场景：PM 给某个 worker 任务的写入范围列进了项目设置文件。
- 操作：worker 用受控写文件去改它，再用验证命令去改它。
- 预期：两次都写不进去；受控写文件那次写明原因，并告诉它这个文件不能改。

**用例（边界）**
- 场景：用户自己在 /one:agents 的设定栏把 PM 存到项目层。
- 操作：保存。
- 预期：照常写进项目设置文件，不受这条保护影响。

## 约束
- C-1：子代理用受控写文件写项目设置文件时，系统应拒绝，写明是哪个文件、为什么不能改；写入范围里列了它也一样。
- C-2：子代理运行的验证命令试图写项目设置文件时，写入应失败，文件内容保持不变。
- C-3：子代理运行的验证命令试图写用户层设置文件时，写入应失败，文件内容保持不变。
- C-4：用户在设定栏保存用户层或项目层设定，不受 C-1、C-2、C-3 限制。

## 验收
### AC-1 受控写文件被拒 ← C-1
- 触发：worker 写入
- Given：任务的写入范围包含项目设置文件
- When：worker 用受控写文件改它
- Then：写入被拒，原因写明这个文件受保护；文件内容不变

### AC-2 验证命令写不进 ← C-2
- 触发：worker 运行验证命令
- Given：命令内容是往项目设置文件里写一行
- When：命令运行结束
- Then：写入失败，文件内容不变

### AC-3 验证命令写不进用户层设置文件 ← C-3
- 触发：worker 运行验证命令
- Given：命令内容是往用户层设置文件里写一行
- When：命令运行结束
- Then：写入失败，文件内容不变

### AC-4 用户保存不受影响 ← C-4
- 触发：在设定栏分别保存到用户层和项目层
- Given：项目受信任
- When：查看两份设置文件
- Then：设定都已经写进去

## 验证路径
1. 让 worker 用受控写文件和验证命令各写一次项目设置文件 → 都写不进，前者有原因（AC-1、AC-2）。
2. 让 worker 用验证命令写用户层设置文件 → 写不进（AC-3）。
3. 在设定栏把 PM 分别存到用户层和项目层 → 两份文件里都出现这项设定（AC-4）。
