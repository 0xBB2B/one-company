# 职责规矩由程序注入，模型在设定栏修改

## 背景与问题
- 用户复制或自定义子代理定义后，只要改写正文，流程规矩就跟着丢了。子代理的提示词以定义正文为主体，worker、reviewer、qa、explore、pm 各自的规矩全写在正文里。例如用户把 reviewer 的正文改成一句"你是安全审查专家"，原型、依赖、需求边界、先红后绿这些检查就全没了，worker 的规矩也就没人查。
- 内置 worker 的正文写死了只适合写代码的做法，比如先写测试、按 Go 官方库风格写注释。用户的需求是做 PPT、写 Vue 时，这些规矩并不适用。
- PM、解释器、草稿核验器只用到定义里的模型和思考等级。想改它们，只能把整份定义同名复制到另一层再手改文件，不直观。
- 项目里的 pi 设置文件现在子代理能改，受控写文件和验证命令都没有保护它。这个文件里有 pi 加载哪些扩展包的设置，本需求还要把模型设定写进去。

## 目标
- 用户自定义的子代理定义只写描述就能用。正文可以为空，也可以只写专长和偏好，流程规矩照样生效。
- 只适合某类工作的写法（注释风格、语言规范）由用户写在自己定义的正文里，reviewer 按这份正文审。
- PM、解释器、草稿核验器的模型和思考等级在 /one:agents 的设定栏里改，分用户层和项目层。
- 子代理改不了项目里的 pi 设置文件。

## 非目标
- 原型改到主窗口澄清阶段设计（另立需求）。
- 用户可配置的工作流。固定流程本身不变：原型、实现、任务审查、检查轮、QA、完成报告、用户验收。
- 角色定义增加工具字段或显示工具。用户靠 skills 和 mcp 追加能力。
- 内置 Go 工程师、Vue 工程师、原型设计师这类专业定义。
- 旧的 PM、解释器、草稿核验器同名覆盖文件继续生效。

## 依赖与交付顺序
01、04 可以同时做；02 → 03 → 05（设定栏先能用，再去掉旧的 pm 栏和内部栏）。

## 整体验证路径
1. 在 /one:agents 把 worker 复制成新定义 → 新文件里有空的 skills 和 mcp，正文为空 → 让 PM 用它派一个任务 → 这次运行的会话记录里能看到 worker 的流程规矩。
2. 在这份定义的正文里写一条规范（例如"新函数要写说明注释"）→ 派 reviewer 审这个任务 → reviewer 收到的内容里有这段正文，违反时列为阻塞。
3. 在设定栏把 PM 改成另一个模型，存到项目层 → 下次启动 PM 时用的是新模型；按 R 清除后，改回内置默认值。
4. 子代理分别用受控写文件和验证命令去写项目里的 pi 设置文件 → 两次都写不进去。

## 决策记录
- **质疑结论**：用户在复制自定义时已经遇到"一改正文就乱套"，而且 reviewer 正文一改，worker 的规矩就没人查，影响整个流程。没有更便宜的替代：只在说明文档里提醒，挡不住改写正文。
- **规矩归程序，专长归用户**：被否决的做法是给每种 worker 配一个审查定义、在任务里指定。那样两份要靠人手同步，新增一种工程师还得再写一个审查定义。把 worker 正文附给 reviewer，规范只有一处来源。
- **内置正文全空，不内置专业定义**（用户 2026-10-13 决定）：正文全空后，专业定义只剩描述不同，没有意义；用户按需复制后自己写。
- **先红后绿注入，保留豁免**：没有可测行为时写明不适用，做 PPT 这类需求不会被卡住；做原型的运行不注入先红后绿。
- **测试名只写期望结果，不带需求章节编号**（用户 2026-10-13 决定）：需求编号只靠 git 查。第二个需求改同一功能时，测试名里的编号会过期。
- **Go 风格说明注释不再是所有 worker 的规矩**（用户 2026-10-13 决定）：它只适合 Go 项目。
- **工具不开放**（用户 2026-10-13 决定）：放开 pi 自带的命令和写文件工具，会绕过写入范围检查和命令沙箱，违反威胁模型"模型输出不可信"；流程工具按职责授权，加了也会被拒。用户自己开发的工具走 MCP。
- **设定放在 /one:agents 最右边一栏，不单独做页面**（用户决定）。存进 pi 自己的设置文件，统一放在 one-company 字段下（用户决定）。实测 pi 1.2.0：两层都能读到这个字段；项目不受信任时不读项目层；pi 写回自己的设置时，这个字段原样保留。
- **设定分用户层和项目层**（用户决定）：保留现在就能按项目区分模型的能力。
- **写错的那一项不生效、列进问题栏**（用户决定）：沿用现在定义文件写错时的处理，不让 PM 因为设定写错而起不来。
- **项目设置文件加保护**：模型设定写进去后，模型输出就能改 PM 用哪个模型，违反"模型输出不可信"。加保护的同时，也补上了子代理能改 pi 扩展包设置的缺口。
- **可配置工作流暂缓**（用户决定）：先用固定流程，有需要再扩展。
