# 原型设计师职责

几个词先说清楚：
- 原型：一份单个 HTML 文件的界面设计，样式和脚本都写在文件里，用户在浏览器里直接打开就能看。
- 原型设计师：一种只负责出原型的子代理职责，只能由主窗口派出。
- 主窗口、主代理：用户直接对话的那个 pi 窗口，以及在里面回答用户的模型。
- 职责规矩：程序按职责固定加进子代理提示词的流程规矩，放在定义正文之后，优先于正文，用户改不到。
- 定义正文：角色定义文件里头部设置下面的那段文字，用户在这里写专长和偏好，可以为空。

## 用户故事
### P0：作为用户，我想要在澄清需求时就让主代理派设计师出原型
**用例（主路径）**
- 场景：用户在主窗口说"设置页要支持深色模式"，主代理已建好这个需求的草稿。
- 操作：主代理派原型设计师，起名"设置页"，写明要画的界面和要求，轮数上限 30。
- 预期：设计师开始运行；面板上出现"● 1 个原型设计运行中"和"设置页（第 1 版）"这一行；设计师交出一个 HTML 文件。

**用例（异常）**
- 场景：PM 在拆计划时想派原型设计师。
- 操作：PM 发起派出。
- 预期：程序拒绝，原因写明原型设计师只能由主窗口派出。

### P0：作为有设计规范的用户，我想要自定义原型设计师，主代理按描述挑
**用例（主路径）**
- 场景：用户复制 prototype 定义为 brand-designer，描述写"按公司品牌规范出原型"，skills 写 brand-kit。
- 操作：用户说"按品牌规范出个设置页原型"。
- 预期：主代理查原型设计师这一类的定义列表，按描述挑中 brand-designer 派出；面板那一行显示 brand-designer。

**用例（边界）**
- 场景：用户点名用 brand-designer，但这份定义文件写错了、不可用。
- 操作：主代理用 brand-designer 派出。
- 预期：派出失败，主代理告诉用户这份定义用不了及原因，不改用别的定义。

### P1：作为用户，我想要在 /one:agents 里看到和复制原型设计师
**用例（主路径）**
- 场景：用户打开 /one:agents。
- 操作：切到 prototype 栏。
- 预期：看到内置的 prototype，模型显示"跟随主会话"，思考显示"跟随"；按 C 能复制。

## 约束
- C-1：当 PM 或任何子代理发起派出原型设计师时，系统应拒绝，原因写明原型设计师只能由主窗口派出。
- C-2：当主代理派出原型设计师时，系统应要求它写明：原型属于哪个需求、原型名称、要画的界面和要求、对话轮数上限（1 到 100）；缺任何一项或超出范围时拒绝派出，原因写明缺什么。
- C-3：当主代理派出原型设计师时，指明的需求不存在或主代理此时不能修改它的草稿，系统应拒绝派出，原因写明先建需求或需求当前的状态。
- C-4：当原型设计师运行时，系统应把轮数上限设进会话配置，用满即停止运行。
- C-5：原型设计师应能读仓库里的文件，不能改仓库里的文件，也不能运行验证命令。
- C-6：内置的 prototype 定义正文应为空；派出时系统应把原型设计师的职责规矩加在正文之后，并写明职责规矩优先于正文。
- C-7：原型设计师的职责规矩应包含：只交一个 HTML 文件，样式和脚本写在文件里，浏览器直接打开就能看；图形界面画出正常、空数据、加载中、出错四种状态，有交互的地方能点；终端界面用深色背景、等宽字体、80 列模拟终端窗口，多步交互按顺序画出每一步；有上一版和用户返工意见时，先读上一版，按意见改。原型设计师的职责规矩不应包含先红后绿。
- C-8：当所用定义没写模型或思考等级时，原型设计师应使用主窗口此刻的模型和思考等级；定义写了的，用定义里的。
- C-9：当原型设计师交稿时，交来的不是单个 HTML 文件或超过 1 MiB，系统应拒收，原因交回设计师，设计师可以在轮数上限内重交；拒收的稿不进确认。
- C-10：当原型设计师没交稿就结束（轮数用满、被停止、主窗口断开、运行出错、所属需求被取消、驳回或完成）时，系统应把这一版标为结束、不再算在途原型，并记下结束原因；主窗口还连着时把原因告诉主代理，断开的在重新连接后主代理查原型状态时能看到。
- C-11：主代理应能列出原型设计师这一类的定义，每条有名称、描述和来源；列表里不出现其他职责的定义。
- C-12：当主代理派出时指定了一个定义名，而这份定义不存在、不可用或不是原型设计师这一类时，系统应拒绝派出，原因写明这份定义为什么用不了，不改用别的定义。
- C-13：主代理的提示词应要求：用户点名的设计师定义优先；用户没点名时按描述挑；点名的用不了时告诉用户，不自行换别的。
- C-14：/one:agents 应在 explore 栏后、设定栏前新增 prototype 栏；栏里有内置定义 prototype，模型显示"跟随主会话"，思考显示"跟随"；右上角的内置计数相应加 1；栏底说明写"只能由主窗口派出，在澄清阶段出界面原型（单个 HTML）。"；能复制，复制出的定义归在这一栏。
- C-15：当主窗口有原型设计师在运行时，面板应显示"● N 个原型设计运行中"，每个运行一行："原型名称（第 v 版）· 定义名 · ↻已用轮数/上限 · 已用时间"；同时有需求、原型设计、检索在运行时，按需求、原型设计、检索的顺序显示。

## 验收
### AC-1 只有主窗口能派 ← C-1
- 触发：派出原型设计师
- Given：PM 运行中
- When：PM 发起派出原型设计师
- Then：被拒绝，原因写明只能由主窗口派出

### AC-2 派出要写全 ← C-2
- 触发：主代理派出原型设计师
- Given：需求草稿已存在
- When：分别缺原型名称、缺要求、轮数上限写 0 或 101
- Then：每次都被拒绝，原因写明缺什么或超出范围

### AC-3 需求必须可改 ← C-3
- 触发：主代理派出原型设计师
- Given：一次指明不存在的需求；一次指明已完成的需求
- When：发起派出
- Then：都被拒绝，原因分别写明先建需求、需求当前的状态

### AC-4 轮数上限在会话配置里 ← C-4
- 触发：派出原型设计师，轮数上限 2
- Given：设计师两轮内不交稿
- When：第 2 轮结束
- Then：运行被停止

### AC-5 只读仓库 ← C-5
- 触发：原型设计师运行中
- Given：仓库里有一个源码文件
- When：设计师读它、试图改它、试图运行验证命令
- Then：读成功；改和运行都被拒绝

### AC-6 规矩注入 ← C-6、C-7
- 触发：派出内置 prototype
- Given：定义正文为空
- When：读取这次运行的提示词
- Then：有原型设计师的职责规矩，包含 C-7 列出的每一项，写明优先于正文，不包含先红后绿

### AC-7 默认跟随主窗口 ← C-8
- 触发：派出原型设计师
- Given：主窗口用 A 模型、high；一次用内置 prototype，一次用写了 B 模型、low 的自定义定义
- When：查看两次运行用的模型和思考等级
- Then：第一次是 A、high；第二次是 B、low

### AC-8 不合格的稿拒收 ← C-9
- 触发：原型设计师交稿
- Given：一次交超过 1 MiB 的 HTML；一次交的不是 HTML
- When：交稿
- Then：都被拒收，设计师收到原因；没有弹出确认窗口；设计师在轮数内重交合格的稿后照常进入确认

### AC-9 没交稿就结束 ← C-10
- 触发：原型设计师运行中
- Given：分别让它轮数用满、被停止、主窗口断开、所属需求被取消
- When：运行结束；断开的那次重新连接后让主代理查原型状态
- Then：四次这一版都不再算在途原型，不挡批准；前两次主代理收到结束原因；断开的那次在查到的状态里能看到结束原因；需求被取消的那次设计师停止运行，结束原因写明需求已关闭

### AC-10 只列原型设计师这一类 ← C-11
- 触发：主代理列定义
- Given：有内置 prototype、用户的 brand-designer、内置 worker
- When：列出原型设计师定义
- Then：列表里有 prototype 和 brand-designer 的名称、描述、来源，没有 worker

### AC-11 点名的用不了不换 ← C-12、C-13
- 触发：主代理派出原型设计师
- Given：指定的定义名分别是不存在的、写错不可用的、worker 这一类的
- When：发起派出
- Then：都被拒绝，原因写明为什么用不了；没有用别的定义派出；主代理提示词里有 C-13 的要求

### AC-12 /one:agents 新栏 ← C-14
- 触发：打开 /one:agents
- Given：没有自定义定义
- When：查看分类栏并切到 prototype 栏
- Then：prototype 栏在 explore 栏后、设定栏前；有内置 prototype，模型"跟随主会话"、思考"跟随"；内置计数比本需求之前多 1；栏底说明文字与 C-14 一致；按 C 复制后新定义出现在这一栏

### AC-13 面板显示 ← C-15
- 触发：主窗口派出两个原型设计师，同时有一个需求和一个检索在运行
- Given：面板显示中
- When：查看面板
- Then：依次是"● 1 个需求运行中"、"● 2 个原型设计运行中"、"● 1 个检索运行中"；原型设计的每行是"原型名称（第 v 版）· 定义名 · ↻已用/上限 · 已用时间"

## 验证路径
1. 在主窗口建一个需求草稿 → 让主代理派内置 prototype 出"设置页" → 面板出现原型设计这一行，提示词里有职责规矩（AC-6、AC-13）。
2. 复制 prototype 为 brand-designer 并写上模型 → 让主代理按描述挑 → 用的是 brand-designer 和它的模型（AC-7、AC-10）。
3. 把 brand-designer 文件改坏，点名用它 → 派出失败，没有换别的（AC-11）。
4. 让 PM 试着派原型设计师 → 被拒（AC-1）。
