# 删掉 PM 的原型流程

几个词先说清楚：
- 原型：一份单个 HTML 文件的界面设计。本需求之后，原型只在主窗口澄清需求时由原型设计师出，用户通过后随需求一起批准。
- PM 的原型流程：本需求之前的做法。PM 拆计划时给要改界面的任务打上界面标记，先派 worker 出原型，用户在状态面板的"待你确认原型"事项里确认，确认后才派实现。
- 状态面板：主窗口输入栏下方列出运行中的需求、检索、原型设计和待用户处理事项的区域（原来叫 PM 面板）。

## 用户故事
### P0：作为用户，我想要原型只在一个地方出、一个地方确认
**用例（主路径）**
- 场景：一个要改界面的需求已经带着原型批准。
- 操作：PM 拆计划并派出任务。
- 预期：计划里的任务没有界面标记；PM 直接派实现，不会先派原型；状态面板里不会出现"待你确认原型"。

### P1：作为升级前有需求在做的用户，我想要事先知道该怎么办
**用例（主路径）**
- 场景：用户打算升级，手上有一个需求的计划里还带着旧的原型记录。
- 操作：用户读 README。
- 预期：README 写明升级前先把这类需求做完或取消。

## 约束
- C-1：PM 拆计划和修改计划时，任务应不再有界面标记；带界面标记的计划应被拒绝，原因写明这个标记已不存在。
- C-2：PM 应不能派出出原型的运行；PM 发起时系统拒绝，原因写明原型由主窗口在澄清阶段出。
- C-3：worker 应不能提交原型；worker 的职责规矩里应不再有"本次只做原型"那一套。
- C-4：状态面板应不再出现"待你确认原型"事项，PM 也不再收到"用户已确认原型"一类的通知。
- C-5：PM 的职责规矩和主代理的提示词里应不再提 PM 的原型流程。
- C-6：README 应删掉 PM 原型流程的说明，改写成新流程；并写明：升级前已在进行、计划里带旧原型记录的需求，先做完或取消再升级，升级后不对这类需求做处理。

## 验收
### AC-1 计划没有界面标记 ← C-1
- 触发：PM 提交计划
- Given：一份计划里有一个任务带界面标记；另一份不带
- When：提交
- Then：带标记的被拒绝，原因写明标记已不存在；不带的被接受

### AC-2 PM 不能派原型 ← C-2
- 触发：PM 派出任务
- Given：一个已在计划里的任务
- When：PM 以出原型的方式派出它
- Then：被拒绝，原因写明原型由主窗口在澄清阶段出

### AC-3 worker 不能交原型 ← C-3
- 触发：派出 worker
- Given：任意任务
- When：worker 尝试提交原型；读取它的提示词
- Then：提交被拒绝；提示词里没有"本次只做原型"的规矩

### AC-4 面板没有原型事项 ← C-4
- 触发：一个要改界面的需求从批准走到完成
- Given：批准版本带原型
- When：观察状态面板和 PM 收到的通知
- Then：全程没有"待你确认原型"事项，PM 没有收到原型确认通知

### AC-5 提示词没有旧流程 ← C-5
- 触发：启动 PM、打开主窗口
- Given：任意项目
- When：读取 PM 和主代理的提示词
- Then：没有"给任务打界面标记""PM 派 worker 出原型""在面板里确认原型"的内容

### AC-6 README ← C-6
- 触发：阅读 README
- Given：本需求合并后的版本
- When：查找原型相关内容
- Then：只描述主窗口出原型、窗口确认、随需求批准的新流程；有一段升级须知，写明先做完或取消带旧原型记录的需求再升级

## 验证路径
1. 带原型批准一个要改界面的需求 → PM 的计划没有界面标记，直接派实现，面板里没有原型事项（AC-1、AC-4）。
2. 让 PM 用出原型的方式派任务、让 worker 提交原型 → 都被拒绝（AC-2、AC-3）。
3. 读 README → 只有新流程和升级须知（AC-6）。
