# 旧版本本机数据库直接报错

## 用户故事
### P0：作为从旧版本升级上来的开发者，我想要程序一打开旧数据库就告诉我该怎么办，以便我不用面对散在各处、看不懂的格式错误

**用例（主路径）**
- 场景：开发者用改名前的版本建过需求，本机数据目录里留着旧的 `data.db`（版本号 2）。
- 操作：升级后打开 pi，主窗口连上守护进程，程序打开 `data.db`。
- 预期：报 `outdated_database`，说明写着"data.db 来自旧版本，和当前版本不兼容；请备份后删除本机数据目录并重新初始化"；`data.db` 的内容一个字节都没变，也没有生成 `-wal` 文件。

**用例（边界 / 异常）**
- 场景：本机数据目录里留着改名前的项目索引库 `index.db`（版本号 1）。
- 操作：程序打开 `index.db`。
- 预期：报 `outdated_database`，说明里写的是 `index.db`，处理办法同上；文件内容不变。

- 场景：本机数据目录里留着移除 spec 之前的 `data.db`（版本号 1）。
- 操作：程序打开它。
- 预期：和版本号 2 一样报 `outdated_database`，处理办法同上。

## 约束
- C-1：新建的 `data.db` 版本号是 3，新建的 `index.db` 版本号是 2；全局库 `global.db` 的版本号不变。
- C-2：打开版本号是 1 或 2 的 `data.db`、版本号是 1 的 `index.db`，报 `outdated_database`；说明里写明是哪个文件，并写"请备份后删除本机数据目录并重新初始化"。
- C-3：报错时不改动这个数据库文件：文件内容前后一致，不生成 `-wal` 文件。
- C-4：其他情况的打开结果和改名前一样：版本号对上的库正常打开；版本号是 0 但已有表的报 `wrong_database_kind`；比当前版本号还大的报"不支持的数据库版本"。

## 验收
- [ ] C-1：新建的 `data.db` 读出版本号 3，`index.db` 读出 2，`global.db` 读出 1。
- [ ] C-2：版本号 1、2 的 `data.db` 和版本号 1 的 `index.db` 分别打开，都报 `outdated_database`，说明里有对应文件名和"请备份后删除本机数据目录并重新初始化"。
- [ ] C-3：上述每次报错前后，文件内容一致，没有 `-wal` 文件。
- [ ] C-4：当前版本号的库能打开；版本号 0 且已有表的报 `wrong_database_kind`；版本号比当前大的报"不支持的数据库版本"。

## 验证路径
1. 跑 `pnpm test` 里的数据库存储测试 → C-1 到 C-4 的用例全部通过。
2. 拿一份改名前版本留下的本机数据目录，用新版本打开 pi → 看到 `outdated_database` 和处理办法；删掉数据目录后重新打开 → 正常初始化。
