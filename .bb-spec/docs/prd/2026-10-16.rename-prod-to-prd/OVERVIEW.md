# 需求正文从 prod 改名为 PRD

## 背景与问题
- 需求正文是用户和主代理一起写、经用户批准的需求说明，PM 和子代理按它干活。产品代码、提示词、文件路径里都管它叫 `prod`：本机正文文件叫 `prod.md`，用户项目里的归档目录叫 `docs/prod/`，提示词里写"读取当前已批准的完整 prod""不读取 prod 全文"。
- 英文开发语境里 `prod` 通常指"生产环境"。模型读到"不读取 prod"时可能理解成"别碰生产环境"，读代码的人也要先猜一下它指什么。
- 开发这个仓库用的 bb-spec 管同类文档叫 PRD，两边叫法不一致。
- 这个词在 `src/` 里出现 855 次、`tests/` 里 819 次，6 个文件名带 `prod`；本机数据库里存着 `prod.saved`、`prod.approved` 这类事件名，项目索引库里有一张 `prod_metadata` 表。

## 目标
- 产品代码、测试、提示词、根目录文档里指需求正文的词统一叫 `prd`；给人和模型读的正文写大写 `PRD`。
- 用户项目里的归档目录、本机的正文文件、Git 交付的提交说明都按新名字工作。
- 旧版本留下的本机数据库打开时明确报错，告诉用户怎么处理，不在任意位置报格式错误。

## 非目标
- 迁移旧数据：不把本机旧的 `prod.md`、数据库里的旧事件名、用户项目里已有的 `docs/prod/` 改成新名字。
- 识别或提醒用户项目里旧的 `docs/prod/` 目录；升级后它按普通目录处理。
- 在 README 里写升级须知。
- 改已合并的 PRD（`.bb-spec/docs/prd/` 下已有的 4 份）和 Git 历史里的提交说明。
- 改产品行为：除了名字和旧数据库报错，需求的起草、批准、派工、关闭、归档、交付流程都和改名前一样。

## 整体验证路径
1. 在仓库根执行 `grep -rIi 'prod' src rules role-rules agents skills shared tests README.md ARCHITECTURE.md CONTRIBUTING.md AGENTS.md | grep -vi 'produc'` → 没有输出；`git ls-files | grep -i prod | grep -vi produc` → 没有输出。
2. 跑类型检查、单元、集成、安装四项纯代码测试 → 全部通过。
3. 用新版本打开一个改名前留下的本机数据目录 → 报 `outdated_database`，说明写着"请备份后删除本机数据目录并重新初始化"，数据库文件内容没变。
4. 删掉本机数据目录后，在一个样例项目里走完一个需求：起草、批准、PM 实施、完成、关闭 → 本机需求目录里是 `prd.md`；样例项目里出现 `docs/prd/<需求编号>.<标题>.md`，没有 `docs/prod/`。
5. 跑全部真实模型验收（P1–P13、M9-AC12、M9-AC2/AC3/AC11）→ 全部通过。

## 决策记录
- **质疑结论**：目前没有证据表明模型真的把 `prod` 读成了"生产环境"，这一条是推测。代价是约 1700 处改名、全部真实模型验收（约 2–3 小时），以及升级的用户要删本机数据目录。用户 2026-10-16 决定照做，理由是叫法和 bb-spec 一致、词义没有歧义。
- **全部改，不只改给人看的字**（用户 2026-10-16 决定）：代码名、文件名、事件名、错误码、路径、提示词、README、测试一起改。被否决的是"只改提示词、工具说明、README、报错文字"：改动小，但文字说 PRD、路径还是 `docs/prod`，读的人对不上。
- **不写迁移，1.0 之前不保证兼容**（用户 2026-10-16 决定）：项目还在开发初期，1.0 之前升级不保证兼容旧版本的数据和归档。被否决的是"程序启动时自动把旧名字改成新名字"：用户无感，但要多写一段过渡代码和测试，违反"不做向后兼容"。
- **升数据库版本号，旧库直接报错**（用户 2026-10-16 决定）：沿用移除 spec 时的做法，data.db 版本号升一级，打开旧库报 `outdated_database` 并说明处理办法。被否决的是"不升版本"：旧记录里的 `prod.*` 事件读出来会在任意位置报格式错误，状态面板也可能显示不出来，出错位置事先不知道。项目索引库 index.db 里的 `prod_metadata` 表也要改名，写 PRD 时一并定为同样处理；index.db 本来就能删掉重建，删本机数据目录时会一起删掉。
- **旧的 docs/prod 不提醒**（用户 2026-10-16 决定）：被否决的是"程序发现 docs/prod 时提醒用户搬目录"，这是一段新功能，也是过渡代码。代价是：用户不手动搬的话，旧归档会被当作普通文档进项目索引，代理按 `docs/prd` 找不到它们。
- **正文写 PRD，代码写 prd**（用户 2026-10-16 决定）：提示词、README、ARCHITECTURE 的正文写大写 `PRD`，这是需求文档的通行写法，模型一眼就能认出；代码名、文件路径、工具参数值写小写 `prd`。被否决的是"正文也全小写"，差别只在正文里的大小写。
