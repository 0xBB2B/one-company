# 设置页布局与导航

设置页：输入 /one:setting 打开的页面。目录：设置页左边那一栏，列出所有分类。分类：目录里的一项，例如 worker、模型、开关。右栏：设置页右边那一栏，显示目录里选中分类的内容。焦点：现在按键作用在哪一栏。

## 用户故事
### P0：作为想改设定的用户，我想要在一个页面里找到所有设定
**用例（主路径）**
- 场景：用户想看看 PM 现在用哪个模型。
- 操作：在 80 列的终端里输入 /one:setting，按 ↓ 把目录光标移到「模型」。
- 预期：右栏立刻显示 PM、解释器、草稿核验器三行，每行写来源、模型、思考等级；底部写"模型：PM 和两个内部代理用哪个模型"。

**用例（边界：窄终端）**
- 场景：用户把终端分屏，只剩 44 列。
- 操作：输入 /one:setting，↓ 到「模型」，按 →。
- 预期：打开时只显示目录，占满整个宽度；按 → 后只显示模型列表，标题写"设置 › 模型"；按 ← 回到目录。

**用例（边界：有写错的文件）**
- 场景：用户层设置文件里 git-delivery 写成了 "yes"。
- 操作：打开 /one:setting。
- 预期：目录最后多一项红色的「问题」，带数字 1；选中它进右栏能看到这一条的原因和文件位置。

## 约束
- C-1：输入 /one:setting 打开设置页。没有交互终端时不打开，提示"需要交互终端才能打开设置页"。
- C-2：终端 60 列及以上时，第一行是"设置"（紫色粗体），右侧写"/one:setting"；下面左边是 20 列宽的目录，一道竖线，右边是右栏，两栏占满整个宽度；最下面是底部说明和按键提示。
- C-3：目录按顺序列出：标题「角色定义」，下面是 worker、reviewer、qa、explore、prototype 五项，每项后面写这一职责生效的定义份数；空一行；标题「设定」，下面是「模型」（写 3）和「开关」（写 1）；有写错的文件时再空一行，加一项红字「问题」，后面写问题条数。没有写错的文件时，不显示「问题」，也不留那一行空行。
- C-4：打开时焦点在目录，光标停在 worker；右栏同步显示 worker 的定义列表。
- C-5：焦点在目录时，↑↓ 换分类，右栏立刻换成选中分类的内容；按 → 或回车，焦点进入右栏。焦点在右栏时，按 ← 回到目录。任何时候按 Esc 都关闭设置页。
- C-6：光标一律写成 ▸；一行展开后，这一行的 ▸ 变成 ▾。焦点在目录时，目录里选中的那一行铺选中底色；焦点在右栏时，目录里选中的那一行去掉底色、改成紫色粗体，选中底色铺在右栏的选中行上。
- C-7：右栏第一行写分类名（紫色粗体）和一句说明：worker"写代码"，reviewer"代码审查：实现是否合理"，qa"功能验收：行为是否符合目标"，explore"只读查资料"，prototype"需求涉及界面时出 HTML 原型"，模型"PM 和两个内部代理用哪个模型"，开关"可选功能，默认都关闭"，问题"这些文件写错了，没有生效"。
- C-8：焦点在目录时，底部说明写选中分类管什么。职责分类写"<职责>：<说明> · N 份定义（<各层份数>）"，各层按项目、用户、内置的顺序，只写份数大于 0 的层，例如"worker：写代码 · 2 份定义（用户 1 · 内置 1）"；模型写"模型：PM 和两个内部代理用哪个模型"；开关写"开关：可选功能，默认都关闭"；问题写"问题：这些文件写错了，没有生效"。焦点在右栏时，底部说明写右栏选中那一行的说明。
- C-9：按键提示按焦点和分类变化：
  - 焦点在目录："↑↓ 选分类  → 进右栏  Esc 退出"
  - 右栏在职责分类："← 回左栏  ↑↓ 选择  回车 详情  C 复制  Esc 退出"；选中行展开后，"回车 详情"改成"回车 收起"
  - 右栏在模型或开关："← 回左栏  ↑↓ 选择  回车 修改  R 清除本层  Esc 退出"
  - 右栏在问题："← 回左栏  ↑↓ 选择  回车 详情  Esc 退出"；展开后改成"回车 收起"
- C-10：终端不到 60 列时，目录和右栏轮流占满整个宽度：
  - 打开时只显示目录，按键提示是"↑↓ 选分类  → 进入  Esc 退出"。
  - 按 → 或回车后只显示右栏，第一行写"设置 › <分类名>"；正在改某一项时写"设置 › <分类名> › <这一项的名字>"，例如"设置 › 模型 › PM"；复制定义时写"设置 › <职责> › 复制"。
  - 按键提示里的"← 回左栏"改成"← 回目录"，按 ← 回到目录。
  - 表格各列按宽度收窄，放不下的文字末尾用 … 截断。
- C-11：终端宽 36 到 80 列时，设置页的每一个画面（目录、各分类的列表、展开的详情、复制时输入名字、各个修改步骤、问题、项目未受信任）里任何一行的显示宽度都不超过终端宽度。底部说明和按键提示放不下时折成多行，按键提示按两个空格隔开的组折行，一组不拆开。
- C-12：问题分类列出所有写错、没生效的文件：角色定义文件写错的、设置文件写错的，都在这里。表头是"文件  层  原因"，每行写文件名、来源标签、短原因（红字）。选中一行按回车展开，依次写原因、现在的写法（红字，有时才写）、影响、文件位置。
- C-13：项目在 pi 里没有设为受信任时，设置页第一行下面多一行黄字"! 项目未受信任：项目层的定义和设定都没有生效"；问题分类里第一条是灰色的"项目未受信任，项目层的定义和设定没有生效"，这一条也计入「问题」的数字。
- C-14：保存或清除设定失败时，底部用红字写"✗ 没有保存：<原因>"，原因里写明是哪个文件出了什么问题；设定保持原来的值，设置页不关闭。

## 验收
- [ ] AC-1 ← C-1：在有交互终端的窗口输入 /one:setting，打开设置页；在没有交互终端的会话里输入，提示"需要交互终端才能打开设置页"。
- [ ] AC-2 ← C-2、C-3：80 列、没有写错的文件时，第一行是"设置"和"/one:setting"；目录依次是 角色定义、worker、reviewer、qa、explore、prototype、空行、设定、模型 3、开关 1，没有「问题」。
- [ ] AC-3 ← C-3：用户层多一份写错的定义文件、设置文件里 git-delivery 写成 "yes" 时，目录最后多一项「问题 2」。
- [ ] AC-4 ← C-4：打开时目录光标在 worker、带选中底色，右栏表头是"名称  来源  模型  思考"，列出 worker 职责下的定义。
- [ ] AC-5 ← C-5：焦点在目录时按 ↓ 到「模型」，右栏换成 PM、解释器、草稿核验器三行；按 → 后右栏第一行带选中底色；按 ← 回到目录；按 Esc 设置页关闭。
- [ ] AC-6 ← C-6：焦点在右栏时，目录里「模型」那一行没有选中底色、是紫色粗体，光标符号是 ▸；在 worker 的定义上按回车展开后，这一行的光标是 ▾。
- [ ] AC-7 ← C-7：依次选中八个分类，右栏第一行的分类名和说明与 C-7 一致。
- [ ] AC-8 ← C-8：目录停在 worker（用户层 1 份、内置 1 份）时，底部是"worker：写代码 · 2 份定义（用户 1 · 内置 1）"；停在模型、开关、问题时与 C-8 一致；进右栏选中 PM 时，底部写 PM 这一行的说明。
- [ ] AC-9 ← C-9：在目录、职责分类、职责分类展开后、模型、开关、问题、问题展开后，各自的按键提示与 C-9 一致。

- [ ] AC-12 ← C-12：问题分类里有一份写错的定义和一条写错的设置文件设定；在定义那一行按回车，依次出现原因、现在是、影响、文件四行。
- [ ] AC-13 ← C-13：项目未受信任时，第一行下面是那行黄字；问题分类第一条是灰色的未受信任说明；「问题」的数字比写错的文件数多 1。
- [ ] AC-14 ← C-14：用户层设置文件内容不是合法的 JSON 时，在模型或开关里保存到用户层，底部红字以"✗ 没有保存："开头并写出这个文件的位置；文件内容没变，列表里的值没变，设置页还开着。

## 验证路径
1. 80 列打开 /one:setting → 看目录、右栏、底部、按键提示（AC-1、AC-2、AC-4、AC-8、AC-9）。
2. ↓ 依次选每个分类，再 → 进右栏、← 回来（AC-5、AC-6、AC-7）。
3. 放一份写错的定义、把设置文件的 git-delivery 写成 "yes"，重开 → 看「问题」（AC-3、AC-12）。
4. 把项目设成不受信任，重开 → 看黄字和问题第一条（AC-13）。
5. 把用户设置文件改成不合法的 JSON，在「模型」里保存到用户层 → 看红字（AC-14）。
6. 依次把终端调到 36、44、59、60 列重复第 1、2 步（AC-10、AC-11）。
