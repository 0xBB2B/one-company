# Git 交付开关

Git 交付：主代理调用交付工具，替用户把已完成并归档的需求提交归档、推送需求分支并建立 PR；默认关闭。开关分类：设置页目录里的「开关」，列出可选功能的开关，现在只有 Git 交付一项。设置文件：pi 的设置文件，用户层在 ~/.pi/agent/settings.json，项目层在项目里的 .pi/settings.json；one-company 的设定都写在其中的 one-company 字段下。用户层设定对所有项目生效；项目层设定只对当前项目生效，优先于用户层，项目在 pi 里受信任才生效。

## 用户故事
### P0：作为想让主代理替我推送的用户，我想要在设置页里打开 Git 交付
**用例（主路径）**
- 场景：用户想在所有项目里都让主代理替自己推送、建 PR。
- 操作：打开 /one:setting，↓ 到「开关」，→，在 Git 交付上回车，选开启，选用户层。
- 预期：用户设置文件的 one-company 字段下写入 "git-delivery": true，文件里其他内容不变；回到开关列表，Git 交付这一行名字变绿、来源是"用户"、状态是绿色的"开启"；底部绿字"✓ Git 交付 改为开启，存到用户层，立即生效"；当前窗口的工具列表里立刻出现交付工具，不用重开 pi。

**用例（边界：设置文件写错）**
- 场景：用户手改用户设置文件，把 git-delivery 写成了 "yes"。
- 操作：打开 /one:setting。
- 预期：Git 交付显示关闭、来源内置；「问题」里有一条"git-delivery 只能写 true 或 false"。

**用例（边界：别的窗口关掉了开关）**
- 场景：用户开着两个 pi 窗口，在窗口 B 的设置页把 Git 交付关掉。
- 操作：在窗口 A 里让主代理交付一个已完成的需求。
- 预期：交付被拒绝，原因写 Git 交付已关闭，建议写"请用户在 /one:setting 的开关里开启 Git 交付后再交付"。

## 约束
- C-1：开关分类的右栏表头是"名称  来源  状态"，有一行 Git 交付：来源标签写内置、用户或项目；状态写"开启"（绿字）或"关闭"（灰字）。选中这一行时，底部写"Git 交付：开启后主代理可以替你提交归档、推送并建 PR · <来源说明> · 立即生效"，来源说明是"内置默认值""来自用户层"或"来自项目层"。
- C-2：在 Git 交付上按回车，右栏依次走两步：
  - 第 1 步标题"修改 Git 交付"，旁边灰字"第 1 步，共 2 步"；两个选项"开启"（说明"主代理可以替你提交归档、推送并建 PR"）和"关闭"（说明"推送和合并由你自己做"）；现在的值前面打 ✓，光标默认停在另一个选项上。
  - 第 2 步标题"Git 交付 改为<开启或关闭>，存到哪一层"，旁边灰字"第 2 步，共 2 步"；选项是项目层和用户层，写法和模型设定选层那一步一样；项目未受信任时项目层灰掉、不能选，并写明原因。
  - 按 Esc 退回上一步，第 1 步按 Esc 取消，什么也不保存，底部写"已取消修改"。
- C-3：保存时只在所选那一层设置文件的 one-company 字段下写 "git-delivery": true 或 false，文件里其他内容保持原样。保存后回到开关列表，这一行名字变绿，来源变成所选的层，底部绿字"✓ Git 交付 改为<开启或关闭>，存到<项目层或用户层>，立即生效"。
- C-4：开关的取值顺序是：项目层（项目受信任时）> 用户层 > 内置默认值。内置默认值是关闭。
- C-5：在 Git 交付上按 R，清除当前生效那一层的 git-delivery，底部绿字写"✓ 已清除<层>的 Git 交付 设定，现在用<下一层的值的说明>"，例如"现在用内置默认值：关闭"或"现在用用户层的值：开启"；来源是内置时只提示"已经是内置默认值"，不写文件。
- C-6：设置文件 one-company 字段下的 git-delivery 不是 true 也不是 false 时，这一层的这一项不生效、改用下一层，并在「问题」里列一条，短原因是"git-delivery 只能写 true 或 false"，现在的写法写出文件里的原样。one-company 字段下出现不认识的键时，「问题」里的原因写"不认识的设定 <键名>，只能是 pm、interpreter、draft-verifier、git-delivery"。
- C-7：每个 pi 窗口启动时，按设置文件里生效的值决定工具列表里有没有交付工具：开启就有，关闭就没有。在设置页里保存或清除 Git 交付后，当前窗口的工具列表立刻跟着变。
- C-8：主代理每次调用交付工具时，按设置文件当时生效的值再核对一次。是关闭时拒绝，原因写"Git 交付已关闭"，建议写"请用户在 /one:setting 的开关里开启 Git 交付后再交付"。
- C-9：输入 /one:git-delivery 时 pi 提示没有这个命令；包里不再注册这个命令。本机全局数据库里以前存的 Git 交付开关不再读取，也不迁移。

## 验收
- [ ] AC-1 ← C-1：没有任何设置文件时，开关分类里 Git 交付来源是内置、状态是灰色"关闭"；底部是"Git 交付：开启后主代理可以替你提交归档、推送并建 PR · 内置默认值 · 立即生效"。
- [ ] AC-2 ← C-2、C-3：在 Git 交付上回车，第 1 步 ✓ 在"关闭"上、光标在"开启"上；回车后第 2 步标题是"Git 交付 改为开启，存到哪一层"；选用户层后，用户设置文件的 one-company 下 git-delivery 是 true，文件里原有的其他内容不变；这一行来源是用户、状态是开启；底部是"✓ Git 交付 改为开启，存到用户层，立即生效"。
- [ ] AC-3 ← C-2：项目未受信任时，第 2 步的项目层是灰的，光标停在用户层；任一步连续按 Esc，两层设置文件都没变，底部是"已取消修改"。
- [ ] AC-4 ← C-4：用户层写 true、项目层写 false、项目受信任时，状态是关闭、来源是项目；项目改为未受信任后，状态是开启、来源是用户。
- [ ] AC-5 ← C-5：来源是用户层时按 R，用户设置文件里 git-delivery 被删掉，底部是"✓ 已清除用户层的 Git 交付 设定，现在用内置默认值：关闭"；来源是内置时按 R 提示"已经是内置默认值"，不创建设置文件。
- [ ] AC-6 ← C-6：用户设置文件里 git-delivery 写成 "yes" 时，状态是关闭、来源是内置，「问题」里有一条"git-delivery 只能写 true 或 false"，展开后现在的写法是 "yes"；one-company 下多写一个键 foo 时，「问题」里有一条"不认识的设定 foo，只能是 pm、interpreter、draft-verifier、git-delivery"。
- [ ] AC-7 ← C-7：设置文件里 git-delivery 是 true 时启动窗口，工具列表里有交付工具；是 false 或没写时没有；在设置页里把它改成开启后，不重启，工具列表里就有了；改回关闭或按 R 清除到关闭后，工具列表里就没有了。
- [ ] AC-8 ← C-8：窗口启动时开关是开启，之后手改设置文件把它改成 false，再调用交付工具，被拒绝，原因是"Git 交付已关闭"，建议是"请用户在 /one:setting 的开关里开启 Git 交付后再交付"。
- [ ] AC-9 ← C-9：包注册的命令里没有 one:git-delivery；全局数据库里存着旧的"已开启"开关、两层设置文件都没写 git-delivery 时，交付工具不在工具列表里，调用会被拒绝。

## 验证路径
1. 没有设置文件时打开 /one:setting → 开关 → 看这一行和底部（AC-1）。
2. 回车 → 开启 → 用户层 → 读用户设置文件、看工具列表（AC-2、AC-7）→ 按 R（AC-5）。
3. 把项目设为不受信任再走一遍选层（AC-3）；两层写不同的值，切换受信任（AC-4）。
4. 手改设置文件写 "yes" 和多一个键，重开看「问题」（AC-6）。
5. 开着窗口时手改成 false，调用交付工具（AC-8）。
6. 看注册的命令列表；在全局数据库里留一条旧开关，启动窗口（AC-9）。
