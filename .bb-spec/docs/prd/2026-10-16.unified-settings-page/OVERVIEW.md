# 统一设置页 /one:setting

## 背景与问题
- 设置分散在两个命令里：PM、解释器、草稿核验器的模型在 /one:agents 最右边的设定栏里改；Git 交付的开关要用单独的 /one:git-delivery 命令开关。用户要记两个入口，以后每加一项设定还会多一个命令。
- Git 交付开关存在本机的全局数据库里，整台电脑只有一份，不能按项目区分；模型设定却存在 pi 设置文件里，分用户层和项目层。同样是设定，存放位置和规则不一样。
- 用户的目标是"以后所有设定都在这一页管理"，页面结构要能不断往里加东西。

## 目标
- 只有一个入口 /one:setting：角色定义、模型设定、开关、写错的文件都在这一页里看和改。
- 以后加一项设定，只在这一页的目录里加一项，不新增命令。
- Git 交付开关和模型设定存在同一个地方，规则一样：分用户层和项目层，项目层优先，项目受信任才生效。
- 终端窄到 36 列也能用。

## 非目标
- 代码目录按模块拆分（另起一轮）。
- 新增别的设定或开关。
- 改模型设定的三步流程、复制定义的名字规则、角色定义文件的格式。
- 改交付工具本身的交付流程（核对、推送、建 PR、选合并方式）。
- 把全局数据库里旧的 Git 交付开关迁移到设置文件。

## 整体验证路径
1. 在没有任何设置文件的环境里打开 /one:setting → 左边目录是 worker、reviewer、qa、explore、prototype、模型、开关，没有「问题」；输入 /one:agents 或 /one:git-delivery，pi 提示没有这个命令。
2. 左栏选「模型」→ 进右栏把 PM 改成 gpt-6-luna、high，存到项目层 → 项目设置文件的 one-company 字段下有 pm 这一项；下次启动 PM 用 gpt-6-luna。
3. 左栏选「开关」→ 把 Git 交付改成开启、存到用户层 → 用户设置文件的 one-company 字段下有 "git-delivery": true；本窗口的工具列表里立刻出现交付工具。
4. 手改用户设置文件，把 git-delivery 写成 "yes" → 重开 /one:setting：目录最后出现红色「问题」，列出这一条；开关显示关闭；让主代理调用交付工具会被拒绝，原因写 Git 交付已关闭。
5. 把终端拉到 44 列 → 打开后只显示目录；进入「模型」后标题是"设置 › 模型"；任何一行都不超出终端宽度。

## 决策记录
- **质疑结论**：不做的话，每加一个设定就多一个命令，Git 交付开关也不能按项目区分。更便宜的替代是只把 Git 交付开关并进 /one:agents 的设定栏（第一版预览就是这样）。用户看过后选择整页重做，原因是"以后所有设定都在这里管理"，页面要能不断往里加东西（用户 2026-10-16 决定）。
- **一个入口，删掉两个旧命令**（用户 2026-10-16 决定）：中途试过"/one:agents 只管角色定义、/one:setting 只管设定"的拆法，用户最后决定全部放进 /one:setting。旧命令不留别名，按项目规矩不做向后兼容。
- **左右两栏布局**（用户 2026-10-16 从三版效果图里选定）：被否决的有两版。一版是一页长列表，所有东西排成一张表，现在已经约 25 行，定义一多就要滚动；另一版是两级分类，顶部大类加二级职责，按键多一层，在一个大类里看不到别的大类。左右两栏以后加设定只在目录里加一行。代价是右栏只剩约 59 列，长名字更容易被截断。
- **光标统一用 ▸，展开用 ▾，「问题」前面不加 ⚠**（用户 2026-10-16 决定）：原来左栏和右栏用 › 和 ▸ 两个符号区分焦点；统一符号后，改用选中底色区分焦点在哪一栏。
- **目录里每一项的说明放在底部，不跟在目录行后面**（用户 2026-10-16 决定）：窄终端的目录预览曾经把说明写在每一行后面，用户要求和宽终端一样放在底部，随光标变化。
- **窄于 60 列时两栏轮流占满整个宽度**（用户 2026-10-16 决定）：原页面支持到 36 列，左右两栏光左栏就占 20 列，60 列以下放不下右栏。被否决的做法是要求终端至少 60 列，比现在倒退。
- **Git 交付开关改存 pi 设置文件**（用户 2026-10-16 决定）：和模型设定放在同一个 one-company 字段下，分用户层和项目层。全局数据库里的旧开关不迁移、不读取，以前开过的人要在设置页里重新开一次（用户 2026-10-16 决定，按项目规矩不做向后兼容）。
- **别的窗口不实时刷新工具列表，调用时再核对**：设置页只能直接改当前窗口的工具列表；别的已开着的 pi 窗口在下次启动时才按设置文件更新。为了不让关掉的开关被别的窗口继续用，交付工具每次被调用时都按设置文件当时的值再核对一遍。
- **存到的那一层被项目层压住时，列表按生效值显示，提示文字这次不改**（用户 2026-10-16 决定，实现后审查发现）：例如项目层写了关闭，用户选"开启、存到用户层"，用户层文件确实写入，但列表和工具列表都按项目层的关闭显示；底部提示仍是"存到用户层，立即生效"，会让人以为已经开启。模型设定一直有同样的问题，提示文字的修正要连同模型设定一起做，另起一轮。
- **保存失败统一用红字写"✗ 没有保存：原因"**：已确认的预览里，开关保存失败用红字写明原因和文件。模型设定的保存失败原来是灰字，同一页里同一种失败统一成一种写法。
