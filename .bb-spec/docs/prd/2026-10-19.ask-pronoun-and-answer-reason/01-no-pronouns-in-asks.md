# 提问文字不用人称代词

## 用户故事
### P0：作为用户，我想要提问窗口里的文字用角色词称呼人，以便我点选的选项理由能原样写进需求草稿、通过核验

**用例（主路径）**
- 场景：用户在澄清企微 BOT 需求，用户本人是需求里的负责人。
- 操作：主代理发起需求澄清提问，第 2 个选项的理由写"任务做完先标为待验收，由你确认通过后再标为已完成"。
- 预期：程序不弹窗，`one_company_user_interact` 的 ask 失败；失败原因写明"第 2 个选项的理由（reason）"含"你"，要改用"用户""AI"或这个人在需求里的角色（如负责人）。

**用例（主路径：改正后）**
- 场景：同上。
- 操作：主代理把理由改成"由负责人确认通过后再标为已完成"重新提问。
- 预期：窗口正常弹出。

**用例（边界）**
- 操作：主代理发起面板事项提问，问题写"您要怎么处理这个任务？"。
- 预期：ask 失败，原因写明问题（question）含"您"。

**用例（边界）**
- 操作：一次提问里问题含"我们"、根源自检含"你"、第 1 个选项标题含"我"。
- 预期：ask 失败，原因把这三处逐条列出，主代理一次就能全部改完。

## 约束
- C1：需求澄清提问（`purpose` 不填或为 `user-confirmation`）的 ask，question、rootCheck、任一选项的 label、reason、recommendedReason 中只要出现"我""你""您"中的任一字，ask 失败、不弹窗。
- C2：面板事项提问（`purpose=panel-item`）的 ask 按 C1 同样检查、同样失败。
- C3：失败原因逐条写出每一处含人称代词的位置（哪个字段、第几个选项、含哪个字），并写明改用"用户""AI"或这个人在需求里的角色（如负责人）。
- C4：五处文字都不含这三个字时，人称检查不影响提问，窗口照常弹出。
- C5：用户在"其他"里自己输入的回答含"我""你""您"时，照常记成用户原话，不被退回。
- C6：主代理规则写明：提问的问题、根源自检、选项标题、理由、推荐理由不用"我""你""您"；指回答问题的人写"用户"或这个人在需求里的角色，指主代理自己写"AI"。

## 验收
- [ ] C1：需求澄清提问的五个字段各放一个"我"/"你"/"您"，分别发起 ask → 每次都失败且没有弹窗。
- [ ] C2：面板事项提问的问题含"您" → ask 失败且没有弹窗。
- [ ] C3：一次提问里三处含人称代词 → 失败原因列出这三处的字段、选项序号和字，并含"用户""AI""角色"的改法说明。
- [ ] C4：五处都不含人称代词的提问 → 窗口弹出，用户能作答。
- [ ] C5：用户选"其他"输入"我来验收" → ask 返回 answered，answer.text 为"我来验收"。
- [ ] C6：主代理规则文件的提问条目里写有"不用'我''你''您'"和"用户""AI"、角色的用法。

## 验证路径
1. 用需求澄清提问，理由写"由你确认" → ask 失败，原因指出第几个选项的 reason 含"你"。
2. 改成"由负责人确认"重新提问 → 窗口弹出。
3. 用面板事项提问，问题写"您" → ask 失败。
4. 用户在"其他"里输入含"我"的文字 → 回答照常返回。
