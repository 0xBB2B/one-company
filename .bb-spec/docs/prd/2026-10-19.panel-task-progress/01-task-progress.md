# 第一行显示任务进度

状态面板：pi 主窗口输入栏下方的区域，每个运行中的需求占一组行。第一行：这组行的汇总行，现在的样子是"└─ ⠹ 角色跳跃 · ↻5 · 5 tool uses · 33.8k token (62%) · 12.3s"，依次是树形分支、状态图标、目标、轮数、工具调用次数、token 用量（括号里是缓存命中率）、耗时。任务：PM 在计划里拆出来、派给子代理做的一件事，分 worker（写代码）、explore（只读查资料）、qa（功能验收）三种。任务状态：每个任务都记着自己现在处于哪一步，"已完成"（completed）表示这件事做完了，worker 任务要审查通过才算；"已取消"（cancelled）表示 PM 把它从计划里拿掉了。

## 用户故事
### P0：作为等 PM 干活的用户，我想要在面板第一行看到任务做完了几个、一共几个，以便知道这个需求还要等多久

**用例（主路径）**
- 场景：用户批准了"角色跳跃"需求，PM 交的计划里有 8 个任务：6 个 worker、1 个 explore、1 个 qa。目前 explore 已完成，2 个 worker 审查通过，1 个 worker 交了代码正在等审查。
- 操作：看输入栏下方的状态面板。
- 预期：第一行是"└─ ⠹ 角色跳跃 · 任务 3/8 · ↻5 · 5 tool uses · 33.8k token (62%) · 12.3s"。等审查的那个 worker 不算进已完成。

**用例（边界：还没有计划）**
- 场景：PM 刚接手需求，还没交计划。
- 操作：看面板。
- 预期：第一行没有"任务"这一段，其余内容和改动前一样。

**用例（边界：计划还在规划阶段）**
- 场景：PM 交了一份有 3 个任务的计划，还没通过检查，第二行写着"规划中（计划 v1 · 3 个任务）"。
- 操作：看面板。
- 预期：第一行有"任务 0/3"。

**用例（边界：有任务被取消）**
- 场景：计划有 5 个任务，1 个已完成，PM 取消了 2 个还没做的。
- 操作：看面板。
- 预期：第一行是"任务 1/3"。

**用例（边界：任务全部被取消）**
- 场景：计划里的任务全部被 PM 取消。
- 操作：看面板。
- 预期：第一行没有"任务"这一段。

**用例（边界：暂停和等待决定）**
- 场景：计划有 4 个任务，已完成 2 个。用户按 p 暂停了 PM；或者 PM 停下等用户裁决。
- 操作：看面板。
- 预期：图标是 ⏸，第一行照常有"任务 2/4"。

## 约束
- C-1：计划里至少有 1 个没取消的任务时，第一行在目标后面、"↻轮数"前面加一段"任务 X/N"，前后各用" · "隔开。格式：`<分支> <图标> <目标> · 任务 X/N · ↻<轮数> · <工具调用次数> tool uses · <token> token<缓存命中率> · <耗时>`。
- C-2：N 是计划里状态不是"已取消"的任务个数，worker、explore、qa 都算。X 是其中状态为"已完成"的个数。其他状态（等审查、审查中、等返工、待更新、等裁决等）都不算进 X。
- C-3：还没有计划，或者计划里的任务全部取消时，第一行没有"任务"这一段，和改动前一模一样。
- C-4：只要满足 C-1，PM 不管是在跑、暂停中、已暂停还是在等决定，也不管计划确认了没有，都显示这一段。
- C-5：X 和 N 每次刷新面板时都按当前计划重新算。任务新完成、新增、被取消，或者已完成的任务因为需求更新改成待更新，下一次刷新后的数字都会跟着变。

## 验收
- [ ] AC-1 ← C-1、C-2：计划 8 个任务，其中 3 个已完成（1 个 explore、2 个 worker），1 个 worker 等审查，其余 4 个待派；面板宽 120 列时第一行是"└─ ⠹ 角色跳跃 · 任务 3/8 · ↻5 · 5 tool uses · 33.8k token (62%) · 12.3s"。
- [ ] AC-2 ← C-2：计划 5 个任务，1 个已完成，2 个已取消，2 个待派：第一行有"任务 1/3"。
- [ ] AC-3 ← C-2：计划 3 个任务，分别处于审查中、等返工、待更新：第一行有"任务 0/3"。
- [ ] AC-4 ← C-3：没有计划时，第一行和改动前的格式完全一样，不含"任务"二字。
- [ ] AC-5 ← C-3：计划里的任务全部已取消时，第一行不含"任务"二字。
- [ ] AC-6 ← C-4：计划 4 个任务、2 个已完成，PM 状态分别为在跑、暂停中、已暂停、等待决定时，第一行都有"任务 2/4"。计划还没确认、有 3 个任务时，第一行有"任务 0/3"。
- [ ] AC-7 ← C-5：同一个需求先有 1 个任务已完成、共 3 个，面板显示"任务 1/3"；把第 2 个任务改成已完成后刷新，显示"任务 2/3"；再把一个已完成的任务改成待更新后刷新，显示"任务 1/3"。

## 验证路径
1. 构造一个没有计划的需求，看第一行没有"任务"这一段（AC-4）。
2. 给它加一份有 3 个任务的计划，计划不确认，看到"任务 0/3"（AC-6 后半）。
3. 按 AC-1、AC-2、AC-3、AC-5 的任务状态分别构造计划，逐个对照第一行（AC-1、AC-2、AC-3、AC-5）。
4. 计划 4 个任务、2 个已完成，把 PM 依次切成在跑、暂停中、已暂停、等待决定，看第一行（AC-6 前半）。
5. 按 AC-7 的顺序改任务状态，每改一次刷新一次面板，看数字变化（AC-7）。
