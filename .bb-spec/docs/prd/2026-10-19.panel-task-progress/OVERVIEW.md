# 状态面板显示任务进度

状态面板：pi 主窗口输入栏下方的区域。每个运行中的需求占一组行：第一行是目标和用量，第二行写 PM 在做什么，再往下是以 ⚑ 开头的待处理事项。任务：PM 在计划里拆出来、派给子代理做的一件事。子代理分三种：worker 写代码，explore 只读查资料，qa 在最后的检查轮里做功能验收。

## 背景与问题
一个需求 PM 往往要跑几十分钟，计划里有好几个任务。现在面板第一行只有目标、轮数、工具调用次数、token 和耗时，第二行只写 PM 眼下在做的那件事。用户看不出这个需求一共几个任务、做完了几个、还剩多少，只能让主代理去查计划。

PM 会同时派多个改不同目录的 worker，所以"现在做到第几个"没有唯一答案。"做完了几个、一共几个"不管什么时候都只有一个值。

## 目标
- 有计划时，第一行在目标后面显示"任务 已完成数/总数"，例如"任务 3/8"。
- 数字按当前计划算：PM 加了任务、取消了任务，或者任务因为需求更新又要重做时，数字跟着变。

## 非目标
- 不显示"正在做第几个"，也不列出每个任务的名字和状态。
- 不加进度条，不显示百分比。
- 第二行"在做什么"、⚑ 事项行、检索和原型设计那两组，都不改。
- 终端太窄时第一行的截断方式不改：照旧从行尾截断，加"…"。

单一子需求，无依赖。

## 整体验证路径
1. 批准一个需求，PM 交计划之前看面板 → 第一行是"└─ ⠹ <目标> · ↻… · … tool uses · … token … · …"，没有"任务"这一段。
2. PM 交了一份有 3 个任务的计划 → 第一行变成"└─ ⠹ <目标> · 任务 0/3 · ↻… "。
3. 第一个 worker 任务审查通过 → 第一行变成"任务 1/3"。
4. PM 取消一个还没做完的任务 → 第一行变成"任务 1/2"。
5. 按 p 暂停这个 PM → 图标变成 ⏸，"任务 1/2"照常显示。

## 决策记录
- 显示"已完成数/总数"，不显示"第几个"。理由：PM 会同时派多个任务，"第几个"没有唯一答案。用户 2026-10-19 决定。
- 进度放在第一行汇总里，紧跟在目标后面、轮数前面。否决放在第二行开头：第二行在暂停、等待决定、检查中时会换成别的文字，进度就会跟着时有时无。用户 2026-10-19 决定。
- 只显示数字"任务 3/8"。否决数字加进度条：进度条多占 10 个字符左右，窄终端上后面的耗时会先被截掉。用户 2026-10-19 决定。
- 总数算计划里所有没取消的任务，worker、explore、qa 都算，和第二行"规划中（计划 v2 · 3 个任务）"里的任务数一致。否决只算 worker：会和第二行的数字对不上。用户 2026-10-19 决定。
- 计划还没确认、PM 还在规划时也显示进度，规则最简单：只要计划里有没取消的任务就显示。用户 2026-10-19 决定。
- 计划里的任务全部取消时不显示这一段，和还没有计划时一样："任务 0/0"看不出任何信息。用户 2026-10-19 决定。
- 已完成只认任务状态"completed"。worker 交完代码后先进入等审查，审查通过才算完成；explore 和 qa 交完结果就算完成。需求更新后，受影响的已完成任务会重新变成待更新，已完成数随之变小，面板照实际显示。
