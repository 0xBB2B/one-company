# 设置页：Git 交付档位和合并方式

设置页：输入 `/one:setting` 打开的页面，左边是目录，右边显示选中分类的内容。「开关」是目录里的一个分类。设置文件：pi 的设置文件，用户层在 `~/.pi/agent/settings.json`，项目层在项目里的 `.pi/settings.json`，one-company 的设定写在其中的 `one-company` 字段下；取值顺序是项目层（项目受信任时）> 用户层 > 内置默认值。

Git 交付的两档：
- 远程：主代理替你推送需求分支、开 PR 或 MR，在 GitHub 或 GitLab 上合并。
- 仅本地：主代理替你在本机把需求分支合进主仓库当前检出的分支，不推送。

合并方式：压缩合并（所有提交压成一个）、普通合并（保留每个提交，另加一个合并提交）、rebase 合并（保留每个提交，接到目标分支后面成一条直线）。

## 用户故事
### P0：作为刚装好 one-company 的用户，我想要不用设置就按仓库情况选好 Git 交付的档位，以便有 GitHub 远端的项目直接能开 PR，纯本地项目也能合并

**用例（主路径）**
- 场景：项目的 origin 是 `git@github.com:acme/shop.git`，本机 gh 登录了 github.com，两层设置文件都没写 Git 交付。
- 操作：打开 `/one:setting`，↓ 到「开关」，→。
- 预期：Git 交付一行来源"内置"、状态"远程"；底部写明"内置默认值：origin 在 github.com，gh 已登录 → 远程"。

**用例（边界）**
- 场景：origin 是私有部署 `git.example.com`，gh 和 glab 都没登录这台主机。
- 操作：同上。
- 预期：状态"仅本地"；底部写"内置默认值：origin 在 git.example.com，gh 和 glab 都没登录这台主机 → 仅本地"。没有 origin 时写"没有 origin → 仅本地"。

### P0：作为团队只允许普通合并的用户，我想要在设置页只勾普通合并，以便交付窗口里只出现这一种

**用例（主路径）**
- 场景：两层设置文件都没写合并方式。
- 操作：在「开关」的合并方式上回车，空格取消压缩合并和 rebase 合并，回车，选用户层。
- 预期：用户设置文件的 `one-company` 下写入 `"merge-methods": ["merge"]`，文件里其他内容不变；合并方式一行名字变绿、来源"用户"、状态"普通合并"；底部绿字"✓ 合并方式 改为 普通合并，存到用户层，立即生效"。

**用例（异常）**
- 场景：用户把三种都取消了。
- 操作：回车。
- 预期：停在第 1 步，下面红字"✗ 至少勾一种合并方式"，什么都没保存。

**用例（异常）**
- 场景：旧版本在用户设置文件里写了 `"git-delivery": true`。
- 操作：打开设置页。
- 预期：用户层的这一项不生效，Git 交付按内置默认值显示；「问题」里列一条，原因"git-delivery 只能写 remote 或 local"，现在的写法写 `true`。

## 约束
- C-1：「开关」分类的说明是"Git 交付怎么交、用哪些合并方式"。右栏表头"名称  来源  状态"，有两行：
  - Git 交付：状态写"远程"或"仅本地"（强调色）。
  - 合并方式：状态按压缩合并、普通合并、rebase 合并的顺序列出勾了的，用" · "隔开，三种都勾时写"压缩 · 普通合并 · rebase"。
- C-2：选中 Git 交付这一行时（包括修改它的两步里），底部写"Git 交付：远程＝推送并开 PR；仅本地＝合进主仓库当前分支 · <来源说明> · 立即生效"。选中合并方式这一行时（包括修改它的两步里），底部写"合并方式：远程和仅本地都只用勾了的方式，压缩合并是推荐方式 · <来源说明> · 立即生效"，来源说明是"来自用户层""来自项目层"或"内置默认值：三种都勾"。Git 交付的来源说明是"来自用户层""来自项目层"，或者内置默认值的判断依据，三种之一：
  - "内置默认值：origin 在 <主机>，gh 已登录 → 远程"（glab 登录时写 glab）；
  - "内置默认值：origin 在 <主机>，gh 和 glab 都没登录这台主机 → 仅本地"；
  - "内置默认值：没有 origin → 仅本地"。
- C-3：内置默认值的判断：有 origin，并且 origin 所在主机在本机 gh 或 glab 的登录记录里，就是远程；否则是仅本地。只读本机登录记录，不联网，私有部署的主机也按登录记录认。glab 的登录记录要求配置文件里这台主机的令牌（token）有值，只有主机条目、令牌为空的不算（glab 第一次运行就会生成一个令牌为空的 gitlab.com 条目）。origin 地址解析不出主机、或 glab 配置文件读不了时，按"认不出"处理，得到仅本地，不报错。
- C-4：在 Git 交付上回车，走两步：
  - 第 1 步标题"修改 Git 交付"，旁边灰字"第 1 步，共 2 步"；选项"远程"（说明"推送需求分支、开 PR，在 GitHub/GitLab 上合并"）和"仅本地"（说明"在本机合进主仓库当前分支，不推送"）；现在的值前面打 ✓，光标停在另一个选项上。
  - 第 2 步标题"Git 交付 改为<远程或仅本地>，存到哪一层"，选层的写法和现在一样，项目未受信任时项目层灰掉。
  - 保存后只在所选那一层写 `"git-delivery": "remote"` 或 `"local"`，文件里其他内容不变；这一行名字变绿，底部绿字"✓ Git 交付 改为<远程或仅本地>，存到<项目层或用户层>，立即生效"。
- C-5：在合并方式上回车，走两步：
  - 第 1 步标题"修改合并方式"，三行复选框，顺序是压缩合并（带绿色"推荐"，说明"一个需求在主分支上是一个提交"）、普通合并（"保留每个提交，另加一个合并提交"）、rebase 合并（"保留每个提交，历史是一条直线"）；按现在生效的值预先勾好；下面灰字"远程和仅本地都生效。远程时只列出仓库也允许的方式；交付窗口里压缩合并排第一、标推荐。"；按键提示"↑↓ 选择  空格 勾选  回车 下一步  Esc 取消"。
  - 一种都没勾时回车不进下一步，下面红字"✗ 至少勾一种合并方式"。
  - 第 2 步标题"合并方式 改为 <勾了的方式，用顿号隔开>，存到哪一层"，选层同上。
  - 保存后只在所选那一层写 `"merge-methods"`，值是勾了的方式的数组，按 squash、merge、rebase 的顺序，例如 `["squash", "merge"]`；这一行名字变绿，底部绿字"✓ 合并方式 改为 <勾了的方式>，存到<层>，立即生效"。
- C-6：两步里按 Esc 退回上一步，第 1 步按 Esc 取消，什么都不保存，底部写"已取消修改"。
- C-7：在任一行按 R，清除当前生效那一层的这一项，底部绿字"✓ 已清除<层>的<Git 交付或合并方式> 设定，现在用<下一层的值的说明>"。Git 交付回到内置默认值时，说明写成"内置默认值：<远程或仅本地>（<C-2 里的判断依据>）"；合并方式的内置默认值是三种都勾。来源已经是内置时只提示"已经是内置默认值"，不写文件。
- C-8：设置文件里 `git-delivery` 不是 `"remote"` 或 `"local"`（包括旧版本写的 `true`、`false`）时，这一层的这一项不生效、改用下一层，「问题」里列一条，原因"git-delivery 只能写 remote 或 local"，现在的写法写出原样。`merge-methods` 不是由 `"squash"`、`"merge"`、`"rebase"` 组成的、不重复的非空数组时同理，原因"merge-methods 只能是 squash、merge、rebase 里的一到三个，不能重复"。`one-company` 下出现不认识的键时，原因写"不认识的设定 <键名>，只能是 pm、interpreter、draft-verifier、git-delivery、merge-methods"。
- C-9：交付工具在两档下都一直在主窗口的工具列表里。主代理每次调用交付工具时，按设置文件当时生效的档位和合并方式办事；改了设置后不用重开 pi。
- C-10：项目是否受信任，设置页、交付工具、主窗口里的解释器和草稿核验器、守护进程都按同一个办法判断：从这个仓库的根目录往上，找 pi 信任记录（`~/.pi/agent/trust.json`）里最近的一条，每次用到时现查。会话所在目录和仓库的信任记录不同、或会话中途改了信任时，各处结论仍一致。

## 验收
- [ ] AC-1 ← C-1、C-2、C-3：origin 在 github.com、gh 已登录、两层都没设置时，开关分类有两行，Git 交付来源"内置"、状态"远程"，合并方式状态"压缩 · 普通合并 · rebase"，选中 Git 交付时底部文字如 C-2 第一种；选中合并方式时底部是"合并方式：远程和仅本地都只用勾了的方式，压缩合并是推荐方式 · 内置默认值：三种都勾 · 立即生效"；进入修改的两步后底部仍是这一行的说明。把 origin 改成没登录的主机、再删掉 origin，底部依次变成 C-2 的第二、第三种，状态变成"仅本地"。
- [ ] AC-2 ← C-3：断网时打开设置页，判断结果和联网时相同，打开过程中没有发出网络请求。
- [ ] AC-3 ← C-4：在 Git 交付上回车，第 1 步 ✓ 在"远程"上、光标在"仅本地"上；回车后第 2 步标题"Git 交付 改为仅本地，存到哪一层"；选项目层后，项目设置文件的 `one-company` 下 `git-delivery` 是 `"local"`，其他内容不变；底部如 C-4。
- [ ] AC-4 ← C-5：合并方式第 1 步三种都预先勾着，压缩合并带"推荐"；取消压缩合并和 rebase 合并后回车，第 2 步标题"合并方式 改为 普通合并，存到哪一层"；选用户层后文件里是 `"merge-methods": ["merge"]`，状态"普通合并"。三种都取消再回车，停在第 1 步并显示红字。
- [ ] AC-5 ← C-6：任一步连续按 Esc，两层设置文件都没变，底部"已取消修改"。
- [ ] AC-6 ← C-7：项目层写了 `"local"` 时在 Git 交付上按 R，项目层的这一项被删掉，底部写"✓ 已清除项目层的 Git 交付 设定，现在用内置默认值：远程（origin 在 github.com，gh 已登录）"；来源是内置时按 R 只提示"已经是内置默认值"，文件没变。
- [ ] AC-7 ← C-8：用户层写 `"git-delivery": true`、`"merge-methods": ["squash", "squash"]`、`"foo": 1` 时，这两项不生效，「问题」里有三条，原因分别如 C-8。
- [ ] AC-8 ← C-9：两档下主窗口工具列表里都有交付工具；在设置页把档位从远程改成仅本地后，不重开 pi，主代理下一次交付就按仅本地办。
- [ ] AC-9 ← C-10：信任记录里父目录受信任、仓库单独记为不信任时，即使 pi 会话认为项目受信任，设置页、交付工具、解释器和草稿核验器都不采用这个仓库的项目层设定；反过来仓库单独记为信任时都采用。两次调用交付工具之间改了信任记录，第二次按新记录办。

## 验证路径
1. 在 gh 已登录的 GitHub 项目里打开设置页 → 两行，Git 交付"远程"，底部写明判断依据。
2. 改成仅本地、存到项目层 → 文件写入 `"local"`；按 R 清除 → 回到"远程"。
3. 合并方式只留普通合并、存到用户层 → 文件写入 `["merge"]`；全取消再回车 → 红字提示。
4. 在用户设置文件里写 `"git-delivery": true` → 「问题」里出现对应条目。
