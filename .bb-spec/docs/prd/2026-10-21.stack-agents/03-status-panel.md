# 状态面板并列显示

几个词先说清：
- 状态面板：主会话输入栏下方的区域。每个运行中的需求占一组行：需求行写目标、任务进度和用量；需求行下面写 PM 在做什么，以及以 ⚑ 开头、等用户处理的待处理事项。
- 任务行：本需求新增的一种行，直接列在需求行下面，一个正在跑或等用户处理的任务占一行。
- 审查代理行：任务处在审查中时，列在任务行下面、再缩进一层的行，一个审查代理占一行。

## 用户故事
### P1：作为用户，我想要在面板上看到同时在跑的每个任务和每个审查，以便知道现在谁在干什么、卡在哪
**用例（主路径）**
- 场景：需求「订单导出」里，T1 写完正在第 1 轮审查（reviewer、go-reviewer 在跑，vue-reviewer 已通过），T2 由 vue-worker 在写。
- 操作：看状态面板。
- 预期：
  ```
  ● 1 个需求运行中
  └─ ⠹ 订单导出 · 任务 2/5 · ↻34 · 210 tool uses · 1.2M token (87%) · 16m40s
       ├ T1 第 1 轮审查
       │ ├ ⠹ reviewer · ↻5/12 · 1m2s
       │ ├ ⠹ go-reviewer · ↻3/12 · 58s
       │ └ ✓ vue-reviewer 通过 · ↻6/12 · 1m40s
       └ ⠹ T2 执行 · vue-worker（第 1 次尝试）· ↻11/20 · 4m30s
  ```

**用例（边界：一个任务等用户裁决，另一个还在跑）**
- 场景：T1 两轮都被打回，T2 还在写。
- 操作：看面板，按 ↓ 进入面板选中 T1 那一行，按 Enter。
- 预期：T1 那一行是「⚑ T1 待裁决：两次未通过审查（go-reviewer）」，需求行仍在转圈；选中后按 Enter 打开这件事的决策包（和现在打开待处理事项一样）。

## 约束
- C-1：需求有子代理在跑，或有和某个任务有关的待处理事项时，需求行下面直接列任务行，不写"N 个任务并行"之类的汇总行，也不写 PM 在做什么那一行。任务行按任务号的先后排列，用 ├ / └ 连线。
- C-2：任务行的写法：
  - 执行中：「⠹ <任务号> 执行 · <定义名>（第 <N> 次尝试）· ↻<已用轮数>/<轮数上限> · <用时>」，定义名是实际派出的角色定义名（如 go-worker、worker、qa）。
  - 审查中：「<任务号> 第 <N> 轮审查」，下面列本轮的审查代理行。
  - 等用户处理：「⚑ <任务号> <事项文字>」，事项文字是现有待处理事项去掉"任务 <任务号> "后的部分，例如「⚑ T1 待裁决：两次未通过审查（go-reviewer）」「⚑ T2 待回答：未决问题」。
- C-3：审查代理行的写法（缩进一层，用 │ ├ └ 连线）：
  - 在跑：「⠹ <定义名> · ↻<已用>/<上限> · <用时>」。
  - 本轮通过：「✓ <定义名> 通过 · ↻<已用>/<上限> · <用时>」，✓ 绿字、其余灰字。
  - 本轮打回：「✗ <定义名> 打回 · ↻<已用>/<上限> · <用时>」。
  - 本轮被跳过：「– <定义名> 已关闭，本轮未审」或「– <定义名> 已不存在，本轮未审」，黄字。
  - 本轮没派、上一轮已通过：「✓ <定义名> 上一轮已通过」，整行灰字。
- C-4：PM 派出的检索也占一行任务行：「⠹ explore 检索 · ↻<已用>/<上限> · <用时>」，排在所有任务之后。
- C-5：没有任务行可列时（PM 在规划、接手、等核对等），照现在的样子显示 PM 在做什么那一行，和需求级的待处理事项（待核对接手理解、待验收完成报告、计划两次被拒、PM 停下了）。有任务行时，需求级的待处理事项以「⚑ <事项文字>」排在任务行之后。
- C-6：需求行的图标规则不变：没有子代理在跑、PM 也停下、有待处理事项时是 ⏸，否则转圈。
- C-7：可选中的行不变，只有需求行和以 ⚑ 开头的行；选中 ⚑ 行按 Enter 打开这件事的决策包，按 p 暂停或恢复 PM。任务进度行和审查代理行不能选中。
- C-8：面板上提到子代理的地方一律写定义名，包括「暂停中：等待 <定义名、定义名> 结束」。
- C-9：每一行都按终端宽度截断，不换行（现有规则）。

## 验收
- [ ] AC-1 ← C-1、C-2：只有 T3 由 go-worker 第 1 次执行时，需求行下面只有一行「⠹ T3 执行 · go-worker（第 1 次尝试）· ↻8/20 · 3m2s」形式的任务行，没有 PM 在做什么那一行；T1、T2、T4 三个同时执行时，三行按任务号排列，没有汇总行。
- [ ] AC-2 ← C-2、C-3：T1 第 1 轮审查中，reviewer、go-reviewer 在跑、vue-reviewer 已通过时，任务行是「T1 第 1 轮审查」，下面三行分别是两个在跑的和「✓ vue-reviewer 通过 · …」；有一个打回时那一行以「✗」开头并写「打回」。
- [ ] AC-3 ← C-3：第 2 轮只派了 reviewer、go-reviewer 时，任务行是「T1 第 2 轮审查」，下面还有一行灰色「✓ vue-reviewer 上一轮已通过」；go-reviewer 被关掉没派时，有一行黄色「– go-reviewer 已关闭，本轮未审」。
- [ ] AC-4 ← C-2、C-6、C-7：T1 待用户裁决、T2 在跑时，T1 那一行是「⚑ T1 待裁决：两次未通过审查（go-reviewer）」，需求行在转圈；按 ↓ 能选中这一行，Enter 后插入的决策包和现在打开这件事时的一样；T2 那一行和审查代理行选不中。
- [ ] AC-5 ← C-4、C-5：PM 派了检索、同时 T2 在执行时，检索行排在 T2 之后；PM 在规划、没有子代理时，第二行是「规划中…」；等核对接手理解时，第二行是「等待核对接手理解」，下面一行是「⚑ 待核对：PM 接手理解 r<N>」。
- [ ] AC-6 ← C-8：暂停一个有 go-worker 和 reviewer 在跑的需求，第二行是「暂停中：等待 go-worker、reviewer 结束」。
- [ ] AC-7 ← C-9：终端 40 列时，所有行都不超过 40 列。

## 验证路径
1. 让 PM 依次派出单个 worker、多个并行 worker、一个任务的多个审查，每一步看面板（AC-1、AC-2）。
2. 构造第 2 轮审查和关掉一个专项审查，看审查代理行（AC-3）。
3. 让一个任务两轮被打回、另一个还在跑，进入面板选中并按 Enter（AC-4）。
4. 让 PM 派检索；在规划和接手阶段看面板（AC-5）；暂停需求（AC-6）；把终端拉窄（AC-7）。
