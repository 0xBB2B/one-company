# 选样例、选层、复制文件

几个词先说清：
- 样例文件：一套样例里要复制的文件。skills 是 `examples/<样例>/skills/<名字>/` 目录里的每个文件，复制到目标层 `skills/<名字>/` 下同名位置；定义是 `examples/<样例>/agents/<名字>.md`，复制到目标层 `agents/<名字>.md`。
- 目标层：用户层是 `~/.pi/agent/skills/`、`~/.pi/agent/agents/`（pi 代理目录下）；项目层是主仓库目录下的 `.pi/skills/`、`.pi/agents/`，在 worktree 里打开 pi 时也是主仓库目录。
- 文件状态：目标位置没有这个文件，叫「未复制」；有，且和样例逐字节相同，叫「已一致」；有，但内容不同，叫「被改过」。
- 样例在某一层的状态：
  - 「未复制」：所有样例文件都未复制，`AGENTS.md` 里也没有样例那一段。
  - 「已复制」：所有样例文件都已一致，`AGENTS.md` 那一段也在且一致。
  - 「有改动」：至少一个样例文件被改过，或 `AGENTS.md` 那一段在但和样例不同。
  - 「部分复制」：上面三种都不是。
  - 「未受信任」：只用于项目层，项目在 pi 里没设为受信任时，不看文件，直接这样写。
  - `AGENTS.md` 那一段：目标 `AGENTS.md` 里从和样例第一行（如「## 后端设计约定」）相同的那一行开始、到下一个二级标题之前的内容；和样例全文去掉末尾空白后相同，就是一致。

## 用户故事
### P0：作为 Go 后端团队的开发者，我想要用一个命令把 Go 样例放进用户层，以便不用手工逐个复制目录
**用例（主路径）**
- 场景：用户第一次用样例，用户层什么都没复制，项目未受信任。
- 操作：输入 `/one:examples` → 选 golang → 选用户层 → 选「复制」。
- 预期：第一个窗口 golang 一行写「Go 后端 · 用户层：未复制 · 项目层：未受信任」；选层窗口项目层变暗，写「项目未受信任，暂不能复制到这里」；确认窗口列出新复制 10 个 skill、2 份定义；复制后 `~/.pi/agent/skills/` 下多出 10 个目录、`~/.pi/agent/agents/` 下多出 `go-worker.md`、`go-reviewer.md`，内容和样例相同。

**用例（异常：有文件被改过）**
- 场景：用户层已有 vue 样例，用户改过 `vue-constraints/SKILL.md` 和 `vue-worker.md`，删掉了 `frontend-constraints/`。
- 操作：输入 `/one:examples` → 选 vue → 选用户层 → 选「复制」。
- 预期：第一个窗口 vue 一行写「用户层：有改动」；确认窗口写「新复制 1：frontend-constraints」「已一致 1：version-policy」「被改过，跳过 1：vue-constraints」，定义一块写「新复制 1：vue-reviewer」「被改过，跳过 1：vue-worker」；复制后两个被改过的文件内容不变；结果提示列出这两个文件的路径。

### P0：作为用户，我想要在复制前看清会替换哪些定义、开关现在是什么状态，以便知道复制后派工会用哪一份
**用例（主路径）**
- 场景：项目受信任，项目层已有 `vue-reviewer.md`，用户把 vue 样例复制到用户层。
- 操作：走到确认窗口。
- 预期：写「复制后替换同名的内置定义。开关按定义名记，vue-worker、vue-reviewer 现在都是开启。」，下一行写「项目层已有 vue-reviewer，在这个项目里用的是项目层那份，用户层这份不生效。」

### P1：作为用户，我想要在已经全部复制过的层上被拦下，以便不做无用的操作
**用例（主路径）**
- 场景：golang 样例在用户层已复制，项目未受信任。
- 操作：输入 `/one:examples` → 选 golang。
- 预期：不弹选层窗口，提示「Go 后端样例在用户层已全部复制，和样例一致；项目未受信任，不能复制到项目层。」

## 约束
- C-1：输入 `/one:examples` 时没有交互终端，只提示「需要交互终端才能打开样例」，不读写任何文件。
- C-2：第一个窗口标题「要用哪套设计规范样例？」，说明行「选中后再选复制到哪一层；skills、角色定义和 AGENTS.md 那一段一起复制。」。包内 `examples/` 下每个子目录占一行，按目录名排序，每行写「<目录名>   <中文名> · 用户层：<状态> · 项目层：<状态>」。中文名：golang 是「Go 后端」，vue 是「Vue 前端」；`examples/` 下每个子目录都要有中文名，由测试检查。
- C-3：选层窗口标题「把 <中文名>样例复制到哪一层？」，两行：
  - 用户层：说明「~/.pi/agent/ · 对你的所有项目生效」。
  - 项目层：说明「<主仓库目录>/ · 只对这个项目生效」。
  - 项目未受信任时，项目层变暗，写「项目未受信任，暂不能复制到这里」。
  - 样例在某层「已复制」时，这一层变暗，写「已全部复制，和样例一致」。
- C-4：两层都变暗时不弹选层窗口，直接提示一行，按情况写「<中文名>样例在用户层已全部复制，和样例一致；项目未受信任，不能复制到项目层。」或「<中文名>样例在用户层和项目层都已全部复制，和样例一致。」，不读写任何文件。
- C-5：确认窗口标题「把 <中文名>样例复制到<层>？」，分三块：
  - 「skills → <目标 skills 目录>」：按 skill 名列出「新复制 N：…」「已一致 N：…」「被改过，跳过 N：…」，数量为 0 的那一类不写。一个 skill 目录里只要有一个文件被改过，这个 skill 算被改过；没有被改过、但有文件未复制，算新复制。
  - 「角色定义 → <目标 agents 目录>」：按定义名，分类同上。
  - 「AGENTS.md → <目标 AGENTS.md>」：写一句这次怎么处理：新建、追加、已有一致不动、已有改过不动，或合并后超限不写。
  - 选项「复制」「不复制」，默认停在「复制」。
- C-6：有定义要新复制时，确认窗口在定义一块下写「复制后替换同名的<现在生效那份所在层>定义。开关按定义名记，<各定义名及开关状态>。」：现在生效的是包内那份写「内置」，是用户层那份写「用户层」。开关状态按设置页列表里显示的状态写「开启」或「关闭」，全部相同时合写成「现在都是开启」或「现在都是关闭」；只有一个定义时写「<名字> 现在是开启」或「<名字> 现在是关闭」。
- C-7：复制到用户层、项目受信任、项目层 `.pi/agents/` 已有同名定义时，对每个这样的定义写一行「项目层已有 <名字>，在这个项目里用的是项目层那份，用户层这份不生效。」。项目未受信任时不写这一行。
- C-8：选「复制」后，只把「新复制」的文件写到目标位置，缺的目录一并创建；「已一致」「被改过」的文件不动。写完每个文件后，它和样例逐字节相同。
- C-9：在确认窗口选「不复制」或按 Esc，或在选样例、选层窗口按 Esc，不读写任何文件，提示「已取消，没有复制任何文件」。
- C-10：复制中途写某个文件失败时立刻停下：已写好的文件保留，写到一半失败的那个文件删掉（下次运行会重新复制它），`AGENTS.md` 不动，提示两行：「✗ 复制没有完成：<原因> <路径>」和「已复制的 N 个文件保留，AGENTS.md 没有动；解决后再运行 /one:examples 会接着补。」。没有权限时原因写「没有权限写入」。
- C-11：复制完成后提示一到三行：
  - 第一行「✓ <中文名>样例已复制到<层>：新复制 N 个文件」，N 是本次写入的文件数；`AGENTS.md` 写入时接着写「，AGENTS.md 已写入「<那一段的标题>」」，句末是「。」。
  - 有被改过、没覆盖的文件时，下一行写「被改过、没有覆盖：<路径>、<路径>」，`AGENTS.md` 那一段被改过时接着写「；AGENTS.md 的「<标题>」一段也没动」，句末是「。」。
  - `AGENTS.md` 写入，且没有跳过的文件时，最后一行写「此后派出的代理按新规范工作。」；`AGENTS.md` 该写没写时，另起一行写明原因。
- C-12：复制完成后，用复制过去的定义和 skill 派工：之后 PM 派出的同名角色用的是目标层那份定义，样例自带的 skill 能被找到。

## 验收
- [ ] C-1：没有交互终端时运行命令，只得到那一句提示，`~/.pi/agent` 和仓库里的文件没有变化。
- [ ] C-2：窗口标题、说明行、行数和每行文字与约束一致；在测试里给 `examples/` 加一个没有中文名的子目录，测试失败。
- [ ] C-2：用测试素材分别造出未复制、部分复制、已复制、有改动、未受信任五种情况，第一个窗口显示的状态与之对应。
- [ ] C-3：项目未受信任时项目层变暗并写那句原因；某层已复制时这一层变暗并写「已全部复制，和样例一致」。
- [ ] C-4：两种两层都变暗的情况各得到对应的一行提示，不弹选层窗口，没有文件变化。
- [ ] C-5：用例「有文件被改过」的确认窗口文字与约束一致；数量为 0 的分类不出现。
- [ ] C-6：生效的是内置定义时写「内置」，复制到项目层且用户层已有同名定义时写「用户层」；一个定义关掉、一个开启时分别写出；只有一个定义要新复制时写「现在是」。
- [ ] C-7：项目受信任且项目层有同名定义时出现那一行；项目未受信任时同样的文件布局不出现。
- [ ] C-8：复制后新文件逐字节等于样例；被改过的文件内容和修改时间都不变。
- [ ] C-9：三个窗口里分别取消，都得到「已取消，没有复制任何文件」，没有文件变化。
- [ ] C-10：让目标 skills 目录不可写后运行，得到两行提示，之前写好的文件还在，`AGENTS.md` 没变；某个文件写到一半失败时，它不留在目标位置。
- [ ] C-11：全部写入、有跳过两种情况的结果提示与约束一致；被改过那一行以「。」结尾。
- [ ] C-12：复制 golang 样例到用户层后，读取角色定义时 go-worker 的来源是用户层，它的 skills 都能找到。

## 验证路径
1. 准备一个空的 pi 代理目录和一个未受信任的仓库，运行 `/one:examples` → 看到两行样例，状态都是「用户层：未复制 · 项目层：未受信任」。
2. 选 golang → 用户层 → 复制 → 不写入 AGENTS.md → 用户层多出 10 个 skill 目录和 2 份定义。
3. 再运行 → golang 一行是「用户层：部分复制」（`AGENTS.md` 那一段还没写）。
4. 改动一份已复制的 skill 再运行 → golang 一行是「用户层：有改动」，确认窗口把它列为「被改过，跳过」，复制后它的内容不变。
