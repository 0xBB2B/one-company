# 追加 AGENTS.md 那一段

几个词先说清：
- 目标 AGENTS.md：选用户层时是 pi 代理目录下的 `AGENTS.md`（默认 `~/.pi/agent/AGENTS.md`），选项目层时是主仓库目录下的 `AGENTS.md`。两份都会作为规范发给每个新派出的代理。
- 样例那一段：样例 `examples/<样例>/AGENTS.md` 的全文。它的第一行是一个二级标题，如「## 后端设计约定」「## 前端设计约定」，下文叫「那一段的标题」。
- 目标里的那一段：目标 AGENTS.md 中，从第一处和「那一段的标题」整行相同的行开始，到下一个以「## 」开头的行之前（没有就到文件末尾）为止的内容。
- 一致：目标里的那一段和样例全文，各自去掉末尾的空白后完全相同。

## 用户故事
### P0：作为用户，我想要复制样例时把团队的关键设计决定一起并进 AGENTS.md，并且先看到改了什么
**用例（主路径）**
- 场景：`~/.pi/agent/AGENTS.md` 里有两行个人规范，没有「## 后端设计约定」。
- 操作：把 golang 样例复制到用户层，确认窗口选「复制」，差异窗口选「写入」。
- 预期：确认窗口的 AGENTS.md 一块写「追加「## 后端设计约定」一段，下一步给你看差异再写」；差异窗口标题「把这些改动写入用户规范 ~/.pi/agent/AGENTS.md？」，原有两行显示为不变，样例全文显示为新增；写入后文件是原内容、一个空行、样例全文。

**用例（边界：合并后超限）**
- 场景：项目根目录的 `AGENTS.md` 已有 12186 字节，golang 样例 4837 字节。
- 操作：把 golang 样例复制到项目层。
- 预期：确认窗口写「合并后 17024 字节，超过 16 KB 上限 640 字节，这次不写。」和「精简 AGENTS.md 后再运行 /one:examples，会只补写这一段。」；选「复制」后不弹差异窗口，skills 和定义照常复制，`AGENTS.md` 不变。

**用例（异常：那一段被改过）**
- 场景：用户层 `AGENTS.md` 已有「## 前端设计约定」，用户改了其中一条。
- 操作：把 vue 样例复制到用户层。
- 预期：确认窗口写「已有「## 前端设计约定」一段，和样例不一样，不动」；不弹差异窗口；`AGENTS.md` 不变。

## 约束
- C-1：确认窗口的 AGENTS.md 一块，按目标 AGENTS.md 的情况写一句：
  - 目标文件不存在：「还没有 AGENTS.md，新建一份，下一步给你看全文再写」。
  - 存在、没有那一段、合并后不超限：「追加「<标题>」一段，下一步给你看差异再写」。
  - 那一段在且一致：「已有「<标题>」一段，和样例一致，不动」。
  - 那一段在但不一致：「已有「<标题>」一段，和样例不一样，不动」。
  - 合并后超限：「合并后 <N> 字节，超过 16 KB 上限 <M> 字节，这次不写。」和下一行「精简 AGENTS.md 后再运行 /one:examples，会只补写这一段。」
- C-2：合并后的内容：目标文件不存在时就是样例全文；存在时是原内容去掉末尾的换行、接一个空行、再接样例全文。合并后按 UTF-8 计超过 16384 字节，就是超限；N 是合并后的字节数，M 是 N 减 16384。
- C-3：只有「新建」或「追加」两种情况，并且用户在确认窗口选了「复制」、所有样例文件都写成功后，才弹差异窗口。其他情况不弹，`AGENTS.md` 不变。
- C-4：差异窗口：
  - 标题：用户层是「把这些改动写入用户规范 <目标路径>？」，项目层是「把这些改动写入项目规范 AGENTS.md？」；目标路径以家目录开头时写成 `~` 开头。
  - 第一行：文件不存在时写「还没有 AGENTS.md，要写入的全文如下：」，存在时写「与现有的 AGENTS.md 相比的改动：」。下面逐行列出原内容（不变）和新增内容。
  - 末尾一行「写入后，此后派出的 PM、worker、reviewer 都按新内容工作。」
  - 选项只有「写入」「不写入」，默认停在「写入」；按 Esc 等于「不写入」。
- C-5：选「写入」后，先重新读一遍目标 AGENTS.md：内容和弹窗前相同，就写入合并后的内容；不同（确认期间被别处改了），就不写。
- C-6：结果提示里 AGENTS.md 没写的几种情况，在第一行之后各加一行：
  - 选了「不写入」：「AGENTS.md 没有写入；想补上就再运行 /one:examples。」
  - 超限：「AGENTS.md 合并后超过 16 KB 上限，没有写入；精简后再运行 /one:examples 补写。」
  - 确认期间被改动：「确认期间 <目标路径> 被别处改动，这次没有写入；再运行 /one:examples 补写。」
- C-7：再次运行时，目标里已有一致的那一段，不会再追加第二份；已有不一致的那一段，不会被改动。

## 验收
- [ ] C-1：五种情况各造一份测试素材，确认窗口里的句子与约束一致；超限句里 N、M 的数字正确。
- [ ] C-2：追加后的文件等于「原内容去掉末尾换行 + 空行 + 样例全文」；目标不存在时等于样例全文；合并后正好 16384 字节时不算超限，16385 字节算超限。
- [ ] C-3：那一段已一致、不一致、超限三种情况都不弹差异窗口；确认窗口选「不复制」时也不弹。
- [ ] C-4：用户层、项目层的差异窗口标题分别与约束一致；选项只有两个；按 Esc 后文件不变。
- [ ] C-5：在差异窗口打开期间改动目标 AGENTS.md 再选「写入」，文件保持被改后的内容。
- [ ] C-6：三种没写的情况，结果提示各多出对应的一行。
- [ ] C-7：写入后再运行一次，目标里那一段只有一份；那一段被改过时运行，文件不变。

## 验证路径
1. 用户层 `AGENTS.md` 写两行个人规范，把 golang 样例复制到用户层并选「写入」→ 文件末尾多出「## 后端设计约定」那一段。
2. 再运行 `/one:examples` → golang 一行是「用户层：已复制」。
3. 改动那一段里的一条，再运行 → golang 一行是「用户层：有改动」；选用户层后确认窗口写「已有「## 后端设计约定」一段，和样例不一样，不动」。
4. 把项目根目录的 `AGENTS.md` 补到 12 KB 以上，把 golang 样例复制到项目层 → 确认窗口写超限的那两句，复制后 `AGENTS.md` 不变。
