# 项目层当场授信

授信记录：pi 在 `~/.pi/agent/trust.json` 里给每个项目记的信任决定。查找时从主仓库根目录往上找最近的一条，找到的是 true 就是"信任"，false 就是"不信任"，一条都没有就是"空"。项目层：设定和定义的存放层级之一，存在项目的 `.pi/` 下，只对这个项目生效，授信记录为"信任"时才生效。存到哪一层：设置页里修改模型设定、Git 交付、合并方式时，最后一步选存到项目层还是用户层的那个选择框。

## 用户故事
### P0：作为在新项目里用 OneCompany 的用户，我想要直接把设定存到项目层

**用例（主路径）**
- 场景：用户在新 clone 的项目 `~/code/shop` 里第一次用 pi，`trust.json` 里没有这个项目，项目里也没有 `.pi/`。
- 操作：输入 `/one:setting`，进「模型」，把 PM 改成 gpt-5.5、high，第 3 步光标停在项目层，按回车。
- 预期：底部提示"✓ PM 改为 gpt-5.5 · high，存到项目层，下次启动 PM 时生效 · 已把本项目设为受信任"；`trust.json` 里 `~/code/shop` 记为 true；`~/code/shop/.pi/settings.json` 的 one-company 字段下有 pm；顶部黄字消失；下次启动 PM 用 gpt-5.5。

**用例（边界：用户选过不信任）**
- 场景：用户以前在 pi 的授信弹窗里对 `~/code/vendor` 选过 Do not trust。
- 操作：在这个项目里打开 `/one:setting`，修改 PM 走到第 3 步。
- 预期：项目层是灰的，不能选，写"你在 pi 里选过不信任这个项目"；光标停在用户层；`trust.json` 不变。

**用例（边界：只看不存）**
- 场景：授信记录为空的项目。
- 操作：打开 `/one:setting`，修改 PM 走到第 3 步后按 Esc 退出，或者选用户层保存。
- 预期：`trust.json` 不变，项目仍然是"还没设为受信任"。

### P0：作为想给项目加专用角色定义或规范样例的用户，我想要直接复制到项目层

**用例（主路径：复制角色定义）**
- 场景：授信记录为空的项目 `~/code/shop`。
- 操作：在 `/one:setting` 的 worker 分区选 worker，按 C，输入新名称 my-worker，复制窗口里选项目层。
- 预期：`~/code/shop/.pi/agents/my-worker.md` 生成；`trust.json` 里这个项目记为 true；提示"✓ 已复制到 ~/code/shop/.pi/agents/my-worker.md，打开它写专长、skills 和 mcp · 已把本项目设为受信任"；回到列表时 my-worker 出现在 worker 分区。

**用例（主路径：复制规范样例）**
- 场景：授信记录为空的项目 `~/code/shop`。
- 操作：输入 `/one:examples`，选 Vue 样例，再选项目层，在确认窗口里确认复制。
- 预期：样例文件复制进项目；`trust.json` 里这个项目记为 true；完成提示末尾有"· 已把本项目设为受信任"。

**用例（异常：写授信记录失败）**
- 场景：授信记录为空，`trust.json` 所在目录没有写权限。
- 操作：在设置页里把 PM 存到项目层。
- 预期：底部红字"✗ 没有保存：<原因>"；项目的 `.pi/settings.json` 没有写入。

**用例（异常：授信写进去了，保存失败）**
- 场景：授信记录为空，项目的 `.pi/settings.json` 是坏的 JSON。
- 操作：在设置页里把 PM 存到项目层。
- 预期：底部红字"✗ 没有保存：<原因> · 已把本项目设为受信任"；`trust.json` 里这个项目记为 true。

## 约束
- C-1：项目层什么时候生效的规则不变：授信记录为"信任"时，项目层的定义和设定生效；"空"和"不信任"时都不生效。
- C-2：授信记录为"空"时，存到哪一层的选择框里项目层可以选，这一行写".pi/settings.json · 选它会把本项目设为受信任"，光标默认停在项目层；选择框下面灰字写"选项目层会把这个项目设为受信任，和在 pi 里输入 /trust 选 Trust 一样；项目里已有的 .pi 设置和角色定义也会一起生效"。模型设定、Git 交付、合并方式三处的选择框都按这条显示。
- C-3：授信记录为"不信任"时，存到哪一层的选择框里项目层是灰的，不能选，这一行写"你在 pi 里选过不信任这个项目"，光标停在用户层；选择框下面灰字写"你在 pi 里选过不信任这个项目。要存到项目层，先在 pi 里输入 /trust 选 Trust，再重开本页"。
- C-4：授信记录为"空"时用户在存到哪一层里选了项目层：程序先把主仓库根目录在 `trust.json` 里记为 true，再写项目设置文件；成功提示在原有文字末尾加"· 已把本项目设为受信任"；回到页面时按新的授信记录重新读取，项目层的定义和设定立即按受信任显示和生效。
- C-5：写授信记录失败时，不写项目层的文件，底部红字"✗ 没有保存：<原因>"（复制定义时是"复制没有完成：<原因>"，复制样例时按 `/one:examples` 现有的失败提示写原因），授信记录保持原样。
- C-6：只有用户在项目层上按回车确认时才写授信记录。打开设置页、浏览、选用户层、按 Esc 取消、在 `/one:examples` 的确认窗口里取消，都不写授信记录。
- C-7：授信记录已经是"信任"时，行为和现在一样：不写授信记录，提示末尾不加"已把本项目设为受信任"。
- C-8：设置页里按 C 复制定义的窗口：授信记录为"空"时，项目层可以选，说明写"<目标文件路径> · 选它会把本项目设为受信任"；选了按 C-4 先写授信记录再复制，成功提示是"✓ 已复制到 <路径>，打开它写专长、skills 和 mcp · 已把本项目设为受信任"。授信记录为"不信任"时，项目层是灰的，写"你在 pi 里选过不信任这个项目，先输入 /trust 选 Trust"。
- C-9：`/one:examples` 选层的窗口：授信记录为"空"时，项目层可以选，说明写"<项目路径>/ · 只对这个项目生效 · 选它会把本项目设为受信任"；用户在确认窗口里确认复制后，按 C-4 先写授信记录再复制，完成提示末尾加"· 已把本项目设为受信任"。授信记录为"不信任"时，项目层是灰的，写"你在 pi 里选过不信任这个项目，先输入 /trust 选 Trust"。
- C-10：`/one:examples` 第一个窗口里每套样例的"项目层：<状态>"：授信记录为"空"或"信任"时写项目层实际的复制状态；"不信任"时写"未受信任"。
- C-11：设置页第一行下面的黄字：授信记录为"空"时写"! 项目还没设为受信任：项目层的定义和设定都没有生效"；"不信任"时写"! 项目未受信任：项目层的定义和设定都没有生效"；"信任"时没有这行。「问题」分类的第一条灰字同样分两种：空时写"项目还没设为受信任，项目层的定义和设定没有生效"，不信任时写"项目未受信任，项目层的定义和设定没有生效"。
- C-12：终端宽 36 到 80 列时，本子需求新增或改动的每一行显示宽度都不超过终端宽度，放不下时折行。
- C-13：授信记录原来为"空"、程序已按 C-4 把本项目记为 true，接着写项目层的文件失败时，授信记录保持 true，失败提示也写明这件事：设置页存模型设定、存开关失败时是"✗ 没有保存：<原因> · 已把本项目设为受信任"；按 C 复制定义失败时，在原有的复制失败提示末尾加" · 已把本项目设为受信任"（如"复制没有完成：没有权限写入 <目录> · 已把本项目设为受信任"）；`/one:examples` 复制失败时，在现有两行失败提示下面另起一行"  · 已把本项目设为受信任"。授信记录原来就是"信任"，或者写授信记录本身失败时，失败提示不加这句。

## 验收
- [ ] AC-1 ← C-1：授信记录为空、项目 `.pi/settings.json` 里有 pm 设定时，PM 用的仍是用户层或内置默认值；`.pi/agents` 里的定义不出现在列表里。
- [ ] AC-2 ← C-2：授信记录为空时，模型设定、Git 交付、合并方式的存到哪一层里，项目层可选、写".pi/settings.json · 选它会把本项目设为受信任"、光标默认在项目层，下面是那段灰字。
- [ ] AC-3 ← C-3：授信记录为 false 时，项目层灰掉、写"你在 pi 里选过不信任这个项目"、光标在用户层，下面是教用户用 /trust 的灰字。
- [ ] AC-4 ← C-4：授信记录为空时把 PM 存到项目层：`trust.json` 里主仓库根目录为 true，项目设置文件写入，提示末尾是"· 已把本项目设为受信任"，重新显示的页面没有黄字。
- [ ] AC-5 ← C-5：`trust.json` 写不进去时，红字"✗ 没有保存：<原因>"，项目设置文件不存在或内容不变，授信记录仍为空。
- [ ] AC-6 ← C-6：授信记录为空时打开设置页、走到第 3 步后 Esc、选用户层保存、在 `/one:examples` 确认窗口取消，`trust.json` 都不变。
- [ ] AC-7 ← C-7：授信记录为 true 时存到项目层，`trust.json` 内容不变，提示里没有"已把本项目设为受信任"。
- [ ] AC-8 ← C-8：授信记录为空时按 C 复制到项目层，文件生成、`trust.json` 为 true、提示文字如约束所写；为 false 时项目层灰掉并写明原因。
- [ ] AC-9 ← C-9：授信记录为空时 `/one:examples` 复制到项目层，确认后文件复制进项目、`trust.json` 为 true、提示末尾有那句话；为 false 时项目层灰掉并写明原因。
- [ ] AC-10 ← C-10：授信记录为空时 `/one:examples` 第一个窗口写项目层的实际复制状态（如"未复制"）；为 false 时写"未受信任"。
- [ ] AC-11 ← C-11：授信记录为空和为 false 时，黄字和「问题」第一条分别是约束里的两种写法；为 true 时都没有。
- [ ] AC-12 ← C-12：36、44、60、80 列下，上面这些画面每一行都不超过终端宽度。
- [ ] AC-13 ← C-13：授信记录为空时，存 PM、存 Git 交付、按 C 复制定义、`/one:examples` 复制到项目层，写授信之后的那一步失败：`trust.json` 为 true，失败提示带"已把本项目设为受信任"，写法如约束所写；授信记录为 true 时同样失败，提示里没有这句。

## 验证路径
1. 新建临时目录当项目，确认 `trust.json` 里没有它 → 打开 `/one:setting`，看黄字（AC-11）。
2. 改 PM 走到第 3 步 → 看项目层那一行和灰字（AC-2）；按 Esc → `trust.json` 不变（AC-6）。
3. 再走一遍，选项目层 → 看提示、`trust.json`、`.pi/settings.json`，黄字消失（AC-4）。
4. 把 `trust.json` 里这一项改成 false，重开 → 第 3 步项目层灰掉（AC-3）；按 C 复制，项目层灰掉（AC-8）。
5. 删掉这一项，输入 `/one:examples` → 第一个窗口写实际状态（AC-10）；选项目层并确认 → 文件复制进项目，`trust.json` 为 true（AC-9）。
