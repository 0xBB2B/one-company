# 通用定义置顶

角色分区：设置页目录里 worker、reviewer、qa、explore、prototype 这 5 项，每项右栏列出这个职责的所有角色定义。通用定义：和分区同名的那个角色定义（worker 分区里的 worker，reviewer 分区里的 reviewer，以此类推），找不到对口的专项定义时就用它干活。分隔线：通用定义下面那一条灰色横线。

## 用户故事
### P0：作为管理角色定义的用户，我想要一眼看出每个分区的兜底定义

**用例（主路径）**
- 场景：用户层有自己复制出来的 my-worker，内置有 worker 和 go-worker、java-worker、node-worker、python-worker、react-worker、vue-worker。
- 操作：在 80 列终端打开 `/one:setting`，目录停在 worker。
- 预期：右栏表头下第一行是 worker（来源"内置"，状态"必须"）；下一行是一条灰色分隔线；线下依次是 my-worker、go-worker、java-worker、node-worker、python-worker、react-worker、vue-worker。

**用例（边界：用户覆盖了通用定义）**
- 场景：用户层有一份 worker.md，覆盖了内置的 worker。
- 操作：打开 worker 分区。
- 预期：第一行仍是 worker，来源显示"用户"；下面是分隔线，线下是其他定义。

**用例（边界：分区里只有通用定义）**
- 场景：qa 分区只有内置的 qa。
- 操作：打开 qa 分区。
- 预期：只有 qa 一行，没有分隔线。

**用例（交互：光标跳过分隔线）**
- 场景：worker 分区，光标在 worker 上。
- 操作：按 ↓，再按 ↑。
- 预期：按 ↓ 后光标直接到 my-worker，按 ↑ 后回到 worker；光标从不停在分隔线上。

## 约束
- C-1：每个角色分区里，和分区同名的通用定义排第一行，不管它来自内置层、用户层还是项目层。
- C-2：分区里除了通用定义还有别的定义时，通用定义下面画一条分隔线：前面留出光标列的 3 列空白，后面用灰色"─"画到右栏最右边。其他定义排在线下，顺序和现在一样：用户层和项目层的在前，内置的在后，同一类按名字排。
- C-3：分区里只有通用定义时，不画分隔线。
- C-4：分隔线不是可选的一行：↑↓ 移动时跳过它；回车展开详情、空格开关、C 复制都只作用在定义行上。通用定义展开详情时，详情显示在它和分隔线之间。
- C-5：目录里每个分区后面的数字仍然是定义的个数，不把分隔线算进去。
- C-6：终端宽 36 到 80 列时，分隔线和其他行一样不超过终端宽度；窄于 60 列只显示右栏时，分隔线画到终端最右边。

## 验收
- [ ] AC-1 ← C-1：worker 分区第一行是 worker；用户层覆盖 worker 后第一行仍是 worker，来源"用户"；reviewer、qa、explore、prototype 分区同理。
- [ ] AC-2 ← C-2：有其他定义时，第二行是 3 列空白加灰色"─"到右栏最右边；线下顺序是用户层和项目层的在前、内置的在后、同类按名字排。
- [ ] AC-3 ← C-3：只有通用定义的分区没有分隔线。
- [ ] AC-4 ← C-4：从通用定义按 ↓ 到线下第一个定义，按 ↑ 回到通用定义；在通用定义上按回车，详情出现在它和分隔线之间；C 和空格作用在光标所在的定义上。
- [ ] AC-5 ← C-5：worker 分区有 8 个定义时，目录里 worker 后面的数字是 8。
- [ ] AC-6 ← C-6：36、44、60、80 列下 worker 分区每一行都不超过终端宽度，分隔线到右栏最右边。

## 验证路径
1. 在用户层放一份 my-worker.md，打开 `/one:setting` 的 worker 分区 → 第一行 worker、第二行分隔线、线下顺序正确（AC-1、AC-2）。
2. 按 ↓ ↑ → 光标跳过分隔线；在 worker 上按回车 → 详情在分隔线上面（AC-4）。
3. 切到 qa 分区 → 只有一行、没有分隔线（AC-3）；看目录数字（AC-5）。
4. 在用户层放一份 worker.md，重开 → 第一行仍是 worker，来源"用户"（AC-1）。
5. 把终端拉到 44 列，进 worker 分区 → 每行都不超宽（AC-6）。
