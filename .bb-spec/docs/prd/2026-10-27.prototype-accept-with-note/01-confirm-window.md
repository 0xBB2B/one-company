# 确认窗口的选项和 Esc

几个词先说清楚：
- 原型：一份单个 HTML 文件的界面设计，用户在浏览器里直接打开就能看。每份原型有名字，同名再出一次就是它的新版本。
- 原型设计师：只负责出原型的子代理，只能由主窗口派出。
- 主窗口、主代理：用户直接对话的那个 pi 窗口，以及在里面回答用户的模型。
- 需求草稿：需求还没被用户批准的下一版内容，显示为"草稿，第 N 版"。
- 在途原型：设计师还在做，或者已经交稿、用户还没选通过、返工、放弃的那一版原型；草稿里有它时不能批准。
- 补充说明：用户选"通过并补充说明"时写的一段话，例如"用 B 方案，A 和 C 不要"，和通过的那一版原型存在一起。

## 用户故事
### P0：作为用户，我想要通过原型时写明选了哪个方案
**用例（主路径）**
- 场景：需求"设置页改版"的草稿是第 3 版，设计师交了"设置页"第 1 版，原型里画了 A、B、C 三种布局。
- 操作：浏览器自动打开这份 HTML，主窗口弹出"确认原型"窗口；用户按 ↓ 把光标移到"通过并补充说明（自己输入）"，输入"用 B 方案（顶部分栏），A 和 C 不要"，回车。
- 预期：对话里出现绿字"已登记：原型「设置页」第 1 版通过，已写进需求草稿。你的说明：「用 B 方案（顶部分栏），A 和 C 不要」"；主代理没有马上回复；用户下次说话时，主代理看到"用户通过了原型「设置页」第 1 版，并补充说明：用 B 方案（顶部分栏），A 和 C 不要"。

**用例（没写字）**
- 场景：同上。
- 操作：光标在"通过并补充说明"上，什么都没输入就按回车。
- 预期：窗口不关，什么都不登记。

### P0：作为用户，我想要按 Esc 就放弃这一版
**用例（主路径）**
- 场景：设计师交了"命令行输出"第 2 版，草稿里已有通过的第 1 版。
- 操作：用户看完不满意，按 Esc。
- 预期：对话里出现绿字"已登记：放弃原型「命令行输出」第 2 版，它不再挡住批准。"；草稿里仍是第 1 版；主代理不回复。

**用例（工具被中断）**
- 场景：主代理用重开确认窗口的工具打开了"设置页"第 1 版的窗口。
- 操作：用户没有在窗口里做选择，而是按快捷键中断了主代理这一轮。
- 预期：窗口关闭，不登记放弃；"设置页"第 1 版仍在等用户确认，之后主代理可以再打开它。

## 约束
- C-1："确认原型"窗口的选项依次是"通过（写进需求草稿）""通过并补充说明（自己输入）""返工（自己输入要改什么）"。光标不在输入行时，底部提示是"↑↓ 选择 · 回车确认 · Esc 放弃这一版"；光标在"通过并补充说明"或"返工"一行时，底部提示是"直接输入 · 回车确认 · ↑↓ 选择 · Esc 放弃这一版"。窗口里其他内容保持现状：标题"确认原型"，依次是需求、原型名称和版本、文件位置、大小和指纹、浏览器是否已打开、上一版的返工意见（有时）、设计师的说明。
- C-2：光标停在"通过并补充说明"一行时，用户的按键直接进这一行下面的输入栏，输入栏显示为"› <已输入的文字>"；输入为空（只有空白也算空）时回车不起作用；超过 4000 字时输入栏下面提示"超出 N 字，最多 4000 字"，回车不起作用。"通过并补充说明"和"返工"两行的输入各自保留：光标移走再移回来，原来输入的字还在。
- C-3：用户在"通过并补充说明"一行输入文字后回车，系统应把这一版写进需求草稿（草稿里已有同名原型时用这一版替换），并把去掉首尾空白后的文字作为这一版的补充说明存下；对话里显示绿字"已登记：原型「<名称>」第 v 版通过，已写进需求草稿。你的说明：「<补充说明>」"。
- C-4：登记了补充说明后，系统应把"用户通过了原型「<名称>」第 v 版，并补充说明：<补充说明>"连同"这句说明已和这一版原型一起存下，批准需求后会原话交给 PM 和子代理。需求正文和这句说明对不上时，按它改正文。"交给主代理；这条消息不在对话里显示，不触发主代理马上回复，主代理在用户下一次说话时看到它。
- C-5：用户选"通过"时，系统照现状把这一版写进草稿，这一版没有补充说明；对话里的绿字仍是"已登记：原型「<名称>」第 v 版通过，已写进需求草稿。"；不告诉主代理、不触发回复。草稿里被替换掉的同名旧版本带的补充说明，不会转到新版本上。
- C-6：用户在确认窗口里按 Esc 时，系统应登记放弃这一版：这一版不再算在途原型，不进草稿；草稿里同名的已通过版本和它的补充说明保持不变；对话里显示绿字"已登记：放弃原型「<名称>」第 v 版，它不再挡住批准。"；不触发主代理回复。主代理用重开确认窗口的工具打开的窗口，按 Esc 也一样登记放弃，工具结果告诉主代理用户放弃了这一版。
- C-7：确认窗口因为工具被中断而关闭、或者当前没有界面、窗口没有显示出来时，系统不登记任何决定，这一版仍是在途原型。
- C-8：返工的行为保持现状：意见为空时不能确认，最长 4000 字；登记后对话里显示"已登记：原型「<名称>」第 v 版返工，你的意见已原话交给主代理重派设计师。"，并触发主代理回复。
- C-9：通过、通过并补充说明、返工、放弃这几种决定，只能由用户在程序窗口里选出或按 Esc 登记；主代理和任何子代理都没有办法直接登记它们，也没有办法写入或修改补充说明。
- C-10：用户要批准的草稿里有在途原型时，主代理收到的拒绝原因里，建议的处理办法是"先把它们处理完（通过、返工，或在确认窗口按 Esc 放弃），再说批准"（只有一份时写"它"，多份时写"这 N 份"）。

## 验收
### AC-1 窗口选项和提示 ← C-1
- 触发：设计师交出"设置页"第 1 版
- Given：草稿第 3 版
- When：查看弹出的确认窗口；把光标分别停在"通过"和"通过并补充说明"上
- Then：选项依次是"通过（写进需求草稿）""通过并补充说明（自己输入）""返工（自己输入要改什么）"；光标在"通过"时底部提示是"↑↓ 选择 · 回车确认 · Esc 放弃这一版"，在"通过并补充说明"时是"直接输入 · 回车确认 · ↑↓ 选择 · Esc 放弃这一版"；其他内容和现状一致

### AC-2 补充说明的输入 ← C-2
- 触发：用户在确认窗口里操作
- Given：光标在"通过并补充说明"上
- When：先直接回车；再输入两个空格回车；再输入 4001 个字回车；再删到 4000 字以内；在"返工"一行输入"甲"后移回"通过并补充说明"
- Then：前三次回车窗口都不关、不登记；4001 字时输入栏下面显示"超出 1 字，最多 4000 字"；移回后"通过并补充说明"一行原来的字还在，"返工"一行仍显示"甲"

### AC-3 通过并补充说明 ← C-3
- 触发：用户在"通过并补充说明"输入"  用 B 方案（顶部分栏），A 和 C 不要 "后回车
- Given：一次草稿里没有"设置页"，第 1 版在等确认；一次草稿里已有通过的"设置页"第 1 版，第 2 版在等确认
- When：登记完成后读取草稿里的"设置页"
- Then：草稿里"设置页"分别是第 1 版和第 2 版，补充说明都是"用 B 方案（顶部分栏），A 和 C 不要"（首尾空白已去掉）；对话里显示 C-3 的绿字，引号里是这句去掉首尾空白的原话

### AC-4 主代理下一轮看到补充说明 ← C-4
- 触发：同 AC-3
- Given：主代理当前空闲
- When：登记完成后，等待一段时间，再由用户说一句话
- Then：登记后主代理没有开始新一轮回复，对话里没有显示这条消息；用户说话后的这一轮里，主代理收到的内容含 C-4 的两句话

### AC-5 普通通过 ← C-5
- 触发：用户选"通过"
- Given：草稿里"设置页"第 1 版带补充说明"用 B"；第 2 版在等确认
- When：选"通过"
- Then：草稿里"设置页"是第 2 版，没有补充说明；对话里绿字和现状一致，没有"你的说明"；主代理没有收到消息、没有被触发回复

### AC-6 Esc 登记放弃 ← C-6
- 触发：用户按 Esc
- Given：草稿里"命令行输出"第 1 版带补充说明"用表格"；第 2 版在等确认。另一次是主代理用重开确认窗口的工具打开第 2 版的窗口
- When：按 Esc
- Then：两次都是：第 2 版不再在途；草稿里仍是第 1 版，补充说明仍是"用表格"；对话里出现 C-6 的绿字；主代理没有被触发回复。第二次的工具结果写明用户放弃了这一版

### AC-7 中断和没有界面不算放弃 ← C-7
- 触发：确认窗口没有经用户按 Esc 关闭
- Given："设置页"第 1 版在等确认
- When：一次是主代理用重开确认窗口的工具打开窗口后，这次工具调用被中断；一次是没有界面时交稿
- Then：两次都没有登记任何决定；"设置页"第 1 版仍在途；之后主代理重开窗口时还能看到它

### AC-8 返工不变 ← C-8
- 触发：用户选"返工"
- Given：第 1 版在等确认
- When：输入空意见回车；再输入"开关放到标题右边"回车
- Then：空意见不能确认；登记后对话里出现 C-8 的文字，主代理被触发回复

### AC-9 只有窗口能登记 ← C-9
- 触发：主代理或子代理试图直接登记通过、通过并补充说明、返工、放弃，或写入、修改补充说明
- Given：有一版在等确认，草稿里有一份带补充说明的原型
- When：用它们能用的所有工具尝试
- Then：都做不到；草稿、补充说明和原型状态不变

### AC-10 拒绝批准的措辞 ← C-10
- 触发：用户要批准草稿
- Given：一次草稿里有一份在途原型；一次有两份
- When：发起批准
- Then：不弹批准窗口；主代理收到的原因里，处理办法分别是"先把它处理完（通过、返工，或在确认窗口按 Esc 放弃），再说批准"和"先把这 2 份处理完（通过、返工，或在确认窗口按 Esc 放弃），再说批准"

## 验证路径
1. 派"设置页"原型 → 交稿后弹窗，选项和底部提示与 C-1 一致。
2. 光标移到"通过并补充说明"直接回车 → 不起作用；输入"用 B 方案"回车 → 对话里出现带"你的说明：「用 B 方案」"的绿字，主代理不回复。
3. 对主代理说"继续" → 主代理这一轮看到"用户通过了原型「设置页」第 1 版，并补充说明：用 B 方案"。
4. 再派"设置页"出第 2 版，交稿后按 Esc → 对话里出现放弃的绿字；草稿里仍是第 1 版，补充说明仍是"用 B 方案"。
5. 再派一版，交稿后不做决定，让主代理用重开窗口的工具打开后中断这次调用 → 这一版仍在途；说"批准" → 被拦下，原因里写"通过、返工，或在确认窗口按 Esc 放弃"。
