# 补充说明交给批准窗口和下游

几个词先说清楚：
- 原型：一份单个 HTML 文件的界面设计，用户在浏览器里直接打开就能看。用户在程序窗口里通过后写进需求草稿，批准需求时一起批准。
- 补充说明：用户在"确认原型"窗口里选"通过并补充说明"时写的一段话，例如"用 B 方案，A 和 C 不要"，和通过的那一版原型存在一起。
- 批准版本：用户批准过的某一版需求，包含这一版的正文和原型。
- PM：需求批准后负责拆计划、派子代理干活的代理。worker 负责实现，reviewer 负责审查 worker 的改动，qa 负责验收。

## 用户故事
### P0：作为用户，我想要批准需求时看到自己对每份原型写的说明
**用例（主路径）**
- 场景：第 2 版需求批准过"命令行输出"第 2 版，当时的补充说明是"用表格那种"；草稿第 3 版里新通过了"设置页"第 1 版，补充说明是"用 B 方案（顶部分栏），A 和 C 不要"；移除了"旧外观弹窗"第 1 版。
- 操作：用户说"批准"。
- 预期：弹出"批准需求"窗口，原型清单依次是绿色的"设置页 第 1 版 本次新确认"、下面一行灰字"你的说明：「用 B 方案（顶部分栏），A 和 C 不要」"；普通颜色的"命令行输出 第 2 版 沿用第 2 版需求"、下面一行灰字"你的说明：「用表格那种」"；红色的"旧外观弹窗 第 1 版 本次移除"，下面没有说明。

### P0：作为用户，我想要干活的代理照着我选的方案做
**用例（主路径）**
- 场景：第 3 版需求批准时带着"设置页"第 1 版，补充说明是"用 B 方案（顶部分栏），A 和 C 不要"。
- 操作：PM 接手需求，拆计划后派 worker 实现、reviewer 审查、qa 验收。
- 预期：PM 收到的原型清单写着"设置页 第 1 版（用户说明：用 B 方案（顶部分栏），A 和 C 不要）"；worker、reviewer、qa 收到的原型清单里，"设置页"那一行下面写着"用户通过时的说明：用 B 方案（顶部分栏），A 和 C 不要"。

## 约束
- C-1："批准需求"窗口的原型清单里，带补充说明的本次新确认或沿用的原型，在它那一行下面多一行灰字"    你的说明：「<补充说明>」"（前面 4 个空格）；本次移除的原型和没有补充说明的原型不加这一行。清单的其他内容（标题行、每行的名称、版本、标签、颜色、排序、最后一行"原型的样子以你在浏览器里通过的那一版为准。"）保持现状。
- C-2：批准需求时，系统应把每份原型的补充说明和它的名称、版本、指纹一起记进这一版需求的原型记录；之后的版本沿用这份原型时，补充说明跟着沿用。
- C-3：PM 派出 worker、reviewer 或 qa 时，任务说明里的原型清单在带补充说明的原型那一行下面，多一行"  用户通过时的说明：<补充说明>"；没有补充说明的原型和现状一样。每个子代理拿到的补充说明来自它所依据的那一版需求。
- C-4：PM 接手需求时收到的说明、以及每次需求更新通知里"当前批准版本附带的原型"清单，带补充说明的原型写成"- <名称> 第 v 版（用户说明：<补充说明>）"；没有补充说明的原型和现状一样。
- C-5：补充说明在批准窗口、PM 和子代理的清单里都是用户原话，不经任何模型转述。

## 验收
### AC-1 批准窗口显示补充说明 ← C-1
- 触发：用户发起批准
- Given：用户故事里的三份原型（新确认的带说明、沿用的带说明、移除的）；另加一份新确认但没有说明的"首页"第 1 版
- When：查看"批准需求"窗口
- Then："设置页"和"命令行输出"那一行下面各有一行灰字"    你的说明：「<原话>」"；"旧外观弹窗"和"首页"下面没有说明行；标题行、颜色、排序和最后一行与现状一致

### AC-2 补充说明随版本沿用 ← C-2
- 触发：用户批准第 3 版，之后再批准只改了正文的第 4 版
- Given：第 3 版草稿里"设置页"第 1 版带补充说明"用 B"
- When：读取第 3 版和第 4 版需求的原型记录
- Then：两版里的"设置页"第 1 版都带补充说明"用 B"

### AC-3 子代理拿到补充说明 ← C-3、C-5
- 触发：PM 依次派 worker、reviewer、qa
- Given：批准版本带"设置页"第 1 版（补充说明"用 B 方案（顶部分栏），A 和 C 不要"）和"命令行输出"第 2 版（没有补充说明）
- When：读取三次运行的提示词
- Then：每份提示词的原型清单里，"设置页"那一行下面有"  用户通过时的说明：用 B 方案（顶部分栏），A 和 C 不要"，和用户原话一字不差；"命令行输出"那一行和现状一样，下面没有说明行

### AC-4 子代理只拿所依据版本的补充说明 ← C-3
- 触发：PM 先后两次派出 worker
- Given：第 3 版需求带"设置页"第 1 版，补充说明"用 B"；PM 按第 3 版派出 worker 甲；之后用户批准第 4 版，把它换成"设置页"第 2 版，补充说明"用 C"
- When：PM 按第 4 版复核计划后派出 worker 乙；分别读取甲、乙的提示词
- Then：甲的是"设置页"第 1 版和"用 B"；乙的是"设置页"第 2 版和"用 C"

### AC-5 PM 的原型清单 ← C-4、C-5
- 触发：PM 接手需求；之后用户批准新版本
- Given：批准版本带"设置页"第 1 版（补充说明"用 B"）和"命令行输出"第 2 版（没有补充说明）
- When：读取 PM 接手时的说明和更新通知
- Then：两处清单都写着"- 设置页 第 1 版（用户说明：用 B）"和"- 命令行输出 第 2 版"

## 验证路径
1. 通过"设置页"并补充"用 B 方案"，普通通过"命令行输出" → 说"批准" → 批准窗口里"设置页"下面有"你的说明：「用 B 方案」"，"命令行输出"下面没有。
2. 确认批准 → PM 接手时的原型清单写着"设置页 第 1 版（用户说明：用 B 方案）"。
3. PM 派 worker → worker 提示词的原型清单里"设置页"下面有"用户通过时的说明：用 B 方案"。
4. 只改正文再批准一版 → PM 更新通知里的清单仍带"用户说明：用 B 方案"。
