# 通过原型时能补充说明，其他里能提问，Esc 即放弃

## 背景与问题
- 原型：一份单个 HTML 文件的界面设计，由原型设计师（只负责出原型的子代理）交稿后，程序打开浏览器并弹出"确认原型"窗口，用户在窗口里决定这一版的去留。
- 现在窗口里的选项是"通过（写进需求草稿）""放弃这一版""返工（自己输入要改什么）"，按 Esc 是"暂不决定"。
- 设计师经常在一份原型里画出 A、B、C 几种方案让用户挑。用户想通过这一版并写明"用 B"，现在做不到：选"通过"不能写字，选"返工"会让设计师重做一版。
- 用户返工时一定会写意见；要放弃的话按 Esc 就够了，不需要单独占一个选项。
- 选"返工"后这一版立刻作废。用户写的话有时只是一个提问（例如"B 方案在窄屏下怎么排？"），主代理答完，原来那版已经没了，要回来只能再派设计师。

## 目标
- 用户在确认窗口里能"通过并补充说明"，写明选了哪个方案或别的补充。
- 补充说明和用户通过的那一版原型存在一起，原话出现在批准需求窗口里，并原话交给 PM 和它派出的 worker、reviewer、qa。
- 主代理在下一轮开始时（通常是用户下次说话时）看到这句补充说明，能据此改需求正文。
- 按 Esc 就登记放弃这一版。
- 用户在"其他（自己输入）"一行写的话交给主代理按内容判断：是提问就回答，要修改就重派设计师；这一版在用户通过或放弃之前一直等确认，用户写过意见后主代理才能重派、顶替这一版。

## 非目标
- 需求完成归档时把补充说明写进归档文件。
- 给已经通过的原型补写或修改补充说明：想改就让设计师再出一版，重新通过时再写。
- "暂不决定、晚点再看"的出口。
- 升级前留下的本机数据继续能用。

## 整体验证路径
1. 主代理派原型设计师出"设置页"，设计师交稿 → 浏览器打开，弹出"确认原型"窗口，选项依次是"通过（写进需求草稿）""通过并补充说明（自己输入）""其他（自己输入）"，底部提示末尾是"Esc 放弃这一版"。
2. 光标移到"通过并补充说明"，直接回车 → 不起作用；输入"用 B 方案（顶部分栏），A 和 C 不要"后回车 → 对话里出现绿字"已登记：原型「设置页」第 1 版通过，已写进需求草稿。你的说明：「用 B 方案（顶部分栏），A 和 C 不要」"，主代理没有马上回复。
3. 对主代理说一句话 → 主代理这一轮看到"用户通过了原型「设置页」第 1 版，并补充说明：用 B 方案（顶部分栏），A 和 C 不要"。
4. 再派一份"命令行输出"，交稿后在"其他"写"表格要不要分页？" → 绿字写明这一版仍在等你确认，主代理回答后重开确认窗口；这时按 Esc → 对话里出现"已登记：放弃原型「命令行输出」第 1 版，它不再挡住批准。"
5. 说"批准" → "批准需求"窗口里"设置页 第 1 版 本次新确认"下面有一行"你的说明：「用 B 方案（顶部分栏），A 和 C 不要」" → 确认。
6. PM 接手 → PM 收到的原型清单和它派出的 worker 收到的原型清单里，"设置页"都带着这句说明原话。

## 决策记录
- **质疑结论**：问题真实存在。设计师在一份原型里给 A、B、C 多个方案时，用户没有地方写"用 B"；返工会让设计师白做一版，单纯通过又会让下游不知道该照哪个方案做。被否决的替代做法：通过后再对主代理口头说"用 B"。这句话只在对话里，不和原型存在一起，下游拿不到用户原话。
- **"放弃这一版"选项换成"通过并补充说明"，按 Esc 就是放弃**（用户 2026-10-27 决定）：用户的原话是"返工一般会写意见，放弃的话直接 ESC 就好了"。代价：去掉了"暂不决定"，按 Esc 后这一版作废，想要回来只能重新派设计师；用户 2026-10-27 确认接受这个代价。被否决的做法：Esc 保持"暂不决定"，放弃改成第四个选项。
- **工具被中断、没有界面时不算放弃**：这两种情况用户没有看到窗口或者没有亲手按 Esc。威胁模型"旧流程与旧记录不产生授权"要求放弃只能来自用户在窗口里的操作。
- **补充说明和原型版本存在一起，原话交给下游**（用户 2026-10-27 决定）：用户选哪个方案就是需求的一部分，要和那一版原型绑定。被否决的做法：只把原话交给主代理，由主代理写进需求正文。这要靠模型转抄，有抄错、漏抄的风险，和返工意见"原话直接交给设计师、不经主代理转述"的做法也不一致。代价：原型的数据格式变了，要升数据库版本号，升级前留下的本机数据打不开。
- **补充说明在主代理下一轮才让它看到，不触发回复**（用户 2026-10-27 决定）：不打断用户；用户下次说话时，主代理看到这句话，就能据此把正文改成只剩选中的方案。被否决的做法：触发主代理马上回复（打扰用户）；完全不告诉主代理（正文和选中的方案可能对不上，要用户自己提醒）。用户 2026-10-27 确认：说明在下一轮开始时交给主代理，在用户说话之前有别的事件先开了一轮时，主代理在那一轮看到，这样即可。
- **补充说明必须写了字才能确认，最长 4000 字**：只通过、不写字的情况已经有"通过"选项。4000 字和"其他"一行的上限一样。
- **"返工"改为"其他（自己输入）"，写下的话交主代理判断，这一版仍在等确认**（用户 2026-10-27 决定）：用户的原话是"不一定是返工也可能是提问需要 Agent 去解答"；名字统一成程序窗口默认的"其他（自己输入）"，和主代理提问窗口一致，也是用户 2026-10-27 提的。被否决的做法：只改名、行为仍和返工一样先作废这一版（提问之后原来那版就没了）；改名为"意见（自己输入：提问或要改的地方）"（用户选了统一用"其他"）。为防止主代理自行作废用户还没处理的版本（威胁模型"模型输出不可信"），只有用户对这一版写过意见，主代理才能重派、顶替它。代价：主代理收到意见时要自己分清是提问还是修改。
