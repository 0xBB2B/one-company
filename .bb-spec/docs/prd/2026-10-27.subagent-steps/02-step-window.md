# 步骤窗口

步骤窗口：在状态面板里选中一个正在运行的子代理行、按回车后弹出的窗口，盖在对话上方，Esc 关闭。子代理：PM 或主窗口派出去干活的代理（worker、reviewer、qa、explore、原型设计师）。步骤：子代理的一次工具调用。工具：子代理能用的操作，pi 自带的有 read（读文件）、grep（搜内容）、find（按文件名找文件）、ls（列目录）；项目自己的工具名字以 `one_company_` 开头，例如 `one_company_change_apply`（预检和写入代码改动）、`one_company_verification_run`（跑命令）；接了 MCP（外部工具服务）的子代理还有 `codemode`（跑一段会调用其他工具的脚本）和 `mcp__` 开头的工具。

窗口运行中的样子（80 列终端）：

```
╭──────────────────────────────────────────────────────────────────────────────
│ T2 执行 · worker（第 1 次尝试）
│ ⠹ 运行中 · 共 13 步 · ↻9/40 · 3m5s
├──────────────────────────────────────────────────────────────────────────────
│ ✓ 读计划
│ ✓ 查项目知识 "导出"
│ ✓ 搜 "exportOrders" 在 src/
│ ✓ 读 src/modules/order/export.ts
│ ✓ 预检改动 src/modules/order/export.ts、src/modules/order/export.test.ts
│ ✓ 写入 src/modules/order/export.ts、src/modules/order/export.test.ts
│ ✗ 跑命令 pnpm vitest run src/modules/order/export.test.ts
│ ✓ 读 src/modules/order/export.ts
│ ⠹ 写入 src/modules/order/export.ts
├──────────────────────────────────────────────────────────────────────────────
│ ↑↓ 滚动 · Esc 关闭
╰──────────────────────────────────────────────────────────────────────────────
```

## 用户故事
### P0：作为等 PM 干活的用户，我想要看到一个 worker 调用过的每个工具和它现在在做的那一步，以便判断它是在干活还是卡住了

**用例（主路径）**
- 场景：worker 在做任务 T2，已经调用了 12 次工具，第 7 次跑命令失败了，第 13 次正在写入 `src/modules/order/export.ts`。
- 操作：在面板里选中 T2 执行行，按回车。
- 预期：弹出窗口，标题"T2 执行 · worker（第 1 次尝试）"，状态行"⠹ 运行中 · 共 13 步 · ↻9/40 · 3m5s"；步骤区按调用先后列出 13 行，前 12 行里 11 行是绿色 ✓、第 7 行是红色 ✗，最后一行"⠹ 写入 src/modules/order/export.ts"的图标在转。

**用例（主路径：实时更新）**
- 场景：窗口开着，光标在步骤区最底下。
- 操作：等 worker 写完、开始跑下一条命令。
- 预期：1 秒内，"写入"那一行变成 ✓，下面多出一行转圈的"跑命令 …"，窗口自动滚到这一行。

**用例（边界：两次工具调用之间）**
- 场景：worker 刚做完第 12 步，模型还没发出下一次工具调用。
- 操作：看窗口。
- 预期：最后一行是转圈的"思考中"，状态行仍是"共 12 步"（"思考中"不算一步）。

**用例（边界：刚开始还没调工具）**
- 场景：worker 刚派出。
- 操作：打开它的步骤窗口。
- 预期：状态行"⠹ 运行中 · 共 0 步 · …"，步骤区只有一行转圈的"思考中"。

**用例（边界：往上翻）**
- 场景：worker 已经调用了 60 次工具，窗口一屏放不下。
- 操作：打开窗口后按 ↑ 若干次。
- 预期：打开时显示的是最新的几步；往上翻后，步骤区第一行写"↑ 上面还有 N 步"，最后一行写"↓ 下面还有 M 步"；这时 worker 又做了一步，窗口停在原处不跳，"下面还有"的数字加 1；按 ↓ 翻回最底下后，又自动跟着新步骤走。

**用例（边界：暂停）**
- 场景：窗口开着，用户在面板上按 p 暂停了 PM，worker 连带暂停。
- 操作：看窗口。
- 预期：状态行变成黄色"⏸ 已暂停 · …"，还没做完的那一步图标换成黄色 ⏸，没有转圈的图标。

**用例（边界：窗口开着时子代理结束）**
- 场景：窗口开着，worker 交完结果。
- 操作：看窗口。
- 预期：窗口不关，全部步骤都还在，状态行变成绿色"✓ 已完成 · 共 15 步 · …"，没有转圈的图标，耗时不再增加。失败时状态行写红色"✗ 失败：<原因>"，被停止时写"✗ 已停止"。

**用例（异常：读不到步骤）**
- 场景：守护进程断开了，或者守护进程重启过、这个子代理之前的步骤已经不在了。
- 操作：打开或开着步骤窗口。
- 预期：状态行写红色"✗ 读不到步骤：<原因>"，步骤区写"守护进程重启后，之前的步骤就没有了。"，底部提示"Esc 关闭"。

## 约束
- C-1：窗口第一行是标题，取自面板上这一行去掉图标、轮数、耗时后的文字：执行行"T2 执行 · worker（第 1 次尝试）"，审查代理"T1 第 1 轮审查 · reviewer"，PM 派出的检索"explore 检索"，原型设计"导出设置页（第 1 版）· prototype"，主窗口的检索"本地 · 现在的导出入口在哪"。
- C-2：窗口第二行是状态行，格式"<图标> <状态> · 共 N 步 · ↻<轮数>/<上限> · <耗时>"，轮数、上限、耗时和面板上这一行的数字一样，没有上限时只写"↻<轮数>"。状态和图标按子代理当前状态取：排队中或运行中是转圈图标加"运行中"；暂停中或已暂停是黄色"⏸ 已暂停"；已完成是绿色"✓ 已完成"；失败是红色"✗ 失败：<原因>"；已停止是红色"✗ 已停止"；被中断是红色"✗ 已中断"。只有运行中时耗时随时间增加。
- C-3：N 是这个子代理到现在一共开始过的工具调用次数，包括正在做的和 codemode 脚本里调用的，不包括"思考中"。
- C-4：步骤区每次工具调用占一行，按开始的先后排列。已结束且成功的打绿色 ✓；已结束且工具报错的打红色 ✗；还没结束的，子代理运行中时是转圈图标，暂停时是黄色 ⏸；子代理已经结束（完成、失败、停止、中断）时，还没结束的步骤打红色 ✗。
- C-5：子代理处于排队中或运行中、且当前没有正在做的工具调用时，步骤区最后多一行转圈的"思考中"（灰色文字）。其他状态下没有这一行。
- C-6：codemode 脚本里调用的工具，各占一行，缩进两格，按开始的先后排在 codemode 那一步下面。
- C-7：每一步的文字按下表取。表里"<…>"是从这次调用的参数里取的值；参数里没有这个值时，连同它前面的连接词一起不写（例如 grep 没给目录时写"搜 "<内容>""）；多个文件用"、"连接。不在表里的工具写工具名本身。

  | 工具（动作） | 显示 |
  |---|---|
  | read | 读 <文件路径> |
  | grep | 搜 "<内容>" 在 <目录> |
  | find | 找文件 <文件名规则> 在 <目录> |
  | ls | 列目录 <目录>，没给目录时写"列目录 ." |
  | one_company_knowledge_query（exact、search、facts） | 查项目知识 "<查的内容>" |
  | one_company_knowledge_query（next） | 查项目知识 |
  | one_company_change_apply（prepare） | 预检改动 <文件1>、<文件2> |
  | one_company_change_apply（apply） | 写入 <文件1>、<文件2> |
  | one_company_change_apply（import） | 导入 <文件1>、<文件2> |
  | one_company_change_apply（status） | 查写入结果 |
  | one_company_verification_run（run） | 跑命令 <命令> |
  | one_company_verification_run（status） | 查命令结果 |
  | one_company_verification_run（stop） | 停命令 |
  | one_company_requirement_manage | 读需求 |
  | one_company_plan_manage | 读计划 |
  | one_company_result_submit | 交结果 |

- C-8：参数里的换行、制表符和其他控制字符换成一个空格。一行超过窗口宽度时从行尾截断，末尾加"…"。
- C-9：窗口开着时，子代理每开始或结束一次工具调用、状态每变一次，窗口在 1 秒内显示出来。转圈图标每 200 毫秒换一帧，和面板上的一样。
- C-10：步骤区一屏放不下时，用 ↑↓ 每次滚一行。上面有被盖住的步骤时，步骤区第一行写"↑ 上面还有 N 步"；下面有被盖住的步骤时，最后一行写"↓ 下面还有 M 步"（灰色）。
- C-11：窗口打开时步骤区显示在最底下。显示在最底下时，新出现的步骤让窗口自动滚到最新一行；用户往上翻过之后，新步骤不让窗口跳动，只更新"下面还有 M 步"的数字；用户翻回最底下后恢复自动跟随。
- C-12：窗口开着时子代理结束，窗口不关，保留结束时的全部步骤，状态行按 C-2 换成结束状态。
- C-13：刚打开、还没拿到数据时，状态行写灰色"读取中…"，步骤区为空，底部提示"Esc 关闭"。
- C-14：拿不到步骤时（守护进程断开、守护进程里已经没有这个子代理的步骤），状态行写红色"✗ 读不到步骤：<原因>"，步骤区写"守护进程重启后，之前的步骤就没有了。"，底部提示"Esc 关闭"。
- C-15：有步骤可看时，底部提示"↑↓ 滚动 · Esc 关闭"。按 Esc 关闭窗口，回到状态面板。
- C-16：步骤只记在守护进程内存里，守护进程退出后清空。同一个任务重派后是新的子代理，步骤从 0 开始记。

## 验收
- [ ] AC-1 ← C-1：五种子代理行（执行、审查代理、PM 派出的检索、原型设计、主窗口检索）分别打开窗口，标题依次是 C-1 里的五个例子。
- [ ] AC-2 ← C-2：子代理分别处于排队中、运行中、暂停中、已暂停、已完成、失败（原因"模型请求失败"）、已停止、被中断时，状态行的图标、颜色和文字符合 C-2；轮数、上限和耗时与面板上这一行一致；没有上限时只有"↻<轮数>"；非运行中的状态下隔 2 秒再看，耗时不变。
- [ ] AC-3 ← C-3、C-6：子代理开始过 3 次工具调用，其中一次是 codemode、脚本里又调了 2 个工具，正在做最后一个；状态行写"共 5 步"。
- [ ] AC-4 ← C-4：运行中的子代理有 3 次调用：成功、报错、还没结束，三行依次是绿色 ✓、红色 ✗、转圈图标。同一份记录在子代理暂停时，第三行是黄色 ⏸；在子代理被停止后，第三行是红色 ✗。
- [ ] AC-5 ← C-5：排队中或运行中、没有正在做的调用时，最后一行是转圈的灰色"思考中"；有正在做的调用、或子代理已暂停、已结束时，没有"思考中"这一行。没有任何调用的排队中或运行中子代理，步骤区只有"思考中"一行，状态行"共 0 步"。
- [ ] AC-6 ← C-6：codemode 下的 2 个调用各占一行，以两个空格缩进，紧跟在 codemode 那一行后面；之后的非 codemode 调用不缩进。
- [ ] AC-7 ← C-7：按 C-7 表里每一行构造一次调用，显示文字与表一致，例如 read `src/a.ts` → "读 src/a.ts"；grep pattern `foo`、path `src/` → "搜 "foo" 在 src/"；grep 只有 pattern → "搜 "foo""；ls 不给 path → "列目录 ."；change_apply apply 两个文件 → "写入 a.ts、b.ts"；verification_run run command `pnpm test` → "跑命令 pnpm test"；`mcp__github__search` → "mcp__github__search"。
- [ ] AC-8 ← C-8：命令参数是"pnpm test\n--run"时显示"跑命令 pnpm test --run"；读一个 200 个字符长的路径，窗口宽 80 列时这一行不超过窗口宽度、以"…"结尾。
- [ ] AC-9 ← C-9：窗口开着，子代理开始一次新的工具调用，1 秒内窗口多出这一行；这次调用结束，1 秒内图标变成 ✓ 或 ✗；子代理被暂停，1 秒内状态行变成"⏸ 已暂停"。
- [ ] AC-10 ← C-10：60 个步骤、步骤区能显示 20 行时，打开后按 ↑ 10 次，第一行写"↑ 上面还有 N 步"、最后一行写"↓ 下面还有 M 步"，N + M + 中间显示的步骤数 = 60。
- [ ] AC-11 ← C-11：打开时最后一行是最新一步；在最底下时新增一步，最后一行变成这新的一步；按 ↑ 翻上去后新增一步，显示的步骤不变、"下面还有"的数字加 1；再按 ↓ 翻回最底下后新增一步，最后一行又是最新的一步。
- [ ] AC-12 ← C-12：窗口开着时子代理完成，窗口仍在，步骤行数和结束前一样，状态行是"✓ 已完成 · 共 N 步 · …"，窗口里没有转圈图标。
- [ ] AC-13 ← C-13：守护进程还没返回数据时，状态行是"读取中…"，没有步骤行，底部是"Esc 关闭"。
- [ ] AC-14 ← C-14：读取时守护进程断开，状态行是红色"✗ 读不到步骤：<原因>"，步骤区是"守护进程重启后，之前的步骤就没有了。"；守护进程里查不到这个子代理的步骤时一样。
- [ ] AC-15 ← C-15：有步骤时底部提示是"↑↓ 滚动 · Esc 关闭"；按 Esc 后窗口关闭，焦点回到状态面板。
- [ ] AC-16 ← C-16：守护进程重启后，同一个子代理的步骤读不到（走 C-14）；同一个任务第 2 次尝试的子代理，打开窗口时"共 0 步"开始，看不到第 1 次尝试的步骤。

## 验证路径
1. 起一个 worker，打开它的步骤窗口，看标题、状态行和"思考中"（AC-1、AC-5）。
2. 让它依次做一次成功、一次报错的调用，再开始一次不结束的调用，对照图标和颜色；中途开始的调用 1 秒内出现（AC-4、AC-9）。
3. 构造 codemode 调用和 C-7 表里每种工具调用，对照文字、缩进和步数（AC-3、AC-6、AC-7、AC-8）。
4. 构造 60 个步骤，按 AC-10、AC-11 的顺序滚动和新增步骤（AC-10、AC-11）。
5. 依次把子代理切成暂停、完成、失败、停止、中断，看状态行和最后一步（AC-2、AC-4、AC-12）。
6. 让守护进程晚一点返回、断开、重启，看读取中和读不到的样子（AC-13、AC-14、AC-16）。
7. 按 Esc 关窗口（AC-15）。
8. 其他四种子代理行各打开一次窗口，看标题（AC-1）。
