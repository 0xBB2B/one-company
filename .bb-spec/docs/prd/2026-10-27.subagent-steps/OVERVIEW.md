# 状态面板查看子代理正在做什么

状态面板：pi 主窗口输入栏下方的区域。每个运行中的需求占一组行，需求下面每个正在跑的子代理占一行；面板底部还有主窗口自己派出的原型设计和检索两组行。子代理：PM 或主窗口派出去干活的代理，包括 worker（写代码）、reviewer（审查）、qa（功能验收）、explore（只读查资料）和原型设计师。步骤：子代理的一次工具调用，例如读一个文件、搜一段代码、写入改动、跑一条命令。

## 背景与问题
PM 派出的 worker 一跑就是十几分钟，面板上它只占一行：一个转圈的图标、轮数和耗时。用户看不出它是在干活还是卡住了，也看不出干到了哪一步。想知道就只能让主代理去翻会话记录，而用户并不想看完整的对话内容，只想知道它现在在干什么、之前做过什么。

## 目标
- 用户在状态面板里选中任意一个正在运行的子代理，按回车，能看到它从开始到现在调用过的全部工具，每一步一行。
- 做完的步骤打绿色 ✓，失败的步骤打红色 ✗，正在做的那一步是转动的图标；两次工具调用之间写"思考中"并转动，看得出它没卡住。
- 窗口开着时内容实时更新。

## 非目标
- 不显示模型说的话、思考内容和工具返回的结果，只显示每一步做了什么。
- 不让子代理自己汇报步骤清单，不改任何代理的提示词。
- 不保存步骤：守护进程退出后，之前的步骤就没有了。已经结束的子代理不提供回头查看的入口。
- 已经结束的子代理行（✓ 通过、✗ 打回、– 等重派、用满、未审）不能选中。
- 面板上原有每一行的文字和样子不改。

## 依赖与交付顺序
01 → 02。02 的窗口从 01 的回车打开。

## 整体验证路径
1. 批准一个需求，等 PM 派出一个 worker。在输入框为空时按 ↓ 进入面板，再按 ↓ 把光标移到"T1 执行 · worker（第 1 次尝试）"这一行 → 这一行被高亮。
2. 按回车 → 弹出窗口，标题是"T1 执行 · worker（第 1 次尝试）"，第二行是"⠹ 运行中 · 共 N 步 · ↻轮数/上限 · 耗时"，下面每行一个步骤，做完的是绿色 ✓，最后一行是转圈的图标。
3. 不关窗口等一会儿 → worker 每调一次工具，窗口在 1 秒内多出一行；光标在最底下时窗口自动跟到最新一行。
4. 按 Esc → 窗口关闭，回到面板，光标还在这个 worker 行。
5. 主窗口派一次检索，按 ↓ 进入面板，选中底部的检索行按回车 → 同样弹出它的步骤窗口。
6. 打开一个 worker 的步骤窗口后等它交完结果 → 窗口不关，第二行变成"✓ 已完成 · 共 N 步 · …"，没有转圈的图标；按 Esc 关掉后，面板上已经没有这一行。

## 决策记录
- 一次工具调用算一步，由程序从工具事件里直接记，不要求模型配合。否决"子代理自己汇报步骤清单"：要改提示词并跑全套真实模型验收，模型还可能漏报、乱报，清单不一定准；否决"只显示一行当前动作"：看不到之前做完了哪些。用户 2026-10-27 决定。
- 显示全部步骤，不只最近几步。用户 2026-10-27 决定。
- 参考 omp（oh-my-pi）的子代理进度显示。omp 只在子代理行下写一行"当前工具 + 意图"，子代理整个跑完后那一行变色，没有逐步打勾，子代理也用不了待办清单工具（`@oh-my-pi/pi-coding-agent/src/task/render.ts:968-990`、`task/executor.ts:3238-3241`）。本需求逐步打勾是用户提出的，不照搬 omp。
- 步骤放在单独弹出的程序窗口里看，不在面板里就地展开。否决就地展开：一个 worker 有几十步，展开后面板会把对话内容挤出屏幕。用户 2026-10-27 决定。
- 每一步写中文动作加参数摘要，例如"读 src/a.ts"。否决直接显示英文工具名：用户要看的是"在做什么"。不在对照表里的工具（如 MCP 工具）显示工具名。用户 2026-10-27 决定。
- 范围包括 PM 派出的子代理，以及主窗口派出的原型设计和检索。用户 2026-10-27 决定。
- 步骤只存在守护进程内存里，不进数据库；窗口开着时子代理结束，窗口停在最后状态。否决"跑完也能回头查"：要新增存储和历史入口，范围大一倍，用户要的是看"现在在做什么"。用户 2026-10-27 决定。
- 只有正在运行的子代理行能选中，已经结束的行选不中；在需求下面的子代理行上按 p 暂停或恢复的是这个需求的 PM，和在 ⚑ 事项行上按 p 一样；原型设计和检索行上按 p 没反应；两步之间显示"思考中"；光标在最底下时自动跟到底；codemode 脚本里调用的工具缩进两格挂在 codemode 那一步下面。以上都画在界面预览里，用户 2026-10-27 确认。
