# 空闲时当场换新

守护进程：每个仓库一个、在后台跑 PM、worker、原型设计师、explore 等代理会话的 Node 进程，同一仓库的多个 pi 窗口共用它。代码指纹：根据 one-company 安装目录里 `package.json` 的 `files` 列出的目录（`src`、`role-rules`、`rules`、`agents`、`skills`、`shared`、`examples`、`assets`、`resources/tree-sitter`）中的文件，以及 `package.json` 本身的内容算出的摘要。代码过旧：守护进程启动时的代码指纹，和此刻磁盘上安装目录的代码指纹不同。空着：守护进程上没有需求在跑（排队、运行中、暂停中、已暂停都算在跑），也没有本窗口以外的窗口连着。项目目录名：守护进程所属仓库的主仓库目录名，例如 `企微BOT`。

## 用户故事
### P0：作为刚更新 one-company 的用户，我想要打开 pi 窗口时自动用上新代码，以便不用手动关窗口、等 10 分钟或结束进程

**用例（主路径：协议版本号变了）**
- 场景：企微BOT 的守护进程是昨天启动的，协议版本号是 6；用户今天合并了新代码，协议版本号升到 7。用户关掉了企微BOT 的唯一一个窗口，9 秒后重新打开 pi。
- 操作：打开 pi。
- 预期：窗口里显示一行灰色消息"企微BOT 的后台进程跑的是旧代码，已停掉并换成当前安装的版本。"；原来的守护进程已退出，新拉起的守护进程在运行；主代理调用需求工具成功。

**用例（主路径：协议版本号没变，只改了守护进程里的逻辑）**
- 场景：守护进程在跑，没有窗口连着；用户合并了只改 `src/modules/pm/task-dispatch.ts` 的代码，协议版本号没变。
- 操作：打开 pi。
- 预期：同上，显示同一行灰色消息，原守护进程退出，换上新的。

**用例（边界：只改了测试或文档）**
- 场景：守护进程在跑，没有窗口连着；用户只改了 `tests/` 下的文件和 `README.md`。
- 操作：打开 pi。
- 预期：窗口直接连上原来的守护进程，不显示换新消息，原守护进程的进程号不变。

**用例（边界：守护进程和磁盘一致）**
- 场景：守护进程是刚按磁盘上的代码拉起的；一个开了很久、代码比磁盘旧的窗口断线后重连上来。
- 操作：旧窗口重连。
- 预期：守护进程不被停掉，进程号不变。

**用例（边界：两个窗口同时打开）**
- 场景：守护进程代码过旧且空着。
- 操作：几乎同时打开两个 pi 窗口。
- 预期：最后只有 1 个新守护进程在运行，两个窗口都连着它，两个窗口里调用需求工具都成功；至少一个窗口显示换新消息。

## 约束
- C-1：窗口打开时（以及连接断开后重连时），连上的守护进程代码过旧且空着 → 停掉它，拉起新守护进程并连上，窗口显示灰色消息"<项目目录名> 的后台进程跑的是旧代码，已停掉并换成当前安装的版本。"。协议版本号相同或不同都这样处理。
- C-2：代码过旧只看守护进程和磁盘的代码指纹：`files` 列出的任一目录中任一文件的内容变了，或者 `package.json` 变了，就算过旧；只改其他文件（如 `tests/`、`README.md`、`AGENTS.md`）不算。
- C-3：守护进程的代码指纹和磁盘一致时，不管连上来的窗口自己的代码新还是旧，它都不会被停掉。
- C-4：守护进程在被要求停下的那一刻已经不空着了（例如另一个窗口刚连上、刚派出需求），它不停；窗口按「忙时等它空下来再换」的规则处理。
- C-5：同时有多个窗口要换掉同一个过旧守护进程时，最后只剩 1 个新守护进程，所有窗口都连着它。
- C-6：换新过程中新守护进程启动失败时，窗口显示的错误和现在拉起守护进程失败时一样（写明启动失败的原因和日志内容）。

## 验收
- [ ] C-1：样例项目里守护进程过旧且空着，打开窗口 → 显示灰色换新消息；原进程号已不存在，有新的守护进程；调用需求工具成功。协议版本号相同、不同各测一次。
- [ ] C-2：只改 `tests/` 下文件后打开窗口 → 守护进程进程号不变、没有换新消息；改 `role-rules/` 下一个文件后打开窗口 → 换新；只改 `package.json` 后打开窗口 → 换新。
- [ ] C-3：守护进程按当前磁盘代码启动，一个代码指纹不同的窗口连上来 → 守护进程进程号不变。
- [ ] C-4：在守护进程收到停下请求前让它带上一个运行中的需求 → 它不退出，窗口进入等待状态。
- [ ] C-5：两个窗口同时连上同一个过旧且空着的守护进程 → 最后只有 1 个守护进程，两个窗口调用需求工具都成功。
- [ ] C-6：让新守护进程启动即退出 → 窗口显示的错误里带启动失败原因和日志内容。

## 验证路径
1. 打开样例项目的窗口 A，记下守护进程进程号 P1，关掉 A。
2. 改 `src/` 下任意一个文件，10 分钟内打开窗口 B → 看到灰色换新消息；`ps -p P1` 已不存在；有新的守护进程 P2。
3. 在 B 里让主代理调用需求工具 → 成功。
4. 关掉 B，只改 `tests/` 下一个文件，打开窗口 C → 没有换新消息，守护进程仍是 P2。
