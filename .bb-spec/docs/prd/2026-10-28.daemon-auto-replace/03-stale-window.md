# 旧窗口提示重开

守护进程：每个仓库一个、在后台跑 PM、worker、原型设计师、explore 等代理会话的 Node 进程，同一仓库的多个 pi 窗口共用它。协议版本号：窗口和守护进程之间消息格式的编号，两边不同就无法通信。旧窗口：在 one-company 代码更新之前打开、一直没重开的 pi 窗口，它内存里跑的还是旧代码。守护进程和磁盘一致：守护进程是按此刻磁盘上装的 one-company 代码启动的。项目目录名：守护进程所属仓库的主仓库目录名，例如 `企微BOT`。`pi -c`：pi 自带的启动参数，接着上一次的会话继续对话。

## 用户故事
### P1：作为开着旧窗口的用户，我想要知道这个窗口为什么用不了需求功能、怎么恢复，以便不去关错窗口、也不丢对话

**用例（主路径）**
- 场景：用户在旧窗口 E 里聊着；另一个新窗口把企微BOT 的守护进程换成了新版本，协议版本号也变了。E 的连接断开后重连。
- 操作：在 E 里让主代理调用需求工具。
- 预期：E 里显示红色错误"Error: 这个窗口是旧版本，和企微BOT 已更新的后台进程不兼容，需求和代理功能用不了。请关掉这个窗口，运行 pi -c 重新打开，接着原来的对话。"；主代理收到的错误原因是"这个窗口是旧版本，和企微BOT 已更新的后台进程不兼容。"，建议是"请用户关掉这个窗口，运行 pi -c 重新打开，接着原来的对话。"；新守护进程仍在运行，进程号不变。

**用例（边界：协议版本号相同）**
- 场景：同上，但这次更新没改协议版本号。
- 操作：在 E 里调用需求工具。
- 预期：调用成功，不显示任何提示。

## 约束
- C-1：守护进程和磁盘一致、协议版本号和窗口不同 → 窗口不停守护进程，显示红色错误"这个窗口是旧版本，和<项目目录名> 已更新的后台进程不兼容，需求和代理功能用不了。请关掉这个窗口，运行 pi -c 重新打开，接着原来的对话。"。
- C-2：C-1 状态下调用需求或代理工具失败，主代理收到的错误原因是"这个窗口是旧版本，和<项目目录名> 已更新的后台进程不兼容。"，建议是"请用户关掉这个窗口，运行 pi -c 重新打开，接着原来的对话。"。
- C-3：C-1 状态下窗口不自动重试连接，也不会停掉守护进程。
- C-4：守护进程和磁盘一致、协议版本号和窗口相同 → 窗口照常使用，不显示任何提示。
- C-5：用户看到的错误和主代理收到的错误里都用项目目录名，不出现 64 位的仓库编号。

## 验收
- [ ] C-1：守护进程按当前磁盘代码启动，一个协议版本号更旧的窗口连上来 → 窗口显示的红色错误文字与 C-1 一致。
- [ ] C-2：同上状态下调用需求工具 → 失败，错误的原因和建议与 C-2 一致。
- [ ] C-3：同上状态下等待 2 分钟 → 守护进程进程号不变，窗口没有发起新的连接。
- [ ] C-4：协议版本号相同的旧窗口连上和磁盘一致的守护进程 → 调用需求工具成功，没有提示。
- [ ] C-5：C-1、C-2 的错误里没有 64 位十六进制编号，带项目目录名。

## 验证路径
1. 打开窗口 E 并保持打开。
2. 升协议版本号并改代码，打开新窗口 F → F 因为 E 还连着而进入等待。
3. 结束旧守护进程 → 30 秒内磁盘上的新代码启动了新守护进程，F 显示换新消息，E 自动重连。
4. 在 E 里调用需求工具 → 显示 C-1 的红色错误，主代理收到 C-2 的原因和建议。
5. 关掉 E，运行 `pi -c` → 原来的对话还在，调用需求工具成功。
