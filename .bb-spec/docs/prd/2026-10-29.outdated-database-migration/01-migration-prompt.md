# 迁移提示框与执行迁移

本机数据库：每个仓库在本机数据目录（默认 `~/.pi/agent/one-company/repos/<仓库编号>/`）下的 `data.db`（需求、运行记录、计划、原型记录）和 `index.db`（项目索引，从代码算出来）。库里记着格式版本号，当前代码要求 `data.db` 是版本 9、`index.db` 是版本 2。守护进程：每个仓库一个、在后台跑代理的 Node 进程，pi 窗口打开时没在跑就自动拉起。程序窗口：pi 窗口里弹出、用 ↑↓ 选择、回车确认的框，黄色边框和标题。补充说明：版本 8 的原型记录里，用户在"确认原型"窗口选"通过并补充说明"时写的话，版本 9 没有这项。

## 用户故事
### P0：作为升级了 one-company 的用户，我想要在打开 pi 窗口时被问要不要把旧库迁移过来，以便接着用进行中的需求，不用删数据目录

**用例（主路径：data.db 和 index.db 都旧）**
- 场景：用户在项目 `企微BOT` 里用过版本 8 的代码，有一个需求正在澄清，里面有一版已通过、写过补充说明"按钮改蓝色"的原型「首页」，还有一版等用户确认的原型「设置页」；`index.db` 是版本 1。用户更新到当前代码，所有 pi 窗口都已关闭，守护进程已退出。
- 操作：在 `企微BOT` 里打开 pi，在弹出的框里选「迁移」，回车。
- 预期：
  - 框的标题是"仓库 企微BOT 的本机数据库是旧版本，要迁移吗？"，内容依次是：
    - `data.db（需求、运行记录）：版本 8 → 9`
    - `  迁移会丢掉原型记录里的「补充说明」（这个功能已经去掉了）`
    - `  迁移前先把 data.db 备份到本机数据目录的 backups/ 下`
    - `index.db（项目索引）：版本 1 → 2，删掉旧索引后重新建`
    - `不迁移，这个窗口里的需求和后台代理功能用不了`
  - 选项是「迁移」「暂不迁移」，默认选中「迁移」；底部提示是"↑↓ 选择 · 回车确认 · Esc 暂不迁移"。
  - 回车后框关掉，窗口底部出现"正在迁移仓库 企微BOT 的本机数据库，先备份 data.db…"。
  - 迁移完成后出现"仓库 企微BOT 的本机数据库已迁移到当前版本。旧 data.db 备份在 <完整路径>。索引会在第一次查询时重新建。"，路径是 `<本机数据目录>/backups/<编号>/data.db`。
  - 守护进程启动；`data.db` 是版本 9；需求还在；原型「首页」那一版仍是已通过，选定方案为空，补充说明没有了；原型「设置页」那一版仍在等确认，方案清单为空，再弹"确认原型"窗口时列"通过"和"其他"。
  - 旧 `index.db` 被删掉，索引按版本 2 重新建，项目索引查询能查到结果。

**用例（主路径：只有 index.db 旧）**
- 场景：`data.db` 已是版本 9，`index.db` 是版本 1。
- 操作：打开 pi，选「迁移」。
- 预期：框里只有两行内容：`index.db（项目索引）：版本 1 → 2，删掉旧索引后重新建` 和 `不迁移，这个窗口里的需求和后台代理功能用不了`；没有备份那一行，不备份；迁移后索引重建，守护进程正常启动。

**用例（异常：选「暂不迁移」或按 Esc）**
- 场景：同主路径。
- 操作：在框里选「暂不迁移」回车，或直接按 Esc。
- 预期：库不变，仍是版本 8；这个仓库的守护进程不启动；窗口底部出现"仓库 企微BOT 的本机数据库是旧版本，这次没有迁移，这个窗口里的需求和后台代理功能用不了。重开 pi 窗口可以再次选择迁移。"；主代理调用 OneCompany 的工具时，报错原因写"仓库 企微BOT 的本机数据库是旧版本，用户这次选了暂不迁移"，下一步写"请用户重开 pi 窗口，在提示框里选「迁移」"。之后关掉窗口重开，框再次弹出。

**用例（异常：迁移失败）**
- 场景：`data.db` 里某条原型记录缺了必填项，转不成版本 9 的格式。
- 操作：打开 pi，选「迁移」。
- 预期：窗口底部出现报错，写明哪个仓库、哪一步失败（`data.db 版本 8 → 9`）、失败的是哪条记录（需求编号、原型名）、为什么失败，以及"数据库没有改动，还是版本 8"、迁移前备份的完整路径、"这个窗口里的需求和后台代理功能用不了，重开 pi 窗口可以再试一次"；`data.db` 内容和版本号都和迁移前一样；`index.db` 也没有被删。

**用例（边界：旧守护进程还在忙）**
- 场景：版本 8 代码的守护进程还在跑一个需求。用户更新代码后新开一个 pi 窗口。
- 操作：打开 pi。
- 预期：先照现在的行为等旧守护进程空下来（窗口里写明在等什么），等的时候不弹框；旧守护进程退出后才弹迁移框。

**用例（边界：两个窗口同时打开）**
- 场景：两个 pi 窗口几乎同时在 `企微BOT` 里打开，库是版本 8。
- 操作：两个窗口都打开。
- 预期：只有一个窗口弹框；另一个窗口等它处理完。用户在弹框的窗口里选了「迁移」并成功后，另一个窗口直接连上守护进程，不弹框；选了「暂不迁移」时，另一个窗口弹自己的框。

**用例（边界：多仓库工作区）**
- 场景：pi 窗口开在 `~/work/`，它本身不是 git 仓库，下面的 `api/` 和 `web/` 两个仓库的 `data.db` 都是版本 8。
- 操作：打开 pi，第一个框选「迁移」，第二个框选「暂不迁移」。
- 预期：先弹 `api` 的框，答完再弹 `web` 的框，标题分别写各自的仓库名；`api` 迁移完成、守护进程启动、功能可用；`web` 的库不变、守护进程不启动，调用 `web` 的功能时报"选了暂不迁移"的错误。

## 约束
- 打开 pi 窗口、要为某个仓库启动新守护进程之前，程序检查这个仓库的 `data.db` 和 `index.db` 的版本号；有一个是可迁移的旧版本（`data.db` 版本 8、`index.db` 版本 1），就在这个仓库的守护进程启动前弹迁移框。
- 两个库都是当前版本，或库还不存在时，不弹框，照常启动。
- 框的标题是"仓库 <仓库显示名> 的本机数据库是旧版本，要迁移吗？"，仓库显示名和状态面板、Shell 任务里显示的仓库名一致。
- 框的内容按库列出：`data.db` 旧时列"data.db（需求、运行记录）：版本 <旧> → <新>"、迁移会丢掉的数据、"迁移前先把 data.db 备份到本机数据目录的 backups/ 下"；`index.db` 旧时列"index.db（项目索引）：版本 <旧> → <新>，删掉旧索引后重新建"；最后一行是"不迁移，这个窗口里的需求和后台代理功能用不了"。
- 框的选项只有「迁移」「暂不迁移」，默认选中「迁移」；Esc 等同于「暂不迁移」，底部提示是"↑↓ 选择 · 回车确认 · Esc 暂不迁移"；样式和现有程序窗口一致（黄色边框和标题）。
- 选「迁移」后：要迁移 `data.db` 时，先把旧 `data.db` 复制一份到 `<本机数据目录>/backups/<编号>/data.db`，复制成功后才开始改；只迁移 `index.db` 时不备份。
- `data.db` 版本 8 到 9 的转换：每条原型记录里，交稿内容加上空的方案清单，加上空的选定方案，去掉补充说明；原型版本历史里的每一项加上空的选定方案，去掉补充说明；其他记录不变；最后把版本号改成 9。
- `data.db` 的转换在一次数据库事务里完成：任何一条记录转换失败，所有改动都不写入，库保持原来的版本和内容。
- `index.db` 版本 1 的迁移是删掉旧 `index.db`，由程序按当前格式重新建索引。`data.db` 迁移失败时不删 `index.db`。
- 迁移进行中，窗口底部显示"正在迁移仓库 <仓库显示名> 的本机数据库……"；成功后显示"仓库 <仓库显示名> 的本机数据库已迁移到当前版本。"，迁移过 `data.db` 时接着写"旧 data.db 备份在 <完整路径>。"，迁移过 `index.db` 时接着写"索引会在第一次查询时重新建。"；之后守护进程照常启动。
- 迁移失败时，窗口底部的报错写明：仓库显示名、失败的那一步（如"data.db 版本 8 → 9"）、失败的记录（需求编号和原型名）、原因、"数据库没有改动"、备份的完整路径（已备份时）、"这个窗口里的需求和后台代理功能用不了，重开 pi 窗口可以再试一次"。这个仓库的守护进程不启动。
- 选「暂不迁移」或 Esc：库不变，这个仓库的守护进程不启动，窗口底部显示"仓库 <仓库显示名> 的本机数据库是旧版本，这次没有迁移，这个窗口里的需求和后台代理功能用不了。重开 pi 窗口可以再次选择迁移。"；之后这个窗口里调这个仓库的 OneCompany 工具，给模型的报错原因是"仓库 <仓库显示名> 的本机数据库是旧版本，用户这次选了暂不迁移"，下一步是"请用户重开 pi 窗口，在提示框里选「迁移」"。
- 重开 pi 窗口时，库仍是可迁移的旧版本，就再次弹框。
- 旧守护进程还在跑、要等它换新时，等它退出后才检查版本、弹框；等待期间不弹框。
- 同一个仓库同一时间只有一个窗口在弹迁移框或执行迁移；其他窗口等它结束。结束后库已是当前版本，就直接连上守护进程、不弹框；库仍是旧版本，就弹自己的框。迁移进行中，别的进程打不开这个库。
- 多仓库工作区里，每个要迁移的仓库各弹一次框，一次只显示一个，前一个答完再弹下一个；一个仓库选了「暂不迁移」或迁移失败，不影响其他仓库。

## 验收
- [ ] `data.db` 版本 8、`index.db` 版本 1 时打开 pi → 守护进程启动前弹出迁移框，标题和五行内容与约束一致
- [ ] 两个库都是当前版本、或库不存在时打开 pi → 不弹框，守护进程照常启动
- [ ] 框的标题里的仓库名和状态面板里显示的仓库名相同
- [ ] 只有 `index.db` 旧时 → 框里只有 index.db 那一行和"不迁移"那一行，没有备份行
- [ ] 框的选项只有「迁移」「暂不迁移」，默认选中「迁移」，底部提示文字与约束一致；按 Esc 的结果和选「暂不迁移」相同
- [ ] 选「迁移」后 `<本机数据目录>/backups/<编号>/data.db` 存在，版本号是 8，内容和迁移前一致；只迁移 `index.db` 时 `backups/` 下没有新增备份
- [ ] 迁移后 `data.db` 版本是 9：已通过的原型版本选定方案为空、没有补充说明；等确认的原型版本方案清单为空、选定方案为空；原型版本历史每一项选定方案为空、没有补充说明；需求、运行记录等其他记录和迁移前相同
- [ ] 迁移后再打开等确认的原型的"确认原型"窗口 → 列"通过"和"其他"
- [ ] 让某条原型记录转换失败 → `data.db` 版本仍是 8，所有记录和迁移前逐条相同，`index.db` 没被删
- [ ] `index.db` 版本 1 迁移后 → 旧文件被删，新 `index.db` 是版本 2，项目索引查询有结果
- [ ] 迁移中和迁移成功时，窗口底部的文字与约束一致（含备份完整路径、"索引会在第一次查询时重新建"按实际迁移的库出现）；成功后守护进程启动，主代理调用需求工具成功
- [ ] 迁移失败时 → 窗口底部报错含仓库名、失败步骤、需求编号和原型名、原因、"数据库没有改动"、备份完整路径、"重开 pi 窗口可以再试一次"；守护进程没有启动
- [ ] 选「暂不迁移」→ 库不变，守护进程没有启动，窗口底部文字与约束一致；之后调 OneCompany 工具，报错原因和下一步与约束一致
- [ ] 选「暂不迁移」后关窗口重开 → 迁移框再次弹出
- [ ] 旧守护进程在忙时打开 pi → 等待期间不弹框；旧守护进程退出后弹框
- [ ] 两个窗口同时打开 → 只有一个弹框；迁移成功后另一个直接连上、不弹框；选「暂不迁移」后另一个弹自己的框；迁移进行中别的进程打开这个库被拒绝
- [ ] 多仓库工作区两个仓库都旧 → 依次弹两个框，标题是各自的仓库名；一个迁移、一个暂不迁移 → 前者可用，后者调用时报"选了暂不迁移"

## 验证路径
1. 用版本 8 的代码在样例项目里建一个需求，交一版原型并选"通过并补充说明"，再交一版原型留着不确认；准备一个版本 1 的 `index.db`。
2. 换成当前代码，打开 pi → 弹出迁移框，核对标题、内容、选项和底部提示。
3. 选「迁移」→ 核对窗口底部的进行中和成功文字，核对备份文件存在且是版本 8。
4. 读 `data.db` → 版本 9，两版原型的字段按约束转换，其他记录不变。
5. 打开等确认的原型的"确认原型"窗口 → 列"通过"和"其他"。
6. 调项目索引查询 → 有结果，`index.db` 是版本 2。
7. 换一个版本 8 的库，打开 pi 选「暂不迁移」→ 库不变，守护进程没起，调工具报"选了暂不迁移"；重开窗口 → 框再次弹出。
8. 换一个有坏记录的版本 8 的库，选「迁移」→ 报错含失败记录和备份路径，库逐条不变。
