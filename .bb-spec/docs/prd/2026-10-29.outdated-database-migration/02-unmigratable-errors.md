# 不能迁移时的报错

本机数据库：每个仓库在本机数据目录（默认 `~/.pi/agent/one-company/repos/<仓库编号>/`）下的 `data.db` 和 `index.db`，库里记着格式版本号，当前代码要求 `data.db` 是版本 9、`index.db` 是版本 2。可迁移的旧版本：当前代码有办法转成当前格式的版本，现在是 `data.db` 版本 8 和 `index.db` 版本 1。没有 pi 界面：pi 以 `pi -p` 这类非交互方式运行，弹不出程序窗口。

## 用户故事
### P1：作为在没有界面的入口里用 one-company 的用户，我想要报错告诉我库能不能迁移、去哪里迁移，以便知道该打开 pi 窗口还是只能删数据

**用例（主路径：没有界面，库可迁移）**
- 场景：项目 `企微BOT` 的 `data.db` 是版本 8，用户用 `pi -p "查一下需求状态"` 运行。
- 操作：主代理调用需求工具。
- 预期：不弹框、不迁移，库仍是版本 8；报错写"本机数据库访问被阻止：outdated_database，data.db 是版本 8，当前版本是 9；打开 pi 窗口，在提示框里选「迁移」"。

**用例（主路径：库太旧，没法迁移）**
- 场景：`data.db` 是版本 5，用户打开 pi 窗口。
- 操作：打开 pi。
- 预期：不弹迁移框；报错写"本机数据库访问被阻止：outdated_database，data.db 是版本 5，太旧了没法迁移；请备份后删除本机数据目录并重新初始化"。

## 约束
- 库是可迁移的旧版本、但没有 pi 界面时：不弹框、不改库，报错是"本机数据库访问被阻止：outdated_database，<库名> 是版本 <旧>，当前版本是 <新>；打开 pi 窗口，在提示框里选「迁移」"。
- `data.db` 是版本 1 到 7 时：不论有没有界面都不弹迁移框，报错是"本机数据库访问被阻止：outdated_database，data.db 是版本 <旧>，太旧了没法迁移；请备份后删除本机数据目录并重新初始化"。
- `data.db` 太旧、`index.db` 可迁移时，按 `data.db` 太旧报错，不弹框。

## 验收
- [ ] `data.db` 版本 8，用 `pi -p` 调需求工具 → 不弹框，库仍是版本 8，报错文字与约束一致
- [ ] `index.db` 版本 1，用 `pi -p` 调项目索引查询 → 不弹框，`index.db` 没被删，报错写"index.db 是版本 1，当前版本是 2；打开 pi 窗口，在提示框里选「迁移」"
- [ ] `data.db` 版本 5，打开 pi 窗口 → 不弹迁移框，报错文字与约束一致
- [ ] `data.db` 版本 5、`index.db` 版本 1，打开 pi 窗口 → 不弹框，按 data.db 太旧报错

## 验证路径
1. 准备一个版本 8 的 `data.db`，用 `pi -p` 调需求工具 → 核对报错文字，库版本仍是 8。
2. 准备一个版本 5 的 `data.db`，打开 pi 窗口 → 没有迁移框，核对报错文字。
