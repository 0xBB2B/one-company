# Shell 任务详情页「来源」显示仓库名

## 背景与问题
- Shell 任务：终端里执行的命令。`/one:ps` 打开 Shell 任务页，列出本窗口主会话和本工作区守护进程（每个仓库一个、在后台跑子代理的进程）启动的任务，选中一条按 Enter 看详情。
- 详情页的「来源」行写这个任务是谁开的。子代理开的 Shell，括号里现在是一串截短的仓库编号，例如 `worker#a1b2c3（仓库 3f9a1c2…8d4e）`。仓库编号是程序按仓库 git 目录路径算出的摘要，用户看不出它对应哪个仓库。
- 工作区里有多个仓库时，用户打开某个子代理 Shell 的详情，没法知道它是哪个仓库里的代理开的，也就没法判断要不要停掉它。
- 程序手边已经有每个仓库的仓库名（主仓库目录名，例如 `/Users/bb/Projects/企微BOT` 的仓库名是 `企微BOT`），同一页面的报错文字已经用它，只有「来源」行还在用编号。

## 目标
- 子代理开的 Shell，详情页「来源」行写成 `<开它的代理>（仓库 <仓库名>）`，用户一眼能认出是哪个仓库。
- 工作区里有两个仓库目录名相同时，「来源」行仍能把它们分开。

## 非目标
- 改 Shell 任务列表页、状态栏的 Shell 数量、页面上的报错文字。
- 改守护进程换新提示等其他地方显示的仓库名。
- 改本窗口主会话开的 Shell 的「来源」写法。

单一子需求，无依赖。

## 整体验证路径
1. 在只含一个仓库 `企微BOT` 的目录打开 pi，让 PM 派出的 worker 跑一条后台命令，`/one:ps` 选中它按 Enter → 「来源」行是 `worker#<6 位>（仓库 企微BOT）`。
2. 在含 `client/api` 和 `server/api` 两个仓库的工作区重复上一步，两个仓库各有一条子代理 Shell → 两条的「来源」分别是 `（仓库 client/api）` 和 `（仓库 server/api）`。
3. 选中主会话自己开的 Shell 按 Enter → 「来源」行是 `主 agent（本窗口）`。

## 决策记录
- 括号里显示仓库名，保留「仓库」两个字：编号无法反查回仓库，仓库名程序已经有，改动只在显示上，不涉及窗口和守护进程之间的通信，不升协议版本号。用户 2026-10-29 看过预览后确认。
- 同名仓库的区分办法：用户 2026-10-29 提出"只显示名字，有一样的就带上上一层的路径"，并确认上一层也一样时继续往上加，直到分得开。
  - 否决"只显示名字、同名不处理"：工作区会往下扫多层目录找仓库，`client/api` 和 `server/api` 这种同名情况真实存在，同名时用户仍然分不清。
  - 否决"同名时名字后面带编号前 7 位"：编号用户认不出来，上层目录名用户认得。
- 同名的几个仓库加同样多层目录（加到这几个都互不相同为止），而不是每个仓库各加到刚好和别人不同：规则简单，同名的几行长得整齐。
- 报错文字和守护进程换新提示里的仓库名这次不改，用户 2026-10-29 确认：用户这次只提了「来源」行。
