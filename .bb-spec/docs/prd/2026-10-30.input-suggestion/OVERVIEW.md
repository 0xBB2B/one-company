# 主会话输入栏的输入建议

## 背景与问题
- 主会话输入栏：pi 主会话窗口底部、用户打字发给主代理的那一栏。它和程序窗口（提问窗口、设置页这类弹出的窗口）里的输入栏不是一个东西。
- 主代理每轮结束时会写一段简报，列出已完成、待解决和下一步。用户读完后，经常要自己把下一句回复敲出来，比如"可以""确认""1 选第一个，2 不思考"。这句话多半能从最近的对话里推出来，但现在每次都得手打。
- pi 自带的输入栏不能显示灰色提示，项目里也从没替换过主会话输入栏。

## 目标
- 主代理每轮正常结束后，程序推测用户下一句最可能说的话，在主会话输入栏为空时显示成灰色提示。
- 主会话输入栏为空时，用户按一次右方向键，就能把这句话变成输入栏里的真实文字，改一改或直接按 Enter 发送。
- 提示不打扰用户：生成期间不显示任何东西，生成失败不报错，用户已经在打字时不改动输入栏。

## 非目标
- 把输入建议加进设置页，单独配模型或思考等级。
- 用 Tab 或其他键填入提示。
- 一次给出多条候选提示让用户挑。
- 在非交互模式（pi 的打印模式、RPC 模式）下生成或显示提示。
- 和其他也替换主会话输入栏的 pi 扩展共存。
- 改主代理的提示词或简报格式。

## 整体验证路径
1. 在 pi 主会话里对主代理说一句话，等这一轮正常结束 → 输入栏先是空的；几秒后出现一行灰色文字，不超过 60 个字。
2. 输入栏为空时按右方向键 → 灰色文字变成正常颜色的真实文字，光标在末尾，没有自动发送。
3. 按 Enter 发送 → 主代理开始新一轮，输入栏里没有旧提示。
4. 再等一轮结束，在提示出现前就开始打字 → 提示返回后输入栏里还是用户打的字；把字全删掉 → 灰色提示出现。
5. 主代理正在回复时按 Esc 打断 → 这一轮不出现提示。

## 决策记录
- 用单独调一次模型来推测，不让主代理在简报里多写一行"建议回复"。用户 2026-10-30 选定。
  - 理由：每一轮都能出提示，纯问答轮也有；不改主代理的提示词，也不改用户读的简报；调用失败只是没有提示，不影响主流程。
  - 否决"主代理在简报里多写一行"：纯问答轮没有简报，也就没有提示；用户读的简报会多出一行；改主代理提示词还要加跑渐进需求完整流程验收。
- 推测要综合已完成、待解决和之前的上下文，不能只抄简报的"下一步"那一行。用户 2026-10-30 提出："不光要看下一步还需要结合已完成，待解决和之前的一些重要的上下文来综合判断"。原因是"下一步"写的是要做的动作，不是用户要打的那句话。
- 模型和主窗口用同一个，不进设置页。用户 2026-10-30 选定。代价是每轮多一次和主窗口同样模型的调用花费。
- 只交最近 3 轮，每轮只带用户说的话和主代理最后的文字回复，不带工具调用和工具输出。用户 2026-10-30 选定。
  - 否决最近 10 轮：多花的 token 约是 3 轮的 3 倍。这个倍数是按轮数估的，没有实测。
  - 否决整个会话：会话一长，花费和速度都没有上限。
- 这次调用不思考；模型不支持关掉思考时，用它支持的最低思考等级。用户 2026-10-30 选定，理由是提示出现得快比猜得准一点更重要。最低等级的补充也是用户 2026-10-30 提出的。
- 提示最多 60 个字。模型返回的话超过 60 个字、有多行，或者夹着控制字符时，不显示提示。用户 2026-10-30 选定。
  - 否决"截到 60 个字或只取第一行再显示"：没按要求写，说明这次结果不可靠；截断后句子会断在半中间。
- 不设单独的超时：新一轮开始前返回的结果都算数，新一轮开始后返回的直接丢掉。用户 2026-10-30 同意。理由是提示晚几十秒到也还有用；模型请求卡死的情况由 pi 自己的请求超时处理。
- 模型返回时输入栏里已经有字，就不覆盖，等用户把输入栏删空后再显示。用户 2026-10-30 提出。
- 提示填进输入栏、用户按 Enter 发出后，就算用户亲口说的话，程序照常解读，包括批准需求，不另加限制。用户 2026-10-30 决定。
  - 理由：字在发送前整句摆在用户眼前，还要连按右方向键和 Enter 两次，这和用户自己打字再发送没有区别。
  - 否决"提示里有'批准'之类的授权词就不显示"：要长期维护一张词表，而且总有漏掉的说法。
- 替换主会话输入栏的已知代价：用户如果还装了别的也替换主会话输入栏的 pi 扩展（比如 vim 模式），两者只有一个能生效。用户 2026-10-30 知道这个代价后同意做。
- 界面按用户 2026-10-30 确认过的预览做：等待时输入栏和平常一样是空的；提示出现时光标停在第一个字上，后面的字是灰色；右方向键只在输入栏为空时起填入作用。
