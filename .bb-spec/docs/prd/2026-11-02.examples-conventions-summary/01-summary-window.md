# 写入窗口显示摘要

几个词先说清：
- 确认窗口：`/one:examples` 选完样例和层之后弹的窗口，列出 skills、角色定义和 AGENTS.md 分别会怎么处理，选项是「复制」「不复制」。
- 写入窗口：在确认窗口选「复制」、文件复制成功后弹的窗口，问要不要把样例那一段写进 `AGENTS.md`，选项是「写入」「不写入」。
- 目标 AGENTS.md：选用户层时是 pi 代理目录下的 `AGENTS.md`，选项目层时是主仓库目录下的 `AGENTS.md`。
- 样例那一段：样例 `examples/<样例>/AGENTS.md` 的全文，第一行是它的标题，如「## 后端设计约定」。
- 行数：样例那一段按换行分开后的行数，文件末尾的换行不多算一行。golang 样例是 68 行，vue 样例是 29 行。

## 用户故事
### P0：作为用户，我想要写入窗口简短到选项一定看得见，以便不用翻内容就能决定写不写

**用例（主路径）**
- 场景：`~/.pi/agent/AGENTS.md` 有 200 行个人规范，没有「## 后端设计约定」，pi 在全屏模式，终端 40 行高。
- 操作：把 golang 样例复制到用户层，确认窗口选「复制」。
- 预期：写入窗口写「在现有 AGENTS.md 末尾追加「## 后端设计约定」一段，共 68 行，原有内容不动。」和样例文件路径，「写入」「不写入」都看得见；选「写入」后文件是原内容、一个空行、样例全文。

**用例（边界：还没有 AGENTS.md）**
- 场景：项目还没有 `AGENTS.md`。
- 操作：把 vue 样例复制到项目层，确认窗口选「复制」。
- 预期：确认窗口写「还没有 AGENTS.md，新建一份，下一步问你是否写入」；写入窗口写「还没有 AGENTS.md，新建一份，写入「## 前端设计约定」一段，共 29 行。」。

**用例（边界：AGENTS.md 是软链接）**
- 场景：`~/.pi/agent/AGENTS.md` 是软链接，指向 `~/dotfiles/pi/AGENTS.md`。
- 操作：把 golang 样例复制到用户层，确认窗口选「复制」。
- 预期：写入窗口第一行仍是黄色的「AGENTS.md 是软链接，实际写到 ~/dotfiles/pi/AGENTS.md」，下面是摘要和样例文件路径。

## 约束
- C-1：确认窗口的 AGENTS.md 一块，两种情况的提示改为：
  - 目标文件不存在：「还没有 AGENTS.md，新建一份，下一步问你是否写入」。
  - 文件存在、没有那一段、合并后不超限：「追加「<标题>」一段，下一步问你是否写入」。
  - 已有一致、已有不一致、合并后超限三种情况的提示不变。
- C-2：写入窗口从上到下依次是：
  - 标题：和现在一样，用户层是「把这些改动写入用户规范 <目标路径>？」，项目层是「把这些改动写入项目规范 AGENTS.md？」。
  - 目标是软链接时，黄色一行「AGENTS.md 是软链接，实际写到 <真实路径>」，和现在一样。
  - 摘要一行，普通颜色。目标文件存在时写「在现有 AGENTS.md 末尾追加「<标题>」一段，共 <行数> 行，原有内容不动。」；不存在时写「还没有 AGENTS.md，新建一份，写入「<标题>」一段，共 <行数> 行。」。
  - 灰色一行「这段内容在 <样例文件路径>」。路径是本次实际读取的样例 `AGENTS.md`；以家目录开头时写成 `~` 开头。
  - 一个空行，然后灰色一行「写入后，此后派出的 PM、worker、reviewer 都按新内容工作。」，和现在一样。
- C-3：写入窗口不显示样例正文，也不显示目标 AGENTS.md 的原有内容；样例的标题只出现在摘要里。
- C-4：不论目标 AGENTS.md 有多长，用户层写入窗口在 80 列下渲染出的总行数不超过 20 行，并且含「写入」「不写入」两个选项。
- C-5：写入窗口的选项、默认项和 Esc 行为不变，选项后写入的文件内容和结果提示不变；项目规范窗口的显示内容不变，仍逐行列出改动。

## 验收
- [ ] C-1：目标文件不存在、文件存在且可追加两种情况，确认窗口的提示和约束一致；已有一致、已有不一致、超限三种情况的提示和现在一样。
- [ ] C-2：用户层和项目层、文件存在和不存在、是软链接和不是软链接的组合下，写入窗口的文字、顺序和颜色都和约束一致；golang 行数是 68，vue 行数是 29；路径以家目录开头时显示为 `~` 开头。
- [ ] C-3：目标 AGENTS.md 含特殊标记行时，写入窗口里找不到这行，也找不到样例除标题外的任何一行。
- [ ] C-4：目标 AGENTS.md 有 500 行时，用户层写入窗口在 80 列下渲染不超过 20 行，含「写入」「不写入」。
- [ ] C-5：选「写入」后文件等于「原内容去掉末尾换行 + 空行 + 样例全文」；选「不写入」和按 Esc 时文件不变；项目规范窗口仍逐行显示 `+ ` 开头的新增行。

## 验证路径
1. 用户层 `AGENTS.md` 写 200 行内容，运行 `/one:examples`，选 golang、用户层 → 确认窗口写「追加「## 后端设计约定」一段，下一步问你是否写入」。
2. 选「复制」→ 写入窗口写「在现有 AGENTS.md 末尾追加「## 后端设计约定」一段，共 68 行，原有内容不动。」，下一行是样例文件路径，没有规范正文，能看到「写入」「不写入」。
3. 选「写入」→ `AGENTS.md` 末尾多出那一段；再运行一次，golang 一行显示「用户层：已复制」。
