# /one:examples 写入窗口改成摘要

## 背景与问题
- 用户运行 `/one:examples` 复制样例时，程序会弹一个写入窗口，问要不要把样例那一段写进 `AGENTS.md`。这个窗口把新增内容和 `AGENTS.md` 原有内容逐行列出来。
- Go 样例有 68 行，再加上用户原有的内容，窗口经常比终端屏幕还高。
- pi 全屏模式下，超出屏幕的部分从窗口尾部切掉，也不能滚动。用户在 84 行高的屏幕上只能看到内容的前面一部分，看不到「写入」「不写入」两个选项。
- 这段内容来自安装包里的样例文件，用户复制样例时已经决定要用它，逐行看的价值不高。

## 目标
- 写入窗口的高度和样例长度、`AGENTS.md` 原有长度都无关，「写入」「不写入」两个选项在常见终端里都看得见。
- 用户仍然能在窗口里知道要写到哪个文件、写多少内容，并能单独选择不写。
- 想看内容的用户，能从窗口里拿到样例文件的路径。

## 非目标
- 修程序窗口超过屏幕高度时尾部被切掉的通用问题：这件事影响所有程序窗口，修完这个需求后单独用 `/revise` 处理。
- 改项目规范窗口（模型改仓库根目录 `AGENTS.md` 时弹的窗口）的显示内容：那里的内容是模型写的，用户必须能逐行看。
- 在窗口里加「查看全文」之类的操作。
- 去掉写入窗口，或改变写入的时机、条件和写入后的文件内容。

## 依赖与交付顺序
单一子需求，无依赖。

## 整体验证路径
1. 在 `~/.pi/agent/AGENTS.md` 已有内容的情况下运行 `/one:examples`，选 golang、用户层 → 确认窗口写「追加「## 后端设计约定」一段，下一步问你是否写入」。
2. 选「复制」→ 写入窗口写明追加 68 行、原有内容不动和样例文件路径，不列任何规范正文，「写入」「不写入」都看得见。
3. 选「写入」→ `AGENTS.md` 末尾多出「## 后端设计约定」那一段，结果提示和现在一样。

## 决策记录
- 写入窗口不显示具体内容，只显示一句摘要和样例文件路径。这改掉了 2026-10-23.examples-command 里「只在用户看过差异后才写入」的目标和写入窗口逐行列内容的约定。用户 2026-11-02 决定。原因：内容太长显示不全，用户认为不需要看具体内容。
- 质疑结论：值得做。实测 100 行的窗口放进 84 行的全屏屏幕时，只显示到第 83 行，选项不可见。隐藏内容不增加风险：内容来自安装包的样例文件，不是模型输出。
- 保留写入窗口，只换内容。否决「去掉写入窗口，选复制就一起写」：那样用户不能只复制 skills 和角色定义而不写 `AGENTS.md`，软链接提示也要挪位置。用户 2026-11-02 决定。
- 程序窗口超高被切掉的通用问题不并进本需求，本需求完成后单独用 `/revise` 修。否决「一起做」：通用修复影响所有程序窗口，改动范围和验收都大得多，分开更容易各自验证。用户 2026-11-02 决定。
- 项目规范窗口不跟着改成摘要：它的内容是模型写的，按「模型输出不可信」，用户要能看全内容再决定写不写。
- 摘要里写行数，不写字节数：行数更直观，16 KB 上限已由确认窗口的超限提示负责。这条是写 PRD 时按确认过的预览定的，用户确认 PRD 时一并认可或推翻。
