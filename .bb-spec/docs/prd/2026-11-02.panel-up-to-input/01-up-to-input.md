# 用 ↑ 回到输入框

状态面板：pi 主窗口输入框下方显示运行中任务的区域。焦点：按键当前由谁接收，输入框为空时按 ↓，焦点进入面板，能选中的行里有一行高亮，这一行就是光标所在的行。第一行：能选中的行里最上面的一行，不算"●"开头的分组标题行。

焦点在面板时，面板底部的提示改成这样：

```
● 1 个原型设计运行中
└─ ⠹ 管理员每日提醒时间设置（第 2 版）· prototype · ↻3/12 · 1m58s
↑↓ 选择 · Enter 查看 · p 暂停/恢复 · 第一行按 ↑ 返回输入框
```

## 用户故事
### P0：作为盯着任务跑的用户，我想要用 ↑ 从面板回到输入框，以便不会因为多按一下 Esc 中断主代理

**用例（主路径：只有一行）**
- 场景：主代理运行中，面板上只有上面这一行原型设计，焦点在面板。
- 操作：按 ↑。
- 预期：焦点回到输入框，底部提示消失，输入框仍然是空的，主代理继续运行。

**用例（主路径：有多行）**
- 场景：面板上能选中的行有 3 行，光标在第 3 行。
- 操作：按 ↑ 3 次。
- 预期：前 2 次光标上移到第 1 行，第 3 次焦点回到输入框。

**用例（主路径：多按了 Esc）**
- 场景：主代理运行中，焦点在面板。
- 操作：连按 3 次 Esc。
- 预期：画面不变，焦点还在面板，主代理继续运行。

**用例（边界：从步骤窗口连按 Esc）**
- 场景：步骤窗口开着，主代理运行中。
- 操作：连按 3 次 Esc。
- 预期：第 1 次关闭窗口回到面板，后 2 次没有反应，主代理继续运行。

**用例（边界：面板内容消失时按 Esc）**
- 场景：光标在需求行，这个需求结束了，面板上已经没有能选中的行，焦点还算在面板。
- 操作：按 Esc。
- 预期：焦点回到输入框，主代理继续运行。

## 约束
- C-1：焦点在面板、光标在第一行时按 ↑，焦点回到输入框。这次按键不交给输入框，输入框的内容不变，不会翻出输入历史。
- C-2：焦点在面板、光标不在第一行时按 ↑，光标上移一行，焦点留在面板。
- C-3：焦点在面板、面板上有能选中的行时按 Esc，焦点和光标都不变，这次按键不交给 pi。
- C-4：焦点在面板、面板上没有能选中的行时按 Esc，焦点回到输入框，这次按键不交给 pi。按其他键时焦点回到输入框，这次按键交给输入框。
- C-5：焦点在输入框时按 Esc，这次按键交给 pi，行为和改动前一样。
- C-6：步骤窗口等程序窗口开着时，Esc 由窗口处理，行为和改动前一样；窗口关闭后焦点回到面板，再按 Esc 符合 C-3。
- C-7：焦点在面板时，底部提示是"↑↓ 选择 · Enter 查看 · p 暂停/恢复 · 第一行按 ↑ 返回输入框"。
- C-8：用 ↑ 回到输入框后，输入框为空时按 ↓ 能再次进入面板。

## 验收
- [ ] AC-1 ← C-1：面板只有一行，焦点在面板，按 ↑，焦点在输入框，这次按键被消费、没有交给输入框；Kitty 键盘协议发送的 ↑ 也一样，按键抬起事件不触发。
- [ ] AC-2 ← C-2：面板有 3 行可选，光标在第 3 行，按 ↑ 两次，光标依次到第 2、第 1 行，焦点一直在面板；第 3 次按 ↑，焦点在输入框。
- [ ] AC-3 ← C-3：焦点在面板、有可选的行，按 Esc 3 次，焦点仍在面板，光标不变，3 次都被消费；Kitty 键盘协议发送的 Esc 也一样。
- [ ] AC-4 ← C-4：焦点在面板、面板变空，按 Esc，焦点在输入框，按键被消费；另一次同样的场景按 Ctrl+C，焦点在输入框，按键没有被消费。
- [ ] AC-5 ← C-5：焦点在输入框按 Esc，按键没有被消费，也不交给面板。
- [ ] AC-6 ← C-6：输入框没有焦点（程序窗口开着）时，↑、Esc 都不被面板处理；窗口关闭后焦点仍在面板，按 Esc 被消费、焦点不变。
- [ ] AC-7 ← C-7：焦点在面板时渲染的最后一行是 C-7 的文字；焦点不在面板时没有这一行。
- [ ] AC-8 ← C-8：按 ↓ 进入面板、按 ↑ 回输入框、再按 ↓，焦点在面板。

## 验证路径
1. 构造只有一行的面板，按 ↓ 进入，看提示，按 ↑，看焦点和输入框（AC-1、AC-7、AC-8）。
2. 构造三行的面板，从第 3 行连按 ↑（AC-2）。
3. 焦点在面板时连按 Esc，看主代理没有被中断（AC-3）。
4. 让面板变空后按 Esc 和 Ctrl+C（AC-4）。
5. 焦点在输入框时按 Esc，主代理运行中会被中断（AC-5）。
6. 打开步骤窗口，连按 Esc（AC-6）。
