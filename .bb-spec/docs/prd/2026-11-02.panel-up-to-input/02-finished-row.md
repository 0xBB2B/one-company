# 选中的子代理跑完后留着

状态面板：pi 主窗口输入框下方显示运行中任务的区域。子代理行：面板上带转圈图标、代表一个正在运行的子代理的行，包括需求下面的执行行、审查代理行、PM 派出的检索行，以及面板底部的原型设计行和检索行。步骤窗口：在子代理行上按回车弹出的窗口，列出子代理做过的每一步。已结束行：光标选中的子代理跑完后，留在面板最下面的那一行。

面板上出现已结束行时的样子：

```
● 1 个需求运行中
└─ ⠹ 订单导出按月分文件 · 任务 1/4 · ↻12 · 86 tool uses · 412.3k token (71%) · 6m12s
   └ ⠹ T3 执行 · worker（第 1 次尝试）· ↻2/40 · 21.0s
● 已结束（光标移开后消失）
└─ ✓ 已完成 · T2 执行 · worker（第 1 次尝试）· ↻21/40 · 6m40s      ← 光标在这一行
↑↓ 选择 · Enter 查看 · p 暂停/恢复 · 第一行按 ↑ 返回输入框
```

## 用户故事
### P0：作为盯着子代理干活的用户，我想要选中的子代理跑完后这一行还在，以便按回车看它做了什么

**用例（主路径）**
- 场景：焦点在面板，光标停在原型设计行，这是面板上唯一的一行。
- 操作：等原型设计跑完，过 90 秒后按回车。
- 预期：原型设计跑完后，"● 1 个原型设计运行中"这一组消失，出现"● 已结束（光标移开后消失）"组，光标在"✓ 已完成 · 管理员每日提醒时间设置（第 2 版）· prototype · ↻12/12 · 2m10s"这一行上。按回车弹出步骤窗口，全部步骤都在，状态行是"✓ 已完成 · 共 15 步 · ↻12/12 · 2m10s"。

**用例（主路径：光标移开）**
- 场景：面板如开头所示，光标在已结束行上。
- 操作：按 ↑。
- 预期：光标移到 T3 执行行，"● 已结束"这一组消失。再按 ↓ 也回不到它。

**用例（主路径：回输入框）**
- 场景：已结束行是面板上唯一的一行，光标在它上面。
- 操作：按 ↑。
- 预期：焦点回到输入框，这一行消失，面板上没有内容。

**用例（边界：没有选中）**
- 场景：焦点在输入框，或者焦点在面板但光标在别的行。
- 操作：等这个子代理跑完。
- 预期：这一行直接消失，和改动前一样。

**用例（边界：步骤窗口开着时跑完）**
- 场景：光标在 T2 执行行，步骤窗口开着。
- 操作：等 T2 跑完，按 Esc 关闭窗口。
- 预期：窗口开着时状态行变成"✓ 已完成"。关闭后回到面板，光标在已结束行上。

**用例（边界：跑失败了）**
- 场景：光标在检索行，这个检索断网失败。
- 操作：看面板，按回车。
- 预期：已结束行写"✗ 失败 · 本地 · 现在的导出入口在哪 · ↻3/20 · 40.0s"，步骤窗口的状态行写出失败原因。

**用例（边界：交稿后还在收尾）**
- 场景：光标在原型设计行，设计师交了稿，面板上这一行随即消失，但设计师的会话还要几秒才真正结束。
- 操作：看面板。
- 预期：先显示"└─ 读取中… · 管理员每日提醒时间设置（第 2 版）· prototype"，会话结束后变成"✓ 已完成 · …"，光标一直在这一行上。

**用例（异常：断线）**
- 场景：光标在 T2 执行行，后台进程断开，面板上的行都消失了。
- 操作：看面板。
- 预期：不出现已结束行，不显示假的结果，和改动前一样。

## 约束
- C-1：焦点在面板、光标在子代理行上，这一行从面板上消失，而且这个子代理确实结束了时，它变成已结束行。子代理的状态是已完成、失败、已停止、已中断时算结束。审查代理跑完后状态从运行中变成通过、打回等，这一行不能再选中，也算消失，同样变成已结束行，它在任务下面的状态行保持原样。
- C-2：已结束行显示在面板最下面、所有分组之后，上面是分组标题"● 已结束（光标移开后消失）"。面板上最多一条已结束行。
- C-3：已结束行的文字是"└─ <结果> · <标题> · ↻<轮数>[/<上限>] · <耗时>"，结果是"✓ 已完成""✗ 失败""✗ 已停止""✗ 已中断"之一，标题和这一行结束前的标题相同，没有上限时只写"↻<轮数>"，耗时不随时间增加。
- C-4：子代理变成已结束行后，光标落在已结束行上，高亮样子和其他行被选中时一样。
- C-5：在已结束行上按回车，弹出步骤窗口，显示这个子代理结束时的全部步骤，状态行按结束状态显示。不论过了多久，也不论后台进程是否已经删掉步骤或重启过，显示的内容都一样。
- C-6：光标离开已结束行，或者焦点回到输入框时，已结束行消失，存着的步骤被丢掉，之后无法再回到这一行。在已结束行上按 ↓ 光标不动，这一行还在。
- C-7：在已结束行上按 p 什么都不发生，不发出暂停或恢复请求。
- C-8：焦点不在面板，或者光标不在这一行时，子代理结束后这一行直接消失，光标按改动前的规则处理。需求行和 ⚑ 事项行消失时，也按改动前的规则处理，光标落到相邻行。
- C-9：读取报错（如后台进程断开），或者读到子代理处于暂停中、已暂停，这一行直接消失，光标落到相邻行，不显示已结束行。
- C-10：取结果期间，这一行显示为"└─ 读取中… · <标题>"，光标留在它上面，分组标题同 C-2；这时按回车打开步骤窗口，走和子代理行一样的读取方式。读到子代理处于排队中或运行中时，说明它还在收尾，这一行保持这个样子，约每秒再读一次，直到符合 C-1 或 C-9。光标移开后停止读取。
- C-11：已结束行对应的子代理又出现在面板的运行行里时，已结束行消失，光标落在这条运行行上。
- C-12：已结束行只存在这个 pi 窗口里：别的窗口看不到，重开窗口后也没有。
- C-13：有已结束行时，面板算有能选中的行，已结束行是面板上唯一的一行时，焦点留在面板。

## 验收
- [ ] AC-1 ← C-1：光标在 T2 执行行，刷新后数据里没有这一行、步骤读取结果是已完成，面板出现已结束行。同样场景换成审查代理、PM 派出的检索、原型设计、主窗口检索各做一次，都出现已结束行。审查代理从运行中变成通过后，同样出现已结束行，任务下面的"✓ reviewer 通过"行还在。
- [ ] AC-2 ← C-2：面板同时有需求、原型设计、检索三组时，已结束分组排在最后，分组标题文字与 C-2 一致。出现一条已结束行后光标移开，它消失，全程不会同时有两条。
- [ ] AC-3 ← C-3：状态分别是已完成、失败、已停止、已中断时，文字开头依次是"✓ 已完成""✗ 失败""✗ 已停止""✗ 已中断"；有上限时写"↻12/12"，上限为空时写"↻12"；隔 2 秒再渲染，耗时不变。
- [ ] AC-4 ← C-4：已结束行出现后，它带选中背景色，其他行不带。
- [ ] AC-5 ← C-5：已结束行出现后，让步骤读取请求改为报错或查无此运行，再按回车，步骤窗口仍显示全部步骤和"✓ 已完成"，不发生"读不到步骤"。
- [ ] AC-6 ← C-6：光标在已结束行，按 ↑ 后这一行消失；再按 ↓ 不会回到它。已结束行是唯一一行时按 ↑，焦点回到输入框、这一行消失、面板不渲染内容。按 ↓ 时光标不动、这一行还在。
- [ ] AC-7 ← C-7：光标在已结束行按 p，没有发出暂停或恢复请求。
- [ ] AC-8 ← C-8：焦点在输入框时子代理结束，不出现已结束行，也不发起步骤读取。焦点在面板、光标在别的行时一样。光标在需求行、这个需求从数据里消失，不出现已结束行，光标落到相邻行。
- [ ] AC-9 ← C-9：步骤读取报错时，这一行消失，光标落到相邻行；读取结果是暂停中或已暂停时也一样；两种情况都不出现已结束分组。
- [ ] AC-10 ← C-10：步骤读取还没返回时，面板显示"└─ 读取中… · <标题>"，光标在它上面；这时按回车打开步骤窗口。读取结果是运行中时，面板仍显示这一行，约 1 秒后再读一次，读到已完成后变成已结束行；读到运行中后光标移开，不再发起读取。
- [ ] AC-11 ← C-11：已结束行存在时，刷新后运行行里又有同一个运行编号，已结束分组消失，光标在这条运行行上。
- [ ] AC-12 ← C-12：改动不新增后台进程请求、事件和数据库内容，`PROTOCOL_VERSION` 不变。
- [ ] AC-13 ← C-13：已结束行是唯一一行时，按 Enter、p 由面板处理，焦点留在面板，不因为"面板没有能选中的行"退回输入框。

## 验证路径
1. 光标停在一个运行中的子代理行，让它跑完，看面板（AC-1、AC-2、AC-3、AC-4、AC-13）。
2. 让后台进程的步骤读取失败，再按回车（AC-5）。
3. 分别按 ↑、↓、p（AC-6、AC-7）。
4. 焦点在输入框时让子代理跑完；光标在需求行时让需求结束（AC-8）。
5. 让步骤读取报错、返回运行中、迟迟不返回（AC-9、AC-10）。
6. 让同一个运行重新出现在运行行里（AC-11）。
7. 对比改动前后的协议版本和请求清单（AC-12）。
