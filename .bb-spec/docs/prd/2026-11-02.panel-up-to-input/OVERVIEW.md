# 状态面板按 ↑ 回输入框，选中的任务跑完后留着

## 背景与问题
- 状态面板：pi 主窗口输入框下方显示运行中任务的区域。输入框为空时按 ↓，按键改由面板接收，这叫焦点进入面板。
- 现在焦点在面板时，按 Esc 回到输入框；焦点在输入框时，按 Esc 交给 pi，主代理运行中就会被中断。两次 Esc 只差一下，用户想退出面板时多按一下，主代理就被中断了。空闲时连按两下 Esc 还会打开 pi 的会话树窗口。
- 用户看着一个子代理干活时，光标停在这一行。子代理一跑完，这一行就消失，光标跳到相邻的行，用户来不及按回车看它做了什么。

## 目标
- 焦点在面板时，按 Esc 不会中断主代理，连按多少次都不会。
- 用户用 ↑ 从面板第一行回到输入框。
- 光标选中的子代理跑完后，这一行留在面板上，用户按回车能看到它的全部步骤，直到用户把光标移开。

## 非目标
- 改变焦点在输入框时 Esc 的行为（中断主代理、连按打开会话树）。
- 改变步骤窗口、提问窗口等程序窗口里 Esc 的行为。
- 查看光标没有选中的已结束子代理，或者提供已结束子代理的历史列表。
- 把已结束子代理的步骤存进数据库，或者让它在重开 pi 窗口后还能看。
- 改变后台进程删除步骤的时间（子代理结束 60 秒后删除）。
- 需求行和 ⚑ 事项行结束或被处理后留在面板上。

## 依赖与交付顺序
02 依赖 01：已结束行靠 ↑ 移开光标后消失，这和 01 的按键规则连在一起，先做 01 再做 02。

## 整体验证路径
1. 主代理运行中，派出一个原型设计，输入框为空时按 ↓ → 焦点进入面板，原型设计行高亮，底部提示写"第一行按 ↑ 返回输入框"。
2. 连按 3 次 Esc → 画面不变，主代理继续运行。
3. 让原型设计跑完 → 这一行移到"● 已结束（光标移开后消失）"组，光标还在它上面，写着"✓ 已完成"。
4. 等 90 秒后按回车 → 弹出步骤窗口，全部步骤都在，状态行是"✓ 已完成"。
5. 按 Esc 关窗口，再按 Esc → 窗口关闭，回到面板，光标还在这一行，第二次 Esc 没有反应。
6. 按 ↑ → 焦点回到输入框，已结束这一行消失，输入框没有翻出历史内容。
7. 再按 Esc → 主代理被中断，和 pi 原来一样。

## 决策记录
- 面板里的 Esc 选了"什么都不发生"。否决"把 Esc 交给 pi"：那样在面板里按一下就会中断主代理，比现在更容易误触，违背这次要解决的问题。代价是面板里不能直接中断主代理，要先回输入框再按 Esc，按键次数和现在一样。用户 2026-11-02 决定。
- ↑ 只在第一行回输入框，其他行仍然上移光标。否决"任何一行按 ↑ 都回输入框"：那样光标下移后再也选不回上面的行。用户 2026-11-02 决定。
- 留下已结束行放宽了 2026-10-27 的决定。当时否决"跑完也能回头查"，理由是要新增存储和历史入口，范围大一倍。这次用户提出光标选中的行不消失，只留这一行，不存数据库，也没有历史入口，范围小得多。用户 2026-11-02 决定。
- 这次改变了 2026-10-27 的行为：当时规定选中的子代理跑完后光标落到相邻行，现在子代理行改为留下，需求行和 ⚑ 事项行保持原样。
- 步骤由 pi 窗口在任务结束时取一份存在自己内存里，光标移开就丢掉。后台进程在子代理结束 60 秒后删除步骤，只留下一行不够，超过 60 秒按回车会读不到。否决"把 60 秒改长"：多长都没有依据，等久了还是读不到，所有已结束的子代理都要多占内存。否决"写进数据库"：这是 2026-10-27 否决过的方向。用户 2026-11-02 决定。
- 已结束行放在面板最下面的单独分组。否决"留在原位"：要把这一行插回后台进程发来的任务列表，需求整组结束时还要另外处理。代价是审查代理跑完后，它在任务下面的"✓ reviewer 通过"还在，"已结束"组里会再出现一次，直到光标移开。用户 2026-11-02 决定。
- 需求行不留下：需求行按回车本来就没有内容可看，留下也没用。用户 2026-11-02 确认预览时同意。
- 质疑结论：用户实际遇到过误触中断，改动只涉及面板按键和一行的去留，值得做。
