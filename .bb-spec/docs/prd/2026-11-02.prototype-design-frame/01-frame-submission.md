# 分开交稿和固定外框

几个词先说清楚：
- 原型：一份单个 HTML 文件的界面设计，用户在浏览器里直接打开就能看。每份原型有名字，同名再出一次就是它的新版本。
- 原型设计师：只负责出原型的子代理，用交稿工具把稿子交给程序。它只能读文件，不能运行命令，也不能开浏览器。
- 原型外框：程序给每份新原型生成的固定外框，左边是切换栏，右边上方是隔离框，隔离框下方是说明区。
- 切换栏：外框左边的深蓝色栏，放原型名称和切换按钮。上线后不存在。
- 说明区：隔离框下方的深蓝色区域，放这次设计的说明。上线后不存在。
- 隔离框：外框右边的独立页面区域（iframe），里面的样式和脚本与切换栏、说明区分开。
- 被设计的页面：设计师交的页面，显示在隔离框里，只含正式上线后用户能看到的内容。
- 页面：用户要看的一块界面，例如"管理员设置页""普通成员看到的页面"。
- 画面：一个页面的一种可切换显示，图形界面是一种状态（如"空数据"），终端界面是一步（如"第 2 步"）。
- 方案清单：设计师交稿时附上的一组方案名称，程序按顺序编字母 A 到 F。

## 用户故事
### P0：作为用户，我想一眼分清要上线的页面和这次设计的说明
**用例（主路径）**
- 场景：设计师交了"管理员每日提醒时间设置"第 2 版，含管理员设置页（正常、空数据、加载中、出错）和普通成员看到的页面，附方案清单"两栏卡片、单栏表单"。
- 操作：浏览器自动打开这份原型。
- 预期：左边是深蓝色切换栏，顶部标签写"设计说明 · 不属于页面"，下面是"管理员每日提醒时间设置"和"第 2 版 · 这一栏上线后不存在"。右边框上方写"▼ 被设计的页面：只有这个框里的内容要实现"，上方右侧是亮青色标签"方案 A：两栏卡片"和"管理员设置页 · 正常"。切换栏最上面有亮青色虚线框，写着"这份原型有 2 个方案，点这里切换对比"。框里只有页面本身，保存按钮写"保存配置"。框下方是深蓝色说明区，顶部同样有"设计说明 · 不属于页面"标签，三块说明并排。

**用例（切换）**
- 场景：同上。
- 操作：在切换栏依次点"出错""方案 B：单栏表单""普通成员看到的页面"。
- 预期：每点一次，右边框重新载入，显示对应内容；说明区里"这个画面的说明"跟着换；点到普通成员页时"状态"组消失（它只有 1 个画面），方案仍是 B。

**用例（终端界面）**
- 场景：设计师出一个三步的命令行交互，切换组名写"步骤"。
- 操作：打开原型，在切换栏点"第 2 步"。
- 预期：切换栏显示"步骤"组，右边框整个是深色终端，文字从左上角开始，按 80 列换行，显示第 2 步的画面。

**用例（简单原型）**
- 场景：设计师只出 1 个页面、1 个画面，没有方案，没写另外两张清单。
- 操作：打开原型。
- 预期：切换栏只有标签、名称和版本，没有切换按钮；说明区只显示写了内容的那块，没有空的小标题；三块都没写时没有说明区，隔离框占满右边。

### P0：作为用户，我不希望模型写的文字弄坏外框
**用例（说明很多）**
- 场景：窗口宽度超过 760 像素，设计师写了十几条说明，放不下。
- 操作：打开原型，把鼠标放到说明区滚动。
- 预期：说明区最高占窗口的三分之一，内容在说明区里滚动；隔离框和切换栏不动。

**用例（说明里带标签）**
- 场景：设计师的说明里写了"按钮用 `<b>` 加粗"。
- 操作：打开原型。
- 预期：说明区原样显示这串文字，`<b>` 没有被当成标签。

### P0：作为原型设计师，交的稿子有问题时要知道怎么改
**用例（清单不合格）**
- 场景：设计师交稿时，"管理员设置页"没有列画面。
- 操作：交稿。
- 预期：交稿被退回，原因写明"页面「管理员设置页」没有画面，至少写 1 个"；不弹确认窗口；改好后重交才弹窗。

## 约束
- C-1：设计师交稿时提交被设计的页面（一份完整的 HTML）、一句话说明和页面清单；可以附方案清单、"只在原型里成立"清单和"还没确认的问题"清单。页面清单里每个页面有名称、至少一个画面，可以写切换组名；每个画面有名称，可以写多条说明。
- C-2：系统按下面的规则检查，任一项不合格就退回交稿、不弹确认窗口，退回原因依次写成：页面清单为空时"页面清单是空的，至少写 1 个页面"；第 k 个页面名称去掉首尾空白后为空时"第 k 个页面名是空的"；两个页面重名时"页面「X」重名"；页面没有画面时"页面「X」没有画面，至少写 1 个"；画面名称去掉首尾空白后为空时"页面「X」的第 k 个画面名是空的"；同一页面里两个画面重名时"页面「X」的画面「Y」重名"。页面不是 HTML、方案清单不合格的退回规则保持现状。
- C-3：系统把交稿内容拼成单个 HTML 文件，写到这一版原型的文件位置。文件大小、文件指纹和 1 MiB 上限都按拼好后的文件计算；超过上限时退回，原因写明实际字节数和上限。
- C-4：拼好的文件用系统默认浏览器按本地文件打开就能看，不引用外部文件，不需要服务器。浏览器标题是"<原型名称> 第 N 版"。
- C-5：切换栏固定在左边，宽 260 像素，深蓝色网格背景，等宽字体，右边缘有一条亮青色虚线，内容太长时只有切换栏自己滚动。从上到下依次是：标签"设计说明 · 不属于页面"、原型名称、"第 N 版 · 这一栏上线后不存在"、方案提示框（有方案清单时才有）、"切换要看的内容"。
- C-5a：说明区在隔离框正下方，和隔离框等宽，深蓝色背景，顶边有一条亮青色虚线。顶部是标签"设计说明 · 不属于页面"和"这一块上线后不存在"，下面从左到右并排"这个画面的说明"、"只在原型里成立"、"还没确认的问题"三块。某一块没有内容时，连小标题一起不显示；三块都没有内容时不显示说明区，隔离框占满右边。"还没确认的问题"按序号列出，其余两块按项目符号列出。
- C-5b：说明区条目之间不留空行，内容下方不留空。窗口宽度超过 760 像素时，说明区按内容决定高度，最高占窗口高度的三分之一，超出时只有说明区自己滚动，隔离框和切换栏不动。
- C-6："切换要看的内容"里依次是"页面"组、当前页面的切换组。切换组名没写时显示"状态"。只有一项可选的组不显示；两组都不显示时，"切换要看的内容"连小标题一起不显示。当前选中的按钮高亮成亮青色。
- C-6a：有方案清单时，方案提示框排在切换按钮最前面，亮青色虚线边框，标题写"这份原型有 N 个方案，点这里切换对比"，N 是方案个数；下面是方案按钮，每个写"方案 <字母>：<名称>"；底部写"最后选哪个，在"确认原型"窗口里定"。切换页面、画面时，方案提示框不变。没有方案清单时不显示方案提示框。
- C-7：右边框上方左侧固定写"▼ 被设计的页面：只有这个框里的内容要实现"，右侧写当前选择：有方案清单时最前面是亮青色标签"方案 <字母>：<名称>"，后面是页面名称、画面名称，用" · "隔开，只有一项可选的组不写。
- C-8：打开时选中第一个页面、它的第一个画面和方案 A。切换页面时，画面回到新页面的第一个，方案不变；切换画面或方案时，其余选择不变。每次切换右边框重新载入，页面里输入的内容清空，"这个画面的说明"换成当前画面的说明。
- C-9：被设计的页面在隔离框里运行时能读到当前选中的页面、画面和方案，并据此显示对应内容；读取方法写在设计师的规矩里。页面和外框的样式互不影响。隔离框是沙箱：页面里的脚本碰不到外框，页面用不了 localStorage、alert、confirm。点击页面里的 `href="#"` 或页内锚点链接时，隔离框仍显示这个页面，外框不会被套进隔离框。
- C-10：页面名称、画面名称、切换组名、各条说明都按纯文字显示，其中的 HTML 标签不生效。
- C-11：在切换栏里切换方案不登记任何决定；用户的决定只认"确认原型"窗口。
- C-12：窗口宽度不超过 760 像素时，从上到下依次是切换栏、隔离框、说明区，说明区的三块上下排列、不限高度，随整个网页一起滚动。方案名称写满 20 字时，任何窗口宽度下都不出现横向滚动。
- C-13：worker、reviewer、qa 和下一版的设计师用读文件工具读拼好的文件时，能直接看到页面的 HTML 标签、文字和样式，内容没有被编码成看不懂的形式。
- C-14：设计师的规矩写明：只有正式上线后用户能看到的内容才放进页面；页面里不写"演示""原型""示例""待确认"这类字样，不画切换条、状态选择和方案标签；按钮和标题写真实文案，示例数据写成真实的样子。页面在沙箱里运行，状态放在脚本变量里，弹窗和提示都画在页面里。这次设计的说明、假数据和假操作的提醒、待确认的问题都写进对应清单。图形界面的正常、空数据、加载中、出错四种状态各是一个画面；终端界面多步交互的每一步是一个画面，切换组名写"步骤"；终端页面铺满隔离框，深色背景，等宽字体，文字从左上角开始，按 80 列换行，不居中。
- C-15：设计师的规矩写明重派时的做法：读上一版文件里的页面和各张清单，按用户原话改，没提到的地方保持不变，再分开交稿；规矩写明文件里页面的两种转义（`&amp;` 是 `&`，`&lt;/textarea` 是 `</textarea`）。
- C-16：新增单点验收 P17：真实模型扮演原型设计师，收到一个带界面的设计任务后交稿；程序判定交稿被收下、四种状态都在页面清单里、页面里没有"演示""原型""待确认"字样。设计得好不好不算进判定。

## 验收
- [ ] C-1：带全部字段的交稿被收下；只带页面、说明和页面清单的交稿也被收下。
- [ ] C-2：每一种不合格的清单都被退回，原因文字与约束一致，不弹确认窗口。
- [ ] C-3：写到文件位置的是拼好的文件，记录的大小和指纹与它一致；页面本身没超 1 MiB、拼好后超过时被退回。
- [ ] C-4：在浏览器里按本地文件打开能正常显示和切换；文件里没有外部地址；浏览器标题正确。
- [ ] C-5：切换栏的宽度、顺序和固定文字与约束一致；切换栏内容很长时，隔离框不跟着滚动。
- [ ] C-5a：说明区的位置、宽度、固定文字和三块的顺序与约束一致；空的说明块连小标题一起不出现；三块都空时没有说明区，隔离框占满右边。
- [ ] C-5b：窗口宽度超过 760 像素、说明很长时，说明区高度不超过窗口的三分之一，内容在说明区里滚动，隔离框和切换栏不动。
- [ ] C-6：只有 1 个页面、1 个画面时，切换区不出现；写了组名时显示组名，没写时显示"状态"。
- [ ] C-6a：有方案清单时，方案提示框排在切换按钮最前面，标题的方案个数、按钮文字和底部文字都正确；切换页面、画面后它不变；没有方案清单时它不出现。
- [ ] C-7：框上方的固定文字正确；有方案清单时右侧最前面是亮青色方案标签；切换后右侧文字跟着变。
- [ ] C-8：默认选中项、切换页面和切换方案后的选中项都符合约束；切换后之前在页面里输入的内容消失。
- [ ] C-9：页面能读到当前选中项并显示对应内容；往页面和外框各加一条全局样式时，另一边不变；页面脚本读不到外层文档；点击页面里的 `href="#"` 和页内锚点链接后，隔离框里仍是这个页面。
- [ ] C-10：说明里写 `<b>`、`<script>` 时，说明区显示这串文字，脚本不运行。
- [ ] C-11：在切换栏切换方案后，原型仍在等确认，看板记录没有变化。
- [ ] C-12：窗口宽度 390 像素时，从上到下是切换栏、隔离框、说明区，说明区的三块上下排列、不限高度，随整个网页一起滚动，没有横向滚动；方案名称写满 20 字时，窗口宽度 390、761、1440 像素下都没有横向滚动。
- [ ] C-13：拼好的文件文本里能直接搜到页面的标签和文字。
- [ ] C-14：设计师的规矩里有这几条要求。
- [ ] C-15：设计师的规矩里有重派时的做法和两种转义。
- [ ] C-16：P17 在真实模型上按验收规则通过。

## 验证路径
1. 用一份带两个页面、四种状态、两个方案和三块说明的交稿走一遍交稿 → 收下，文件写到原型位置，弹确认窗口。
2. 在浏览器里打开这份文件 → 外框三块的位置、固定文字、默认选中项都符合约束。
3. 逐个点切换按钮 → 右边框、当前选择和说明都跟着变。
4. 把浏览器窗口拉到 390 像素宽 → 从上到下是切换栏、隔离框、说明区。
5. 交一份画面为空的清单 → 被退回，原因写明哪个页面缺画面。
