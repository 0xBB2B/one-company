# 下游只对照页面

几个词先说清楚：
- 原型：一份单个 HTML 文件的界面设计。需求批准后，worker（写代码的子代理）、reviewer（审查改动的子代理）、qa（验收的子代理）都用读文件工具读它。
- 切换栏：原型外框左边的栏，放切换按钮，上线后不存在。
- 说明区：隔离框下方的区域，放这次设计的说明，上线后不存在。
- 被设计的页面：原型外框右边隔离框里的页面，只含正式上线后用户能看到的内容。
- 选定方案：用户在"确认原型"窗口里选中的方案，其余方案不做。

## 用户故事
### P0：作为用户，我不希望切换栏和说明区的内容被当成功能做出来
**用例（主路径）**
- 场景：批准的原型里，说明区写着"点'保存配置'只改这个原型里的显示，不写数据库"，页面里的按钮写"保存配置"。
- 操作：PM 派 worker 实现，再派 reviewer 和 qa。
- 预期：worker 只实现页面，按钮写"保存配置"，保存时真的写数据库；产品里没有切换栏、说明区和"被设计的页面"这行字。

**用例（页面不一致）**
- 场景：worker 把页面里的"保存配置"写成了"保存"。
- 操作：reviewer 审查。
- 预期：reviewer 按原型不一致列为阻塞。

**用例（说明区不算）**
- 场景：实现和页面一致，但产品里没有说明区里写的"这个画面的说明"文字。
- 操作：qa 验收。
- 预期：qa 不因此列阻塞。

## 约束
- C-1：worker 的规矩写明：原型文件分切换栏、隔离框里的被设计的页面和说明区，只实现页面；说明区的说明可以用来理解页面，切换栏、说明区和外框本身不实现。
- C-2：reviewer 的规矩写明：核对原型时只对照被设计的页面，页面的布局、文案、各种状态、交互与实现不一致时列为阻塞；切换栏、说明区和外框里的文字与实现不一致不算阻塞。
- C-3：qa 的规矩写明：验收原型时只对照被设计的页面，页面的布局结构、文案、样式、各种状态与交互一致才算已验证；切换栏、说明区和外框里的内容不列入验收。
- C-4：原型有选定方案时，下游只对照页面里选定方案的显示，"其余方案不做"的现有要求保持不变。
