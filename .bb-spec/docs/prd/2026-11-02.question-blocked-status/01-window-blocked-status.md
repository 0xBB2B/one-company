# 问答窗口上报等待状态

## 用户故事
### P0：作为在 Vibe42 里同时跑多个窗格的用户，我想要代理弹窗等我时收到通知，以便及时回来回答

**用例（主路径）**
- 场景：用户让主代理澄清需求后，切到别的窗格写代码。
- 操作：主代理调用提问工具，弹出提问窗口，问题是"要不要深色模式"。
- 预期：pi 上报 `blocked`，种类是 `question`，文字是"要不要深色模式"；用户回答后，pi 上报 `working`。

**用例（边界：窗口排队）**
- 场景：确认原型窗口在排队，等提问窗口关闭后才显示。
- 操作：用户回答提问窗口。
- 预期：确认原型窗口显示出来时，pi 上报 `blocked`，文字是这个窗口的标题。排队期间不为确认原型窗口上报。

**用例（边界：用户自己打开窗口）**
- 场景：主代理没在运行，用户输入 `/one:examples`。
- 操作：程序弹出选择窗口，用户选完。
- 预期：这个窗口不上报 `blocked`。

**用例（边界：压缩期间弹窗）**
- 场景：用户运行 `/compact`，压缩期间设计师交稿，弹出确认原型窗口。
- 操作：窗口显示出来，用户稍后回答。
- 预期：pi 上报 `blocked`，文字是窗口标题；窗口关闭后，窗格回到 pi 当时该显示的状态。

**用例（异常：运行中止）**
- 场景：提问窗口开着，用户中止主代理这一轮。
- 操作：中断信号先关闭窗口，主代理随后停下。
- 预期：窗口关闭时主代理还算运行中，pi 上报 `working`；主代理停下后，pi 上报 `idle`，窗格最终显示 `idle`。

**用例（边界：窗口开着时主代理已停下）**
- 场景：设计师交稿弹出确认原型窗口，窗口开着时主代理这一轮结束。
- 操作：用户回答窗口。
- 预期：窗口开着时窗格保持 `blocked`；用户回答后，pi 上报 `done`。

## 约束
- 问答窗口包括提问、确认、选择、选择或输入四种。主代理正在运行时，从窗口显示出来到关闭，窗格状态都是 `blocked`，种类为 `question`。状态由 pi 上报和恢复，程序只告诉 pi 这个窗口在等用户。
- 压缩和分支摘要期间算主代理正在运行。
- `blocked` 的文字是窗口的问题文字。提问窗口用问题本身，确认和选择窗口用窗口标题。
- 窗口显示时主代理没在运行，这个窗口不上报 `blocked`。
- 在队列里排队、还没显示的窗口不上报。
- 设置页、Shell 页、步骤窗口这类查看页面不上报。
- pi 低于 1.5.0 时窗口照常工作，不报错，只是没有等待状态和通知。

## 验收
- [ ] 主代理运行中打开提问窗口，窗口显示时告诉 pi 在等用户，种类是 `question`，文字是问题本身。
- [ ] 主代理运行中打开确认窗口、选择窗口、选择或输入窗口，都告诉 pi 在等用户，文字是窗口标题。
- [ ] 压缩或分支摘要期间（`isIdle()` 为 false）打开窗口，同样告诉 pi 在等用户。
- [ ] 主代理没在运行时打开窗口，不告诉 pi 在等用户。
- [ ] 两个窗口排队时，第二个窗口显示之前不为它上报；显示之后上报它自己的文字。
- [ ] 设置页、Shell 页、步骤窗口打开时不上报。
- [ ] pi 忽略这项信息时，窗口照常打开、回答、关闭，返回的结果不变。
- [ ] 开发依赖是 pi 1.5.0，全量测试和真实模型验收都在这个版本上通过。

## 验证路径
1. 主代理运行中依次打开四种问答窗口 → 每个窗口都告诉 pi 在等用户，文字是问题或标题。
2. 主代理停下后打开窗口 → 不告诉 pi 在等用户。
3. 用 pi 1.5.0 或更新版本在 Vibe42 里让主代理真实弹出提问窗口，并切到别的窗格 → 窗格显示等待状态，通知显示问题文字；回答后恢复 `working`。
