# 问答窗口上报等待状态

## 用户故事
### P0：作为在 Vibe42 里同时跑多个窗格的用户，我想要代理弹窗等我时收到通知，以便及时回来回答

**用例（主路径）**
- 场景：用户让主代理澄清需求后，切到别的窗格写代码。
- 操作：主代理调用提问工具，弹出提问窗口，问题是"要不要深色模式"。
- 预期：pi 上报 `blocked`，种类是 `question`，文字是"要不要深色模式"；用户回答后，pi 上报 `working`。

**用例（边界：窗口排队）**
- 场景：确认原型窗口在排队，等提问窗口关闭后才显示。
- 操作：用户回答提问窗口。
- 预期：程序先为提问窗口上报 `working`，再为显示出来的确认原型窗口上报 `blocked`，文字是这个窗口的标题。排队期间不为确认原型窗口上报。

**用例（边界：用户自己打开窗口）**
- 场景：主代理没在运行，用户输入 `/one:examples`。
- 操作：程序弹出选择窗口，用户选完。
- 预期：程序不上报任何状态。

**用例（异常：运行中止）**
- 场景：提问窗口开着，用户中止主代理这一轮。
- 操作：中断信号先关闭窗口，主代理随后停下。
- 预期：窗口关闭时主代理还算运行中，程序上报 `working`；主代理停下后，pi 上报 `idle`，窗格最终显示 `idle`。

**用例（边界：窗口开着时主代理已停下）**
- 场景：设计师交稿弹出确认原型窗口，窗口开着时主代理这一轮结束，pi 上报了 `done`。
- 操作：用户回答窗口。
- 预期：程序不补报 `working`，窗格保持 `done`。

## 约束
- 问答窗口包括提问、确认、选择、选择或输入四种。主代理正在运行时，窗口显示出来的那一刻上报 `blocked`，种类为 `question`。
- `blocked` 的文字是窗口的问题文字。提问窗口用问题本身，确认和选择窗口用窗口标题。
- 问题文字有换行时，上报成一行，换行变成空格。
- 上报过 `blocked` 的窗口关闭时，不论回答、取消还是被信号中断，只要主代理还在运行，就上报 `working`，文字是当前会话名，没有会话名时不带文字。
- 窗口关闭时主代理已经停下，程序不上报，保留 pi 上报的结果。
- 窗口打开时主代理没在运行，打开和关闭时都不上报。
- 在队列里排队、还没显示的窗口不上报。
- 上报的程序名固定为 `pi`，和 pi 自己上报的一致。
- 设置页、Shell 页、步骤窗口这类查看页面不上报。

## 验收
- [ ] 主代理运行中打开提问窗口，上报一次 `blocked`，种类是 `question`，文字是问题本身，程序名是 `pi`。
- [ ] 主代理运行中打开确认窗口、选择窗口、选择或输入窗口，都上报 `blocked`，文字是窗口标题。
- [ ] 带换行的问题上报后，文字是一行，换行变成空格。
- [ ] 窗口因回答、Esc、信号中断关闭且主代理还在运行时，都上报 `working`，文字是会话名。
- [ ] 没有会话名时，上报的 `working` 不带文字。
- [ ] 窗口关闭时主代理已经停下，程序不上报。
- [ ] 主代理没在运行时打开窗口，打开和关闭都不上报。
- [ ] 两个窗口排队时，第二个窗口显示之前不为它上报；显示之后上报它自己的文字。
- [ ] 设置页、Shell 页、步骤窗口打开和关闭时都不上报。

## 验证路径
1. 主代理运行中依次打开四种问答窗口并关闭 → 每个窗口都先上报 `blocked`，关闭后上报 `working`。
2. 主代理停下后打开窗口并关闭 → 没有任何上报。
3. 在 Vibe42 里让主代理真实弹出提问窗口，并切到别的窗格 → 窗格显示等待状态，通知显示问题文字；回答后恢复 `working`。
