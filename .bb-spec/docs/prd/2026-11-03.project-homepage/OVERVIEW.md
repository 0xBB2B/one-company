# 项目主页与 README 开头

## 背景与问题

第一次打开仓库的人，看完第一屏还是不知道 OneCompany 是什么、凭什么值得试。

- README 的徽章下面直接是「前置条件」和一大段 GitHub 合并设置，没有"这是什么、为什么用它"。
- README 没解释 pi 是什么，也没给链接。不知道 pi 的读者看不懂项目。
- Tests 徽章只是一张写着 `pnpm test` 的静态图片，不反映测试结果。仓库没有 CI（代码提交后自动跑测试的服务）。
- 横幅图占满约一屏，图上画了 STRATEGY（战略）和 MONITORING（监控），产品里没有这两种角色。
- 项目没有主页。README 全是中文，不懂中文的读者没有入口。

## 目标

- 新读者在 README 第一屏看到项目是什么、核心卖点在哪。
- 新读者打开主页 30 秒内看懂项目，并能复制到安装命令。
- 主页有中文和英文两版，可以切换。
- 主页上的每条说法都能在 README 或代码里找到依据。
- `main` 分支上 `site/` 的内容变化后，主页自动更新。

## 非目标

- 不翻译 README 全文，不新增英文 README。
- 不改 README「前置条件」及其后面的内容。
- 不给产品界面做英文版。
- 不做文档站，不把 README 拆到主页上。
- 不加 CI 测试，不加真实测试徽章。
- 不改账号主页 `0xbb.me` 的设置。
- 不做社交分享图、访问统计、订阅表单。
- 不写用户评价、下载量、star 数这类数据。

## 整体验证路径

1. 在本地打开 `site/index.html`，第一屏能看到标题、一句话介绍和安装命令；点"复制"后粘贴，得到完整安装命令。
2. 点语言按钮切到英文，页面全部换成英文，并写明产品界面目前是中文；刷新后还是英文。
3. 把浏览器宽度缩到 390 像素，页面变成单列，整页没有横向滚动条。
4. 在 GitHub 上看分支的 README，第一屏能看到新横幅图、一句话介绍、徽章和导航，没有 Tests 徽章，图下没有重复的大标题。
5. 跑 `pnpm run typecheck`、`pnpm test`、`pnpm run test:integration`、`pnpm run test:installation`，全部通过。
6. 合并到 `main`、加好 DNS 记录后，GitHub Actions 的部署任务成功，打开 `https://one-company.0xbb.me/` 看到第 1 步的页面。

## 决策记录

- **问题定性**：用户提的是"更高大上"。查下来根子是开头没把项目讲清楚，所以这次先解决"讲清楚"，视觉服务于这件事。
- **只写能证明的事**：不编数据、不编用户评价，"只在 macOS 上测过"这类限制写在主页上。项目 0 star、没有发布版本，夸大的说法经不起点开仓库核对。
- **去掉 Tests 徽章**：它不反映测试结果。没有选择加 CI 换真徽章，因为那是另一个需求。
- **主页中英双语（用户 2026-11-02 决定）**：主页是外部读者的第一落点，只有中文够不着开源社区；同时写明产品界面目前是中文，不让人误以为已有英文版。否决了只做中文（国际读者看不懂）和只做英文（和中文 README、中文产品脱节）。
- **`site/` 目录加 Actions 部署（用户 2026-11-02 决定）**：这样只发布这一个目录，以后加构建步骤也方便。代理原本推荐 `docs/` 目录直接发布，因为少一个工作流；用户选了发布范围更干净的做法。否决了 VitePress 等框架：只有一页，不值得新增依赖。
- **主页用深色控制室方案（用户 2026-11-02 决定）**：琥珀色专门标"只有用户能做"的步骤。代理原本推荐公司章程方案（米色纸面、红色印章），用户选了和项目气质一致的深色方案。
- **重做横幅图（用户 2026-11-02 决定）**：否决了保留旧图（两个不存在的角色还留着）和删掉横幅（第一屏失去视觉重点）。
- **新横幅图用网页画后导出，不用 AI 生图**：文字准确，七个节点和主页七步完全一致。导出后只提交图片，不提交画图用的网页。
- **新横幅图改矮、图下去掉重复标题**：宽高比从 16:9 改成约 3:1，让第一屏能看到介绍。标题和标语已经在图上，再写一遍只是占地方。这一处由代理提出，用户确认预览时同意。
- **首屏放状态面板，不放横幅图**：状态面板是产品真实的样子，比概念图更能说明产品。示例里保留程序每次都会显示的工具调用次数，和 README 的示例一致（用户 2026-11-03 决定；最初为了窄屏放得下删掉过，审查时发现这样就不是程序真实显示的样子）。
- **系统字体，不加载外部字体**：Google Fonts 在国内访问不稳定，系统字体没有这个风险。
- **语言记忆（用户 2026-11-02 决定）**：访客手动切换后浏览器记住选择，常用另一种语言的访客不用每次重新切。
- **主页地址用专用子域名 `one-company.0xbb.me`（用户 2026-11-03 决定）**：用户的账号主页绑了 `0xbb.me`，GitHub 让同账号的项目站点默认跟随它，2026-11-03 实测 `https://0xbb2b.github.io/one-company/` 会 301 跳到 `https://0xbb.me/one-company/`。原计划写 github.io 地址是代理按默认规则推断、没有实测，审查时才发现。否决了直接用 `0xbb.me/one-company/`（挂在个人主页路径下）和保留 github.io 地址（多一次跳转，写的地址和实际地址不一致）。
- **卖点只写程序真的做到的事（用户 2026-11-03 决定）**：审查对照代码发现原文有 3 处说宽了：结果拒收看的是整个需求所有任务的范围，不是单个任务；"新增第三方依赖要你裁决"只是提示词规矩，程序不拦，所以删掉；归档只在需求以完成关闭时发生。"同一文件只有一个任务能写"改成派工门槛的准确说法。主页标题写着"程序核对的才算"，靠模型自觉的规矩不能写在这里。
- **主页标题（用户 2026-11-02 决定）**：中文写"一个人，撑起一家有规矩的 AI 公司。"，英文沿用现有标语 "One human. A governed autonomous company."。
