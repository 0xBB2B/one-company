# 复制样例不碰 AGENTS.md

几个词先说清：
- 层目录：用户层是 pi 代理目录（默认 `~/.pi/agent/`），skills 放在它下面的 `skills/`，角色定义放在 `agents/`；项目层是主仓库目录下的 `.pi/`，下面同样是 `skills/`、`agents/`。
- 一份：一个 skill 目录算一份 skill，一个定义文件算一份角色定义。
- 要复制的：目标位置还缺文件的 skill（其中有文件被改过也算），以及目标位置还没有的定义。
- 一样的：目标位置每个文件都和样例相同的 skill 或定义。
- 被改过的：目标位置至少有一个文件和样例不同的 skill 或定义。
- 要新复制的定义：要复制的那些角色定义。

## 用户故事
### P0：作为用户，我想要复制样例时不往 AGENTS.md 写东西，以便其他代理不收到和它们无关的规范

**用例（主路径）**
- 场景：`~/.pi/agent/AGENTS.md` 里有两行个人规范；用户层还没复制过 golang 样例。
- 操作：运行 `/one:examples`，选 golang、用户层，确认窗口选「复制」。
- 预期：确认窗口只有两行「复制 12 份到 ~/.pi/agent/：10 份 skill、2 份角色定义。」；选「复制」后直接显示「✓ Go 后端样例已复制到用户层：新复制 12 个文件。」，中间不弹别的窗口；`~/.pi/agent/AGENTS.md` 还是那两行。

**用例（边界：AGENTS.md 里留着以前复制的那一段）**
- 场景：仓库根目录 `AGENTS.md` 里有以前复制进来的「## 后端设计约定」一段；项目层 skills 和定义都和样例一致。
- 操作：运行 `/one:examples`。
- 预期：golang 一行显示「项目层：已复制」；`AGENTS.md` 不变。

### P0：作为用户，我想要确认窗口正常时只说几份，有特殊情况才说明，以便一眼看懂会发生什么

**用例（主路径：部分已有）**
- 场景：用户层已有 golang-testing，和样例一样；其他都没有。
- 操作：选 golang、用户层。
- 预期：确认窗口是「复制 11 份到 ~/.pi/agent/：9 份 skill、2 份角色定义。」「已经有、和样例一样的 1 份，跳过。」两行，不列任何名字。

**用例（异常：有特殊情况）**
- 场景：项目层已有改过的 version-policy；用户层已有 go-worker.md；go-reviewer 在 `/one:setting` 里关着；项目受信任。
- 操作：选 golang、项目层。
- 预期：份数那几行下面空一行，接着是三行黄字：「你改过的 1 份保留你的版本，不覆盖：skills/version-policy」「go-worker 会替换你在用户层的同名定义 ~/.pi/agent/agents/go-worker.md。」「go-reviewer 在 /one:setting 里是关闭，复制后照样关闭，派工不会用它。」

## 约束
- C-1：`examples/golang/`、`examples/vue/` 下只有 `skills/` 和 `agents/`，没有 `AGENTS.md`。
- C-2：`/one:examples` 运行全程不读、不写目标层的 `AGENTS.md`：运行前后用户级和仓库根目录的 `AGENTS.md` 内容相同，文件原来不存在时运行后也不存在。
- C-3：每个样例在每一层的状态只按 skills 和角色定义算：全部和样例一样是「已复制」，全部没有是「未复制」，有被改过的是「有改动」，其他是「部分复制」。目标 `AGENTS.md` 里有没有样例那一段、内容是什么，都不影响状态。
- C-4：选样例窗口的说明是「选中后再选复制到哪一层；skills 和角色定义一起复制。」。
- C-5：确认窗口的标题和选项不变（「把 <中文名>样例复制到<层名>？」，选项「复制」「不复制」），正文按顺序写：
  - 第一行：有要复制的时写「复制 <总份数> 份到 <层目录>：<a> 份 skill、<b> 份角色定义。」，a 或 b 为 0 时省掉那一半和中间的顿号；没有要复制的时写「这一层没有要复制的。」。
  - 第二行：一样的有 K 份（K ≥ 1）时写「已经有、和样例一样的 <K> 份，跳过。」；K 为 0 时不写这一行。
  - 下面几种特殊情况，有任一种时先空一行，再每种一行，用黄色（警示色），按下面的顺序：
    1. 有被改过的：「你改过的 <M> 份保留你的版本，不覆盖：<路径1>、<路径2>…」，路径相对层目录，skill 写 `skills/<名字>`，定义写 `agents/<名字>.md`。被改过的 skill 里还有缺的文件时，在它的路径后面紧接着写「（缺的 <n> 个文件照样补上）」，n 按文件计。
    2. 复制到项目层，要新复制的定义在用户层已有同名文件：每个这样的定义一行「<名字> 会替换你在用户层的同名定义 <用户层定义文件路径>。」。
    3. 要新复制的定义在 `/one:setting` 里是关闭：每个这样的定义一行「<名字> 在 /one:setting 里是关闭，复制后照样关闭，派工不会用它。」。
    4. 复制到用户层、项目受信任，要新复制的定义在项目层已有同名文件：每个这样的定义一行「项目层已有 <名字>，在这个项目里用的是项目层那份，用户层这份不生效。」。
  - 没有特殊情况时不空行，正文到第二行（或第一行）为止。
  - 不列要复制的、一样的 skill 和定义的名字；替换的是包里内置的定义时不写说明。
  - 层目录、路径以家目录开头时写成 `~` 开头。
- C-6：确认窗口选「复制」后复制完文件，直接显示结果提示，中间没有别的窗口。
- C-7：结果提示第一行是「✓ <中文名>样例已复制到<层名>：新复制 <N> 个文件。」，N 按文件计；有被改过的文件时第二行是「被改过、没有覆盖：<完整路径1>、<完整路径2>…。」；没有就只有第一行。复制到项目层时把本项目设为了受信任，末尾照样加「 · 已把本项目设为受信任」。
- C-8：复制中途失败时，提示是「✗ 复制没有完成：<原因> <目录>/」，第二行「已复制的 <n> 个文件保留；解决后再运行 /one:examples 会接着补。」；原因的写法和现在一样（没有权限写入、目标位置已有别处写的同名文件、其他错误的第一行）。

## 验收
- [ ] C-1：`ls examples/golang examples/vue` 只列出 `agents`、`skills`。
- [ ] C-2：用户层、项目层各复制一次 golang 样例，两处 `AGENTS.md` 运行前后逐字节相同；`AGENTS.md` 原来不存在的那一层，运行后仍不存在。
- [ ] C-3：项目层 skills、定义都和样例一致，`AGENTS.md` 里有以前复制的「## 后端设计约定」或没有，状态都是「已复制」；删掉一份 skill 后变成「部分复制」；改动一个 skill 文件后变成「有改动」。
- [ ] C-4：选样例窗口的说明一字不差是「选中后再选复制到哪一层；skills 和角色定义一起复制。」。
- [ ] C-5：主路径、部分已有、全部跳过或被改过、四种特殊情况各一例，确认窗口正文和约束写的逐行一致；只缺 skill 时第一行是「复制 3 份到 ~/.pi/agent/：3 份 skill。」；正文里没有出现「AGENTS.md」。一份有两个文件的 skill 改过一个、缺另一个，其他都和样例一样时，第一行是「复制 1 份到 ~/.pi/agent/：1 份 skill。」，黄字是「你改过的 1 份保留你的版本，不覆盖：skills/<名字>（缺的 1 个文件照样补上）」。
- [ ] C-6：选「复制」后只弹出过确认窗口这一个带选项的窗口（选样例、选层之后），接着就是结果提示。
- [ ] C-7：全新复制 golang 到用户层，结果只有一行「✓ Go 后端样例已复制到用户层：新复制 12 个文件。」；有一个文件被改过时多出第二行；项目层首次授信时末尾带「 · 已把本项目设为受信任」。
- [ ] C-8：让目标 skills 目录不可写后复制，提示第一行是「✗ 复制没有完成：没有权限写入 <目录>/」，第二行是「已复制的 <n> 个文件保留；解决后再运行 /one:examples 会接着补。」。

3. 在仓库根目录 `AGENTS.md` 末尾手动贴上以前样例的「## 后端设计约定」一段，再运行 `/one:examples` → 项目层状态和贴之前一样。
