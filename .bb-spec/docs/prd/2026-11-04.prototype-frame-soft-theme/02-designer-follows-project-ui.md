# 设计师结合项目整体界面出原型

几个词先说清楚：
- 原型设计师：one-company 里只负责出原型的子代理。它只能读仓库里的文件，不能改文件，不能运行命令，也不能开浏览器。
- 设计师的规矩：程序固定加进原型设计师提示词的流程规矩，用户改不到。
- 被设计的页面：设计师交的页面，显示在原型外框的隔离框里，只含正式上线后用户能看到的内容。
- 整体布局：项目里每个页面都套着的公共部分，比如顶栏、侧边导航、页脚、页面的内容区宽度和边距。
- 现有样式：项目代码里定下的配色、字体、字号、间距、圆角，以及按钮、表格、表单这些组件的样子。
- 界面代码：项目里决定用户看到什么的源码，包括页面组件、布局组件、样式文件，以及命令行程序里拼输出文字的代码。
- 样例项目：测试专用的一个小业务项目。

## 用户故事
### P0：作为看原型的用户，我想看到这次改动放在整个应用里是什么样子
**用例（改已有页面）**
- 场景：项目是一个网页后台，每个页面都有顶栏导航"工作台、订单、客户、设置"，主色是青绿色 `#0f766e`。设置页现在有"账号安全""通知"两块。用户要在设置页加一个"每日提醒时间"。
- 操作：主代理派设计师出原型，设计师交稿后用户打开原型。
- 预期：隔离框里是整张设置页：顶上是同样的顶栏导航，"设置"处于选中的样子；"账号安全""通知"两块按现在的样子还在；新加的"每日提醒时间"放在设置页里，按钮、输入框用项目的青绿色和现有组件的样子。

**用例（做新页面）**
- 场景：同一个项目，用户要加一个"报表"页面。
- 操作：设计师出原型。
- 预期：隔离框里的报表页套着同样的顶栏导航，内容区宽度、边距、配色、按钮样子都和项目其他页面一致。

**用例（项目还没有界面代码）**
- 场景：一个刚建的项目，仓库里还没有任何页面组件和样式文件。
- 操作：设计师出原型。
- 预期：设计师按任务说明自己定布局和样式，和现在的做法一样。

## 约束
- C-1：设计师的规矩写明：动手画之前，先读任务说明里的 DESIGN.md，整体布局（顶栏、侧边导航、页脚、内容区宽度和边距）、现有样式（配色、字体、字号、间距、圆角）和组件照它画；DESIGN.md 没写到的（比如这个页面现在的具体内容、DESIGN.md 里没有的组件），再去仓库里找对应的界面代码读；仓库里还没有 DESIGN.md 时，先读界面代码，弄清上面这些。
- C-2：设计师的规矩写明：改已有页面时，先把这个页面照现在的样子整页还原，包括整体布局和页面里这次不改的部分，再只改这次要改的地方。
- C-3：设计师的规矩写明：做新页面时，把它套进项目现有的整体布局，用现有样式和现有组件的样子画；项目里没有的组件，按现有样式的配色、字号、间距画。
- C-4：设计师的规矩写明：终端界面同样照现有命令的输出格式还原，包括前缀、颜色、对齐方式和提示文字的写法。
- C-5：设计师的规矩写明：仓库里找不到界面代码时，按任务说明自己定布局和样式；找到了但读不懂某一部分的样子时，把读不懂的地方写进 openQuestions，不猜。
- C-6：新增单点验收 P20：准备一个样例项目，里面有一个布局组件（顶栏导航写着 4 个固定的导航文字）、一个写着主色值的样式文件、一个已有两块固定标题的设置页。真实模型扮演原型设计师，任务是在设置页里加一个设置项。程序判定：交稿被收下；交上来的页面里有这 4 个导航文字、这个主色值（大小写不论）和设置页原有的两块标题。设计得好不好不算进判定。

## 验收
- [ ] C-1：设计师的规矩里有"先读 DESIGN.md，没写到的再读界面代码；没有 DESIGN.md 时先读界面代码"这一条，写明了整体布局和现有样式各包括什么。
- [ ] C-2：设计师的规矩里有"改已有页面时先整页还原，再只改要改的地方"这一条。
- [ ] C-3：设计师的规矩里有"新页面套进现有整体布局，用现有样式和组件画"这一条。
- [ ] C-4：设计师的规矩里有"终端界面照现有命令的输出格式还原"这一条。
- [ ] C-5：设计师的规矩里有"找不到界面代码时自己定；读不懂的写进 openQuestions"这一条。
- [ ] C-6：P20 在真实模型上按验收规则通过。

## 验证路径
1. 读设计师的规矩 → C-1 到 C-5 的五条都在里面。
2. 跑 P20 → 交稿被收下，交上来的页面里能搜到 4 个导航文字、主色值和设置页原有的两块标题。
3. 在一个有网页界面的项目里让主代理出一个改已有页面的原型，打开看 → 隔离框里是整张页面，顶栏导航和原有内容都在，只多了这次要加的部分。
