# 界面设计规范文件 DESIGN.md

几个词先说清楚：
- DESIGN.md：用户项目仓库根目录下的界面设计规范文件，写明这个项目界面的颜色、字体、间距、布局、组件等，全部用数值写。
- 原型设计师：one-company 里只负责出原型的子代理，只能读文件，不能写文件，用交稿工具把稿子交给程序。
- 交稿：设计师调 `result_submit` 的 `prototype` 动作，把页面、页面清单、说明等交给程序。程序检查不合格就退回，退回时把原因告诉设计师，让它改了重交。
- "确认原型"窗口：程序收下原型后在 pi 里弹出的终端窗口，用户在里面选"通过"或某个方案，也可以选"其他"写意见让主代理重派。
- 方案字母：设计师画了多个方案时，程序按顺序给方案编的字母 A 到 F。
- 对比度：两个颜色的亮度之比，按 WCAG 2.1 的公式从色值算出来，越大越容易看清。
- 派工：程序启动 worker、reviewer、原型设计师等子代理，并把任务说明和要遵守的规范一起发给它。

## 用户故事
### P0：作为用户，我想每份原型都照同一份界面设计规范画，风格统一
**用例（第一次建立）**
- 场景：项目里已经有网页界面，主色是 `#0f766e`，仓库根目录还没有 DESIGN.md。用户让主代理出"设置页加每日提醒时间"的原型。
- 操作：设计师读完界面代码后交稿，交稿里带一份 DESIGN.md 全文；用户在"确认原型"窗口里看到"通过后在仓库根目录新建 DESIGN.md，之后的原型、实现和审查都照它做。"，选"通过"。
- 预期：仓库根目录出现 DESIGN.md，十章齐全，颜色章的主色是 `#0f766e`；程序没有自动提交它。

**用例（第二次沿用）**
- 场景：同上，DESIGN.md 已经在仓库里。用户又让主代理出"报表页"的原型。
- 操作：设计师交稿，只改了组件章；用户在窗口里看到"通过后同时更新仓库根目录的 DESIGN.md：改了组件一章。"，选"通过"。
- 预期：DESIGN.md 只有组件章变了，其余九章一字不差。

**用例（没有变化）**
- 场景：设计师交的 DESIGN.md 和仓库里的一字不差。
- 操作：打开"确认原型"窗口，选"通过"。
- 预期：窗口里没有"通过后……DESIGN.md"那一行；DESIGN.md 文件没被改写，修改时间不变。

### P0：作为用户，我要 DESIGN.md 里全是可以量化的数值，不是含糊的描述
**用例（缺项被退回）**
- 场景：设计师交的 DESIGN.md 里，字体章没写"正文字号"。
- 操作：交稿。
- 预期：交稿被退回，原因写"DESIGN.md「字体」缺少「正文字号」"；不弹"确认原型"窗口；补上后重交才弹窗。

**用例（对比度不够被退回）**
- 场景：老代码里次要文字是 `#999999`，背景是 `#ffffff`。设计师照抄进 DESIGN.md。
- 操作：交稿。
- 预期：交稿被退回，原因写明"DESIGN.md「颜色 · 明亮」里次要文字 #999999 和背景 #ffffff 的对比度是 2.85:1，低于「无障碍」写的正文最低对比度 4.5:1"。设计师改成合规的色值重交，并在 openQuestions 里写明"次要文字由 #999999 改为 #6b7280，老页面会跟着变"。

### P0：作为用户，我要做出来的界面也照 DESIGN.md
**用例（实现和审查）**
- 场景：需求批准后，PM 派 worker 写界面代码，派 reviewer 审查。
- 操作：worker 按钮写成了 `#2563eb`，DESIGN.md 的主色是 `#0f766e`。
- 预期：worker 和 reviewer 收到的任务说明里都有 DESIGN.md 全文；reviewer 把"按钮颜色和 DESIGN.md 主色不一致"列为阻塞。

### P1：作为用户，我不希望别的改动被覆盖
**用例（交稿后被改过）**
- 场景：需求甲和需求乙各派了一个设计师。乙的原型先通过，DESIGN.md 已经被改写；甲的设计师是在那之前读的 DESIGN.md。
- 操作：打开甲的"确认原型"窗口。
- 预期：窗口里写"设计师交稿后，仓库根目录的 DESIGN.md 被改过。要通过，请在「其他」里写意见，让主代理按最新的 DESIGN.md 重派一版。"；"通过"那一项选不了，后面写"设计师交稿后 DESIGN.md 被改过，这一版不能通过"；DESIGN.md 保持乙写入后的内容。

## 约束
- C-1：设计师每次交原型都必须带 DESIGN.md 全文。只画一种方案，或各方案风格相同时，交一份；各方案风格不同时，每个方案各交一份，按方案字母对应，每个方案都要有。没带、或者多方案时缺了某个方案，交稿被退回，原因写明缺哪一份。
- C-2：DESIGN.md 全文最大 16 KiB（16384 字节），超过时交稿被退回，原因写明实际字节数和上限。
- C-3：DESIGN.md 必须有下面十章，每章是一个二级标题，标题文字一字不差：`## 风格`、`## 颜色`、`## 字体`、`## 间距`、`## 圆角与阴影`、`## 布局`、`## 组件`、`## 状态`、`## 无障碍`、`## 终端界面`。缺某一章时交稿被退回，原因写"DESIGN.md 缺少「<章名>」章"。十章是最低要求，可以按需另加二级标题的章（比如 `## 图表`），程序不查新加章的内容。同一个章名出现两次时退回，原因写"DESIGN.md 的「<章名>」章出现了两次，合成一章"。读全文前先去掉开头的 BOM（编辑器加在文件最前面的不可见标记），把 `\r\n` 换行统一成 `\n`。
- C-4：每个必填项写成一行"`- <项名>：<值>`"，冒号用中文"："或英文":"都可以。每章除了必填项还可以写别的内容，程序不管。同一章（颜色章是同一节）里同一个必填项写了两行时退回，原因写"DESIGN.md「<章名>」的「<项名>」写了两次，只留一行"；颜色章里同一个三级标题出现两次时退回，原因写"DESIGN.md「颜色」的「<节名>」一节出现了两次，合成一节"。缺必填项时交稿被退回，原因写"DESIGN.md「<章名>」缺少「<项名>」"；值的格式不对时退回，原因写"DESIGN.md「<章名>」的「<项名>」要写成<格式说明>，如<例子>"。各章的必填项和值的格式如下：

  | 章 | 必填项 | 值的格式 |
  |---|---|---|
  | 风格 | 主题 | "明亮"、"暗黑"或"明亮、暗黑" |
  | 风格 | 参考设计体系 | 设计体系名称，没有写"无" |
  | 颜色 | 主题章写了几套就分几节，每节是一个三级标题 `### 明亮` 或 `### 暗黑`；每节都有：主色、主色悬停、文字、次要文字、禁用文字、边框、背景、卡片背景、成功、警告、出错、提示 | `#` 加 6 位十六进制，如 `#0f766e` |
  | 字体 | 字体 | 字体名，多个用英文逗号隔开 |
  | 字体 | 标题 1 字号、标题 2 字号、标题 3 字号、正文字号、辅助文字字号 | 像素，如 `14px` |
  | 字体 | 正文行高 | 倍数，如 `1.5` |
  | 字体 | 常规字重、加粗字重 | 100 到 900 之间的整百数 |
  | 间距 | 基本单位 | 像素 |
  | 间距 | 档位 | 一组像素值，用英文逗号或顿号隔开，如 `4px、8px、16px`；每一档都必须是基本单位的整数倍 |
  | 圆角与阴影 | 小圆角、大圆角 | 像素 |
  | 圆角与阴影 | 卡片阴影、弹窗阴影 | CSS 阴影值，或"无" |
  | 布局 | 内容区最大宽度、页面边距、手机平板分界、平板桌面分界 | 像素 |
  | 布局 | 侧栏宽度、顶栏高度 | 像素，或"无" |
  | 组件 | 按钮高度、按钮左右内边距、输入框高度、表格行高、弹窗宽度、图标尺寸 | 像素 |
  | 状态 | 加载中出现时间、动画时长 | 毫秒，如 `300ms` |
  | 状态 | 提示条消失时间 | 毫秒，或"不自动消失" |
  | 无障碍 | 正文最低对比度、图标和边框最低对比度 | 比值，如 `4.5:1` |
  | 无障碍 | 焦点框宽度 | 像素 |
  | 无障碍 | 最小点击区域 | 宽×高像素，如 `44×44px`，乘号用"×"或"x" |
  | 终端界面 | 每行列数 | 正整数 |
  | 终端界面 | 成功颜色、警告颜色、出错颜色、提示颜色 | 红、绿、黄、蓝、品红、青、白、灰之一 |

  项目没有终端界面时，终端界面章正文只写一行"无"，不写必填项。
- C-5：间距章的每一档不是基本单位的整数倍时，交稿被退回，原因写"DESIGN.md「间距」的档位 <值> 不是基本单位 <值> 的整数倍"。
- C-6：无障碍章的正文最低对比度低于 4.5:1、图标和边框最低对比度低于 3:1 时，交稿被退回，原因写明写的值和下限。
- C-7：颜色章每一节里，文字和背景、次要文字和背景的对比度不低于无障碍章写的正文最低对比度，主色和背景的对比度不低于图标和边框最低对比度。不够时交稿被退回，原因写"DESIGN.md「颜色 · <节名>」里<项名> <色值> 和背景 <色值> 的对比度是 <实际值，保留两位小数>:1，低于「无障碍」写的<项名> <值>"。
- C-8：多个方案各交一份 DESIGN.md 时，C-2 到 C-7 每份都检查，退回原因前面加"方案 <字母> 的"。
- C-9：派原型设计师时，程序把仓库根目录 DESIGN.md 此刻的全文放进任务说明；仓库里没有时写明"仓库根目录还没有 DESIGN.md，这次交稿要新建一份"。重派下一版时，任务说明里还写明上一版交的 DESIGN.md 在哪个文件。程序记下派工时 DESIGN.md 的内容指纹，没有文件时记成"没有"。
- C-10：设计师的规矩写明：先读任务说明里的 DESIGN.md，原型照它画；每次交稿都带 DESIGN.md 全文，没改的章原样照抄；仓库里没有 DESIGN.md 时，先从项目界面代码里读出现有的值写进去，代码里没有的项按现代界面设计规范补；DESIGN.md 只写全项目通用、多个页面会重复用到的设计规范，单个页面的布局、某个需求的文案和数据、设计说明、待确认的问题都不写进去；十章装不下的通用规范才另加一章；现有的值不合 C-6、C-7 时写合规的新值，原型也按新值画，并把"<项名>由<老值>改为<新值>，老页面会跟着变"写进 openQuestions；C-3、C-4 的章名、项名和值的格式。
- C-11："确认原型"窗口里，设计师说明的下一行按情况显示一行普通颜色的文字（不是灰色）：
  - 仓库里没有 DESIGN.md："通过后在仓库根目录新建 DESIGN.md，之后的原型、实现和审查都照它做。"
  - 有，且这次交的和它不一样："通过后同时更新仓库根目录的 DESIGN.md：改了<章名>、<章名>……<N>章。"章名先按 C-3 的顺序列十章里内容有变化的，再按出现顺序列新加、删掉或改了的其他章；第一个二级标题之前的开头文字变了时，最后加"开头的说明"并算一章；N 用中文数字写，如"两章"。
  - 多个方案各一份："通过后同时更新仓库根目录的 DESIGN.md："，下一行缩进写"方案 A 改了<章名>……；方案 B 改了<章名>……。"，和仓库里一样的方案写"方案 C 不变"。
  - 这次交的和仓库里一字不差（去掉 BOM、统一换行后比较；只调换了章的先后顺序也算不变）：不显示这一行。
- C-12：用户选"通过"（或选某个方案）时，程序把这份（或这个方案对应的那份）DESIGN.md 写到仓库根目录，不提交；和仓库里一字不差时不写。选"其他"或按 Esc 时不写。
- C-13：打开"确认原型"窗口时，仓库根目录 DESIGN.md 的内容指纹和 C-9 记下的不一样，窗口在 C-11 那一行的位置显示"设计师交稿后，仓库根目录的 DESIGN.md 被改过。要通过，请在「其他」里写意见，让主代理按最新的 DESIGN.md 重派一版。"；"通过"和各方案选项都选不了，后面写"设计师交稿后 DESIGN.md 被改过，这一版不能通过"；"其他"和 Esc 照常可用。窗口打开时一致、用户选择之后写入之前才变了的，不写入、不登记通过，原型仍在等确认，主窗口弹出提示"DESIGN.md 在你确认时被改过，这一版没有通过"，对话里写明"原型「<名称>」第 <N> 版没有通过：DESIGN.md 在你确认时被改过。在窗口里选「其他」写意见，让主代理按最新的 DESIGN.md 重派一版；可以用 one_company_prototype confirm 重开确认窗口。"。
- C-14：派 worker 和 reviewer 时，仓库根目录有 DESIGN.md 就把全文放进任务说明，写明"界面设计规范（来源：仓库根目录 DESIGN.md；界面改动必须遵守）"；没有时不放。派 PM、qa、explore 时不放。
- C-15：worker 的规矩写明：改动涉及界面时，原型里画了的按原型，原型没画到的颜色、字号、间距、圆角、组件尺寸用 DESIGN.md 里的值。reviewer 的规矩写明：任务说明里有 DESIGN.md 时，界面改动用了既不在 DESIGN.md 里、也不在原型里的颜色、字号、间距、圆角或组件尺寸，列为阻塞。
- C-16：主窗口和所有子代理用 edit、write 改仓库根目录的 DESIGN.md（文件名不分大小写）时被拦下，主窗口的原因写"DESIGN.md 只能随原型通过写入：派原型设计师出一版原型，用户通过后由程序写入"；worker 写它时原因写"DESIGN.md 只能随原型通过写入，不能用工具直接改"，下一步写"派原型设计师出一版原型，用户通过后由程序写入；需要改设计规范时在结果里说明"；PM 提交它时原因写"这是界面设计规范文件 DESIGN.md，只能随原型通过写入，不能提交：<路径>"。用户自己在编辑器里改不受影响。
- C-17：升级到这一版时，数据库迁移把还在做或还在等确认的原型标成作废，作废原因写"升级后交原型要带 DESIGN.md，这一版作废，请重派"；迁移确认框写一句"升级前还在做、或还在等你确认的原型会作废，需要重派（它们交稿时没带 DESIGN.md）"；已经通过或放弃的原型、用户对原型提过的意见都不受影响。
- C-18：单点验收 P17 的判定加一项"交稿里的 DESIGN.md 通过程序检查"；P21 的判定加一项"交稿里的 DESIGN.md 颜色章主色是样例项目的主色值"。

## 验收
- [ ] C-1：没带 DESIGN.md 被退回；多方案时少一份被退回，原因写明缺哪个方案；一份对应所有方案、每个方案各一份两种交法都被收下。
- [ ] C-2：16384 字节的 DESIGN.md 被收下，16385 字节的被退回，原因写明字节数和上限。
- [ ] C-3：十章依次各缺一章，都被退回，原因写明缺的章名；章名多一个字或少一个字也算缺；多加一章 `## 图表` 被收下；`## 颜色` 出现两次被退回，原因与约束一致；带 BOM、用 `\r\n` 换行的合格全文被收下。
- [ ] C-4：每个必填项依次缺一项，都被退回，原因写明章名和项名；表里每种值的格式各给一个写错的例子，都被退回，原因写明要的格式和例子；中文冒号、英文冒号都被收下；主题只写"明亮"时只要 `### 明亮` 一节；终端界面章只写"无"时被收下；同一节里"主色"写两行、`### 明亮` 出现两次，各自被退回，原因与约束一致。
- [ ] C-5：基本单位 4px、档位里有 10px 时被退回，原因与约束一致。
- [ ] C-6：正文最低对比度写 4:1、图标和边框最低对比度写 2.5:1 时，各自被退回。
- [ ] C-7：次要文字 `#999999` 配背景 `#ffffff` 被退回，原因里的对比度是 2.85:1；主色和背景对比度不够被退回；暗黑一节对比度不够同样被退回。
- [ ] C-8：方案 B 那份缺章时被退回，原因以"方案 B 的"开头。
- [ ] C-9：仓库里有 DESIGN.md 时，设计师的任务说明里有它的全文；没有时写着那句话；重派时写着上一版 DESIGN.md 的文件位置。
- [ ] C-10：设计师的规矩里有这几条要求。
- [ ] C-11：新建、改了两章、多方案、一字不差四种情况下，窗口里那一行的文字和约束一致；那一行不是灰色；只加了一章 `## 图表` 时写"改了图表一章"；只改了开头文字时写"改了开头的说明一章"；仓库里是 `\r\n` 换行、交的是同样内容的 `\n` 换行时不显示这一行。
- [ ] C-12：选"通过"后仓库根目录的 DESIGN.md 是交的那份，git 里显示为未提交的改动；选方案 B 写入的是方案 B 那份；一字不差时文件修改时间不变；选"其他"、按 Esc 后文件不变。
- [ ] C-13：派工后改了 DESIGN.md 再打开窗口，"通过"选不了，提示文字一致，选"其他"能写意见；窗口打开后、选"通过"前改了 DESIGN.md，原型仍在等确认，DESIGN.md 保持别处改的内容，对话里有那句提示。
- [ ] C-14：worker、reviewer 的任务说明里有 DESIGN.md 全文和来源说明；PM、qa、explore 的没有；仓库里没有 DESIGN.md 时 worker、reviewer 的也没有。
