# 步骤窗口的边框和折行

步骤窗口：在状态面板上选中一个子代理行、按回车后弹出的窗口，盖在对话上方，Esc 关闭。它从上到下依次是：标题（子代理行去掉图标、轮数、耗时后的文字）、状态行（"⠹ 运行中 · 共 N 步 · ↻轮数/上限 · 耗时"这样一行）、步骤区（每次工具调用一步，做完打 ✓、报错打 ✗、正在做的转圈）、底部提示（"↑↓ 滚动 · Esc 关闭"）。

80 列、24 行终端里，标题很长、某一步很长时的样子：

```
╭──────────────────────────────────────────────────────────────────────────────╮
│ 联网 · 仅做公开资料只读调研，不写文件、不实施。核实 OpenAI Codex 桌面应用：1 │
│ macOS/Windows 当前官方支持平台与架构；2 自定义 model provider / base_url /   │
│ API key / model=auto 的官方配置方式、是否共用 ~/.codex/config.toml、模型列表 │
│ /自定义模型支持；3 第三方配置工具能否通过官方扩展点在 Codex 桌面应用里生效   │
│ ⠹ 运行中 · 共 12 步 · ↻5/12 · 51.9s                                          │
├──────────────────────────────────────────────────────────────────────────────┤
│ ✓ web_search                                                                 │
│ ✗ 跑命令 pnpm vitest run src/modules/order/export.test.ts                    │
│   src/modules/order/export-month.test.ts --reporter verbose --run            │
│ ⠹ 思考中                                                                     │
├──────────────────────────────────────────────────────────────────────────────┤
│ ↑↓ 滚动 · Esc 关闭                                                           │
╰──────────────────────────────────────────────────────────────────────────────╯
```

## 用户故事

### P0：作为等子代理干活的用户，我想要在步骤窗口里看到完整的标题、状态和每一步，以便知道它在查什么、卡在哪一步

**用例（主路径：标题很长）**
- 场景：80 列、24 行的终端。用户从主窗口发起一次联网检索，问题有 300 个字，检索已调用 12 次工具。
- 操作：在面板上选中这个检索行，按回车。
- 预期：窗口四边都有边框，每一行最后一列都是"│"；标题折成多行，连起来就是问题原文，一个字不少，没有"…"；状态行"⠹ 运行中 · 共 12 步 · ↻5/12 · 51.9s"跟在标题下面。

**用例（主路径：某一步很长）**
- 场景：worker 第 7 步跑了一条 110 个字符长的命令，失败了。
- 操作：打开它的步骤窗口。
- 预期：这一步占两行。第一行是"✗ 跑命令 pnpm vitest run …"，第二行接着写命令剩下的部分，开头和第一行的"跑命令"对齐，图标那一列空着；整条命令一个字不少。

**用例（边界：往上翻）**
- 场景：worker 做了 40 步，其中好几步各占两行，一屏放不下。
- 操作：打开窗口，按 ↑ 若干次。
- 预期：每按一次，内容往下挪一行。可见区最上面可能是某一步的第二行，这一行没有图标。顶部的"↑ 上面还有 N 步"、底部的"↓ 下面还有 M 步"，加上可见区里露出第一行的步数，等于 40。

**用例（边界：失败原因很长）**
- 场景：worker 因为"模型请求失败：请求 … 时连接被对方重置（ECONNRESET），已重试 5 次仍然失败 …"这样 120 个字的原因失败了。
- 操作：打开它的步骤窗口。
- 预期：红色状态行"✗ 失败：<原因> · 共 9 步 · ↻9/40 · 3m41s"折成多行，原因一个字不少。

## 约束

- C-1：窗口的边框占满终端宽度，四边都画。第一行是"╭"、一串"─"、"╮"；标题与状态行下面、步骤区下面各有一行"├"、一串"─"、"┤"；最后一行是"╰"、一串"─"、"╯"。中间每一行以"│ "开头、以" │"结尾，右边的"│"都在这一行的最后一列。
- C-2：终端不少于 10 列时，标题、状态行（包括失败原因）、每一步的文字、读不到步骤时的说明、底部提示，一行放不下时折到下一行，内容一个字不少，不加"…"。
- C-3：一步的文字折行后，接着写的行开头空出和"图标 + 空格"一样宽的位置，和这一步第一行的文字对齐。codemode 下缩进两格的步骤，接着写的行同样和它自己的文字对齐。（codemode：跑一段会调用其他工具的脚本，脚本里调用的工具在它下面缩进两格列出。）
- C-4：整个窗口的行数不超过终端高度减 1。步骤区能用的行数是：终端高度减 1，再减去其余各行实际占的行数（4 行边框和分隔线，加上标题、状态行、底部提示折行后的行数），最少 3 行；按 3 行算时窗口可以超过终端高度。
- C-5：步骤区放不下时，↑↓ 每按一次滚一行。可见区上面有被盖住的行时，第一行写"↑ 上面还有 N 步"；下面有被盖住的行时，最后一行写"↓ 下面还有 M 步"（灰色）。N 是第一行在可见区上面的步数；M 是第一行在可见区下面的步数，"思考中"不算。
- C-6：窗口打开时，步骤区显示在最底下。显示在最底下时，有新步骤或者某一步变长，窗口自动滚到最后一行；用户往上翻过之后，新内容不让窗口跳动，只更新"下面还有 M 步"；翻回最底下后恢复自动跟随。
- C-7：终端宽度变了以后，下一次刷新按新宽度重新折行，右边的"│"仍在最后一列。

## 验收

- [ ] AC-1 ← C-1：80 列下打开窗口，每一行的显示宽度都是 80；第一行以"╭"开头、"╮"结尾，两条分隔线以"├"开头、"┤"结尾，最后一行以"╰"开头、"╯"结尾；其余每行第一列和最后一列都是"│"。
- [ ] AC-2 ← C-2：标题 300 字、80 列时，标题占 2 行以上，去掉边框和行首行尾的空格后连起来等于原文；窗口里任何一行都不以"…"结尾。失败原因 120 字时，状态行同样折行，连起来含完整原因。读一个 200 个字符长的路径时，这一步折成 3 行，连起来是"读 <完整路径>"。
- [ ] AC-3 ← C-3：一步文字折成 3 行时，第 2、3 行在"│ "之后先空 2 列，文字和第一行"图标 + 空格"之后的文字在同一列开始；codemode 下缩进两格的一步折行时，接着写的行在"│ "之后先空 4 列，同样和它第一行的文字在同一列开始。
- [ ] AC-4 ← C-4：24 行终端里，标题占 4 行、状态行和底部提示各占 1 行时，步骤区最多 13 行，整个窗口不超过 23 行；标题占 1 行、状态行占 1 行时，步骤区最多 16 行。终端只有 10 行、标题占 4 行时，步骤区仍有 3 行。
- [ ] AC-5 ← C-5：40 步、其中 12 步各占 2 行、步骤区 16 行时，从最底下按 ↑ 一次，可见区整体往下挪一行；按 ↑ 若干次后，N + M + 可见区里露出第一行的步数 = 40。可见区第一行是某一步的第二行时，这一步算在 N 里。
- [ ] AC-6 ← C-6：在最底下时新增一步（占 2 行），最后两行变成这一步；按 ↑ 翻上去后新增一步，可见区内容不变、"下面还有"的数字加 1；按 ↓ 翻回最底下后再新增一步，最后一行又是最新的一步。
- [ ] AC-7 ← C-7：同一窗口先按 80 列显示，再按 60 列显示，60 列下每一行宽度都是 60，最后一列都是边框字符，标题仍然一个字不少。

## 验证路径

1. 80 列、24 行终端里发起一次问题有 300 字的联网检索，打开它的步骤窗口 → 四边边框完整，标题折行、一个字不少（AC-1、AC-2、AC-4）。
2. 让 worker 跑一条 110 个字符的命令、读一个 200 字符的路径，打开窗口 → 两步各自折行，接着写的行和文字对齐（AC-2、AC-3）。
3. 让 worker 做 40 步，按 ↑ 若干次，再让它多做一步，再按 ↓ 到底 → 滚动、计数、跟随都符合预期（AC-5、AC-6）。
4. 窗口开着时把终端从 80 列拉到 60 列 → 按新宽度重新折行，右边框在最后一列（AC-7）。
