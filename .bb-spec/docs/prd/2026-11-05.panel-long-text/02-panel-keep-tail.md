# 面板行保留尾部参数

状态面板：主会话输入栏下方的区域。每个运行中的需求占一组行，第一行叫需求行；需求下面每个任务占一行，审查中的任务再缩进一层，列出每个审查代理；面板底部另有主窗口派出的原型设计和检索两组行。子代理跑完、光标还停在它上面时，它留在面板最下面"● 已结束"组里，叫已结束行。

尾部参数：一行里跟在名字后面、表示用量的那串文字，例如"· prototype · ↻5/10 · 4m49s"。↻ 后面是已用轮数和上限，最后是耗时。

80 列下的样子（第一个 ⠹ 是转圈图标，光标在最后一个检索行上）：

```
● 1 个需求运行中
└─ ⠹ 订单导出按月分文… · 任务 2/5 · ↻9 · 30 tool uses · 1.2M token (85%) · 3m5s
     ├ ⠹ T3 执行 · order-export-specialist-worker（第 2 次尝试）· ↻8/20 · 3m2s
     ├ T1 第 2 轮审查
     │ ├ ⠹ reviewer · ↻3/20 · 41.2s
     │ └ – vue-reviewer 2 次没交出结论，本轮结束后交你裁决 · ↻40/40 · 12m3s
     ├ ⠹ explore 检索 · ↻3/12 · 20.1s
     └ ⚑ T4 待你裁决：worker 两次没做完，要拆分任务、调整目标，还是你自己接手
● 1 个原型设计运行中
└─ ⠹ 桌面接入工具安装配置原型：模型提供方、接口地址…· prototype · ↻5/10 · 4m49s
● 1 个检索运行中
└─ ⠹ 联网 · 仅做公开资料只读调研，不写文件、不实施。核实 OpenAI… · ↻5/12 · 51.9s
↑↓ 选择 · Enter 查看 · p 暂停/恢复 · 第一行按 ↑ 返回输入框
```

## 用户故事

### P0：作为同时跑着好几个子代理的用户，我想要名字再长也能在面板上看到每个子代理的轮数和耗时，以便判断它是不是快用完轮数、是不是跑得太久

**用例（主路径：检索问题很长）**
- 场景：80 列终端。用户从主窗口发起一次联网检索，问题有 300 个字，已用 5 轮、跑了 51.9 秒，上限 12 轮。
- 操作：看面板。
- 预期：检索行是"└─ ⠹ 联网 · 仅做公开资料只读调研…… · ↻5/12 · 51.9s"：问题在中间截短，末尾加"…"，行尾完整的"· ↻5/12 · 51.9s"；整行不超过 80 列。

**用例（主路径：原型设计名字很长）**
- 场景：原型名"桌面接入工具安装配置原型：模型提供方、接口地址和密钥分三步填写"，第 1 版，设计师定义名 prototype，已用 5 轮，上限 10 轮，跑了 4 分 49 秒。
- 操作：看面板。
- 预期：这一行以"· prototype · ↻5/10 · 4m49s"结尾；原型名和"（第 1 版）"一起被截短，末尾加"…"。

**用例（边界：终端很窄）**
- 场景：终端只有 40 列，需求行的尾部参数"· 任务 2/5 · ↻9 · 30 tool uses · 1.2M token (85%) · 3m5s"本身就超过 40 列。
- 操作：看面板。
- 预期：需求行整行从行尾截断，末尾是"…"，和以前一样；原型设计行是"└─ ⠹ 桌面接…· prototype · ↻5/10 · 4m49s"，名字留几个字，尾部完整。

## 约束

- C-1：下面这些行，名字放不下时截短的是名字，名字末尾加"…"，后面接完整的尾部参数；行首的树枝符号和图标保留不变。各行的名字和尾部参数是：
  | 行 | 名字 | 尾部参数 |
  |---|---|---|
  | 需求行 | 需求目标 | " · 任务 <已完成>/<总数>"（有计划时才有）、" · ↻<轮数> · <N> tool uses · <用量> token (<缓存命中率>)"（缓存命中率没有时不写括号）、" · <耗时>" |
  | 执行行 | "<任务号> 执行 · <定义名>（第 N 次尝试）" | "· ↻<轮数>/<上限> · <耗时>" |
  | 审查代理行 | 定义名和状态文字，如"✓ reviewer 通过""– vue-reviewer 2 次没交出结论，本轮结束后交你裁决" | " · ↻<轮数>/<上限> · <耗时>"；"已关闭，本轮未审""已不存在，本轮未审"这两种没有尾部参数 |
  | PM 派出的检索行 | "explore 检索" | " · ↻<轮数>/<上限> · <耗时>" |
  | 原型设计行 | "<原型名>（第 N 版）" | "· <设计师定义名> · ↻<轮数>/<上限> · <耗时>" |
  | 主窗口检索行 | "联网 · <问题>"或"本地 · <问题>" | " · ↻<轮数>/<上限> · <耗时>" |
  | 已结束行 | "<结果> · <标题>"，标题和原来那一行一样 | " · ↻<轮数>/<上限> · <耗时>"；原来是原型设计行时，前面再加"· <设计师定义名>"；还在读取结果的"读取中… · <标题>"没有轮数和耗时，原型设计的仍保留"· <设计师定义名>" |
  没有上限时轮数写"↻<轮数>"，和以前一样。
- C-2：整行放得下时，和以前一样完整显示，不加"…"。
- C-3：终端太窄、留给名字的宽度不到 2 列（放不下 1 个字宽加"…"）时，整行从行尾截断，末尾加"…"，和以前一样。
- C-4：没有尾部参数的行照旧从行尾截断，末尾加"…"：分组标题（"● N 个需求运行中"等）、⚑ 待处理事项行、PM 在做什么那一行、"T1 第 2 轮审查"这样的任务行、按键提示。
- C-5：每一行的显示宽度都不超过终端宽度；面板上的行仍然一行显示一个，不折行。选中行的蓝底、各段文字的颜色和以前一样。

## 验收

- [ ] AC-1 ← C-1：80 列下，问题 300 字的主窗口检索行以"· ↻5/12 · 51.9s"结尾，"· ↻"前面紧挨着的是"…"，整行宽度不超过 80。
- [ ] AC-2 ← C-1：80 列下，名字很长的原型设计行以"· prototype · ↻5/10 · 4m49s"结尾，"（第 1 版）"不在这一行里，"· prototype"前面紧挨着的是"…"。
- [ ] AC-3 ← C-1：80 列下，目标很长的需求行以"· 任务 2/5 · ↻9 · 30 tool uses · 1.2M token (85%) · 3m5s"结尾；定义名很长的执行行以"· ↻8/20 · 3m2s"结尾；名字很长的审查代理行以"· ↻40/40 · 12m3s"结尾；名字很长的已结束行以"· ↻12/12 · 2m3s"结尾；原来是原型设计的已结束行以"· prototype · ↻12/12 · 2m3s"结尾。这几行的名字末尾都是"…"。
- [ ] AC-4 ← C-2：名字和尾部参数加起来不超过终端宽度时，这一行和以前一模一样，没有"…"。
- [ ] AC-5 ← C-3：40 列下，需求行（尾部参数超过 40 列）整行从行尾截断，以"…"结尾，宽度不超过 40；同样 40 列下，原型设计行是"└─ ⠹ 桌面接…· prototype · ↻5/10 · 4m49s"。
- [ ] AC-6 ← C-4：80 列下，100 字的 ⚑ 事项行、100 字的"在做什么"行都从行尾截断，以"…"结尾。
- [ ] AC-7 ← C-5：80 列和 40 列下，面板每一行的显示宽度都不超过终端宽度；光标所在的行仍是蓝底。

## 验证路径

1. 80 列终端里同时跑一个目标很长的需求（下面有执行、审查、PM 派出的检索）、一个名字很长的原型设计、一个问题很长的联网检索 → 各行的尾部参数都完整显示在行尾（AC-1、AC-2、AC-3、AC-7）。
2. 把光标移到检索行上，等它跑完 → 已结束行的尾部参数完整（AC-3）。
3. 再让一个名字短的子代理跑起来 → 它那一行和以前一样，没有"…"（AC-4）。
4. 看 ⚑ 事项行和"在做什么"行 → 照旧从行尾截断（AC-6）。
5. 把终端调到 40 列 → 需求行整行截断，原型设计行和检索行保留尾部参数（AC-5、AC-7）。
