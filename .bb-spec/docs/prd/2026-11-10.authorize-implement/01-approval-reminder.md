# 批准时提醒并写明授权了什么

## 用户故事
### P0：作为用户，我想在批准需求时就知道可以顺便授权实施，以便批准完 PM 就能开工

**用例（主路径）**
- 场景：用户让主代理做"登录支持手机号"，主代理整理好需求草稿。
- 操作：主代理展示草稿要点、请用户批准；用户回复"批准并开始实施"（@ 到这个需求）。
- 预期：主代理请批准的那条回复里，有一句提醒"批准后要直接开始实施，可以在同一句话里说'批准并开始实施'"；批准后需求生效，批准结果写明已授权实施；主代理接着建工作区并派 PM，派出成功。

### P0：作为用户，我只说了"批准"时，想马上知道还没授权实施，以便决定要不要现在开工

**用例（主路径）**
- 场景：同上，用户只回复"批准这一版"（@ 到这个需求）。
- 操作：主代理登记批准。
- 预期：需求生效；批准结果写明没有授权实施；主代理告诉用户"需求已生效，还没授权实施；要开始实施请说'授权实施'"；主代理没有建工作区，也没有派 PM。

**用例（异常）**
- 场景：需求已生效、批准清单里没有实施，主代理仍然去派 PM。
- 操作：主代理调用派出 PM。
- 预期：派出被拒，原因是"批准清单没有实施授权"，建议是请用户在主窗口说要实施，再用补授权登记。

## 约束
- 主代理请用户批准需求时，在展示草稿要点之后提醒一句：批准后要直接开始实施，可以在同一句话里说"批准并开始实施"。
- 登记批准成功后，返回给主代理的结果写明这次批准有没有授权实施：批准原话明确授权了实施时写"已授权实施"，否则写"没有授权实施"。
- 批准结果写明没有授权实施时，主代理不建工作区、不派 PM，直接告诉用户需求已生效但还没授权实施，要开始实施就说"授权实施"。
- 派出 PM 因批准清单里没有实施而被拒时，给主代理的建议是：请用户在主窗口说要实施，再用补授权登记。
- 批准原话明确授权了实施（如"批准并开始实施"）时，批准清单里有实施，派出 PM 成功（现有行为，保持不变）。

## 验收
- [ ] 主代理的规矩里，请用户批准那一条写有"批准后要直接开始实施，可以在同一句话里说'批准并开始实施'"的提醒要求；真实模型验收里，主代理请批准的回复包含这句提醒的意思（含"实施"二字）。
- [ ] 批准原话"批准并开始实施" → 登记结果里写"已授权实施"；批准原话"批准这一版" → 登记结果里写"没有授权实施"。
- [ ] 主代理的规矩写明：批准结果没有授权实施时，不建工作区、不派 PM，告诉用户还没授权实施、要开始实施就说"授权实施"；真实模型验收里，用户只说"批准这一版"后，主代理没有调用建工作区和派出 PM，回复里告诉用户还没授权实施。
- [ ] 批准清单没有实施时派出 PM → 被拒，原因"批准清单没有实施授权"，建议文字指向在主窗口说要实施、用补授权登记。
- [ ] 批准原话"批准并开始实施" → 批准清单里有实施，派出 PM 成功。

## 验证路径
1. 新建一个需求草稿，看主代理请批准的回复 → 有"批准并开始实施"的提醒。
2. 用户回复"批准这一版"（@ 到需求） → 登记结果写"没有授权实施"；主代理告诉用户还没授权实施，没有建工作区、没有派 PM。
3. 直接调用派出 PM → 被拒，建议指向补授权。
4. 另建一个需求，用户回复"批准并开始实施" → 登记结果写"已授权实施"，派出 PM 成功。
