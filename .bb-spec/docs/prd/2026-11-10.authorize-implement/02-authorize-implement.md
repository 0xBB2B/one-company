# 补授权实施

## 用户故事
### P0：作为用户，我批准时忘了说"实施"，想说一句话补上，以便 PM 开始干活

**用例（主路径）**
- 场景：需求"跨平台 Codex 中台模型接入工具"已批准第 2 版，草稿没有再改，批准清单里没有实施。
- 操作：用户在主窗口说"需求我看过了，授权实施"（没有 @ 到需求）。
- 预期：弹出"授权实施"确认窗口；用户选"确认"后登记成功，结果写明已授权实施；批准清单里各段落的确认情况和补授权前一样，多了"实施"；主代理接着建工作区（已建就跳过）并派 PM，派出成功。

**用例（边界：@ 到了需求）**
- 场景：同上。
- 操作：用户说"@跨平台 Codex 中台模型接入工具 授权实施"。
- 预期：不弹窗，直接登记成功。

**用例（异常：没明确说要实施）**
- 场景：同上。
- 操作：用户只说"继续"，主代理去补授权。
- 预期：不登记；主代理收到原因"这句话没有明确说要实施"，建议请用户在主窗口说清楚是否要实施；这句原话作废。

**用例（异常：原话带了范围限制或修改）**
- 场景：同上。
- 操作：用户说"授权实施登录，账单以后再说"，主代理去补授权。
- 预期：不登记；原因写明这句话除了授权实施还带了范围限制或修改，补授权只能整版授权；建议把原因告诉用户，要缩小范围就先改需求草稿，再连同"实施"一起批准；这句原话作废。

**用例（异常：草稿有未批准的修改）**
- 场景：需求已批准第 2 版，之后草稿又改过、还没批准。
- 操作：用户说"授权实施"，主代理去补授权。
- 预期：不登记；原因写明草稿有未批准的修改，建议请用户把新版本连同"实施"一起批准。

**用例（边界：已经授权过）**
- 场景：这一版批准时已授权实施。
- 操作：用户又说"授权实施"，主代理去补授权。
- 预期：不弹窗、不登记，返回"这一版已经授权实施"。

**用例（异常：取消）**
- 场景：弹出"授权实施"确认窗口。
- 操作：用户选"取消"或按 Esc。
- 预期：不登记；主代理收到"用户取消了确认"。

## 约束
- 适用条件：需求已生效、当前保存的就是已批准的版本、批准清单里还没有实施。三条都满足时，用户在主窗口说一句明确要实施的话，主代理用补授权登记；成功后批准清单里有实施，结果写明已授权实施。
- 补授权不重审需求正文：成功后批准清单里每个段落的确认情况（已确认、待定、排除）与补授权前完全一致，只多了"实施"。
- 补授权只登记实施：原话里同时说了提交、推送等其他动作，也只登记实施。
- 原话没有明确说要实施（如"继续""好的"）：不登记，原因"这句话没有明确说要实施"，建议请用户在主窗口说清楚是否要实施；这句原话作废。
- 原话除了授权实施，还带了范围限制或修改（例如暂缓、排除某部分，提出未决问题，要求修改需求内容）：不登记，原因写明这句话除了授权实施还带了范围限制或修改，补授权只能整版授权；建议把原因告诉用户，要缩小范围就先改需求草稿，再连同"实施"一起批准；这句原话作废。原话里同时说了提交、推送等其他动作不算限制，照旧只登记实施。
- 草稿有未批准的修改：不登记，原因写明草稿有未批准的修改，建议请用户把新版本连同"实施"一起批准。
- 需求不在生效状态（还是草稿、已关闭或已取消）：不登记，原因写明需求不在生效状态。
- 这一版已经授权实施：不弹窗、不登记，返回"这一版已经授权实施"。
- 原话没有 @ 到需求：弹"授权实施"确认窗口，样子和现有批准需求确认窗口相同（黄色边框，选项"确认""取消"，提示行"↑↓ 选择 · 回车确认 · Esc 取消"）。内容依次是：
  - 标题"授权实施"；
  - "需求：<需求标题>（已批准第 N 版）"；
  - 灰字"编号：<需求编号> · 仓库：<仓库目录名>"；
  - 灰字"简介：<需求简介>"，没有简介时不显示这一行；
  - 空一行；
  - "确认后登记"实施"授权，PM 按已批准的第 N 版规划和派工。"
  选"确认"才登记；选"取消"或按 Esc 不登记，主代理收到"用户取消了确认"。
- 原话 @ 到了需求：不弹窗，直接登记。
- 只认用户在主窗口亲口说的话：用户在提问窗口里点选的回答不能用来补授权，补授权被拒，原因是窗口里的回答只算回答，请用户在主窗口直接说。
- 批准新版本时不沿用补授权：新版本的批准原话没说实施，新版本的批准清单里就没有实施。
- 补授权成功后，派出 PM 成功；PM 正式规划时的实施范围是已批准版本里全部已确认的实施目标段落，和批准时就授权实施的结果相同。
- 主代理的规矩：用户要补授权实施时用补授权登记，不用重新批准，也不用提问窗口；补授权成功后照规矩继续：工作区没建就先建，建好了直接派 PM。

## 验收
- [ ] 需求已生效、草稿无未批准修改、清单无实施，用户 @ 到需求说"授权实施" → 登记成功，结果写"已授权实施"，批准清单里有实施。
- [ ] 补授权成功后，批准清单里每个段落的确认情况与补授权前逐项相同。
- [ ] 原话"授权实施并推送" → 只登记实施，清单里没有推送。
- [ ] 原话"继续" → 不登记，原因"这句话没有明确说要实施"，这句原话再用来登记会被拒。
- [ ] 原话"授权实施登录，账单以后再说"（解读出实施动作之外还有暂缓、排除、未决或修改条目）→ 不登记，原因写明带了范围限制或修改、补授权只能整版授权，建议先改需求草稿再连同"实施"一起批准；批准清单不变；这句原话再用来登记会被拒。
- [ ] 草稿有未批准修改时补授权 → 不登记，原因写明草稿有未批准的修改，建议把新版本连同"实施"一起批准。
- [ ] 需求是草稿、已关闭或已取消时补授权 → 不登记，原因写明需求不在生效状态。
- [ ] 已授权实施时再补授权 → 不弹窗、不登记，返回"这一版已经授权实施"。
- [ ] 没有 @ 到需求时补授权 → 弹出确认窗口，标题、各行文字、选项和提示行与约束一致；没有简介时不显示简介行；选"确认"→ 登记成功；选"取消"或按 Esc → 不登记，主代理收到"用户取消了确认"。
- [ ] @ 到需求时补授权 → 不弹窗，直接登记成功。
- [ ] 用提问窗口里点选的回答补授权 → 被拒，原因写明窗口里的回答只算回答。
- [ ] 补授权后用户只说"批准这一版"批准新版本 → 新版本的批准清单里没有实施。
- [ ] 补授权成功后派出 PM → 成功；PM 正式规划的实施范围与批准时就授权实施的同一份需求相同。
- [ ] 主代理的规矩写明补授权的用法和成功后的下一步；真实模型验收里，用户只说"批准这一版"之后说"授权实施"，主代理用补授权登记成功并派出 PM。

## 验证路径
1. 建好并批准一个需求（原话只说"批准这一版"），确认清单里没有实施。
2. 不 @ 需求说"授权实施" → 弹出"授权实施"确认窗口，内容与约束一致；选确认 → 登记成功，段落确认情况不变，多了实施。
3. 再说一次"授权实施" → 返回"这一版已经授权实施"，不弹窗。
4. 主代理派出 PM → 成功。
5. 改草稿、保存但不批准，说"授权实施" → 不登记，提示把新版本连同"实施"一起批准。
6. 只说"批准这一版"批准新版本 → 新清单里没有实施。
