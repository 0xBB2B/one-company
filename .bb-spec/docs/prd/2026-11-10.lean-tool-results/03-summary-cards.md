# 主窗口卡片简短显示

卡片是 pi 主窗口对话流里一次工具调用或一条插入消息占的那一块。展开键是 pi 自带的快捷键（`app.tools.expand`，默认 Ctrl+O），在卡片的收起和展开两种显示之间切换。

## 用户故事

### P0：作为用户，我想要每张工具卡片一眼看出做了什么、结果如何，以便不用读 JSON

**用例（主路径）**
- 场景：主代理查了原型状态。原型「桌面接入工具安装配置原型」第 3 版在等用户确认。
- 操作：看主窗口。
- 预期：卡片第一行是粗体「原型状态」加灰色需求标题，第二行是"桌面接入工具安装配置原型：第 3 版等你确认"。不显示 `request={...}`，也不显示 JSON。

**用例（主路径）**
- 场景：检索结果送达，有 6 条结论、8 条来源、2 条没查到、3 条没核实，网页没读全，用了 13 轮。
- 操作：看主窗口。
- 预期：卡片第一行是粗体「检索结果」加灰色问题；下面两行是"完成 · 13 轮 · 结论 6 条 · 来源 8 条"和"· 没查到 2 条 · 没核实 3 条 · 网页没读全 · 编号 01a1bdf1"。不显示结论正文。

### P0：作为用户，我想要按展开键看到完整内容，以便排查问题时不用翻会话文件

**用例（主路径）**
- 场景：主代理刚修改了需求草稿，卡片收起显示"已保存 · 第 14 版"。
- 操作：按 Ctrl+O。
- 预期：摘要下面出现灰色"调用参数"和排好版的参数 JSON，再下面是灰色"完整结果"和排好版的完整结果 JSON，里面有 commit、prdHash 这些没发给模型的字段。再按一次 Ctrl+O 收起。

### P0：作为用户，我想要工具失败时一行看懂原因

**用例（边界 / 异常）**
- 场景：主代理确认一个已经通过的原型，工具失败。
- 操作：看主窗口。
- 预期：红底卡片，第一行是粗体「确认原型」加灰色原型名，第二行红字"失败：没有待你确认的版本，当前第 3 版已通过"。"建议"那一行收起时不显示，按 Ctrl+O 能看到完整报错文字。

### P1：作为用户，我想要工具还在执行时看到它在做什么

**用例（主路径）**
- 场景：主代理调了初始化项目索引，还没返回。
- 操作：看主窗口。
- 预期：灰底卡片只有标题行：粗体「初始化项目索引」加灰色仓库名。

## 约束

1. 主窗口里所有 one_company 工具（requirement_manage、user_interact、agent_manage、prototype、workflow_manage、git_deliver、project_manage、knowledge_query）的卡片，以及检索结果卡片，都按本节显示。pi 自带工具的卡片不变。「提问」卡片（user_interact 的 ask、ask-tech，含面板事项 panel-item 的提问）保持现在的样子。
2. 标题行 = 粗体动作名 + 两个空格 + 次要灰（muted）色的对象名。对象名：涉及需求的写需求标题，还没拿到标题时写"需求 <编号前 8 位>"，拿到后换成标题；涉及原型的写原型名；涉及运行的写"编号 <前 8 位>"；初始化索引写仓库目录名；查代码写"搜索「<文字>」"或"<路径或符号>"；检索写问题本身。
3. 各卡片的动作名和收起时的摘要如下表。摘要里多项信息用次要灰色的"· "隔开；运行编号只写前 8 位。

| 卡片 | 动作名 | 收起时的摘要 |
|---|---|---|
| requirement_manage · create | 新建需求 | 已创建 · 第 N 版 |
| requirement_manage · updateDraft | 修改需求草稿 | 已保存 · 第 N 版 |
| requirement_manage · read、next | 读需求 | 第 N 版 · 读了 X KB · 已读完 / 还有下一页 |
| requirement_manage · diff | 对比需求修订 | 第 A 版 → 第 B 版 · 已读完 / 还有下一页 |
| requirement_manage · metadata | 需求状态 | 草稿 / 已生效 · 第 N 版 · 还有 K 段没确认（K 为 0 时不写这一项） |
| requirement_manage · confirmUpdate；user_interact · reply | 确认更新 | 需求已生效（成功绿）· 第 N 版；没生效时写 blockedReason |
| requirement_manage · list | 列出需求 | N 个需求 |
| requirement_manage · authorizeImplement | 授权实施 | 已授权实施（成功绿）· 第 N 版；这一版之前就授权过时加"· 之前就已授权"；用户这句话里有内容没登记成决定时加"· K 处没登记成决定" |
| user_interact · adjudicate 的 reply | 登记决定 | 状态和登记结果，一行 |
| user_interact · pm-intake 的 ask、forward | 接手复核 | PM 理解已覆盖全部场景 / 还有 N 个场景没覆盖 · PM 决定 M 条（M 为 0 时不写这一项） |
| user_interact · pm-intake 的 reply | 接手复核 | 已登记 · 复核通过 / 要 PM 改正 / 要改需求 / 要请用户澄清 · 问题 K 条（K 为 0 时不写这一项） |
| agent_manage · dispatch（explore） | 派出检索 | 已派出 · 编号 xxxxxxxx · 最多 N 轮 |
| agent_manage · dispatch（pm） | 派出 PM | 已派出 · 编号 xxxxxxxx |
| agent_manage · 取检索来源 | 检索来源 | 取到 N 条来源 · 搜索词 M 个（本地检索写"读过 M 个文件"） |
| agent_manage · status | 查看运行 | 运行状态 · 第 N 轮 |
| agent_manage · pause、resume、stop、message | 暂停运行 / 续接运行 / 停止运行 / 转话给 PM | 结果状态，一行 |
| prototype · designers | 列出原型设计师 | N 位设计师 |
| prototype · dispatch | 派出原型设计 | 已派出 · 第 N 版 · 编号 xxxxxxxx |
| prototype · status | 原型状态 | 每个原型一行：<原型名>：第 N 版<在等什么>；只显示前 2 个，超过 2 个时第二行末尾加"· 还有 K 个原型" |
| prototype · confirm、remove | 确认原型 / 删除原型 | 工具返回的那句话 |
| workflow_manage · delivery-check | 需求流程 | 可以交付（成功绿）；不能交付时写"还不能交付 · <第一个卡住原因>"，卡住原因多于 1 项时末尾加"· 共 N 项" |
| workflow_manage · 其余动作 | 需求流程 / 关闭需求（close） | 关闭成功写"已关闭"（成功绿），其余写状态和下一步，一行 |
| git_deliver | 交付 | 结果状态 · PR 链接（有链接时） |
| project_manage · init、refresh | 初始化项目索引 / 刷新项目索引 | 完成 · N 个文件 · 跳过 K 个 |
| project_manage · workspace-prepare | 准备需求工作区 | 就绪 · 分支 <名>，下一行写目录 |
| project_manage · 其余动作 | 按动作取名（如"备份""恢复""更新项目规范"） | 结果状态，一行 |
| knowledge_query | 查代码 | 找到 N 条 · 已读完 / 还有下一页 |
| 检索结果消息（交了结果） | 检索结果 | 第一行：完成 · N 轮 · 结论 N 条 · 来源 N 条；第二行：· 没查到 N 条 · 没核实 N 条 · 网页没读全（截断时）· 编号 xxxxxxxx；为 0 的项不写 |
| 检索结果消息（没交结果） | 检索结果 | 红字"没有结果：<原因>" |

4. 收起时一张卡片最多 3 行（标题行 + 最多 2 行摘要）。
5. 收起时一行超出终端宽度，先截长短不定的文字，计数和状态保留，被截的那段末尾写"…"：原型状态卡片的一行在原型名和状态里截较长的那段（状态从右边截），行尾的"· 还有 K 个原型"保留；交付检查卡片截卡住原因，"还不能交付"和"· 共 N 项"保留。这些文字截到只剩"…"仍放不下时（终端很窄），整行从右边截，末尾写"…"。
6. 卡片里的文字只用正文色（text）、次要灰（muted）、成功绿（success）、错误红（error），不用 dim。
7. 工具还没返回时，卡片只有标题行。
8. 按展开键时，工具卡片在摘要下面依次显示：次要灰色"调用参数"、排好版的调用参数 JSON、次要灰色"完整结果"、排好版的完整结果 JSON（含只在留存部分里的字段）。检索结果消息展开时只显示"完整结果"和完整报告。再按一次收起。
9. 工具失败时，卡片显示标题行，下面一行错误红"失败：<原因>"，原因取自报错文字里"原因："后面那一段；展开后显示完整报告文字。检索没交结果时同样一行红字。
10. 卡片只改显示，发给模型的内容不受影响。
11. 项目根目录新增 DESIGN.md，写明本项目的终端界面规范：颜色只用 pi 主题的颜色名，色值按 pi 自带深浅两套主题记录；对话卡片的写法按本节；无障碍例外表记下 muted、accent、error、浅色 success、dim 对卡片底色对比度不到 4.5:1。

## 验收

- [ ] 1：主窗口里约束 1 列出的每个工具各调一次，卡片都不显示 `request={...}` 和 JSON；pi 自带工具卡片与改前相同；「提问」卡片与改前相同。
- [ ] 2：标题行的对象名按约束 2 显示；只有需求编号时先显示"需求 <前 8 位>"，结果回来后换成标题。
- [ ] 3：表里每一行用测试素材各渲染一次，摘要文字与表一致；为 0 的检索计数项不显示。
- [ ] 4：所有卡片收起时不超过 3 行。
- [ ] 5：终端宽 80 列时：原型名很长的原型状态卡片，名字被截短、"第 N 版<在等什么>"和"· 还有 K 个原型"完整；没交稿原因很长时，原因被截短、原型名和"· 还有 K 个原型"完整；卡住原因很长的交付检查卡片，"还不能交付"和"· 共 N 项"完整；每行不超过终端宽度。终端窄到这些文字截完仍放不下时，整行从右边截。
- [ ] 6：渲染出的卡片文字里没有用 dim 颜色。
- [ ] 7：工具执行中只渲染出标题行。
- [ ] 8：按展开键后出现"调用参数""完整结果"两段，完整结果里含留存部分的字段（如 updateDraft 的 commit）；检索结果展开后含来源摘录。再按一次恢复收起样子。
- [ ] 9：失败时卡片第二行是"失败：<原因>"，原因与报错文字里"原因："那一段一致；不显示"建议"；展开后能看到完整报错文字。
- [ ] 10：同一次调用，开关卡片显示方式（收起、展开）前后，发给模型的内容逐字相同。
- [ ] 11：项目根目录有 DESIGN.md，含 10 节，无障碍例外表有上述 5 项。
- [ ] 实际界面与确认过的预览页逐项对比一致。

## 验证路径

1. 用测试素材渲染每种卡片的收起、进行中、展开、失败四种状态 → 文字和颜色按约束 2–9。
2. 在样例项目里打开 pi 主窗口，走一遍派检索、改草稿、查原型状态、确认原型失败 → 截图和预览页逐项对比。
3. 在主窗口按 Ctrl+O → 卡片在收起和展开之间切换。
