# 设置页里设为受信任

设置页：输入 `/one:setting` 打开的页面，左栏是分类目录，右栏是选中分类的内容。「问题」：目录最后一个分类，列出写错、没生效的文件及原因；授信记录不是"信任"时，第一条是"项目还没设为受信任"（记录为空）或"项目未受信任"（记录为不信任），下文叫"授信那一条"。授信记录：pi 在 `~/.pi/agent/trust.json` 里给每个项目记的信任决定，有信任、不信任、空三种。项目：主仓库根目录；不在 Git 仓库里时是 pi 启动所在的目录。N：项目 `.pi/agents/` 下 `.md` 文件的份数。

## 用户故事
### P0：作为在新项目里用 OneCompany 的用户，我想要在「问题」里直接把项目设为受信任，以便项目层的定义当场生效

**用例（主路径）**
- 场景：项目 `~/Projects/Codex5x` 的 `.pi/agents/` 下有 5 份定义，`trust.json` 里没有这个项目。
- 操作：输入 `/one:setting`，在左栏选「问题」，按 → 进右栏，光标停在授信那一条；按回车；在弹出的窗口里选"设为受信任"。
- 预期：选中授信那一条时，按键提示是"←/Esc 回左栏  ↑↓ 选择  回车 设为受信任"，底部说明是"按回车把本项目设为受信任，项目层的 5 份定义就会生效"；按回车弹出"把这个项目设为受信任？"窗口；选"设为受信任"后 `trust.json` 里 `~/Projects/Codex5x` 为 true，设置页重新打开：顶部黄字消失，「问题」分区消失，左栏停在 worker，右栏 worker 列表里来自项目层的定义名字是绿色，底部绿字"✓ 已把本项目设为受信任，项目层的 5 份定义已生效"。

**用例（边界：取消）**
- 场景：同上。
- 操作：在确认窗口里选"取消"，或按 Esc。
- 预期：回到设置页，仍停在「问题」的授信那一条，底部灰字"已取消，授信记录没有改"；`trust.json` 不变。

**用例（异常：写授信记录失败）**
- 场景：同上，`trust.json` 所在目录没有写权限。
- 操作：在确认窗口里选"设为受信任"。
- 预期：回到设置页，仍停在「问题」的授信那一条，顶部黄字还在，底部红字"✗ 没有设为受信任：<原因>"；`trust.json` 不变。

**用例（边界：用户选过不信任）**
- 场景：`trust.json` 里这个项目为 false。
- 操作：进「问题」，光标停在授信那一条，按回车。
- 预期：和现在一样，展开详情，不弹确认窗口；按键提示是"回车 详情"或"回车 收起"；底部说明是"在 pi 里把这个项目设为受信任后，项目层的 5 份定义就会生效"。

## 约束
- C-1：授信记录为"空"、光标停在授信那一条时，按键提示是"←/Esc 回左栏  ↑↓ 选择  回车 设为受信任"（窄于 60 列时"回左栏"写成"回目录"，和其他提示一致）；底部说明是"按回车把本项目设为受信任，项目层的 N 份定义就会生效"，N 为 0 时是"按回车把本项目设为受信任，项目层的定义就会生效"。「问题」里其他行的按键提示和回车行为不变。
- C-2：授信记录为"空"时，在授信那一条上按回车，设置页关掉，弹出确认窗口，样式和设置页里按 C 复制时"复制到哪一层"的窗口一样。窗口内容依次是：标题"把这个项目设为受信任？"；"项目：<项目路径>"（家目录写成 `~`）；"设为受信任后，项目里的 .pi 设置和角色定义都会生效。"；灰字"和在 pi 里输入 /trust 选 Trust 一样，会记进 pi 的授信记录。"；两个选项"设为受信任"（说明"记进授信记录，项目层马上生效"）和"取消"（说明"不改授信记录，回到设置页"），光标默认在"设为受信任"；提示行"↑↓ 选择 · 回车确认 · Esc 取消（不改授信记录）"。窗口里不列出定义名字和文件。
- C-3：在确认窗口选"设为受信任"：按选的那一刻的授信记录处理。记录仍为"空"时，把项目在 `trust.json` 里记为 true；然后重新打开设置页，按新的授信记录读取：顶部黄字和授信那一条消失，「问题」里没有别的行时整个分区消失；焦点在左栏，选中 worker；各角色分区里来自项目层的定义名字显示为绿色，按下一个键后恢复原色；底部绿字"✓ 已把本项目设为受信任，项目层的 N 份定义已生效"，N 为 0 时是"✓ 已把本项目设为受信任"。
- C-4：选"设为受信任"那一刻授信记录已经是"信任"（例如在别的窗口里输入过 `/trust`）时，不写 `trust.json`，页面和提示同 C-3。已经是"不信任"时，不写 `trust.json`，回到设置页，仍停在「问题」的授信那一条，底部红字"✗ 没有设为受信任：你在 pi 里选过不信任这个项目，先输入 /trust 选 Trust"。
- C-5：写 `trust.json` 失败时，授信记录保持原样，回到设置页，仍停在「问题」的授信那一条，顶部黄字还在，底部红字"✗ 没有设为受信任：<原因>"，原因只取错误信息的第一行。
- C-6：在确认窗口选"取消"或按 Esc：不写 `trust.json`，回到设置页，仍停在「问题」的授信那一条，底部灰字"已取消，授信记录没有改"。
- C-7：授信记录为"不信任"时，授信那一条的行为不变：回车展开、收起详情，按键提示是"回车 详情"或"回车 收起"，底部说明是"在 pi 里把这个项目设为受信任后，项目层的 N 份定义就会生效"（N 为 0 时没有"N 份"）。
- C-8：终端宽 36 到 80 列时，本子需求新增或改动的每一行（按键提示、底部说明、确认窗口各行、成功失败取消提示）显示宽度都不超过终端宽度，放不下时折行。

## 验收
- [ ] AC-1 ← C-1：授信记录为空、项目有 5 份定义时，光标在授信那一条上，按键提示和底部说明是约束里的写法；0 份定义时底部说明没有"N 份"；光标移到「问题」里另一行时，按键提示是"回车 详情"。
- [ ] AC-2 ← C-2：授信记录为空时在授信那一条上按回车，弹出的窗口标题、各行文字、两个选项及说明、默认光标、提示行都是约束里的写法，窗口里没有定义名字。
- [ ] AC-3 ← C-3：选"设为受信任"后，`trust.json` 里项目为 true；重新打开的设置页没有黄字、没有「问题」分区（只有授信那一条时）、焦点在左栏 worker、项目层定义名字为绿色、底部绿字是约束里的写法；按一个键后绿色消失；「问题」里还有写错的文件时，分区还在、授信那一条消失。
- [ ] AC-4 ← C-4：窗口打开期间把 `trust.json` 里项目改成 true，再选"设为受信任"，`trust.json` 内容不变、页面同 AC-3；改成 false，再选"设为受信任"，`trust.json` 仍为 false、底部红字是约束里的写法。
- [ ] AC-5 ← C-5：`trust.json` 写不进去时，授信记录仍为空，设置页停在授信那一条，黄字还在，底部红字"✗ 没有设为受信任：<原因第一行>"。
- [ ] AC-6 ← C-6：在窗口里选"取消"、按 Esc，`trust.json` 都不变，设置页停在授信那一条，底部灰字"已取消，授信记录没有改"。
- [ ] AC-7 ← C-7：授信记录为 false 时，在授信那一条上按回车展开详情、再按回车收起，不弹窗口，按键提示和底部说明是约束里的写法。
- [ ] AC-8 ← C-8：36、44、60、80 列下，上面这些画面每一行都不超过终端宽度。

## 验证路径
1. 新建临时 Git 项目，`.pi/agents/` 下放 5 份定义，`trust.json` 里没有它 → 打开 `/one:setting`，进「问题」，看按键提示和底部说明（AC-1）。
2. 按回车 → 看确认窗口（AC-2）；按 Esc → 看灰字，`trust.json` 不变（AC-6）。
3. 把 `trust.json` 所在目录设为只读，再选"设为受信任" → 看红字，记录不变（AC-5）；恢复权限。
4. 再选"设为受信任" → 看重新打开的页面和 `trust.json`（AC-3）。
5. 把 `trust.json` 里这一项改成 false，重开 → 回车只展开详情（AC-7）。
6. 把终端拉到 36、44、60 列重复上面的画面 → 每行不超宽（AC-8）。
