# 启动时问授信

授信记录：pi 在 `~/.pi/agent/trust.json` 里给每个项目记的信任决定，有信任、不信任、空三种。项目：主仓库根目录；不在 Git 仓库里时是 pi 启动所在的目录。项目层定义：项目 `.pi/agents/` 下的 `.md` 文件，授信记录为"信任"时才被 OneCompany 加载。N：项目层定义的份数。pi 会问授信的文件：pi 启动时发现了就弹自己授信窗口的那些文件，即 pi 启动所在目录里的 `.pi/settings.json`、`.pi/mcp.json`、`.pi/extensions`、`.pi/skills`、`.pi/prompts`、`.pi/themes`、`.pi/SYSTEM.md`、`.pi/APPEND_SYSTEM.md`，以及这个目录或它上级目录里的 `.agents/skills`。

## 用户故事
### P0：作为 clone 了一个带角色定义的项目的用户，我想要启动 pi 时就被问信不信任这个项目，以便知道项目里的定义要授信才生效

**用例（主路径：信任）**
- 场景：项目 `~/Projects/Codex5x` 的 `.pi/` 下只有 `agents/`，里面 5 份定义；`trust.json` 里没有这个项目。
- 操作：在这个项目里启动 pi；在弹出的窗口里选"信任"。
- 预期：启动后弹出"要信任这个项目吗？"窗口；选"信任"后 `trust.json` 里这个项目为 true，主窗口出绿字"✓ 已把本项目设为受信任，项目层的 5 份定义已生效"；接着输入 `/one:setting`，没有黄字，5 份定义出现在各自分区；退出再启动，不再弹窗。

**用例（主路径：不信任）**
- 场景：同上。
- 操作：启动 pi，在窗口里选"不信任"。
- 预期：`trust.json` 里这个项目为 false；主窗口出灰字"已把本项目记为不信任，项目层的定义不加载；要改时在 pi 里输入 /trust"；退出再启动，不再弹窗。

**用例（主路径：以后再说）**
- 场景：同上。
- 操作：启动 pi，在窗口里选"以后再说"，或按 Esc。
- 预期：`trust.json` 不变；主窗口出灰字"这次没有加载项目层的 5 份定义，下次启动 pi 时再问"；退出再启动，又弹出窗口。

**用例（边界：pi 自己已经问过）**
- 场景：项目里同时有 `.pi/agents/` 和 `.pi/settings.json`，`trust.json` 里没有这个项目。
- 操作：启动 pi，在 pi 自带的授信窗口里选"Trust (this session only)"。
- 预期：OneCompany 的窗口不弹。

**用例（边界：没有定义的项目）**
- 场景：项目里没有 `.pi/agents/`，或里面没有 `.md` 文件；`trust.json` 里没有这个项目。
- 操作：启动 pi。
- 预期：不弹窗。

**用例（异常：写授信记录失败）**
- 场景：同主路径，`trust.json` 所在目录没有写权限。
- 操作：启动 pi，选"信任"。
- 预期：主窗口出红字"✗ 没有记下你的选择：<原因>"；`trust.json` 不变；下次启动还会弹窗。

## 约束
- C-1：同时满足下面五条时弹窗，少一条都不弹：pi 刚启动（`/new`、`/resume`、`/fork`、`/reload` 不算）；pi 有界面（print、JSON、RPC 模式和 OneCompany 派出的子代理都没有界面）；项目的授信记录为"空"；项目层定义至少 1 份；pi 启动所在目录里没有 pi 会问授信的文件。
- C-2：窗口样式和设置页里按 C 复制时"复制到哪一层"的窗口一样。窗口内容依次是：标题"要信任这个项目吗？"；"项目：<项目路径>"（家目录写成 `~`）；"项目里有角色定义，项目受信任后才会生效。"；灰字"你的选择会记进 pi 的授信记录，和在 pi 里输入 /trust 一样。"；三个选项"信任"（说明"项目层马上生效，以后不再问"）、"不信任"（说明"项目层不加载，以后不再问；要改时输入 /trust"）、"以后再说"（说明"这次不加载，下次启动 pi 时再问"），都不标推荐，光标默认在"信任"；提示行"↑↓ 选择 · 回车确认 · Esc 以后再说"。窗口里不列出定义名字和文件。
- C-3：选"信任"：项目在 `trust.json` 里记为 true；主窗口出绿字"✓ 已把本项目设为受信任，项目层的 N 份定义已生效"；这次会话里之后打开的设置页、启动的 PM 和派出的子代理都按"信任"读取项目层。
- C-4：选"不信任"：项目在 `trust.json` 里记为 false；主窗口出灰字"已把本项目记为不信任，项目层的定义不加载；要改时在 pi 里输入 /trust"。
- C-5：选"以后再说"或按 Esc：不写 `trust.json`；主窗口出灰字"这次没有加载项目层的 N 份定义，下次启动 pi 时再问"。
- C-6：选"信任"或"不信任"后写 `trust.json` 失败：授信记录保持原样；主窗口出红字"✗ 没有记下你的选择：<原因>"，原因只取错误信息的第一行。
- C-7：终端宽 36 到 80 列时，窗口的每一行和 C-3 到 C-6 的提示显示宽度都不超过终端宽度，放不下时折行。

## 验收
- [ ] AC-1 ← C-1：五个条件都满足时弹窗；分别去掉其中一条（`/new` 或 `/resume` 进入、没有界面、授信记录为 true 或 false、`.pi/agents/` 为空或不存在、项目里有 `.pi/settings.json`、上级目录有 `.agents/skills`），都不弹窗。
- [ ] AC-2 ← C-2：窗口标题、各行文字、三个选项及说明、默认光标、提示行都是约束里的写法，没有"推荐"字样，没有定义名字。
- [ ] AC-3 ← C-3：选"信任"后 `trust.json` 里项目为 true，绿字是约束里的写法；接着打开 `/one:setting` 没有黄字，项目层定义出现在列表里；再启动不弹窗。
- [ ] AC-4 ← C-4：选"不信任"后 `trust.json` 里项目为 false，灰字是约束里的写法；再启动不弹窗。
- [ ] AC-5 ← C-5：选"以后再说"和按 Esc，`trust.json` 都不变，灰字是约束里的写法；再启动又弹窗。
- [ ] AC-6 ← C-6：`trust.json` 写不进去时选"信任"，记录仍为空，红字"✗ 没有记下你的选择：<原因第一行>"。
- [ ] AC-7 ← C-7：36、44、60、80 列下，窗口和提示每一行都不超过终端宽度。

## 验证路径
1. 新建临时 Git 项目，`.pi/agents/` 下放 5 份定义，`trust.json` 里没有它 → 启动 pi，看窗口（AC-1、AC-2）。
2. 按 Esc → 看灰字，`trust.json` 不变；退出再启动 → 又弹窗（AC-5）。
3. 选"不信任" → 看灰字和 `trust.json`；退出再启动 → 不弹窗（AC-4）。
4. 删掉 `trust.json` 里这一项，启动选"信任" → 看绿字、`trust.json`、`/one:setting`（AC-3）。
5. 删掉这一项，在项目里加 `.pi/settings.json` 再启动 → 只弹 pi 自己的窗口（AC-1）。
6. 删掉 `.pi/settings.json` 和 `.pi/agents/` 下所有文件再启动 → 不弹窗（AC-1）。
7. 把 `trust.json` 所在目录设为只读，恢复 `.pi/agents/`，启动选"信任" → 看红字（AC-6）；恢复权限。
8. 把终端拉到 36、44、60 列重复第 1 步 → 每行不超宽（AC-7）。
