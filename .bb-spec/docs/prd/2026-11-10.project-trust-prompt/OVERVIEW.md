# 项目授信入口

授信记录：pi 在 `~/.pi/agent/trust.json` 里给每个项目记的信任决定，从主仓库根目录往上找最近的一条：true 是"信任"，false 是"不信任"，一条都没有是"空"。项目层：存在项目 `.pi/` 下、只对这个项目生效的角色定义和设定，授信记录为"信任"时才生效。项目层定义：项目里 `.pi/agents/*.md` 这些角色定义。

## 背景与问题
- 项目里有 `.pi/agents` 角色定义、授信记录为"空"时，设置页顶部黄字写"项目还没设为受信任"，「问题」里也有一条，但这一条按回车只能展开详情，底部说明让用户回 pi 里去设。用户看到了问题却不能当场解决，只能先知道 pi 有 `/trust` 命令，退出设置页再去输。
- 现在设为受信任只有一条路：在设置页把设定存到项目层、或把定义复制到项目层时顺带设。只想让项目里已有的定义生效、不想存任何东西的用户，没有直接的入口。
- pi 只在项目里有 `.pi/settings.json`、`.pi/skills` 这类文件时才在启动时问授信，只带 `.pi/agents` 的项目 pi 不问。比如从别人那里 clone 来的项目带着角色定义，用户不打开设置页，就不知道这些定义没有生效。

## 目标
- 授信记录为"空"时，用户在设置页「问题」里选中未受信任那一条按回车，确认后当场把项目设为受信任，页面马上按受信任显示。
- 启动 pi 时，项目里有角色定义、授信记录为"空"、pi 自己又不会问的情况下，弹窗问用户信不信任这个项目。

## 非目标
- 改"项目层什么时候生效"的规则：仍然只有授信记录是"信任"时项目层才生效。
- 授信记录为"不信任"时提供改回信任的入口：用户在 pi 里明确选过不信任，仍然要用户自己在 pi 里输入 `/trust` 改。
- 在确认窗口和启动弹窗里逐个列出会生效的文件和定义。
- 在完全没有 `.pi/agents` 定义的项目里启动时弹窗。
- 改 pi 自己的授信弹窗和 `/trust` 命令。

## 依赖与交付顺序
01 和 02 互不依赖，可以同时做。

## 整体验证路径
1. 准备一个 Git 项目，`.pi/` 下只有 `agents/acme-worker.md`，`trust.json` 里没有它 → 在这个项目里启动 pi，弹出"要信任这个项目吗？"窗口。
2. 按 Esc → 主窗口出灰字"这次没有加载项目层的 1 份定义，下次启动 pi 时再问"，`trust.json` 不变。
3. 输入 `/one:setting`，进「问题」，选中"项目还没设为受信任"那一条 → 按键提示是"回车 设为受信任"；按回车 → 弹出"把这个项目设为受信任？"窗口。
4. 选"设为受信任" → 设置页重新打开，黄字和「问题」分区消失，左栏停在 worker，底部绿字"✓ 已把本项目设为受信任，项目层的 1 份定义已生效"，`trust.json` 里这个项目为 true。
5. 退出 pi 再启动 → 不再弹授信窗口。

## 决策记录
- **质疑结论**：不改的话，项目层定义没生效时，用户只能先知道 pi 有 `/trust` 命令、离开设置页手动设一次；clone 来的带定义的项目，用户可能一直不知道定义没生效。值得改（用户 2026-11-10 决定）。
- **设置页「问题」里按回车直接设为受信任**（用户 2026-11-10 提出）：「问题」已经指出了项目没受信任，就应该能在这里当场解决。2026-10-26 那次只在"选项目层保存或复制"时顺带授信，它的非目标只排除了设置页以外的入口，这次在设置页里加入口不违背它。
- **只在授信记录为"空"时可以这样设，"不信任"保持现状**（用户 2026-11-10 从两个方案里选定）：和 2026-10-26 的决定一致，用户在 pi 里明确选过不信任的项目，设置页不替用户改。被否决的：两种状态都能按回车设为受信任，相当于在设置页放一个 `/trust` 入口，会覆盖用户在 pi 里做过的明确选择。
- **按回车先弹确认窗口，确认后才写授信记录**（用户 2026-11-10 决定）：设为受信任后项目里已有的 `.pi` 设置和角色定义都会生效，pi 下次启动还会加载项目里的扩展。一按就设，clone 来的陌生项目会在用户没看清时被放行。被否决的：按了直接设。
- **确认窗口和启动弹窗只写项目路径和一句说明，不逐个列出会生效的东西**（用户 2026-11-10 看完第 1 版预览后决定）：授信是对整个项目的决定，用户只需要知道是哪个项目、同意信任它。第 1 版预览列出了定义名单，以及 `.pi/settings.json`、`.pi/skills`、`.pi/extensions`、`.pi/mcp.json` 这些文件，被否决。代价是窗口里不再单独提醒"扩展会运行代码"。
- **启动时也问，推翻 2026-10-26 那份 PRD 的非目标"不在设置页以外的地方加'信任这个项目'的入口"**（用户 2026-11-10 提出）：只带 `.pi/agents` 的项目 pi 不会问授信，用户不打开设置页就不知道定义没生效。
- **启动弹窗只在项目里有 `.pi/agents` 定义时弹**（用户 2026-11-10 从两个方案里选定）：完全空的项目设不设受信任对 OneCompany 没有影响，用户第一次把东西存到项目层时会顺带设好，在这种项目里弹窗是白打扰。被否决的：每个授信记录为空的项目都问。
- **pi 自己会问授信的项目，启动弹窗不弹**：pi 1.5.0 文档（`docs/security.md`「Resources protected by project trust」）写明，项目里有 `.pi/settings.json`、`.pi/mcp.json`、`.pi/extensions`、`.pi/skills`、`.pi/prompts`、`.pi/themes`、`.pi/SYSTEM.md`、`.pi/APPEND_SYSTEM.md` 或 `.agents/skills` 时，pi 启动时会弹自己的授信窗口。pi 的窗口里有"只信任这一次"的选项，选了不写授信记录（`dist/core/trust-manager.js` 的 `getProjectTrustOptions`）；只看记录为空就弹，用户刚在 pi 窗口里选完又会被问一遍。
- **启动弹窗三个选项：信任 / 不信任 / 以后再说**（用户 2026-11-10 从两个方案里选定）：前两个写进授信记录、以后不再问；"以后再说"和 Esc 不写记录，下次启动再问。和 pi 自带授信窗口的记录方式一致。被否决的：只有"信任 / 以后再说"，不想信任的项目每次启动都会被问。
- **启动弹窗三个选项都不标推荐**（用户 2026-11-10 确认预览）：是否信任一个项目只能由用户判断，程序不替用户推荐。
- **设为受信任成功后左栏停在 worker，取消时底部写"已取消，授信记录没有改"**（用户 2026-11-10 确认预览）。
- **界面按确认过的预览实现**（用户 2026-11-10 确认第 2 版预览）。
- **写入的信任来自用户在窗口里当场的选择**：符合"旧流程与旧记录不产生授权"，和在 pi 里输入 `/trust` 选 Trust 的效果一样，记在主仓库根目录这一项上。
