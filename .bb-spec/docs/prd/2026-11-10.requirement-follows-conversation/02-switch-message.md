# 切换后在对话里说一声

本文用到的词：

- 对话线：pi 主会话里从对话开头走到当前位置的那一条路线。回到某一步再继续就多出一条新线。
- 跟线内容：草稿需求要跟着对话线走的全部内容，包括标题、正文、简介、短决定、待答提问、批准清单、原型、DESIGN.md、AGENTS.md。
- 程序消息：扩展程序往 pi 对话里插入的一条消息，用 pi 自带的默认样式显示：紫色底框，第一行是加粗的紫色方括号消息类型，下面是灰色正文。用户和主代理看到的是同一条。

## 用户故事

### P0：作为写需求的用户，我想换对话线后马上知道需求变成了哪一版，以便确认我回到了想要的版本

**用例（主路径）**
- 场景：「订单导出」保存到版本 10，用户按两次 Esc 回到版本 5 那一步。
- 操作：选好那一步。
- 预期：对话最后出现一条程序消息，第一行 `[one-company.requirement-restore]`，正文一行 `「订单导出」已恢复至版本 5`；主代理不因为这条消息自动回复。

**用例（多个需求、三种结果）**
- 场景：换到的线上，「订单导出」要恢复到版本 5，「会员积分」已批准，「消息通知」恢复失败。
- 操作：换线。
- 预期：一条消息里依次是三块，块与块之间空一行：
  ```
  「订单导出」已恢复至版本 5

  「会员积分」已批准，以库里的版本 14 为准

  「消息通知」没能恢复至版本 3，仍是版本 6
  - 原因：需求自己的 Git 仓库里找不到版本 3 那次保存的提交
  - 下一步：主代理先读取库里的内容再操作；要用回版本 3，让主代理照对话里的内容重新保存一次
  - 运行日志：~/.pi/agent/one-company/repos/<仓库>/logs/<启动编号>.log
  ```

**用例（什么都没变）**
- 场景：用户回到的那一步和当前用的是同一个版本，原型、决定也都一样。
- 操作：换线。
- 预期：不插消息。

## 约束

1. 换线（回到某一步、`/fork`、`/resume`、启动时 `pi -c` 或 `pi --session`）以后，只要有一个需求在本窗口里用的跟线内容变了，或者有已批准的需求在这条线上停在批准之前，或者有需求恢复失败，就在对话最后插入一条程序消息。这几种都没有时不插。
2. 启动时用 `pi -c`、`pi --session` 接着旧对话，"变了"指这条线上的跟线内容和这个需求最近保存的那一份不同。
3. 消息类型是 `one-company.requirement-restore`。插入后主代理不自动开始新一轮。
4. 每个需求一块，块与块之间空一行。顺序：已恢复的在前，已批准的其次，没能恢复的最后；同一种里按需求在这条线上最后一次保存的先后排。
5. 已恢复的需求只写一行：`「<需求标题>」已恢复至版本 <N>`。N 是这条线上最后一次保存时主代理看到的版本号。不列出正文、短决定、原型具体变了什么。
6. 已批准、在这条线上停在批准之前的需求，只写一行：`「<需求标题>」已批准，以库里的版本 <M> 为准`。M 是库里这个需求当前的版本号。
7. 没能恢复的需求，第一行写 `「<需求标题>」没能恢复至版本 <N>，仍是版本 <M>`，M 是本窗口现在用的那一份（最近保存的那一份）的版本号；下面三行列表依次写：`原因：<哪一步、为什么失败>`、`下一步：<建议怎么做>`、`运行日志：<日志文件路径>`。原因不写错误码。
8. 需求标题用本窗口当前这条线上的标题。

## 验收

- [ ] 约束 1：版本 10 回到版本 5，插入一条消息；回到的那一步和当前完全一样时，不插消息；只涉及已批准的需求时也插消息。
- [ ] 约束 2：另一个对话把需求保存到版本 7 后，用 `pi -c` 打开停在版本 5 的旧对话，插入"已恢复至版本 5"；旧对话停在的就是版本 7 时不插消息。
- [ ] 约束 3：消息第一行显示 `[one-company.requirement-restore]`；插入后主代理没有开始新的一轮回复。
- [ ] 约束 4：三种结果同时出现时，顺序是已恢复、已批准、没能恢复，块与块之间各空一行；两个已恢复的需求按在这条线上最后保存的先后排。
- [ ] 约束 5：已恢复的块只有一行，文字是 `「订单导出」已恢复至版本 5`。
- [ ] 约束 6：已批准的块只有一行，版本号是库里当前的版本号。
- [ ] 约束 7：恢复失败的块，第一行带两个版本号，下面依次是原因、下一步、运行日志三行，原因里没有错误码，日志路径指向真实存在的文件。
- [ ] 约束 8：两条线上标题不同，消息里用换到的那条线上的标题。

## 验证路径

1. 建需求「订单导出」保存到版本 10，两次 Esc 回到版本 5 → 对话最后出现紫色底框消息，第一行 `[one-company.requirement-restore]`，正文 `「订单导出」已恢复至版本 5`，主代理没有回复。
2. 在版本 5 的线上批准另一个需求「会员积分」，再切回版本 10 那条线（「会员积分」在这条线上还停在批准之前）→ 消息里有 `「订单导出」已恢复至版本 10` 和 `「会员积分」已批准，以库里的版本 <M> 为准` 两块，中间空一行。
3. 在当前线上原地切到同一步 → 不插消息。
