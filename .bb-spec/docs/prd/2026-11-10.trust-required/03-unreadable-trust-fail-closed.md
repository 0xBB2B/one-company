# 读不了授信记录时照常运行

授信记录：pi 在 `~/.pi/agent/trust.json` 里给每个目录记的信任决定。读不了：文件写坏、值不合法或所在目录只读，pi 读它时报错。守护进程：OneCompany 在后台常驻、负责派 PM 和子代理的进程，一个仓库一个。项目层：项目 `.pi/` 下的角色定义、设定和 skill。`<文件>`：授信记录文件路径，家目录写成 `~`。`<原因>`：错误信息的第一行。

## 用户故事
### P0：作为正在用 OneCompany 的用户，我想要 trust.json 被写坏时 OneCompany 不至于整个用不了，以便改好文件前也能继续工作

**用例（主路径：守护进程照常启动）**
- 场景：OneCompany 已启用，守护进程还没启动；这时 `trust.json` 被写成 `{"a": true,}`。
- 操作：让主代理开始一个需求，PM 派一个 worker。
- 预期：守护进程正常启动，PM 和 worker 正常派出；项目层的角色定义、设定、skill 不加载，用用户层和内置的。

**用例（主路径：Git 交付停下）**
- 场景：同上，有一个已完成关闭的需求。
- 操作：主代理调用交付工具交付这个需求。
- 预期：不推送、不合并、不建 PR；工具失败原因里写"读不了授信记录 <文件>：<原因>"，建议"改好这个文件后再交付"。

## 约束
- C-1：守护进程启动、派 PM 和子代理、读模型设定、读关闭名单、读角色目录、找 skill 时，授信记录读不了一律按不信任处理（项目层不加载），不因此报错、不退出、不拒绝派工。
- C-2：主窗口为解释器、草稿核验器选模型，以及取需求文档规范时，授信记录读不了按不信任处理（用用户层或内置），不因此报错。
- C-3：交付工具交付需求时授信记录读不了 → 不推送、不合并、不建 PR、不改任何文件，工具失败，原因写明是哪一步失败、"读不了授信记录 <文件>：<原因>"，建议"改好这个文件后再交付"。
- C-4：授信记录能读时，以上各处的行为和现在一样：信任时项目层生效，空和不信任时不生效。

## 验收
- [ ] AC-1 ← C-1：`trust.json` 写坏时拉起守护进程成功，派 PM、派带定义的 worker 成功，用的是用户层和内置的定义、设定、skill；项目层的同名定义没有被用上。
- [ ] AC-2 ← C-2：`trust.json` 写坏时解释器、草稿核验器的模型取用户层设定或跟随主会话；需求文档规范取用户层或包内默认。
- [ ] AC-3 ← C-3：`trust.json` 写坏时调用交付工具，结果为失败，原因和建议符合约束，仓库的分支、提交和远程都没有变化。
- [ ] AC-4 ← C-4：`trust.json` 为信任、空、不信任三种时，上面各处的结果和改动前一致（现有测试保护）。

## 验证路径
1. 写坏 `trust.json`，启动守护进程 → 正常启动（AC-1）。
2. 派 PM 和一个项目层与用户层都有同名定义的 worker → 用的是用户层那份（AC-1）。
3. 调用解释器、取需求文档规范 → 用的是用户层或默认（AC-2）。
4. 对一个已完成关闭的需求调用交付工具 → 失败原因符合约束，仓库没变化（AC-3）。
5. 恢复 `trust.json`，跑现有测试 → 全部通过（AC-4）。
