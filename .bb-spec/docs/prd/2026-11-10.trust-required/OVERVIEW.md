# 进项目先授信

授信记录：pi 在 `~/.pi/agent/trust.json` 里给每个目录记的信任决定，查找时从给定目录往上找最近的一条，有信任、不信任、空三种；文件写坏、值不合法或所在目录只读时读不出来，叫"读不了"。项目：主仓库根目录，不在 Git 仓库里时是 pi 启动的目录。项目层：项目 `.pi/` 下的角色定义、设定和 skill。启用 / 停用：本次 pi 会话里 OneCompany 是否运行。

## 背景与问题
- 现在 OneCompany 在没受信任的项目里也照常运行，只是项目层悄悄不生效。为了让用户知道并能补救，陆续加了一串半信任状态下的分支：设置页顶部黄字和「问题」里的授信条目、在「问题」里按回车设为受信任、选项目层时顺带授信、不信任时项目层变灰、`/one:examples` 里"未受信任"的状态、启动时只在有 `.pi/agents` 时才问授信、读不了授信记录时的各种提示。每加一个用到项目层的功能，都得再考虑一遍"没受信任时怎么办"。
- 守护进程等地方直接读授信记录，`trust.json` 写坏时守护进程装配失败，OneCompany 整个用不了。

## 目标
- OneCompany 只在授信记录为"信任"的项目里运行。启动 pi 时记录为空就弹窗问；不信任、读不了、或用户这次不用，本次会话停用，并说明原因和怎么启用。
- 删掉所有半信任状态下的界面和分支：能用 OneCompany 时，项目层总是生效。
- 授信记录读不了时，守护进程和各处照常运行，不报错退出；Git 交付停下不交付。

## 非目标
- 改 pi 自己的授信弹窗和 `/trust` 命令。
- pi 开着时授信记录变了，当场启用或停用 OneCompany：只在启动时判断，下次启动生效。
- 停用时把 `/one:` 命令从 pi 的命令列表里去掉：pi 不支持注销命令，命令保留，只回一行说明。
- 改 OneCompany 派出的子代理：子代理会话不加载扩展，不受这条规则影响。

## 依赖与交付顺序
01 → 02（02 删掉的分支依赖 01 保证"能用就一定受信任"）；03 与它们互不依赖，可以同时做。

## 整体验证路径
1. 准备一个 Git 项目，`trust.json` 里没有它 → 启动 pi，弹出"要在这个项目里使用 OneCompany 吗？"，弹窗出来前没有状态面板。
2. 按 Esc → 灰字"OneCompany 这次没有启用，下次启动 pi 时再问"；输入 `/one:setting` → 只回一行"OneCompany 在这个项目停用：项目还没授信。重开 pi 时在弹窗里选信任即可启用"，不打开页面。
3. 重开 pi，选"信任" → 绿字"✓ 已把本项目设为受信任，OneCompany 已启用"，状态面板出现；输入 `/one:setting`，没有任何授信相关的提示，"存到哪一层"里项目层直接可选。
4. 把 `trust.json` 里这一项改成 false，重开 → 不弹窗，灰字说明已选过不信任和怎么改。
5. 把 `trust.json` 写成 `{"a": true,}`，重开 → 红字"✗ OneCompany 在这个项目停用：读不了授信记录 …"。
6. 在 OneCompany 已启用的会话里把 `trust.json` 写坏，再派一个 worker → 守护进程照常派出，只是项目层定义不加载；让主代理交付一个已关闭的需求 → 交付工具报读不了授信记录、不交付。

## 决策记录
- **质疑结论**：不做的话，每个用到项目层的功能都要处理"没受信任"的情况，这几天就为此加了一串分支和提示，`trust.json` 写坏还会让守护进程起不来。规则改成"受信任才用"后，这些分支都能删掉。代价是每个新项目第一次用 OneCompany 要先授信一次；不信任的项目里完全用不了 OneCompany。值得做（用户 2026-11-10 提出并确认）。
- **授信记在主仓库根目录**（用户 2026-11-10 从两个方案里选定）：和守护进程、设置页按仓库判断的口径一致（2026-10-20 已定"按仓库现查"）；本项目的 worktree 在主仓库目录外，按启动目录记会让每个 worktree 都要单独授信。被否决的：按 pi 启动的目录记。
- **弹窗三个选项：信任 / 不信任 / 这次不用**（用户 2026-11-10 选定）：前两个写进授信记录，以后不再问；这次不用和 Esc 不写，下次启动再问。和 pi 自带授信窗口的记法一致。被否决的：只有"信任 / 这次不用"，不想用的项目每次启动都会被问。
- **已记为不信任的项目直接停用，提示怎么改**（用户 2026-11-10 选定）：尊重用户做过的明确选择。被否决的：每次启动仍弹窗问。
- **没有界面的模式里已信任才用，否则停用**（用户 2026-11-10 选定）：没法问，规则和有界面时一致，不留例外。被否决的：没有界面时照常用，那就得保留半信任分支。
- **启动时读不了授信记录就停用，红字写原因**（用户 2026-11-10 选定）：弹窗问了也写不进去。被否决的：弹窗问、选信任本次启用，守护进程读不到信任，项目层仍不生效，前后不一致。
- **只在启动时判断**（用户 2026-11-10 选定）：pi 开着时授信记录变了，本次会话的启用 / 停用不变；守护进程加载项目层时仍按当时的记录现读。被否决的：每次用工具或命令前都重新检查，每次都要读文件，正在跑的需求可能中途被卡住。
- **`/new`、`/resume`、`/fork`、`/reload` 之后不弹窗，按当时的记录启用或停用**（用户 2026-11-10 确认预览）：弹窗只在 pi 刚启动时出现。
- **读不了授信记录时 Git 交付停下报错、不交付**（用户 2026-11-10 选定）：项目层可能设了"仅本地"，按不信任退回默认方式，可能把不该推的代码推到远程。被否决的：按不信任照常交付。其他地方（守护进程、PM 模型、需求文档规范、解释器模型）读不了时按不信任照常运行。
- **停用时 `/one:` 命令保留，只回一行说明**：pi 1.5.0 的扩展接口没有注销命令的办法（`docs/extensions.md` 只有 `registerCommand`）；工具可以用 `pi.setActiveTools()` 对模型隐藏（同文档「pi.getActiveTools() / pi.getAllTools() / pi.setActiveTools(names)」一节）。
- **删掉的半信任分支**：2026-10-26 `settings-trust-and-generic-first` 的"选项目层顺带授信"、"不信任时项目层变灰"、黄字和「问题」授信条目的写法；2026-11-10 `project-trust-prompt` 的「问题」里按回车设为受信任、启动时只在有 `.pi/agents` 且 pi 不问时才弹窗；本分支前两个修复里设置页和 `/one:examples` 的"读不了授信记录"界面。新规则下 OneCompany 能运行时项目一定受信任，这些都用不上了。
- **pi 自己也会问授信的项目**：项目里有 `.pi/settings.json` 等文件时 pi 先弹自己的窗口；用户在那里选了记住的"Trust"或"Do not trust"，记录就不为空，OneCompany 不再问；选了"只信任这一次"时记录仍为空，OneCompany 会再问一次。接受这一次重复，不为它单独加判断。
- **验收和集成测试的样例项目要先写好授信记录**：验收用的主窗口是有界面的，样例项目没授信会卡在弹窗上。这是测试素材的调整，不改产品行为。
- **停用时 bash 照常可用，启用时 OneCompany 的工具全部补回，判断授信出错时停用并红字写原因**（用户 2026-11-10 决定，来自实施时的审查）：OneCompany 用自己的 bash 顶替了 pi 原版，停用时若一起藏掉，模型就没有 bash 可用，所以停用时把 bash 整个换回 pi 原版（用户 2026-11-10 从三个方案里选定：参数说明、shell、命令前缀、会话环境变量都和 pi 原版一样；被否决的：保留 OneCompany 的 bash 只把执行转给 pi，模型仍看得到"后台运行"参数，用了会卡住；放宽 PRD 不保证一致）。授信判断还没完成时执行 `/one:` 命令回"还在判断授信"（用户 2026-11-10 选定，被否决的：复用"项目还没授信"，对已受信任的项目会误导）。pi 会记住会话里移出过的工具，resume 曾经停用过的旧会话时工具会一直缺着，所以启用时把 OneCompany 的工具全部补回；代价是用户自己用 pi 的 `--tools` 关掉的 OneCompany 工具也会被打开（很少见）。判断授信的过程出错时按停用处理，不能出错放行；被否决的：出错时不提示（`/one:` 命令会误报"项目还没授信"）。
- **界面按确认过的预览实现**（用户 2026-11-10 确认）。
