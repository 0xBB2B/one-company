# 原型确认窗口的 DESIGN.md 冲突提示写准

## 背景与问题
- 原型确认窗口：设计师交来界面原型后，pi 里弹出的"确认原型"窗口。用户在这里选"通过"或"放弃这一版"，也可以在「其他（自己输入）」一行写意见。
- DESIGN.md 冲突：设计师照某一版 DESIGN.md（界面设计规范）画了原型，交稿后、用户通过前，DESIGN.md 又被改了。这时这一版不能通过，"通过"一项选不了。
- 问题一：窗口里的提示写"要通过，请在「其他」里写意见，让主代理按最新的 DESIGN.md 重派一版"。用户会以为在「其他」写一句话，这一版就能通过。实际上写意见后这一版不会通过，主代理重派设计师，新的一版交来后还要再确认一次。
- 问题二：提示里写「其他」，窗口里那一行实际叫「其他（自己输入）」，两个名字对不上。
- 问题三：提示里写"仓库根目录的 DESIGN.md 被改过"。需求内容跟着 pi 对话线走以后，比较的是当前对话线上的 DESIGN.md，没有时才用仓库根目录的，所以"仓库根目录的"不准。
- 用户确认窗口时才发现 DESIGN.md 被改过的情况，对话里的提示和交给主代理的下一步建议，也用了同样的说法。

## 目标
- 用户看到冲突提示，就知道这一版不能通过、在哪一行写意见、写了之后会发生什么。

## 非目标
- 改冲突的判断方法，以及冲突时哪些选项能选。
- 改「其他（自己输入）」一行的名字。
- 改原型确认窗口的其他文字和排版。

## 整体验证路径
1. 设计师交稿后改动 DESIGN.md，打开原型确认窗口 → 窗口最后一行写"设计师交稿后 DESIGN.md 被改过，这一版不能通过。想继续，请在「其他（自己输入）」里写意见，主代理会按最新的 DESIGN.md 重派一版，新的一版还要再确认一次。"，"通过"一项仍然选不了。
2. 窗口打开时 DESIGN.md 没变，用户选"通过"前一刻被改 → 对话里的提示和交给主代理的下一步建议都写"在窗口里选「其他（自己输入）」写意见，主代理会按最新的 DESIGN.md 重派一版，新的一版还要再确认一次"。

## 决策记录
- 用户 2026-11-12 决定修这句提示，并要求先出预览；2026-11-13 看过预览后确认"可以"。
- 文字写成"这一版不能通过。想继续，请在「其他（自己输入）」里写意见……新的一版还要再确认一次"：先说结果，再说下一步，最后说之后还要做什么。
- 去掉"仓库根目录的"，只写"DESIGN.md 被改过"：比较的对象可能是对话线上的 DESIGN.md，写具体位置反而不准，用户也不需要知道比的是哪一份。
- 原 PRD 2026-11-04.prototype-frame-soft-theme 第 03 子需求逐字规定了旧文字。它已合并、冻结不改，这次的文字以本 PRD 为准。
- 改动只换文字，不改冲突判断和选项是否能选，所以只开这一份小需求，不重写原需求。
