# 术语表

> 全项目术语唯一权威源，仅 /spec 维护。跨语言 / 跨文档以英文锚点对齐；别名按需增补，只登记实际使用过的语言写法。

| 锚点 | 定义 | 别名 |
|---|---|---|
| structured-verdict | 实现、审查或验收角色通过调用方传入的 Schema 提交、字段精确匹配且语义自洽的唯一对象 | 结构化裁决 |
| flow-agent | 只在需求、修订、对账或提交流程的既定步骤中被主 agent 调用的子代理 | 流程专用子代理 |
| review-snapshot | 提交前审查启动时记录的分支头与内容指纹，用于核对审查结果对应的正是待推送的内容 | 审查快照 |
| material-decision | 存在合理替代方案、已选定其一准备执行，且该选择会改变行为、范围、授权、架构、风险、恢复路径或流程分支的选择 | 材料性决定 |
| decision-ledger | 在本机用户数据区按仓库及需求分别保存 AI 决定与用户决定的追加式记录，一项材料性决定恰好占一行 | 决策记录 |
| product-decision | 会改变外部可观察行为、数据、安全、权限、验收标准，或无法从已确认规范与项目惯例唯一推导的选择 | 产品决策 |
| repair-round | 某个审查角色返回未通过后，由主 agent 完成一次归因、修复派发并再次调用原审查角色的完整循环 | 自动返修轮次 |
| task-file | 描述单项任务的自包含文档，包括 frontmatter 元数据及正文 | 任务文件、task 文件 |
| example-code-block | 任务文件中用于展示代码示例的围栏代码块 | 示例代码块 |
| deliverable-code-block | 任务文件中承载 DDL、API 契约或配置完整成品的围栏代码块 | 成品代码块 |
| parent-session | 用户直接交互并发起流程派工的会话 | 主会话 |
| child-run | 一次固定角色派工产生的独立会话及其运行身份、状态和结果 | 子运行 |
| run-diagnostics | 与失败子运行关联、在本机保存并经凭据脱敏的实际错误详情及必要定位信息 | 错误诊断 |
| role-settings | 按角色分别配置、在任务启动时解析生效的模型、思考等级与 MCP 服务集合 | 角色配置 |
| mcp-allowlist | 角色配置中为该角色勾选、限于宿主当前已配置服务的 MCP 服务集合，默认为空，项目列表整体覆盖全局列表 | MCP 白名单、MCP 选择、角色 MCP 集合 |
| command-namespace | 本包五个流程与设置入口共用的 /pi-spec: 前缀，不包含独立 Shell 管理命令 /ps | 命令命名空间 |
| agents-panel | 仅展示当前主会话子运行活动与控制操作的实时界面 | Agents 面板 |
| paused-run | 已确认不再推进但保留同次宿主运行内上下文和进度、可由用户手动继续的子运行 | 已暂停 |
| user-stopped-run | 用户主动终止且确认清理后的子运行终态，不提供该运行恢复或重启入口 | 用户停止 |
| execution-turn | 一次模型回复及该回复触发的工具执行，不等于模型内部推理步骤 | 执行轮次 |
| planning-preflight | 主会话在规划派工前核对需求确认、任务编辑状态、范围占用和验证条件的检查 | 规划前检 |
| task-skeleton | 完整任务正文生成前确定的行为切片、文件归属、真实依赖、切换节点与验证边界 | 任务骨架 |
| verification-contract | 每任务关于真实入口、必须成立的行为、关键场景、模拟边界及验证责任的紧凑约定 | 验证约定 |
| mechanical-validation | 只读核对任务格式、原文和集合关系而不证明业务行为正确的固定检查 | 机械检查 |
| test-credibility | 测试通过目标入口和有效断言区分行为存在与缺失，不借理想模拟绕过要验证的保护或连接 | 测试证明力、可信测试 |
| affected-regression | 本次行为变化可能影响的已有行为测试，在任务交付前按验证约定执行 | 受影响回归 |
| same-cause-defect | 不同复现共同源于同一错误假设或状态、数据、接口边界判断的问题 | 同类缺陷、同根因问题 |
| managed-shell | 经受管理入口启动的一次命令及其后代进程，绑定唯一任务身份和具体宿主；一个任务只计一个 Shell | Shell 任务、受管理 Shell |
| shell-host | 启动 Shell 的具体主会话或子运行；手动 !、!! 命令归属当前主会话 | Shell 宿主 |
| background-shell | 主或子 agent 通过 bash 的 background: true 启动、返回任务编号而不等待结束的受管理 Shell；指定的 timeout 仍约束执行寿命 | 后台 Shell、background-bash |
| shell-summary | 位于原状态栏下方、Agents 上方，显示当前主会话全部活动 Shell 总数与宿主角色分布的入口行 | Shell 汇总行 |
| shell-manager-page | /ps 与汇总行回车共用、临时替换输入栏的 Shell 列表及只读详情界面 | Shell 管理页 |
| work-range | 任务声明并获准处理的文件或目录范围，包含写入及需要稳定内容的验证保护 | 工作范围 |
| safe-handoff | 原任务不再对范围写入且交付信息可读后，新任务重新核对现场并取得该范围的交接 | 安全交接 |
| local-workflow-data | 位于 `~/.pi/agent/pi-spec/`，按仓库及需求归属的决策与运行数据，仅在本机保存而不随 Git 同步 | 本机流程数据、流程数据 |
| workflow-user-data | 本包在 `~/.pi/agent/pi-spec/` 下保存流程数据的本机用户空间，与仓库工作目录分离 | 本机用户数据区 |
| execution-metadata | 需求阶段、任务进度、子运行及提交关联、备注、运行描述、执行时间、返修轮次、阻塞原因和开发现场等非定义数据 | 运行信息、运行字段 |
| state-version | 一次已确认运行信息版本的标识，供工具拒绝依据过期内容发起的更新，不等同于代码版本或验证证据 | 状态版本 |
| repository-identity | 用于将同一 Git 仓库的各 worktree 归组并与其他仓库区分的身份，不以分支名称或需求简称代替 | 仓库身份、仓库标识 |
| requirement-identity | 仓库内单个需求的稳定归属，供文档、决策、运行信息和开发现场关联使用 | 需求身份、需求标识 |
| worktree | 同一 Git 仓库的一份独立工作目录，与其他工作目录共享仓库而可使用不同分支 | 独立工作目录 |
