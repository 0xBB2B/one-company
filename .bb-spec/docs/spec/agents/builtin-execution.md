# 内置四角色执行

## 目的
让用户只安装本包即可使用四个流程专用子代理，不必安装其他子代理系统。

## 逻辑
系统自行提供规划、实现、白盒审查和黑盒验收四个固定角色的加载与派工，每次派工使用独立的新会话。
派工成功返回唯一的运行标识，主 agent 可以查询该次运行的状态和结果；收到派工成功不等于任务已经完成。
角色只承担需求、修订、对账与提交流程中的既定职责，不接受任意自定义角色、嵌套派工或通用工作流。
符合流程阶段要求、依赖已完成且写入范围不冲突的任务可以并行，系统不另设角色级或全局并发数量上限。
宿主、模型服务或系统资源不可用时如实报告错误，不通过安装或切换到其他子代理系统继续运行。

## 约束
- C-1：在只安装本包且宿主与所需模型可用的环境中，系统应能够分别派工四个固定角色，无需加载其他子代理系统。
- C-2：当派工成功时，系统应返回唯一运行标识，并允许区分运行中、正常结束、失败、取消与中断，不得把启动成功当作任务通过。
- C-3：当多个任务满足阶段、依赖和文件不冲突条件时，系统应允许其并行，不施加角色级或全局并发数量上限；不满足条件的任务不得并行启动。
- C-4：如果角色不受支持或启动所需的宿主、模型、资源不可用，系统应报告具体失败，不启动替代角色、其他子代理系统或未经授权的执行方式。

## 例子
五个写入范围互不相交的实现任务同时就绪，系统为它们分别返回运行标识并允许并行；随后请求一个不受支持的角色，系统拒绝该请求而不影响已有任务的身份。

## 验收
### AC-1 四个角色不依赖其他子代理系统  ← C-1
- 触发: 操作 在未安装其他子代理系统的环境中分别派工规划、实现、白盒审查和黑盒验收角色
- Given: 本包已安装，宿主与模型可用，每个角色均收到符合职责的最小任务和必要输入
- When: 分别派工四个角色
- Then: 四次派工均能启动对应角色，没有要求安装或加载其他子代理系统

### AC-2 运行身份与任务通过分离  ← C-2
- 触发: 操作 连续派工两个尚未完成的角色任务并按返回标识查询
- Given: 两个任务都不会在启动时立即完成
- When: 查询各次运行
- Then: 两个标识不同，查询分别指向对应任务且显示运行中，没有把任何一次启动判为任务通过

### AC-3 并行只受任务关系约束  ← C-3
- 触发: 操作 派工五个同时就绪且写入范围不冲突的实现任务，再请求依赖未完成或写入范围冲突的任务
- Given: 宿主与模型资源充足，五个就绪任务在观察期间持续运行
- When: 观察各任务是否开始执行
- Then: 五个就绪任务均可并行执行，没有因默认数量上限排队；依赖未完成或写入范围冲突的任务没有并行启动

### AC-4 不支持的角色与启动故障不被绕过  ← C-4
- 触发: 操作 请求不受支持的角色，或在宿主不可用的环境派工
- Given: 请求尚未执行任何任务动作
- When: 系统处理请求
- Then: 返回包含具体原因的失败，没有启动其他角色或其他子代理系统
