# 内置执行

## 目的
让用户只安装本包即可派出需求代理与角色子代理，不必安装其他子代理系统。

## 逻辑
主会话派出需求代理、需求代理派出角色，都由本包在对应仓库的守护进程内创建独立会话执行。
派工成功返回唯一运行身份，可以查询状态与结果；收到派工成功不等于任务完成。
运行状态区分运行中、暂停中、已暂停、等待答复、正常结束、失败、用户停止、中断与停止不确定。
满足形状顺序、依赖已完成且写入范围不冲突的任务可以并行，不设角色级或全局并发数量上限。
守护进程、模型服务或系统资源不可用时如实报告错误，不切换到其他子代理系统或未经授权的执行方式。

## 约束
- C-1：在只安装本包且守护进程与所需模型可用的环境中，系统应能派出需求代理及角色目录内的任一角色，无需其他子代理系统。
- C-2：当派工成功时，系统应返回唯一运行身份，并允许区分运行中、暂停中、已暂停、等待答复、正常结束、失败、用户停止、中断与停止不确定，不得把启动成功当作任务通过。
- C-3：当多个任务满足形状顺序、依赖和写入范围不冲突条件时，系统应允许并行且不施加数量上限；不满足条件的任务不得并行启动。
- C-4：如果角色不可用或守护进程、模型、资源不可用，系统应报告具体失败，不启动替代角色或其他执行方式。

## 例子
需求代理为五个写入范围互不相交的任务同时派出五个 worker，各自返回运行身份并并行；随后请求一个目录外角色，系统拒绝且不影响已有运行。

## 验收
### AC-1 不依赖其他子代理系统 ← C-1
- 触发: 操作 在未安装其他子代理系统的环境派出需求代理，再由它派出四个默认角色
- Given: 本包已安装，守护进程与模型可用
- When: 观察五次派工
- Then: 均成功启动，没有要求安装或加载其他系统

### AC-2 运行身份与状态集合 ← C-2
- 触发: 操作 派出两个不会立即完成的运行并查询，再分别使其暂停、等待答复、失败与中断
- Given: 各状态可被制造
- When: 按身份查询
- Then: 两个身份不同且查询各指向对应任务；各状态如实区分，启动成功未被判为通过

### AC-3 并行只受任务关系约束 ← C-3
- 触发: 操作 派出五个就绪且写入范围不冲突的任务，再请求依赖未完成或写入冲突的任务
- Given: 资源充足
- When: 观察执行
- Then: 五个任务并行且未因数量上限排队；不满足条件的任务未并行启动

### AC-4 故障不被绕过 ← C-4
- 触发: 操作 请求目录外角色，或在模型不可用时派工
- Given: 请求尚未执行任何动作
- When: 系统处理请求
- Then: 返回具体失败原因，没有启动其他角色或执行方式
