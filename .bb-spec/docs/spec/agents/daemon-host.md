# 守护进程宿主

## 目的
让需求代理脱离单个窗口进程持续工作，同一工作区的各窗口与 worktree 共享执行现场，工作区之外互不可见。

## 逻辑
一个仓库对应一个守护进程，以仓库身份区分；窗口连接其启动目录子树内全部仓库的守护进程，在仓库或其 worktree 内启动的窗口只连接本仓库的。
首个需要派工、查询或控制的窗口自动拉起对应守护进程，已在运行时只连接，不重复启动；工作区外的窗口不连接、不可见。
守护进程直接读取本机模型配置与凭据访问模型服务，不经窗口转发，窗口关闭不影响请求。
无活动需求代理且无窗口连接持续超过空闲时限时自动退出；存在运行中、暂停中或等待用户答复的需求代理时不退出。
守护进程不可达时窗口如实显示不可达与原因，不把旧状态显示为运行中，不在窗口内降级执行派工。
守护进程崩溃、被强杀或机器重启后，其中的运行标记为中断并保留现场，不自动重跑。
合盖睡眠不是中断：唤醒后守护进程与其中会话继续；所有超时、失联与空闲计时检测时钟跳变并扣除睡眠间隔。

## 约束
- C-1：当窗口需要派工、查询或控制而目标仓库的守护进程未运行时，系统应自动启动该仓库唯一的守护进程并连接；已运行时只连接，同一仓库同一时间不得存在两个守护进程；同仓库各 worktree 与启动目录覆盖该仓库的窗口连接同一个守护进程，启动目录不覆盖该仓库的窗口不得连接。
- C-2：当守护进程执行模型请求时，系统应直接使用本机模型配置与凭据，不依赖任何窗口在线，也不把凭据写入会话记录或提示。
- C-3：当守护进程内没有运行中、暂停中或等待答复的需求代理且没有窗口连接持续超过空闲时限时，系统应让守护进程退出；任一条件不满足时应保持运行。
- C-4：如果窗口无法连接守护进程或守护进程在运行期间崩溃，系统应在窗口显示不可达及具体原因，把其中运行标记为中断并保留现场，不显示为运行中、不自动重跑、不在窗口内替代执行。
- C-5：当机器睡眠后唤醒时，系统应继续守护进程内的会话，并从 Shell 超时、结束保留、心跳失联和空闲退出等计时中扣除睡眠间隔，不因睡眠误判超时、失联或空闲。

## 例子
用户在公司窗口派出需求代理后合上笔记本；回家在同一仓库的另一个 worktree 打开新窗口，守护进程仍在运行，面板显示同一需求代理，其后台测试命令没有因为一小时睡眠而被判超时；在其他目录启动、不覆盖该仓库的窗口看不到它。

## 验收
### AC-1 每仓库单实例与共享范围 ← C-1
- 触发: 操作 在守护进程未运行时从同仓库两个 worktree 窗口几乎同时派工，再从覆盖该仓库的父目录窗口和不覆盖它的窗口分别查询
- Given: 可观察进程列表与各窗口连接目标
- When: 观察进程与四次请求结果
- Then: 目标仓库只出现一个守护进程，两次派工归属同一守护进程；父目录窗口能连接并看到该运行，不覆盖它的窗口没有连接也看不到

### AC-2 凭据不依赖窗口 ← C-2
- 触发: 操作 派出需求代理后关闭派出它的窗口，再让需求代理发起模型请求
- Given: 本机凭据有效，会话记录可检查
- When: 观察请求结果与记录内容
- Then: 请求成功完成，会话记录与提示中没有凭据明文

### AC-3 空闲退出与保持 ← C-3
- 触发: 操作 分别在有暂停需求代理、有等待答复需求代理、无需求代理但有窗口连接、无需求代理且无连接四种状态下等待超过空闲时限
- Given: 空闲时限已知且可观察守护进程存活
- When: 时限届满后检查进程
- Then: 前三种状态守护进程保持运行，第四种状态守护进程退出

### AC-4 不可达与崩溃如实显示 ← C-4
- 触发: 操作 在需求代理运行中强杀守护进程，再从窗口查询并尝试派工
- Given: 强杀前面板显示运行中
- When: 观察面板、查询结果与派工结果
- Then: 面板显示守护进程不可达及原因，原运行标记为中断且成果保留；派工返回具体失败而非在窗口内执行，重新拉起后中断运行没有自动重跑

### AC-5 睡眠不计入超时 ← C-5
- 触发: 操作 启动带 60 秒超时的后台命令并让系统睡眠 5 分钟后唤醒
- Given: 命令在睡眠前已运行 10 秒，唤醒后仍需 20 秒完成
- When: 唤醒后观察命令、面板与守护进程状态
- Then: 命令未被判超时并正常完成，窗口与守护进程未互相判为失联，守护进程未因睡眠期间空闲而退出
