# 流程专用子代理

## 目的
让规划、实现、白盒审查、黑盒验收四个子代理只承担流程职责，不被主 agent 在日常对话中随手借用。

## 逻辑
本包提供 `pi-spec.planner`、`pi-spec.worker`、`pi-spec.reviewer`、`pi-spec.acceptance` 四个子代理。它们只在需求流程、修订流程、对账流程与提交流程的既定步骤中被主 agent 调用；主 agent 在咨询、阅读、极小改动或任何未进入这些流程的场景下不得调用它们，也不得用它们替代自己完成工作。每个子代理默认沿用主会话模型，用户可在 pi 设置中按名字逐个指定模型；主 agent 调用时不覆盖模型。

## 约束
- C-1：在未进入需求、修订、对账或提交流程的对话期间，系统应不调用四个流程专用子代理中的任何一个。
- C-2：当主 agent 需要在流程之外委派工作时，系统应使用非流程专用的子代理，不得借用这四个角色。
- C-3：当流程调用四个子代理时，系统应沿用用户在设置中为该子代理指定的模型，未指定时沿用主会话模型，不得在调用时自行覆盖。

## 例子
用户在闲聊中问“这个函数是干什么的”，主 agent 自己阅读并回答，没有调用任何流程专用子代理；随后用户执行需求流程，主 agent 按流程调用 `pi-spec.planner`，模型为用户在设置里为它指定的那一个。

## 验收
### AC-1 日常对话不调用流程子代理  ← C-1, C-2
- 触发: 操作 在未进入任何流程的对话中请主 agent 解释一段代码并顺手改一个常量
- Given: 四个流程专用子代理均已加载
- When: 主 agent 完成回答与改动
- Then: 会话中没有出现对四个流程专用子代理的任何调用

### AC-2 沿用用户指定的模型  ← C-3
- 触发: 操作 在 pi 设置中为 `pi-spec.reviewer` 指定一个与主会话不同的模型，然后执行提交前审查
- Given: 其余三个子代理未指定模型
- When: 流程调用 `pi-spec.reviewer` 与 `pi-spec.worker`
- Then: 审查者以用户指定的模型运行，worker 以主会话模型运行，主 agent 的调用没有传入模型覆盖
