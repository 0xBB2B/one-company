# MCP 按角色配置接入

## 目的
让角色目录中的各角色只使用用户为其勾选的外部服务，而不自动获得宿主配置的全部 MCP 权限。

## 逻辑
每个角色的 MCP 集合来自该角色配置中勾选的服务，候选限于宿主当前已配置的服务；未勾选时该角色没有任何 MCP。MCP 能力在守护进程内该角色的会话中装载，适配器入口与配置由派出窗口探测后随派工传入。
系统只提供已勾选且当前已配置、可用的服务；被移除或禁用的已勾选服务不成为角色启动前提，也不自动替换为其他服务。
通过本包提供的 MCP 入口进行发现、查看说明或调用时，都受同一集合约束，不能利用通用入口访问未勾选的服务。
任务不依赖缺失能力时可以继续；确实需要的能力未勾选、缺失、认证失败或调用失败时，角色如实报告阻塞与未完成的验证，不虚报通过。
开放 MCP 不改变角色职责、文件读写权限或技能继承；白盒审查者不修改代码，黑盒验收者不读取源码或任务文件。

## 约束
- C-1：当系统在守护进程内为任一角色提供 MCP 能力时，系统应只开放该角色配置中勾选且当前已配置、可用的服务；未勾选的服务以及宿主新增但未勾选的服务不自动开放。
- C-2：当角色通过本包提供的 MCP 入口发现、查看或调用工具时，系统应对所有入口应用该角色的同一服务集合，集合外的服务不可通过该入口访问。
- C-3：如果已勾选服务未配置或被禁用，系统应允许不依赖它的任务启动与执行；如果任务必须使用的能力未勾选、缺失或调用失败，系统应报告具体阻塞和未完成验证，不判为已验证通过。
- C-4：当角色使用 MCP 时，系统应保持该角色既有职责及技能继承，不允许借 MCP 绕过只读审查或黑盒验收的文件访问边界。

## 例子
用户配置了 context7、chrome-devtools 和 codegraph，为 worker 勾选 context7、为 acceptance 勾选 chrome-devtools；worker 只得到 context7 入口，acceptance 只得到 chrome-devtools 入口，reviewer 未勾选则没有 MCP。另一个项目没有浏览器服务，命令行任务仍可执行；必须操作网页的验收则报告浏览器能力缺失，不提交已验证通过的结论。

## 验收
### AC-1 角色只获得勾选且可用的服务  ← C-1
- 触发: 操作 配置 context7、chrome-devtools 和 codegraph，为 worker 勾选 context7、为 acceptance 勾选 chrome-devtools，planner 与 reviewer 不勾选，再分别启动四个角色
- Given: 三个服务均可用
- When: 查看各角色可访问的 MCP 服务
- Then: worker 只可访问 context7，acceptance 只可访问 chrome-devtools，planner 与 reviewer 没有任何 MCP；没有角色自动获得 codegraph

### AC-2 通用入口不能绕过角色集合  ← C-2
- 触发: 操作 通过角色可用的 MCP 入口发现、查看或调用该角色未勾选服务的工具
- Given: 该服务已在宿主配置且已为另一角色勾选
- When: 角色请求该服务的工具
- Then: 请求没有获得集合外工具的访问能力，该服务没有因请求被调用

### AC-3 缺失服务只阻塞依赖它的任务  ← C-3
- 触发: 操作 在浏览器服务已勾选但被禁用的环境分别执行命令行任务与必须操作网页的验收，再在浏览器服务未勾选的环境执行同一验收
- Given: 命令行任务不依赖浏览器，网页验收必须通过浏览器执行
- When: 角色处理各自任务
- Then: 命令行任务可以启动并执行，网页验收在两种情况下均明确报告缺失能力及未完成验证，没有判为已验证通过；服务认证或调用失败时同样报告具体阻塞

### AC-4 MCP 不改变角色边界  ← C-4
- 触发: 操作 在开放已勾选 MCP 的情况下请求白盒审查角色修改代码，或请求黑盒验收角色读取源码与任务文件
- Given: 两个角色已获得已勾选的 MCP 能力
- When: 角色处理越界请求
- Then: 越界修改与读取均没有执行，两个角色的技能继承和原有职责没有因 MCP 开放而改变
