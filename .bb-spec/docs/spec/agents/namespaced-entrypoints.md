# 统一命令前缀

## 目的
让用户通过同一前缀发现和调用本包的所有会话命令。

## 逻辑
本包提供 /pi-company:new、/pi-company:resume、/pi-company:revise、/pi-company:sync、/pi-company:setting 和 /pi-company:ps 六个入口；后续新增命令同样使用 /pi-company: 前缀。
new 接收需求描述并开始新需求，resume 继续已有需求并支持 --verify，revise 接收问题描述并进入修复流程，sync 接收可选功能领域并核对规范与代码，setting 打开角色设置页面。
ps 打开当前窗口与工作区的终端命令任务列表，供用户查看状态和停止任务。
命令候选、帮助说明和继续操作指引使用完整命令名称；参数保持原本的含义。
入口无法加载目标流程或页面时明确报告失败，不自动转到其他入口或误报成功。

## 约束
- C-1：当用户发现或调用本包命令时，系统应提供上述六个入口，并使当前及后续新增的所有会话命令均以 /pi-company: 开头；帮助和继续操作指引使用相同名称。
- C-2：当用户调用四个流程入口时，系统应将需求描述、问题描述、--verify 或功能领域范围传给对应流程，保持其含义，不混淆流程目标或丢失参数。
- C-3：当本包注册命令时，系统应仅注册统一前缀下的入口，不提供前缀之外的别名。
- C-4：如果入口无法加载目标流程、角色设置页面或 Shell 管理页，系统应显示具体失败原因，不自动调用其他入口或报告成功。

## 例子
用户执行 /pi-company:resume --verify，继续需求并只对已完成任务重跑验证；执行 /pi-company:sync agents，核对指定功能领域；执行 /pi-company:ps，查看和停止终端命令任务。

## 验收
### AC-1 六个入口与统一前缀 ← C-1
- 触发: 操作 加载本包后打开命令候选，并查看帮助和继续操作指引
- Given: 本包已加载，pi 支持交互命令
- When: 检索本包命令
- Then: 可以发现 new、resume、revise、sync、setting 和 ps 六个入口，所有注册名称均以 /pi-company: 开头，帮助和指引与注册名称一致

### AC-2 流程路由与参数保持含义 ← C-2
- 触发: 操作 分别执行 /pi-company:new 增加订单导出、/pi-company:revise 导出内容缺失、/pi-company:resume --verify 和 /pi-company:sync agents
- Given: 对应流程所需环境已准备，继续需求的场景中存在已完成任务，核对场景中存在指定功能领域
- When: 各入口处理命令
- Then: 新需求与修复流程收到完整描述，继续需求时对已完成任务重跑验证，规范核对仅处理指定领域，没有调用错误流程或丢失参数

### AC-3 不提供前缀外别名 ← C-3
- 触发: 操作 检查本包的全部注册命令
- Given: 本包已加载，包含流程、设置和 Shell 管理入口
- When: 检索未以 /pi-company: 开头的名称
- Then: 没有本包注册的命令或别名

### AC-4 入口加载失败如实报告 ← C-4
- 触发: 操作 在目标流程、设置页面或 Shell 管理页无法加载时调用对应命令
- Given: 其他入口仍可加载，但用户没有请求它们
- When: 入口处理调用
- Then: 显示具体失败原因，没有调用其他入口或报告成功
