# 运行暂停与继续

## 目的
让用户在任意窗口暂停不需要立即执行的运行，并让断网后的运行在联网后无人值守地安全续接。

## 逻辑
用户暂停单个或全部运行时立即请求取消当前操作，阻止对应运行继续开始模型请求与工具操作；取消未确认时显示正在暂停。
暂停保留会话上下文、已确认结果、排队消息与任务进度；继续不是从起点重做，结果不明的操作继续前先只读核对。
暂停需求代理连带暂停其正在运行的角色；全部暂停覆盖本工作区全部需求代理并阻止新派工，全部继续解除。
实际连接故障只暂停受影响运行并标明网络原因；已识别的连接故障包括连接中断，以及模型响应流在扣除睡眠间隔后超过空闲阈值仍无数据；认证失败、额度不足与业务失败保持真实类别。
守护进程周期性探测连通性；恢复后对网络原因暂停的运行先只读核对再自动继续，并经中继通知主会话；手动暂停的运行不自动继续。
暂停与继续控制不依赖模型服务响应，任一窗口发起均作用于守护进程内对应运行。

## 约束
- C-1：当用户暂停一个运行时，系统应立即请求取消当前操作并阻止后续执行，确认不再继续后才显示已暂停；无法确认时显示具体原因，不假报成功；暂停需求代理时连带暂停其运行中的角色。
- C-2：当用户继续已暂停运行时，系统应保留原进度、上下文、排队消息与已确认结果，对结果不明的中断操作先只读核对，不盲目重复有副作用的操作。
- C-3：当用户全部暂停时，系统应处理本工作区全部需求代理及其角色并阻止新派工；全部继续应恢复所有已暂停运行并解除阻止；已停止或未确认暂停的运行不被继续。
- C-4：如果运行遇到已识别的连接故障（连接中断，或模型响应流在扣除睡眠间隔后超过空闲阈值仍无数据），系统应仅暂停受影响运行并标明网络原因；认证失败、额度不足及业务失败不得冒充断网。
- C-5：当守护进程探测到网络恢复时，系统应对网络原因暂停的运行先只读核对结果不明的操作，再自动继续并经中继通知主会话；用户手动暂停的运行保持暂停；探测失败不计入错误或返修轮次。
- C-6：当任意窗口发起暂停或继续时，系统应作用于守护进程内对应运行，不依赖模型服务响应，也不依赖派出窗口在线。

## 例子
用户合上笔记本，worker 的模型请求在唤醒时失败并按网络原因暂停；连上家里 Wi-Fi 后守护进程探测成功，worker 核对刚才写到一半的文件后自动继续，主会话收到"已自动恢复"。

## 验收
### AC-1 暂停须确认并连带角色 ← C-1
- 触发: 操作 暂停一个正在调用两个角色的需求代理，再对一个无法确认取消的运行暂停
- Given: 角色各有后续写入操作
- When: 系统处理暂停
- Then: 需求代理与两个角色均在确认后显示已暂停且不再写入；无法确认的运行显示正在暂停或原因

### AC-2 继续保留进度并核对 ← C-2
- 触发: 操作 对有文件修改、排队消息与未确认副作用操作的运行暂停后继续
- Given: 一个操作已完成，一个操作未返回确认
- When: 用户继续
- Then: 保留结果、文件与排队消息，先核对不明操作，不重复副作用，不从起点重做

### AC-3 全部暂停与全部继续范围 ← C-3
- 触发: 操作 在本工作区两个仓库与工作区外一个仓库均有运行时全部暂停，尝试派工，再全部继续
- Given: 另有一个已停止运行
- When: 观察各运行与派工
- Then: 本工作区运行全部暂停且派工被阻止，工作区外不受影响；全部继续恢复本工作区已暂停运行并解除阻止，已停止运行不被继续

### AC-4 故障分类 ← C-4
- 触发: 操作 分别制造连接中断、响应流超过空闲阈值无数据、认证失败、额度不足与业务失败，并对照一次跨越睡眠的响应流等待
- Given: 同时有不受影响的本地任务
- When: 系统处理
- Then: 只有连接中断与响应流空闲超时进入网络暂停并标明原因，其余保持真实类别，不受影响任务继续；跨越睡眠的等待扣除睡眠间隔后未超阈值，不进入暂停

### AC-5 联网自动续接与手动暂停例外 ← C-5
- 触发: 操作 断网使两个运行网络暂停，手动暂停第三个运行，恢复网络后观察
- Given: 其中一个网络暂停运行有结果不明的写入
- When: 守护进程探测到恢复
- Then: 两个网络暂停运行先只读核对再自动继续且主会话收到通知；手动暂停运行保持暂停；断网期间探测失败未计入错误

### AC-6 任意窗口离线可控 ← C-6
- 触发: 操作 关闭派出窗口，从另一个 worktree 窗口在模型服务不可用时暂停与继续该运行
- Given: 运行在守护进程内
- When: 观察控制结果
- Then: 控制不等待模型响应即生效，状态按守护进程真实结果更新
