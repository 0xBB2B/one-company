# 角色配置与生效范围

## 目的
让用户为四个角色选择合适的模型、思考等级与 MCP 服务，并按项目覆盖个人默认值。

## 逻辑
规划、实现、白盒审查和黑盒验收角色各自拥有模型、思考等级与 MCP 服务集合三项配置。
配置支持全局默认与当前项目覆盖；同一角色同一配置项以项目显式值优先，项目未指定时使用全局值。
未显式指定模型或选择沿用主会话时，在启动子任务时使用主会话当前模型，不由主 agent 临时另选模型。
四个角色均在没有显式思考配置时沿用任务启动时主会话的思考等级，不为规划角色设置单独固定等级；最终可用等级受有效模型支持范围约束。
MCP 服务集合在两个范围都未保存时为空；项目保存过该角色的列表时整体覆盖全局列表，不取并集。已勾选服务在宿主被移除或禁用时保留配置，任务启动时只提供当前可用的已选服务。
每次任务启动时确定自己的有效配置，之后保存配置不会中途更换该任务的模型、思考等级或 MCP 集合。
无效模型或不受支持的显式思考等级必须明确报错，不悄悄改成另一模型或另一显式等级。

## 约束
- C-1：当系统解析角色配置时，系统应对模型、思考等级与 MCP 服务集合分别应用项目显式配置优先于全局默认的规则，MCP 列表以整体覆盖而非合并方式生效，不影响其他角色或无关设置。
- C-2：当模型未显式指定或选择沿用主会话时，系统应使用任务启动时的主会话模型；四个角色均在未显式配置思考等级时沿用主会话当前等级，不固定规划角色为 medium 或把全部角色固定为 high，并依据有效模型的支持范围确定可用等级。
- C-3：当用户保存角色配置时，系统应仅对后续启动任务应用新值，不中途更换已经启动任务的模型、思考等级与 MCP 集合。
- C-4：如果显式配置的模型不可用或显式思考等级不受有效模型支持，系统应显示角色及具体原因，不静默使用其他模型或其他显式等级。
- C-5：当角色的 MCP 集合在两个范围均未保存，或已勾选服务当前不可用时，系统应分别按空集合和当前可用子集提供服务，保留原配置不自动删除，不以其他服务替代。

## 例子
全局将实现角色设为模型甲和 high，当前项目只把该角色的模型改为同样支持 high 的模型乙；当前项目启动的实现任务使用模型乙和 high，其他项目仍使用模型甲和 high。已经启动的任务保持原配置。全局为该角色勾选 context7，当前项目勾选 chrome-devtools，当前项目的实现任务只获得 chrome-devtools。

## 验收
### AC-1 项目逐项覆盖且角色相互独立  ← C-1
- 触发: 操作 保存全局实现角色的模型甲与 high，再为当前项目仅设置该角色的模型乙
- Given: 两个模型均可用且支持 high，其他角色已有独立配置
- When: 在当前项目和另一个没有覆盖配置的项目启动实现任务
- Then: 当前项目使用模型乙与 high，另一项目使用模型甲与 high，其他角色及无关设置没有变化

### AC-2 启动时解析继承与默认值  ← C-2
- 触发: 操作 在角色未显式指定模型和思考等级时分别启动四个角色
- Given: 主会话模型可用且支持 high 和 medium，各角色没有显式思考配置
- When: 先在主会话为 high 时分别启动四角色，再将主会话改为 medium 后启动新的四角色任务
- Then: 两批任务均使用启动时的主会话模型，第一批四角色均为 high、第二批均为 medium；显式选择沿用模型不改变结果，不因打开设置页或沿用而写入固定角色等级

### AC-3 保存不改变已启动任务  ← C-3
- 触发: 操作 在实现任务运行期间为该角色保存另一个有效模型、思考等级和 MCP 列表
- Given: 原任务尚未结束，新配置有效
- When: 查询原任务并在其结束后启动下一任务
- Then: 原任务保持启动时的模型、思考等级与 MCP 集合，下一任务使用新保存配置

### AC-4 无效显式配置不被悄悄替换  ← C-4
- 触发: 操作 为角色提供不可用模型，或为有效模型提供不支持的显式思考等级
- Given: 另一个模型或等级可用，但用户没有选择它
- When: 保存或使用该显式配置
- Then: 系统显示角色和具体配置错误，没有以另一个模型或等级启动该角色

### AC-5 MCP 整体覆盖、默认为空且失效项保留  ← C-1, C-5
- 触发: 操作 全局为 worker 勾选 context7 与 chrome-devtools，当前项目仅为 worker 勾选 codegraph，在宿主禁用 codegraph 前后各启动一次 worker；另启动从未保存 MCP 配置的 reviewer
- Given: 三个服务在禁用前均可用
- When: 查看各次启动的角色可用 MCP 及保存的配置
- Then: 禁用前 worker 只获得 codegraph，不合并全局的两个服务；禁用后 worker 没有可用 MCP 但配置仍保留 codegraph 且未被替换为其他服务；reviewer 没有任何 MCP
