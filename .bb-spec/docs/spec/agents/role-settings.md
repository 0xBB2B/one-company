# 角色配置与 MCP 接入

## 目的
让用户为角色目录中的每个角色（含需求代理）选择合适的模型、思考等级与外部服务，按项目覆盖个人默认值，并让角色只使用为其勾选的服务，而不自动获得宿主配置的全部 MCP 权限。

## 逻辑
角色目录中的每个角色（含需求代理）各自拥有模型、思考等级与 MCP 服务集合三项配置。
配置支持全局默认与当前项目覆盖；同一角色同一配置项以项目显式值优先，项目未指定时使用全局值。
模型未显式指定或选择沿用主会话时，任务启动时使用主会话当前模型，不由主会话临时另选模型。
所有角色在没有显式思考配置时沿用任务启动时主会话的思考等级；最终可用等级受有效模型支持范围约束。
MCP 服务集合在两个范围都未保存时为空；项目保存过该角色的列表时整体覆盖全局列表，不取并集。候选限于宿主当前已配置的服务；已勾选服务在宿主被移除或禁用时保留配置，任务启动时只提供当前可用的已选服务，不以其他服务替代。
每次任务启动时确定自己的有效配置，之后保存配置不会中途更换该任务的模型、思考等级或 MCP 集合。
无效模型或不受支持的显式思考等级必须明确报错，不悄悄改成另一模型或另一显式等级。
MCP 能力在守护进程内该角色的会话中装载，适配器入口与配置由派出窗口探测后随派工传入。角色通过本包提供的 MCP 入口发现、查看说明或调用时，都受同一集合约束，不能利用通用入口访问未勾选的服务。
任务不依赖缺失能力时可以继续；确实需要的能力未勾选、缺失、认证失败或调用失败时，角色如实报告阻塞与未完成的验证，不虚报通过。
开放 MCP 不改变角色职责、文件读写权限或技能继承；白盒审查者不修改代码，黑盒验收者不读取源码或任务文件。

## 约束
- C-1：当系统解析角色配置时，系统应对模型、思考等级与 MCP 服务集合分别应用项目显式配置优先于全局默认的规则，MCP 列表以整体覆盖而非合并方式生效，不影响其他角色或无关设置。
- C-2：当模型未显式指定或选择沿用主会话时，系统应使用任务启动时的主会话模型；所有角色在未显式配置思考等级时沿用任务启动时的主会话等级，并依据有效模型的支持范围确定可用等级。
- C-3：当用户保存角色配置时，系统应仅对后续启动任务应用新值，不中途更换已经启动任务的模型、思考等级与 MCP 集合。
- C-4：如果显式配置的模型不可用或显式思考等级不受有效模型支持，系统应显示角色及具体原因，不静默使用其他模型或其他显式等级。
- C-5：当系统在守护进程内为任一角色提供 MCP 能力时，系统应只开放该角色配置中勾选且当前已配置、可用的服务；两个范围均未保存时为空集合；未勾选的服务及宿主新增但未勾选的服务不自动开放；已勾选但当前不可用的服务保留配置不自动删除，不以其他服务替代。
- C-6：当角色通过本包提供的 MCP 入口发现、查看或调用工具时，系统应对所有入口应用该角色的同一服务集合，集合外的服务不可通过该入口访问。
- C-7：如果已勾选服务未配置或被禁用，系统应允许不依赖它的任务启动与执行；如果任务必须使用的能力未勾选、缺失、认证失败或调用失败，系统应报告具体阻塞和未完成验证，不判为已验证通过。
- C-8：当角色使用 MCP 时，系统应保持该角色既有职责、文件访问边界及技能继承，不允许借 MCP 绕过只读审查或黑盒验收的边界。

## 例子
全局将实现角色设为模型甲和 high，当前项目只把该角色的模型改为同样支持 high 的模型乙；当前项目启动的实现任务使用模型乙和 high，其他项目仍使用模型甲和 high，已经启动的任务保持原配置。用户配置了 context7、chrome-devtools 和 codegraph，全局为实现角色勾选 context7、当前项目为其勾选 chrome-devtools，并为验收角色勾选 chrome-devtools；当前项目的实现任务只获得 chrome-devtools，验收角色只得到 chrome-devtools，审查角色未勾选则没有 MCP；必须操作网页的验收在没有浏览器服务时报告能力缺失，不提交已验证通过的结论。

## 验收
### AC-1 项目逐项覆盖且角色相互独立 ← C-1
- 触发: 操作 保存全局实现角色的模型甲与 high，再为当前项目仅设置该角色的模型乙
- Given: 两个模型均可用且支持 high，其他角色已有独立配置
- When: 在当前项目和另一个没有覆盖配置的项目启动实现任务
- Then: 当前项目使用模型乙与 high，另一项目使用模型甲与 high，其他角色及无关设置没有变化

### AC-2 启动时解析继承与默认值 ← C-2
- 触发: 操作 在角色未显式指定模型和思考等级时分别启动目录中的各角色（含需求代理）
- Given: 主会话模型可用且支持 high 和 medium，各角色没有显式思考配置
- When: 先在主会话为 high 时分别启动各角色，再将主会话改为 medium 后启动新的各角色任务
- Then: 两批任务均使用启动时的主会话模型，第一批各角色均为 high、第二批均为 medium；显式选择沿用模型不改变结果，打开设置页或沿用都不写入固定角色等级

### AC-3 保存不改变已启动任务 ← C-3
- 触发: 操作 在实现任务运行期间为该角色保存另一个有效模型、思考等级和 MCP 列表
- Given: 原任务尚未结束，新配置有效
- When: 查询原任务并在其结束后启动下一任务
- Then: 原任务保持启动时的模型、思考等级与 MCP 集合，下一任务使用新保存配置

### AC-4 无效显式配置不被悄悄替换 ← C-4
- 触发: 操作 为角色提供不可用模型，或为有效模型提供不支持的显式思考等级
- Given: 另一个模型或等级可用，但用户没有选择它
- When: 保存或使用该显式配置
- Then: 系统显示角色和具体配置错误，没有以另一个模型或等级启动该角色

### AC-5 MCP 整体覆盖、默认为空且失效项保留 ← C-1, C-5
- 触发: 操作 全局为实现角色勾选 context7 与 chrome-devtools，当前项目仅为其勾选 codegraph，在宿主禁用 codegraph 前后各启动一次实现角色；另启动从未保存 MCP 配置的审查角色，并在宿主新增一个未勾选的服务
- Given: 三个服务在禁用前均可用
- When: 查看各次启动的角色可用 MCP 及保存的配置
- Then: 禁用前实现角色只获得 codegraph，不合并全局的两个服务；禁用后没有可用 MCP 但配置仍保留 codegraph 且未被替换；审查角色没有任何 MCP；新增服务没有自动开放给任何角色

### AC-6 通用入口不能绕过角色集合 ← C-6
- 触发: 操作 通过角色可用的 MCP 入口发现、查看或调用该角色未勾选服务的工具
- Given: 该服务已在宿主配置且已为另一角色勾选
- When: 角色请求该服务的工具
- Then: 请求没有获得集合外工具的访问能力，该服务没有因请求被调用

### AC-7 缺失服务只阻塞依赖它的任务 ← C-7
- 触发: 操作 在浏览器服务已勾选但被禁用的环境分别执行命令行任务与必须操作网页的验收，再在浏览器服务未勾选的环境执行同一验收
- Given: 命令行任务不依赖浏览器，网页验收必须通过浏览器执行
- When: 角色处理各自任务
- Then: 命令行任务可以启动并执行，网页验收在两种情况下均明确报告缺失能力及未完成验证，没有判为已验证通过；服务认证或调用失败时同样报告具体阻塞

### AC-8 MCP 不改变角色边界 ← C-8
- 触发: 操作 在开放已勾选 MCP 的情况下请求白盒审查角色修改代码，或请求黑盒验收角色读取源码与任务文件
- Given: 两个角色已获得已勾选的 MCP 能力
- When: 角色处理越界请求
- Then: 越界修改与读取均没有执行，两个角色的技能继承和原有职责没有因 MCP 开放而改变
