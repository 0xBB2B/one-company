# 子运行错误诊断

## 目的
让用户按运行身份查到失败时实际取得的具体原因，不必翻阅整份会话记录。

## 逻辑
子运行失败或因异常无法确认已停止时，保存与该运行关联的错误详情及必要定位信息。
详情只包含实际取得的错误说明、名称、堆栈、底层原因、错误码、状态码和请求标识，以及运行身份、模型、失败时间。最终失败或因异常无法确认已停止且发生过结构化提交时，同一详情文件另保存提交诊断：尝试数、有效数、每次调用 ID（如有）、校验或工具错误、有效及接受状态、重复投递及冲突次数；不保存提交对象正文或 SDK 错误附带的完整参数。
错误原文不因界面摘要长度限制而截断；原始错误与后续清理错误分别保留。
上游只提供简短错误或没有说明时如实标注未取得更多详情，不推断断网、不补造原因。
错误详情原样保存在本机用户数据区，与会话记录受同样的本机限定。
错误详情独立于会话记录保存，正常成功运行不新增错误详情。
按运行身份查询时可定位已保存的详情，界面保持有界摘要；重新打开宿主后仍可读取，不恢复或重跑任务。
详情保存或读取失败时明确提示，不掩盖原始失败、不伪报保存成功，不改变重试、暂停、停止或成功失败判定。

## 约束
- C-1：当子运行失败或因异常无法确认已停止时，系统应保存该运行实际取得的完整错误及必要定位信息，原文不作长度截断，原始和后续清理错误分别保留；缺少底层原因时应明确说明，不伪造或推断原因。
- C-2：当用户按运行身份查询时，系统应提供有界错误摘要及可定位的详情保存状态；已保存详情在运行结束或重新打开宿主后仍可读取，摘要截断不影响详情，也不触发任务恢复或重跑。
- C-3：如果错误详情保存或读取失败，系统应明确报告具体原因及未完整保存或无法读取状态，不覆盖原始失败、不伪报保存成功，也不改变原运行判定或增加模型与工具重试。
- C-4：当最终失败或因异常无法确认已停止的运行发生过结构化提交时，系统应在原错误详情中保存每次提交的 ID（如有）、有效及接受状态、具体错误和重复投递或冲突次数，并分开保存尝试数与有效数；后续重复提交错误不得覆盖此前尝试的错误。记录不包含提交正文或 SDK 附带的完整参数，读取时验证记录与计数，成功运行不新增诊断文件。

## 例子
某子运行失败，上游仅返回 terminated；用户按运行身份查询，看到该原文及未取得更多原因的说明，没有为了排错额外保存此前对话或全部工具输出，也没有自动重发请求。

## 验收
### AC-1 实际错误完整保留且不猜测 ← C-1
- 触发: 操作 分别让子运行以长错误、多层原因、仅 terminated、缺少说明结束，再制造原始错误之后的清理异常
- Given: 可核对上游实际返回内容，包括 4001 和 50001 字符的错误、堆栈、错误码、状态码与请求标识
- When: 按运行身份查看失败详情
- Then: 可取得字段及原文完整保留并关联正确模型和失败时间，原始及清理错误分别可查；缺失原因如实说明，没有猜测断网或伪造堆栈

### AC-2 只记错误且成功运行不新增详情 ← C-1, C-4
- 触发: 操作 在正常会话和工具内容中放入独立普通标记，在最终错误中放入普通文本与测试凭据，分别执行成功和失败运行
- Given: 可以观察新增记录与文件首次写入内容
- When: 检查诊断新增记录和对外错误展示
- Then: 失败运行的错误详情只含错误与定位信息，不含独立会话或工具标记；成功运行不新增错误详情，错误文本含凭据均原样保留

### AC-3 有界摘要及结束后查询 ← C-2
- 触发: 操作 让两个不同模型配置的子运行失败，其中一个返回超过摘要上限的错误，再正常关闭并重新打开宿主
- Given: 两个失败的错误详情均已成功保存
- When: 分别按运行身份查询摘要及完整详情
- Then: 返回可定位的正确详情和真实保存状态，摘要长度有界但完整错误未被截断，两个运行不混淆，重新打开后仍可读且没有恢复或重跑旧任务

### AC-4 保存与读取故障不掩盖原错误 ← C-3
- 触发: 操作 分别制造错误详情写入失败和已保存详情读取失败
- Given: 子运行有明确原始失败，可观察模型请求次数、工具操作次数及原运行状态
- When: 结束并查询该运行
- Then: 原始错误仍可见，详情保存或读取故障及实际状态明确，不伪报保存成功，不改变原运行判定，也没有因诊断故障新增请求或工具重试

### AC-5 提交诊断保留各次错误且不保存正文 ← C-1, C-2, C-4
- 触发: 操作 首次提交失败后纠正，再制造重复有效提交或模型异常，并重新读取失败详情；另验证纠正后正常成功
- Given: 错误中含测试凭据和长错误说明，提交正文含独立标记
- When: 按运行身份读取同一详情文件，再分别篡改尝试计数、接受状态或附加结果正文后读取
- Then: 失败详情保留各次提交 ID、错误和接受状态，计数区分尝试及有效提交，长错误与凭据原样未改、无结果正文；原始错误不被提交诊断覆盖，损坏或越界字段报告不可读；纠正后正常成功不新增诊断文件
