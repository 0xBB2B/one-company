# 会话记录持久化

## 目的
让需求代理与角色的完整过程可回看，并在守护进程重启后能原样接续。

## 逻辑
守护进程内每个需求代理与角色会话都以宿主可重载的 SQLite 会话记录保存在本机用户数据区，按仓库与运行身份归档。
记录包含对话消息、思考内容、工具调用与结果、结构化提交与错误，内容原样保存不作改写。
上下文压缩由宿主按其设置自动产生并追加为会话条目；重载时按压缩后视图重建上下文，数据库保留完整历史。
记录只在本机保存，不自动上传，不进入版本管理；其他系统用户默认不可读。
续接中断运行时从 SQLite 会话记录原样重载上下文，恢复当前分支位置，只对当前分支中没有结果的工具调用补入一条固定的"调用因守护进程中断"结果，再核对工作区后继续，不从任务起点重做。
记录随运行记录保留，不自动删除；按运行身份可定位查看页与错误详情所需内容。

## 约束
- C-1：当守护进程创建需求代理或角色会话时，系统应把该会话完整记录为可重载的 SQLite 会话记录保存在本机用户数据区，按仓库与运行身份定位；元数据和持久化条目的主键均为 UUIDv7，SDK 条目编号用于父链引用，严格顺序由流内事务序号确定。
- C-2：当记录写入时，系统应原样保存内容不作改写，数据库权限限制为当前用户，不自动上传或加入版本管理。
- C-3：当用户续接因守护进程中断的运行时，系统应从 SQLite 恢复当前分支和压缩后视图，完整历史仍保留；仅对当前分支中没有结果的工具调用补入固定中断结果，核对工作区后继续。条目和当前分支位置同事务保存，过期写入者不能覆盖已提交上下文。
- C-4：如果会话写入失败，系统应停止当前运行并报告保存失败，不继续使用未保存的历史；读取失败应拒绝续接或查看并报告原因，不改写已保存记录或已结算结果。

## 例子
守护进程在 worker 写到一半时被机器重启杀死；用户回来点续接，worker 会话从数据库重载，看到自己之前的修改与测试结果后继续，而不是重新开始。

## 验收
### AC-1 完整记录可定位 ← C-1
- 触发: 操作 运行一个需求代理及其角色，按运行身份查找记录
- Given: 会话产生了消息、工具调用与结构化提交
- When: 读取数据库记录
- Then: 两个会话各有可重载的数据库记录，内容与实际过程一致，按仓库与运行身份可定位

### AC-2 原样保存与本机限定 ← C-2
- 触发: 操作 让工具结果含测试凭据，检查数据库记录与权限，并提交推送仓库
- Given: 凭据格式可识别
- When: 检查文件内容、权限与 Git 内容
- Then: 记录中凭据原样保留，数据库及其 WAL/SHM 仅当前用户可读，提交与推送不含记录

### AC-3 重载续接 ← C-3
- 触发: 操作 在角色运行中强杀守护进程，重新拉起后由用户续接
- Given: 中断前会话已有多轮消息与文件修改，已发生过一次宿主压缩，且中断时有一次工具调用尚未返回结果
- When: 观察续接后的会话与行为
- Then: 会话上下文与中断前的压缩后视图一致，数据库仍保留压缩前全部条目，未返回的工具调用带有固定的"调用因守护进程中断"结果，核对工作区后从中断点继续，未重做已完成步骤

### AC-4 写读故障不虚报 ← C-4
- 触发: 操作 分别制造记录写入失败与读取失败
- Given: 运行状态可查询
- When: 观察报告与运行判定
- Then: 写入故障使当前运行失败且不能继续追加；读取故障明确拒绝操作，已保存历史和结算结果保持不变；均未显示保存成功
