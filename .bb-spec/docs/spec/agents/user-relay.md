# 用户对话中继

## 目的
让用户始终只与主会话对话，需求代理的提问、通知与用户的补充都经同一条通道，不因窗口关闭丢失。

## 逻辑
需求代理需要用户决策或确认时提出问题，问题带仓库与需求身份进入守护进程队列；用户的答复经主会话送回需求代理。
问题投递到本工作区所有已连接窗口（含各 worktree 与成员仓库窗口）；首个答复生效，其余窗口的同一问题撤回；工作区外的窗口不收到。
本工作区没有任何窗口连接时问题与通知排队；下一个本工作区窗口打开并连接时立即推送到该窗口主会话。
用户在主会话提出的补充需求由主会话判断归属：属于本工作区某个进行中需求时转发给对应需求代理，否则按新需求处理。
需求代理的完成、阻塞、自动恢复、契约变更请求等通知走同一通道；通知不需要答复，契约变更请求由主会话裁定后再以补充形式转发相关需求代理。
面板只展示存在待答问题的标记，不提供在面板内作答或对话的入口。

## 约束
- C-1：当需求代理提出问题时，系统应把带仓库与需求身份的问题投递到本工作区所有已连接窗口，由主会话向用户展示；首个答复送达需求代理后，其余窗口的该问题应撤回；工作区外的窗口不得收到。
- C-2：当本工作区没有窗口连接时，系统应保留问题与通知；下一个本工作区窗口连接后应立即推送给其主会话，不丢失、不重复。
- C-3：当用户在主会话提出补充时，系统应由主会话判断是否属于本工作区进行中需求并转发给对应需求代理；转发结果应回执给主会话。
- C-4：当需求代理产生完成、阻塞、自动恢复或契约变更请求等通知时，系统应经同一通道送达主会话；需求代理之间不得直接互发消息；面板只显示待答标记，不提供对话入口。

## 例子
需求代理在用户离开后提出"接口错误码采用 A 还是 B"，问题排队；用户回家在同一工作区打开新窗口，主会话立即展示该问题，用户回答后需求代理继续，公司窗口再打开时该问题已撤回。

## 验收
### AC-1 投递范围与首答生效 ← C-1
- 触发: 操作 在本工作区两个窗口与工作区外一个窗口均打开时让需求代理提问，从其中一个本工作区窗口作答
- Given: 三个窗口均已连接各自可见的守护进程
- When: 观察各窗口的展示与需求代理收到的答复
- Then: 只有两个本工作区窗口收到问题，答复送达需求代理后另一窗口的问题被撤回，工作区外窗口从未收到

### AC-2 无窗口排队与推送 ← C-2
- 触发: 操作 关闭本工作区所有窗口后让需求代理提问并产生一条完成通知，再打开一个本工作区新窗口
- Given: 守护进程持续运行
- When: 新窗口连接后观察主会话
- Then: 问题与通知各恰好推送一次，顺序与产生顺序一致，作答后需求代理继续

### AC-3 补充需求转发 ← C-3
- 触发: 操作 在主会话提出一条属于本工作区进行中需求的补充和一条全新需求
- Given: 进行中需求有活动需求代理
- When: 主会话处理两条输入
- Then: 第一条转发给对应需求代理并得到回执，第二条按新需求流程处理，没有转发

### AC-4 通知经中继且代理间不直连 ← C-4
- 触发: 操作 让一个需求代理完成需求、另一个需求代理提出契约变更请求，并让第三个需求代理尝试直接向第二个发送消息
- Given: 主会话窗口打开
- When: 观察主会话、面板与消息路径
- Then: 完成通知与契约变更请求均到达主会话；直接互发被拒绝且未送达；面板对存在待答问题的条目显示标记，没有输入或作答入口
