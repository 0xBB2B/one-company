# 用户主动停止子运行

## 目的
让用户终止不再需要的子代理，并由主会话根据实际现场决定后续工作。

## 逻辑
停止或全部停止针对当前主会话的子运行，等待会话及受管理工具进程停止并清理对应资源；清理完成前显示正在停止或具体失败，不提前进入结束灰显计时。
已产生的文件修改和必要运行记录保留，不自动撤销或删除成果。
主会话收到与运行身份对应的用户主动停止通知，不能把停止当作成功完成。
停止是旧运行的终态，不再提供继续、恢复或重启入口。
主会话后续根据任务现场和正常流程决定是否另行派工；新派工是新的子运行，不机械立即重拉。

## 约束
- C-1：当用户在 Agents 列表停止单个或全部子运行时，系统应等待对应会话及受管理工具进程停止并清理资源后才确认用户停止，操作范围仅限当前主会话，保留已有文件修改和必要证据；不能仅销毁会话对象或发出取消请求就宣称清理完成。
- C-2：当用户停止被确认时，系统应向所属主会话通知用户主动停止及对应运行身份，不将其判为任务通过，也不默认立即重新启动同一任务。
- C-3：在用户已停止的运行上，系统应不提供继续、恢复或重启功能；若主会话后续按正常流程重新派工，应产生新的独立运行身份。
- C-4：如果停止或后代进程清理无法确认，系统应显示具体不确定原因，不谎报清理完成，不启动可能重复写入的新运行。

## 例子
用户停止正在编辑的实现子代理，修改保留，主会话得知用户主动终止；面板不再提供旧运行继续按钮，主会话核对现场后再决定是否提出新的派工。

## 验收
### AC-1 停止范围与成果保留 ← C-1
- 触发: 操作 在两个窗口均有子运行时，先停止本窗口一个运行，再全部停止
- Given: 本窗口至少两个子运行已写入文件，另一个窗口也有任务
- When: 系统处理停止并核对清理结果
- Then: 清理完成后才显示用户停止并开始结束保留期，对应本窗口运行及受管理进程确实停止，其他窗口不受影响，文件和必要运行证据未被删除或回滚

### AC-2 通知真实原因而非通过 ← C-2
- 触发: 操作 用户停止一个尚未通过结果校验的子运行
- Given: 所属主会话可处理通知，任务尚未完成
- When: 停止被确认并通知主会话
- Then: 主会话得知对应运行被用户主动停止，没有按成功推进门禁，也没有仅因收到停止通知就机械重拉

### AC-3 旧运行无恢复入口 ← C-3
- 触发: 操作 检查已停止条目的可用操作，再由主会话按正常流程另行派工
- Given: 旧运行已确认用户停止，新的派工另有合法任务和范围
- When: 查看旧运行并启动后续新运行
- Then: 旧运行没有继续、恢复或重启入口，新派工身份与旧运行不同，旧记录仍保持停止终态

### AC-4 后代残留不能误报 ← C-4
- 触发: 操作 让子运行启动独立后代且中间进程迅速退出，再停止该运行
- Given: 后代仍可能执行写入，普通父子关系已变化
- When: 系统清理并报告停止结果
- Then: 后代确实停止后才报告清理完成；无法确认时显示不确定且禁止重叠新派工，不以已追踪名单为空冒充全部停止
