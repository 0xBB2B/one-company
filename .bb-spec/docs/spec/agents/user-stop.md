# 用户主动停止

## 目的
让用户在任意窗口终止不再需要的运行，并由主会话根据实际现场决定后续工作。

## 逻辑
停止作用于守护进程内指定运行；停止需求代理时连带停止其全部角色与 Shell，停止单个角色时其需求代理收到该角色被用户停止的结果。
等待会话及受管理工具进程停止并清理后才确认停止；清理完成前显示正在停止或具体失败，不提前进入结束灰显计时。
已产生的文件修改与会话记录保留，不自动撤销。
主会话经中继收到用户停止通知及运行身份，不把停止当作成功。
停止是终态，不提供继续、恢复或重启入口；需求代理的重新派出是新的运行身份。

## 约束
- C-1：当用户在任意窗口停止一个需求代理时，系统应停止其全部角色与受管理 Shell，确认清理后才显示用户停止；停止单个角色时应把该结果送达其需求代理，不能仅销毁会话对象就宣称清理完成。
- C-2：当停止被确认时，系统应保留文件修改与会话记录，并经中继向主会话通知用户主动停止及运行身份，不判为通过。
- C-3：在已停止的运行上，系统应不提供继续、恢复或重启；重新派出的需求代理应有新的运行身份。
- C-4：如果停止或后代进程清理无法确认，系统应显示具体不确定原因，不谎报清理完成，不启动可能重复写入的新运行。

## 例子
用户在家里的窗口停止公司窗口派出的需求代理，它的两个 worker 与测试进程一并停止，修改保留，主会话收到用户停止通知；面板不再提供该运行的继续按钮。

## 验收
### AC-1 连带停止与清理确认 ← C-1
- 触发: 操作 从非派出窗口停止一个正在调用两个角色且各有后台 Shell 的需求代理，再单独停止另一需求代理的一个角色
- Given: 各进程持续活动
- When: 观察清理与状态
- Then: 需求代理、两个角色与其 Shell 均确认停止后才显示用户停止；单独停止的角色结果送达其需求代理，需求代理未被停止

### AC-2 保留成果并通知 ← C-2
- 触发: 操作 停止一个已写入文件的角色
- Given: 主会话窗口打开
- When: 停止确认
- Then: 文件与会话记录保留，主会话收到含运行身份的用户停止通知，未按成功推进门禁

### AC-3 终态无恢复 ← C-3
- 触发: 操作 检查已停止条目的按钮，再由主会话重新派出同一需求
- Given: 需求仍未完成
- When: 观察面板与新运行
- Then: 已停止条目没有继续、恢复或重启入口；新运行身份与旧运行不同

### AC-4 后代残留不能误报 ← C-4
- 触发: 操作 让角色启动独立后代且中间进程退出后停止该运行
- Given: 后代仍可能写入
- When: 系统清理并报告
- Then: 后代确实停止后才报告清理完成；无法确认时显示不确定且不派出重叠新运行
