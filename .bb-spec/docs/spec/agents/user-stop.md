# 用户主动停止

## 目的
让用户在任意窗口终止不再需要的运行，并由主会话根据实际现场决定后续工作。

## 逻辑
停止作用于守护进程内指定运行；停止需求代理时连带停止其全部角色与 Shell，停止单个角色时其需求代理收到该角色被用户停止的结果。
守护进程确认收到停止请求并向会话及其受管理 Shell 发出停止后，运行即记为用户停止，这是终态；各 Shell 进程清理是否确认是 Shell 任务自身的状态，在 Shell 列表与面板条目上显示，不改变运行状态。
已停止运行的写入范围释放与重叠派工判断以登记表为准：该运行在登记表中仍有活动或清理未确认的 Shell 任务时，范围不释放，不派出可能重复写入的新运行；全部任务结束或确认清理后释放。
已产生的文件修改与会话记录保留，不自动撤销。
主会话经中继收到用户停止通知及运行身份，不把停止当作成功。
停止是终态，不提供继续、恢复或重启入口；需求代理的重新派出是新的运行身份。

## 约束
- C-1：当用户在任意窗口停止一个需求代理时，系统应向其全部角色与受管理 Shell 发出停止，守护进程确认停止请求已发出后把该运行记为用户停止；停止单个角色时应把该结果送达其需求代理；各 Shell 的清理是否确认作为 Shell 任务自身状态显示在 Shell 列表与面板条目上，不改变运行状态。
- C-2：当运行记为用户停止时，系统应保留文件修改与会话记录，并经中继向主会话通知用户主动停止及运行身份，不判为通过。
- C-3：在已停止的运行上，系统应不提供继续、恢复或重启；重新派出的需求代理应有新的运行身份。
- C-4：如果已停止运行在登记表中仍有活动或清理未确认的 Shell 任务，系统应保持其写入范围不释放，不派出与之写入范围重叠的新运行，并在 Shell 列表与面板条目显示具体不确定原因，不谎报清理完成；全部任务结束或确认清理后才释放范围。

## 例子
用户在家里的窗口停止公司窗口派出的需求代理，它的两个实现角色与测试进程收到停止后运行显示用户停止，修改保留，主会话收到用户停止通知，面板不提供该运行的继续按钮；其中一个测试进程的后代清理尚未确认，Shell 列表与面板条目显示该 Shell 待确认，与该运行写入范围重叠的新派工被拒，直到它结束。

## 验收
### AC-1 连带停止与状态归属 ← C-1
- 触发: 操作 从非派出窗口停止一个正在调用两个角色且各有后台 Shell 的需求代理，再单独停止另一需求代理的一个角色
- Given: 各进程持续活动
- When: 观察运行状态与 Shell 状态
- Then: 停止请求确认发出后需求代理即显示用户停止，两个角色与其 Shell 均收到停止；Shell 清理进度只显示在 Shell 列表与面板条目上；单独停止的角色结果送达其需求代理，需求代理未被停止

### AC-2 保留成果并通知 ← C-2
- 触发: 操作 停止一个已写入文件的角色
- Given: 主会话窗口打开
- When: 运行记为用户停止
- Then: 文件与会话记录保留，主会话收到含运行身份的用户停止通知，未按成功推进门禁

### AC-3 终态无恢复 ← C-3
- 触发: 操作 检查已停止条目的按钮，再由主会话重新派出同一需求
- Given: 需求仍未完成
- When: 观察面板与新运行
- Then: 已停止条目没有继续、恢复或重启入口；新运行身份与旧运行不同

### AC-4 后代残留不释放范围 ← C-4
- 触发: 操作 让角色启动独立后代且中间进程退出后停止该运行，再请求与其写入范围重叠的新派工
- Given: 后代仍可能写入
- When: 系统处理停止与派工
- Then: 运行显示用户停止，该 Shell 任务在列表与面板条目显示清理未确认及原因；重叠派工被拒且范围未释放；后代确实停止后范围释放、派工通过
