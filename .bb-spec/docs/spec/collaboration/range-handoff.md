# 跨窗口工作范围交接

## 目的
让多个需求并行时不相互覆盖文件，又不把局部冲突扩大为整个项目等待。

## 逻辑
主会话修改规范与需求文档、需求代理及角色修改产品文件均须声明并协调实际工作范围。
重叠文件或目录的写入同一时间只由一个任务获准，未获准的冲突任务等待，其他工作继续。
原任务在不再写入并保存必要交付信息后释放范围，不因新窗口请求就被强制打断。
新窗口接手前重新读取最新文件并核对计划，不能拿等待前的旧内容覆盖新成果。
一次工作所需的重叠范围统一协调，不能让双方各持有部分范围相互永久等待。
命令的写入范围无法静态确认时，以执行前后的内容指纹核对代替事前阻止；越界修改使本任务失败并使受影响范围的验证结论失效。
持有者失联时以可机械判定的事实判断其已停止：角色或需求代理持有的范围，在其运行进入终态，或运行为中断且 Shell 登记表无其活动任务时释放；主会话持有的范围，在该窗口登记已注销、心跳过期且开机标识已变化、或窗口进程不存在时释放。满足条件即自动释放；判定不了时保留冲突保护并显示原因，用户可显式释放并留下决策记录。

## 约束
- C-1：当多个窗口同时请求重叠写入范围时，系统应只允许一个任务取得对应写入权，适用于主会话、需求代理及角色；不重叠的任务不应因此被阻止。
- C-2：当任务等待交接时，系统应只等待冲突部分并显示受阻原因，不自动暂停、取消或抢占原任务；原任务安全释放后再允许接手。
- C-3：当新任务接手已释放范围时，系统应重新读取文件和交付信息，核对旧计划；如果文件已变化，不得直接用旧内容覆盖当前成果。
- C-4：如果持有范围的持有者失联，系统应按可机械判定的停止事实处理：角色或需求代理持有的范围在其运行进入终态，或运行为中断且 Shell 登记表无其活动任务时自动释放；主会话持有的范围在该窗口登记已注销、心跳过期且开机标识已变化、或窗口进程不存在时自动释放；任一事实都无法判定时保留冲突保护并显示原因，用户显式释放并留下决策记录后才允许交接。
- C-5：当多个任务请求交叉重叠的多个范围时，系统应避免双方各占一部分而相互等待，其他无关任务仍可推进。
- C-6：当任务执行无法静态确认写入范围的命令时，系统应在命令启动前记录其他任务所占范围的内容指纹，命令结束后核对；如果发现越界修改，应把本任务判为失败并使受影响范围的验证结论失效，不依赖口头提醒。

## 例子
甲占用文件一，乙需要文件一和文件二，丙只需要文件三；乙等待且不占住资源阻塞甲完成，丙并行。甲交付释放后乙读取最新文件并执行，甲关闭不影响交接。丙执行一条脚本时改动了甲占用的文件一，丙的任务被判失败，甲对文件一的验证结论失效。

## 验收
### AC-1 并发申请只有一个获准 ← C-1
- 触发: 操作 从两个独立窗口同时请求修改相同文件，再请求修改互不重叠的文件
- Given: 开始时没有占用，一个请求来自主会话文档操作，另一个来自需求代理派出的角色
- When: 两边同时申请并尝试写入
- Then: 重叠写入只有一方获准，没有两边先检查后都成功的竞争；不重叠文件可以同时推进

### AC-2 局部等待且不抢占 ← C-2
- 触发: 操作 在原任务写入期间启动包含冲突与不冲突部分的新需求
- Given: 原任务未到安全交接节点，新需求至少一个部分独立
- When: 新窗口推进工作并等待冲突部分
- Then: 独立部分继续，冲突部分显示等待，原任务没有被自动暂停取消；只有释放后才接手

### AC-3 接手重新核对内容 ← C-3
- 触发: 操作 在等待窗口完成初步分析后，让原任务修改文件并交付释放
- Given: 新窗口分析时的文件与交付后文件不同
- When: 新窗口接手执行
- Then: 重新读取并核对差异，没有按旧内容盲目覆盖已交付修改

### AC-4 失联持有者按停止事实释放 ← C-4
- 触发: 操作 分别让持有范围的角色运行进入终态、标记为中断且 Shell 登记表无其活动任务、标记为中断但登记表仍有其活动任务；再分别让持有范围的窗口注销登记、心跳过期且开机标识变化、窗口进程消失、心跳过期但开机标识未变且进程仍存在；最后对未释放的场景由用户显式释放
- Given: 每个场景都有新窗口请求相同范围
- When: 系统核对停止事实并处理新窗口的请求
- Then: 角色前两种与窗口前三种场景自动释放并允许接手；中断仍有活动任务与心跳过期但开机标识未变的场景保留保护并显示原因，用户显式释放后留下决策记录并允许交接

### AC-5 交叉范围不相互永久等待 ← C-5
- 触发: 操作 两个任务以相反顺序请求两个相同范围
- Given: 还有一个完全无关任务就绪
- When: 系统协调多个范围
- Then: 不出现双方各占一个范围而永久互等，无关任务继续

### AC-6 命令越界写入判违规 ← C-6
- 触发: 操作 让一个任务执行会修改另一任务所占文件的命令，再执行一条只修改自己范围的命令
- Given: 两个任务的范围已获准且内容指纹可核对，另一任务对被改文件已有通过的验证结论
- When: 命令结束后系统核对指纹
- Then: 越界命令所属任务被判为失败并显示越界文件，另一任务对该文件的验证结论标记失效并要求重新验证；只改自己范围的命令正常通过，两次核对均不依赖提示词提醒
