# 并行验证与交付一致性

## 目的
让审查、验收和提交对应实际被检查的内容，不因其他窗口修改而错误放行。

## 逻辑
只读分析可并行，需要稳定文件版本的审查与验收应保护其实际验证范围。
其他窗口影响该范围的修改等待安全交接，不影响验证范围的工作不被额外阻塞。
验证前后核对内容，受到未受控修改影响的结论不能沿用，必须重新核实受影响验证。
共享工作目录中的版本提交只纳入本任务获准范围内的路径；其他宿主有活动任务时不切换分支或重置共享现场。
完整分支审查仍检查完整约定范围，不能为了并行把门禁静默缩小，也不能把其他窗口通知当作裁决。

## 约束
- C-1：当审查或验收需要稳定内容时，系统应保护实际验证范围，重叠写入等待，不重叠工作可继续，不因保护局部范围就全局串行。
- C-2：如果验证期间或放行前发现验证对象发生变化，系统应拒绝沿用旧通过结论并要求重新核对受影响验证，不把原先通过当作当前版本通过。
- C-3：当多个宿主（窗口主会话或需求代理）在共享工作目录提交时，系统应只把本任务获准范围内的路径纳入提交，不混入其他需求的改动；当其他宿主存在活动任务时，系统应拒绝切换分支或重置共享现场并显示受阻原因。
- C-4：当执行完整分支审查及结构化门禁时，系统应保持既定检查范围和裁决要求，不因多窗口并行缩减范围；无法取得一致验证现场时应明确等待或阻塞，而非假报通过。

## 例子
甲在验收面板，乙准备改面板且另有文档任务；面板修改等待，独立文档工作继续。若外部操作改动了甲的验证内容，甲的旧通过不能直接用于当前交付。乙提交时只带自己范围内的文档路径，甲仍在活动，乙请求切换分支被拒绝。

## 验收
### AC-1 验证范围保护与独立并行 ← C-1
- 触发: 操作 在一个窗口验收受保护文件时，从另一窗口请求重叠修改和独立修改
- Given: 验证范围已确定，独立文件不属于该范围
- When: 两类修改请求到达
- Then: 重叠修改等待，独立修改可继续，验证过程中没有受控的重叠写入

### AC-2 对象改变使旧结论失效 ← C-2
- 触发: 操作 在验证开始后通过外部操作改变被验证文件，并尝试使用原结果放行
- Given: 原结果属于修改前内容，修改不是本次验证已覆盖的内容
- When: 系统核对当前内容与验证记录
- Then: 不使用旧结论放行，明确指出对象已变化并要求重新验证受影响部分

### AC-3 共享提交按范围纳入且他人活动时不切换 ← C-3
- 触发: 操作 一个窗口主会话与一个需求代理各有未提交修改时，分别请求提交，再在需求代理仍有活动任务时请求切换共享分支
- Given: 两个需求的获准范围可区分，工作区同时含两个需求的改动
- When: 系统处理版本操作
- Then: 各宿主提交只包含各自获准范围内的路径，另一需求的改动留在工作区未被带入；分支切换被拒绝并显示需求代理活动任务作为原因，其现场未被破坏

### AC-4 全分支门禁不被弱化 ← C-4
- 触发: 操作 在并行需求存在时请求完整分支白盒审查，并发送另一窗口的通过声明
- Given: 门禁要求完整范围及合法结构化裁决，可能暂时无法稳定该范围
- When: 系统准备和核对审查
- Then: 保持完整范围与裁决检查；无法稳定时显示等待或阻塞，不以局部结果或窗口消息代替通过
