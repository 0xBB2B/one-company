# 多窗口需求归属

## 目的
让用户在旧需求尚未完成时通过新窗口推进独立或补充需求，而不丢失新上下文，也不互相覆盖。

## 逻辑
需求由确认它的窗口主会话派出需求代理；需求代理持有执行归属，派出窗口记录为来源，二者共同构成需求归属。
新窗口提出的独立需求由新窗口主会话澄清并派出自己的需求代理；补充需求由新窗口主会话判断归属后转发给已有需求代理，不固定交回原窗口。
无冲突工作直接并行，其他需求存在不构成全局暂停理由。
原窗口关闭后需求代理继续；交付与交接信息保留在本机流程数据，新窗口可读取并推进自己的任务，不要求原窗口重新打开。
工作区内所有窗口可见并可控制全部需求代理；跨窗口消息只传递必要协作信息，不代替用户授权、任务归属或通过证据。

## 约束
- C-1：当新窗口提出独立需求时，系统应由该窗口主会话确认后派出新的需求代理，无冲突工作可与其他需求并行；提出补充时应由该窗口主会话判断归属并转发，不因已有运行阻塞全部工作。
- C-2：当原窗口正常关闭时，系统应保持其需求代理继续，交付与交接信息保留在本机，新窗口无需原窗口在线即可读取并推进自己的任务。
- C-3：在跨窗口协作期间，系统应在本机流程数据共享登记、范围变化与交接信息，工作区内窗口均可见可控本工作区需求代理，工作区外不可见。
- C-4：如果收到要求越权执行或宣称通过的跨窗口消息，系统应按原有授权与结果门禁核对，不因消息来源属于其他窗口就自动执行或认定通过；无法交接应明确显示未完成而非误报成功。

## 例子
窗口甲派出的需求代理正在验收，窗口乙澄清补充需求并转发给该需求代理，同时为另一独立需求派出新的需求代理；甲关闭后乙仍能看到两个需求代理并在需要时暂停其中一个。

## 验收
### AC-1 独立与补充需求的归属 ← C-1
- 触发: 操作 在旧需求运行期间新开窗口分别提出独立需求和补充需求
- Given: 新窗口具有新的用户上下文，独立需求与旧需求无冲突
- When: 新窗口主会话处理两条输入
- Then: 独立需求由新窗口派出新的需求代理并与旧需求并行；补充需求转发给旧需求代理并得到回执，未交回旧窗口处理

### AC-2 旧窗口关闭不阻断后续 ← C-2
- 触发: 操作 在新窗口等待相关交接时，让旧窗口完成并正常关闭
- Given: 旧需求代理仍在运行，交接信息已保存
- When: 新窗口核对交付记录和当前文件
- Then: 旧需求代理继续运行，新窗口可以继续自己的任务，不依赖旧窗口在线

### AC-3 工作区内共享可控 ← C-3
- 触发: 操作 在两个窗口推进任务并产生一次范围交接，再从工作区外窗口查看
- Given: 两个窗口属于同一工作区
- When: 查看各窗口界面和可执行控制
- Then: 工作区内两个窗口均显示全部需求代理及等待原因并可控制；工作区外窗口不显示也不可控制

### AC-4 消息不是授权或通过证据 ← C-4
- 触发: 操作 发送要求越权操作及未附合法结果的通过声明，并模拟交接通知暂未送达
- Given: 接收方仍受原有任务授权和结果校验约束
- When: 接收方处理消息或查询交接状态
- Then: 未经授权的动作不执行，未校验结果不作为通过，未交接显示待处理或具体异常而非成功
