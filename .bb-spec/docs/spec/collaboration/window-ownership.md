# 多窗口需求归属

## 目的
让用户在旧需求尚未完成时通过新窗口推进独立或补充需求，而不丢失新上下文。

## 逻辑
同一工作目录中各主会话登记负责的需求、阶段与工作范围，必要协作信息在后台共享。
新需求或补充需求默认由提出并澄清它的新窗口负责执行，不固定交回原窗口。
无冲突工作直接并行，其他需求存在不构成全局暂停理由。
必要交付和交接信息保留供后续读取，原窗口正常完成关闭后新窗口仍可继续。
界面只显示本窗口任务，跨窗口信息仅作为影响本任务的等待或异常原因。
消息只传递必要协作信息，不复制完整对话，不代替用户授权、任务归属或通过证据。

## 约束
- C-1：当新窗口提出独立或补充需求时，系统应保持新窗口对该需求的执行归属，无冲突工作可与旧窗口并行，不因已有运行而阻塞所有工作。
- C-2：当原窗口正常完成并释放工作范围后关闭时，系统应允许新窗口读取必要交付记录、核对当前文件并推进自己的任务，不要求原窗口重新打开。
- C-3：在跨窗口协作期间，系统应在后台共享必要登记、范围变化和交接信息，仅向当前窗口展示影响本任务的原因，不提供其他窗口任务列表或跨窗口暂停停止入口。
- C-4：如果收到要求越权执行或宣称通过的跨窗口消息，系统应按原有授权与结果门禁核对，不因消息来源属于其他窗口就自动执行或认定通过；无法交接应明确显示未完成而非误报成功。

## 例子
窗口甲正在验收，窗口乙澄清补充需求并规划不冲突工作；甲完成关闭后乙读取成果并继续实施补充，乙不需要甲的新对话或再次派工。

## 验收
### AC-1 独立及补充需求归属新窗口 ← C-1
- 触发: 操作 在旧需求运行期间新开窗口分别提出独立需求和补充需求
- Given: 新窗口具有新的用户上下文，至少一个工作部分与旧需求无冲突
- When: 新窗口澄清并推进任务
- Then: 新需求仍由新窗口负责，不固定交回旧窗口，无冲突工作与旧窗口同时推进

### AC-2 旧窗口关闭不阻断后续 ← C-2
- 触发: 操作 在新窗口等待相关交接时，让旧窗口完成并正常关闭
- Given: 旧窗口交付和释放信息已经保存，新窗口有后续任务
- When: 新窗口核对交付记录和当前文件
- Then: 新窗口可以继续自己的任务，不依赖旧窗口在线，不恢复旧子代理身份

### AC-3 后台协作与界面隔离 ← C-3
- 触发: 操作 在两个窗口推进任务并产生一次范围交接
- Given: 当前窗口需要了解受阻文件，另一个窗口有自己的任务
- When: 查看当前窗口界面和可执行控制
- Then: 只显示本窗口任务及必要等待原因，没有其他窗口进度列表或控制入口，交接信息仍可供当前主会话处理

### AC-4 消息不是授权或通过证据 ← C-4
- 触发: 操作 发送要求越权操作及未附合法结果的通过声明，并模拟交接通知暂未送达
- Given: 接收窗口仍受原有任务授权和结果校验约束
- When: 接收窗口处理消息或查询交接状态
- Then: 未经授权的动作不执行，未校验结果不作为通过，未交接显示待处理或具体异常而非成功
