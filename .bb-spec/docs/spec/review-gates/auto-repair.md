# 非产品问题自动返修

## 目的
把可由测试、实现和既有规则解决的技术问题在流程内自动闭环，不打扰用户。

## 逻辑
归因为可自动解决的问题后，主 agent 先向 AI 决策记录写入修复路径，再在用户已授权的目标、文件范围和验收标准内派发 worker 完成 Red → Green → 自验收的修复，随后调用原审查角色重审。两个审查角色的返修路径相同：白盒审查者在修复提交后对整个分支重新审查，黑盒验收者在修复通过白盒审查后重新验收。

## 约束
- C-1：当审查问题不需要产品决策且修复不超出用户已授权的目标、文件范围和验收标准时，系统应自动派发 worker 修复，并再次调用原审查角色。
- C-2：如果修复需要扩大目标、文件范围或验收标准，系统应把该问题视为产品决策，不得自动返修。

## 例子
白盒审查者指出一处遗漏的错误处理，问题在已批准的文件范围内，主 agent 记录决定后派发 worker 修复并重新调用白盒审查者，全程没有询问用户。

## 验收
### AC-1 白盒审查问题自动修复  ← C-1
- 触发: 操作 让白盒审查者报告一个不涉及产品决策的实现或测试问题
- Given: 用户已批准的目标、文件范围和验收标准足以完成修复
- When: 主 agent 完成问题归因
- Then: AI 决策记录先出现归因与修复路径记录，随后系统自动派发 worker 修复并由白盒审查者重审，期间没有询问用户

### AC-2 提交前审查问题自动修复  ← C-1
- 触发: 操作 在提交前审查中让白盒审查者报告一个不涉及产品决策的阻塞问题
- Given: 问题可在已批准范围内通过测试或实现改动解决
- When: 主 agent 校验审查结果并完成归因
- Then: 系统先写入 AI 决策记录，再自动完成修复与必要验证，再调用白盒审查者重审，未执行任何未经审查的远端写入

### AC-3 黑盒验收问题自动修复  ← C-1
- 触发: 操作 让黑盒验收者报告一个由实现偏差造成的验收失败
- Given: 规范与验收明确且不需要用户选择
- When: 主 agent 核对验收结果和报告并完成归因
- Then: 系统先写入 AI 决策记录，再自动派发 worker 修复、重新通过白盒审查并再次调用黑盒验收者，期间没有询问用户

### AC-4 超出授权范围不自动返修  ← C-2
- 触发: 操作 让白盒审查者报告一个必须修改任务文件范围之外文件才能解决的问题
- Given: 该文件不在任务声明的范围内
- When: 主 agent 完成问题归因
- Then: 系统没有派发修复，而是把该问题作为产品决策向用户提出
