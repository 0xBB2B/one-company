# 黑盒验收的关注点

## 目的
让黑盒验收回答“功能做全了吗、真的能用吗”，而不只是逐条核对输出。

## 逻辑
黑盒验收者不读源码与任务文件，只依据规则文件的逻辑、例子与验收条目，在真实运行环境中操作。它逐条执行验收并比对输出，同时以使用者视角检查规则描述的入口是否存在且可达、按例子操作能否走通、错误场景的提示是否可理解并指向正确的下一步、功能是否只在验收条目的精确输入下才成立。逐条比对全部通过但功能缺失、不可达或不可用时，验收仍为 rejected。

## 约束
- C-1：当系统执行黑盒验收时，系统应把功能是否完善、是否可用作为验收关注点，并在报告中记录可用性观察。
- C-2：如果规则文件描述的功能在真实环境缺失、不可达、不可用，或只在验收条目的精确输入下才成立，系统应把验收结论置为 rejected 并写明具体原因，即使逐条验收全部通过。
- C-3：当系统执行黑盒验收时，系统应禁止验收者读取源码、任务文件或其他仓库文件，验收依据只来自规则文件与真实环境的可观察行为。

## 例子
规则文件描述“命令行工具支持导出报表”，验收条目只给了一个固定日期的输入；验收者按条目操作通过，但换成规则例子中的日期范围时命令报错且提示不可理解。验收报告记录该可用性问题，结论为 rejected。

## 验收
### AC-1 逐条通过但不可用即拒绝  ← C-1, C-2
- 触发: 操作 让规则文件描述的功能只在验收条目的精确输入下成立
- Given: 逐条验收全部通过，按规则例子中的其他输入操作时功能报错
- When: 验收者完成验收并写出报告
- Then: 报告的可用性观察记录该问题，结论为 rejected，需求不被置为 accepted

### AC-2 验收者不读仓库文件  ← C-3
- 触发: 操作 执行黑盒验收并观察验收者的文件访问
- Given: 仓库中存在源码、任务文件与配置文件
- When: 验收者完成验收
- Then: 验收者只读取了给定的规则文件与它自己写出的报告，没有读取其他仓库文件
