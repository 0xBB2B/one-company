# 可信测试与实现分阶段

## 目的
让测试证明真实要求，而不是只证明测试安排好的理想过程。

## 逻辑
同一个实现角色在一次运行中完成验证约定核对、测试编写、可信失败、实现及自验收。
开始生产修改前，检查测试是否经过目标入口、模拟是否改变完成时机或错误含义、保护缺失时是否仍可能通过。
针对保护要求，测试必须包含不遵守理想步骤的输入，不能依赖模型主动听从提示。
涉及接入的任务保留本次要证明的真实连接，模拟仅用于约定允许的外部边界。
有行为变化时，失败必须来自目标行为缺失；纯重构或行为已存在的情况核实已有行为和测试证明力，不制造失败。
无效测试、环境缺失、测试与业务冲突均明确报告，不通过弱化断言或修改测试含义获得通过。

## 约束
- C-1：当实现角色处理任务时，系统应在同次运行中先按业务规则与验证约定建立测试并核对证明力，再进入生产修改；不拆为额外测试角色或第二次实现派工。
- C-2：当验证系统保护或真实接入时，系统应覆盖违反理想操作顺序的输入，并保留目标连接；不得靠手工设置终态、预设模型先核对或改变真实异步含义来证明要求。
- C-3：如果失败由语法、导入、夹具、环境或测试数据错误造成，系统应拒绝把它当作可信行为失败；行为已存在时核实真实入口和已有证据，不故意破坏代码制造失败。
- C-4：当实现进入通过阶段时，系统应保持测试的业务含义和关键断言，不跳过、弱化或替换成绕开目标的测试；完成目标验证后执行约定的受影响回归与最终验证。

## 例子
模型在暂停恢复后不做核对就再次写入，测试必须观察系统阻止重复副作用；把模型安排成主动先读文件不能证明保护存在。

## 验收
### AC-1 同次交付证明真实保护 ← C-1, C-2, C-4
- 触发: 操作 让实现角色交付一个阻止未核实写入重放的任务
- Given: 原行为缺少保护，真实入口可用，验证约定要求覆盖不核对及无关核对后的重试
- When: 实现角色完成测试、修改和自验收
- Then: 同次运行先由实际重放建立行为失败，再由系统保护使测试通过，模型不配合也不会重复写入，目标、回归及最终验证均有证据，关键断言未弱化

### AC-2 无效证明与伪失败不得交付 ← C-2, C-3, C-4
- 触发: 操作 分别提交直接设置暂停状态、只安排模型主动核对、把异步完成改为立即成功、导入错误和弱化断言的测试证据
- Given: 各证据声称已经证明目标行为或完成先失败后通过
- When: 核对测试证明力和交付证据
- Then: 每个案例均指出具体失真原因并不予通过，不以测试名称、数量或曾经失败代替实际证明

### AC-3 已有行为不人为制造失败 ← C-3
- 触发: 操作 执行一个目标行为已经存在且无需生产改动的任务
- Given: 真实入口和可捕获回归的测试证据可以核实
- When: 新验证意外直接通过
- Then: 核实已有行为并如实提交无变更证据，不故意破坏测试或生产行为；证据不足时报告阻塞
