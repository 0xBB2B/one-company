# 黑盒验收直接裁决

## 目的
让黑盒验收不经过多步编排，需求代理只核对验收者的结构化对象与其写出的报告，一致才接受需求。

## 逻辑
需求代理以一次直接调用派工黑盒验收者，输入为规则文件路径清单、唯一验收报告路径和运行环境启动方式，并传入验收结果的结构化格式。验收者先写入指定报告，再提交唯一对象，顶层恰好包含九个字段：阶段、裁决、摘要、问题清单、证据清单、验收结果、报告位置、逐条结果、未覆盖项；逐条结果的每个条目恰好包含编号、结果、观察、差异四个字段。需求代理只读取该报告做一致性核对，从不转录、覆盖或回滚它。

## 约束
- C-1：当系统执行黑盒验收时，系统应由需求代理以一次直接调用派工黑盒验收者，不得为该验收启动多步编排，并仅依据结构化对象的裁决、逐条结果与指定报告的一致性决定是否接受需求。
- C-2：当系统执行黑盒验收时，系统应仅允许黑盒验收者写入调用方指定的验收报告，需求代理不得转录、覆盖或回滚该报告。
- C-3：当验收者返回 PASS 时，系统应要求逐条结果非空且全部为通过、问题清单与未覆盖项为空、报告位置精确等于指定位置，且报告结论为 accepted，四者缺一即不接受需求。
- C-4：如果验收者已写入报告但结构化门禁失败或与报告不一致，系统应保留本次报告作为诊断证据，不把需求置为 accepted，并显示具体差异。

## 例子
需求进入验收，需求代理直接调用验收者；验收者写好报告并提交全部 PASS 的对象，报告路径与结论一致，需求被接受。界面上没有出现多步编排。

## 验收
### AC-1 直接调用并以结构化对象裁决  ← C-1, C-3
- 触发: 操作 执行需求黑盒验收
- Given: 黑盒验收者作为门禁被需求代理直接调用
- When: 验收者提交字段集合与 PASS 语义均符合约定的对象，且报告路径与结论一致
- Then: 界面没有为该验收显示多步编排，需求被置为 accepted

### AC-2 结果与报告不一致时拒绝  ← C-3, C-4
- 触发: 操作 让黑盒验收者提交 PASS，但报告路径不同或报告结论为 rejected
- Given: 需求处于 accepting 状态，验收者已写入本次报告
- When: 需求代理核对提交对象与指定报告
- Then: 本次报告保留，需求不被置为 accepted，界面显示对象与报告不一致的具体字段

### AC-3 验收报告由验收者唯一写入  ← C-2, C-4
- 触发: 操作 执行黑盒验收并让验收者写入指定报告后不提交结构化对象
- Given: 调用方已指定唯一验收报告路径并保存其调用前内容
- When: 验收者写入本次报告后以说明文字结束而未提交对象
- Then: 指定路径保留验收者写入的本次报告，需求代理不转录、覆盖或恢复调用前内容，需求不被置为 accepted
