# 自动返修轮次上限

## 目的
防止自动返修无限循环，同时不把纯技术问题转嫁给用户。

## 逻辑
每个审查门禁独立计数：一次归因、修复派发并再次调用原审查角色为一轮。第三轮重审仍未通过时，需求代理 按固定规则停止并报告技术阻塞；停止是确定性状态转换，不写入决策记录。

## 约束
- C-1：在同一审查门禁的自动返修期间，系统应最多执行 3 轮修复与重审。
- C-2：如果同一审查门禁的第 3 轮返修后仍未通过，系统应记录技术阻塞并停止，不得继续返修，也不得把纯技术问题转为用户决策请求。

## 例子
白盒审查者连续三轮对同一分支返回 FAIL，需求代理 停止返修，需求停在审查阶段并说明技术阻塞，没有向用户提问。

## 验收
### AC-1 自动返修三轮后停止  ← C-1, C-2
- 触发: 操作 让同一审查门禁的非产品问题连续三轮修复后仍未通过
- Given: 每轮修复都由已有授权或必要的材料性 AI 决定覆盖，并由原角色重审
- When: 第 3 轮审查再次返回未通过
- Then: 系统停止继续返修并报告技术阻塞，不向用户询问如何解决纯技术问题，决策记录不增加机械状态记录
