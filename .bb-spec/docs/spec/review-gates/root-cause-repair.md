# 同类缺陷的根因返修

## 目的
让返修解决已经暴露的一类错误，而不是每轮只补上一次给出的单个例子。

## 逻辑
主会话对未通过项逐条归因，区分当前任务问题、独立问题和需要用户选择的产品决策。
在获准返修范围内，首次修复先明确错误假设、同类受影响场景以及本轮要增加的验证。
同一根因再次失败时，先重新核对相应状态、数据边界或接口契约，再派发修复，不只追加一个局部案例。
新的同类验证只证明原有要求，不借此增加功能、改变验收或扩大写入权限。
审查返修仍只由实现角色修改，审查角色保持只读，各审查门禁最多三轮。
没有既定自动返修授权的失败仍按原停止与授权边界处理，本规则不自动开启额外重试。

## 约束
- C-1：当主会话准备首次获准返修时，系统应先列明错误假设、同类受影响场景及验证补充，在材料性决定记录成功后再派实现角色修复，不仅转发一个失败例子。
- C-2：如果同一根因在后续交付或审查中再次失败，系统应先重新核对状态、数据边界或接口设计，给出与复现关联的修复方向，再在获准范围内执行。
- C-3：当归因发现独立问题或修复需要扩大目标、文件范围及验收标准时，系统应分别建立独立任务或请求用户裁决，不把独立问题混入返修或自行扩权。
- C-4：当返修推进时，系统应保持审查角色只读、既定授权和各审查门禁三轮上限；第三轮仍未通过时停止，不通过改名、重派或改归属重置同一门禁轮次，也不为未获准失败自动新增重试。

## 例子
首次发现分片处理串用状态后，返修同时检查消息和内容块隔离；同根因再次出现时先重查输入边界，不继续只针对新例子添加特判。

## 验收
### AC-1 首次返修包含同类场景 ← C-1
- 触发: 操作 对一个因输入边界混淆而失败的任务启动已获准返修
- Given: 原要求已包含相互独立输入不影响彼此，写入范围足够
- When: 主会话归因并派工
- Then: 派工前的修复要求明确错误假设、相关输入类别和验证补充，材料性决定先成功记录，修改只派给实现角色

### AC-2 重复根因先核对设计 ← C-2
- 触发: 操作 在同一根因第二次出现时请求返修
- Given: 上一轮具体案例已修复，但同类输入或时序仍违反原要求
- When: 主会话准备下一轮修复
- Then: 先给出与新旧复现关联的状态、数据边界或接口核对结论，再派范围内修复，不仅追加针对新案例的特判要求

### AC-3 范围与轮次不能因根因返修扩张 ← C-3, C-4
- 触发: 操作 分别对独立问题、超出授权问题、同一门禁第三轮失败及未获准自动重试的失败请求继续返修
- Given: 各案例的任务归属、授权及既有轮次可核对
- When: 主会话处理请求
- Then: 独立问题有独立任务，超出授权先询问，第三轮失败停止且不重置轮次，未获准失败不新增自动重试，审查角色没有修改文件
