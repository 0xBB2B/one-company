# 结构化裁决

## 目的
让派工方对实现、审查与验收角色的结果只做结构化格式校验与语义谓词判定，杜绝从自然语言推断通过。

## 逻辑
派工方（需求代理，提交前审查时为主会话）派工实现者、白盒审查者或黑盒验收者时传入结构化格式，角色必须按该格式提交唯一对象；对象顶层内容与约定精确一致，类型、非空性与枚举合法，通过与未通过的内容组合自洽。
提交尝试与有效提交分别统计：首个有效对象被接受前，工具错误或校验失败允许以新调用纠正；最终仍无合法对象时视为未通过，并展示具体原因，不从自然语言推断通过。首个有效对象被接受后，不允许再发起新的提交。
同一工具调用标识的相同完成事件重复投递不增加尝试数或有效数；同一标识内容冲突则失败。缺少标识时每次事件独立处理，不伪造标识或把所有无标识事件合并。
系统在该次运行正常完成后才将合法对象交给流程门禁；启动回执、提前提交的对象或异常退出均不能单独构成通过依据。
规划角色交付任务文件与规划报告，不要求上述三类结构化裁决。

## 约束
- C-1：当实现、审查或验收角色结束时，系统应只接受通过调用方结构化格式校验的唯一对象作为结果，顶层内容必须精确匹配约定。
- C-2：如果角色结束时仍未提交合法对象，包括对象含约定外内容或缺少内容、类型或枚举错误、或通过与未通过同其他内容组合矛盾，系统应把门禁视为未通过并显示具体原因，不得从结果文本或自然语言中推断通过。首个合法对象被接受前的失败尝试允许以新调用纠正，纠正成功不残留此前提交错误作为最终失败。
- C-3：在角色运行尚未正常完成或已失败、取消、中断的期间，系统应不因启动成功、提前提交合法对象或自然语言表示成功而推进通过门禁。
- C-4：当结构化提交完成事件重复投递时，系统应按工具调用标识去重，相同标识和内容只处理一次，相同标识内容冲突应失败；无标识的事件独立处理。首个有效对象被接受后出现新的提交必须失败，即使新提交内容相同或工具报错；多个失败尝试不得被误报为多个有效提交。

## 例子
审查者只在结果文本里写“审查完成，无问题”而没有提交对象，派工方视为未通过，界面显示“未提交结构化对象”，流程停止。

## 验收
### AC-1 合法对象被接受  ← C-1
- 触发: 操作 让实现、审查或验收角色提交一个内容与语义均符合约定的对象
- Given: 派工方正在等待该角色的裁决
- When: 角色调用结束
- Then: 系统依据该对象的裁决继续后续流程，界面没有校验错误

### AC-2 偏差结果失败关闭  ← C-2
- 触发: 操作 让实现、审查或验收角色不提交对象、提交额外内容，或提交裁决为通过却带非空问题清单的对象
- Given: 派工方正在等待该角色的裁决
- When: 角色调用结束
- Then: 系统把门禁视为未通过，显示具体的校验失败原因，后续动作没有执行

### AC-3 运行未正常完成不能提前放行  ← C-3
- 触发: 操作 让角色提交合法通过对象后继续运行，再让该运行异常退出或被取消
- Given: 派工方已收到派工成功回执，但角色运行尚未正常完成
- When: 在提前提交对象后及异常退出或取消后分别检查门禁
- Then: 两个时刻都没有推进通过门禁，异常退出或取消的具体原因可查询，提前对象没有被当作成功结果

### AC-4 失败提交可纠正且事件去重不放宽唯一性 ← C-1, C-2, C-3, C-4
- 触发: 操作 分别提交格式错误、阶段错误或工具错误，再用新的调用标识提交唯一合法对象；重复投递各次相同完成事件
- Given: 首个合法对象尚未被接受，运行最终正常结束
- When: 收集完成事件并取得最终结果；另验证两个有效提交、同一标识不同内容、无标识的多次事件及合法提交后模型异常
- Then: 失败后纠正及相同事件重复投递均可返回唯一合法对象，尝试数与有效数分开统计；两个有效提交、有效提交后的新失败调用、同一标识内容冲突及模型异常均不能通过；无标识的事件不合并，完全无提交仍明确失败
