# 白盒审查

## 目的
让白盒审查一次看到完整改动，把精力集中在会造成真实损害的问题上；提交前只依据可完整校验的结构化裁决与审查快照决定是否推送。

## 逻辑
需求的所有任务完成并各自通过自验收后，需求代理对当前分支相对基线的完整改动派工白盒审查，不在单个任务完成时派工。
审查者先以攻击者视角找可触发的安全问题，再以真实非恶意故障视角找鲁棒性问题，每条发现给出位置、触发条件或攻击路径、影响与修复方向；然后逐条核对每个任务的验收在测试与实现中的可追踪关系与测试证明力。没有实际触发路径的问题不阻断。
审查者只读：系统核对其每条命令前后的工作区指纹，出现写入即该次运行判失败并记违规，而不是事后通报。
提交前审查由主会话记录审查快照（分支头与内容指纹），以一次直接调用派工白盒审查者，输入为仓库位置、基线、规范与验收、审查重点和快照，并传入审查裁决的结构化格式。主会话核对对象与快照一致后才允许推送或创建合并请求，远端写入前重新采集的快照也必须一致。
提交前审查未通过时，需求回退到执行阶段，主会话重新派出需求代理以新的运行身份接手归因与返修；返修后重新经验收与提交前审查。

## 约束
- C-1：当需求进入白盒审查时，系统应在所有任务完成后以整个分支为对象派工审查，不得在单个任务完成时派工。
- C-2：当白盒审查者审查时，系统应把安全性与鲁棒性作为首要重点，每条发现必须包含位置、触发条件或攻击路径、影响与修复方向。
- C-3：如果某个问题没有实际可触发的路径，系统应不把它作为阻断项，也不要求为其增加防御代码。
- C-4：当白盒审查者完成重点审查后，系统应逐条核对每个任务的验收在测试与实现中的可追踪关系，测试遗漏或证据不可信即为阻断项。
- C-5：当白盒审查者执行命令时，系统应核对命令前后的工作区指纹，出现写入即把该次运行判为失败并记录违规。
- C-6：当系统执行提交前审查时，系统应由主会话以一次直接调用派工白盒审查者，不为该审查启动多步编排，并仅依据结构化对象的裁决、阶段专用内容与审查快照一致性决定是否允许远端写入。
- C-7：当提交前审查的白盒审查者返回通过时，系统应要求问题清单与发现清单为空、可追踪关系与证据清单非空，且审查头与内容指纹精确等于调用方快照。
- C-8：如果提交前审查者未提交对象、对象未通过结构化校验、语义矛盾或与审查快照不一致，系统应把阶段检查视为未通过，保留本地提交，不执行任何远端写入并显示具体原因。
- C-9：如果提交前审查未通过，系统应把需求回退到执行阶段，由主会话重新派出需求代理以新的运行身份接手归因与返修，返修后重新经验收与提交前审查才可再次进入远端写入；该返修计入白盒阶段检查的轮次上限。

## 例子
三个并行任务先后完成，需求代理只在第三个完成后派工一次覆盖整个分支的白盒审查；审查者报告一处路径穿越（含攻击路径与修复方向）和一条未被测试覆盖的验收，两者进入返修，一处只有数据库文件被手工破坏才触发的分支写为建议。返修后用户执行提交前审查，主会话记录快照并直接调用审查者，收到通过且快照一致的对象后推送分支。

## 验收
### AC-1 只在全部完成后审查整个分支 ← C-1
- 触发: 操作 执行一个含三个任务的需求
- Given: 三个任务依次完成并各自通过验证
- When: 前两个任务完成时与第三个任务完成时分别观察
- Then: 前两个任务完成时没有派工白盒审查，第三个任务完成后派工一次覆盖整个分支的白盒审查

### AC-2 安全与鲁棒性发现带触发路径 ← C-2, C-3
- 触发: 操作 让分支中同时存在一处可触发的路径穿越和一处只在不可能场景下才触发的分支
- Given: 白盒审查者已被派工
- When: 审查者提交裁决
- Then: 路径穿越作为阻断项出现且带位置、攻击路径、影响与修复方向；不可能场景的分支不作为阻断项，也没有要求增加防御代码

### AC-3 测试遗漏是阻断项 ← C-4
- 触发: 操作 让某个任务的一条验收没有对应测试
- Given: 安全与鲁棒性审查未发现问题
- When: 审查者核对可追踪关系并提交裁决
- Then: 裁决为未通过，问题定位到该任务的该条验收

### AC-4 审查者写入工作区即运行失败 ← C-5
- 触发: 操作 让白盒审查者在审查过程中执行一条修改仓库文件的命令
- Given: 命令执行前的工作区指纹已记录
- When: 该命令结束
- Then: 命令后指纹与命令前不一致，该次审查运行判为失败并记录违规，其裁决不被采纳

### AC-5 提交前直接调用并以快照裁决 ← C-6, C-7
- 触发: 操作 在功能分支上执行提交前审查
- Given: 主会话已记录审查快照，白盒审查者被主会话直接调用
- When: 审查者提交语义与快照均符合约定的通过对象
- Then: 界面没有为该审查显示多步编排，系统允许远端写入

### AC-6 非法结果失败关闭 ← C-8
- 触发: 操作 让提交前审查者不提交对象、提交额外内容、内容缺失、语义矛盾或快照不一致的结果
- Given: 本地提交已完成，远端尚未写入
- When: 审查者调用结束
- Then: 系统把阶段检查视为未通过，显示校验失败的具体原因，不执行远端写入，本地提交保持不变

### AC-7 提交前审查未通过回退执行阶段 ← C-9
- 触发: 操作 让提交前审查者返回带阻断发现的未通过
- Given: 需求此前已通过验收并处于待提交状态
- When: 主会话收到未通过裁决
- Then: 需求阶段回到执行，主会话派出的需求代理拥有新的运行身份并接手归因与返修；返修完成后需求重新经过验收与提交前审查，期间没有任何远端写入
