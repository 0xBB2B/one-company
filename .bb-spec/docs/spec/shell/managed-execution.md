# 统一 Shell 执行

## 目的
让当前会话启动的每条 Shell 命令都有明确归属，长命令可后台运行而不脱离管理。

## 逻辑
主 agent、四类流程专用子代理的 bash 工具，以及用户的 !、!! 命令都属于受管理入口。
每次命令形成一个 Shell 任务，命令启动的后代进程归入同一任务；子运行启动的任务属于该次子运行，手动命令属于当前主会话。
统一接管不扩大已有命令权限，不改变工作目录、环境及 !、!! 的输出是否进入模型上下文的区别。
主、子 agent 的 bash 工具仅在 background 为 true 时显式后台执行；省略 background 或为 false 时等待真实结果，不因耗时较长而自动转后台。
手动 !、!! 保持原输入方式与等待行为，只接入统一管理，不增加后台选项或后台命令前缀。
显式后台执行只返回可识别的任务编号与启动状态，不等待命令执行完毕，也不把已启动当作执行成功。
后台模式可同时指定 timeout，按秒从进程启动时计时，提前返回不解除或重置计时；到期开始停止任务及其后代，确认清理后才报告超时结束，未指定则不增加默认寿命上限并仍受宿主生命周期约束。
登记或启动失败时显示具体失败，不能绕过管理继续启动命令。

## 约束
- C-1：当任一受管理入口启动命令时，系统应登记唯一 Shell 任务及具体宿主，将其后代归于同一任务；只向当前主会话展示和开放其自身及子运行的任务，不扩大命令授权或改变工作目录、环境、! 与 !! 的上下文语义。
- C-2：当主、子 agent 的 bash 调用省略 background 或提供 false，或用户通过手动 !、!! 执行命令时，系统应等待真实执行结果并返回实际输出及退出结果；手动入口不增加后台选项或后台命令前缀，长时间运行不自动切换执行方式，失败不得显示为成功。
- C-3：当主、子 agent 的 bash 调用提供 background: true 且启动成功时，系统应在命令尚未结束时返回任务编号与运行状态，允许宿主继续其他工作；同一任务在查询和界面中的身份及宿主保持一致，已启动不等于执行成功。
- C-4：如果无法登记或启动受管理命令，系统应返回具体失败，不返回虚构的运行任务或改用未受管理入口；超时及取消不得以遗留活跃后代作为执行已经结束的证据。
- C-5：当后台 bash 同时指定合法 timeout 时，系统应接受该组合，按秒从进程启动时计时，提前返回任务编号不解除或重置计时，到期开始停止该任务及其后代，确认清理后才报告超时结束而非执行成功；如果清理无法确认，应保留任务并显示具体不确定原因。未指定 timeout 时不增加默认寿命上限，任务仍受宿主生命周期约束。

## 例子
主 agent 启动开发服务并选择后台执行，获得任务编号后继续工作；实现子代理同时等待测试结果，两个 Shell 都能在当前主会话中查到，宿主身份各自明确。

## 验收
### AC-1 所有入口归属准确且权限不扩大 ← C-1
- 触发: 操作 分别通过主 agent、四类子 agent 的授权 bash 调用及手动 !、!! 启动延迟结束的命令，同时在另一窗口启动命令
- Given: 命令执行目录、环境和授权范围已知，至少一条命令会产生多个后代；!! 的输出有可区分标记
- When: 查看本会话 Shell 列表及命令实际影响，并尝试子 agent 未获授权的命令
- Then: 每次授权启动只登记一个任务且宿主正确，后代不重复登记，另一窗口任务不可见不可控制；原权限、目录、环境与 !、!! 的上下文区别不变，未授权调用被拒绝

### AC-2 默认及手动入口等待真实结果 ← C-2
- 触发: 操作 主、子 agent 分别省略 background 和提供 background: false 调用 bash，并通过 !、!! 执行延迟成功和延迟失败且有输出的命令
- Given: 命令在等待期间均能从外部确认仍在运行，实际退出结果不同；已知手动入口的原输入方式
- When: 在命令运行期间查看 Shell 列表，再等待各自完成并检查手动入口的使用说明
- Then: 运行期间显示等待结果且没有提前返回后台启动回执；结束后输出与实际退出结果一致，失败没有被当作成功；手动入口没有新增后台选项或后台命令前缀，输入方式与等待行为不变

### AC-3 agent 显式后台返回可管理任务 ← C-3
- 触发: 操作 主 agent 和四类子 agent 分别通过 bash 的 background: true 启动获准的持续运行命令，取得回执后让同一宿主执行另一项授权工作
- Given: 后台命令在第二项工作开始时仍可确认运行，子 agent 的命令已满足原授权边界
- When: 对照启动回执与 Shell 列表中的任务及宿主
- Then: 每次命令结束前已返回任务编号并允许第二项工作开始；编号和具体宿主一致，回执只表示启动而非命令通过

### AC-4 启动失败及取消不失管 ← C-4
- 触发: 操作 分别制造登记失败、启动失败，并对产生后代的执行施加超时或取消
- Given: 能观察命令及后代是否仍有执行活动
- When: 查看返回结果及清理结果
- Then: 登记失败没有启动命令，启动失败显示具体原因而非伪造运行回执；超时或取消确认结束前后代确实停止，无法确认时明确显示不确定原因

### AC-5 后台回执不解除超时与宿主约束 ← C-5
- 触发: 操作 以 background: true、timeout: 1 启动会产生持续后代的命令，并另启动不提供 timeout 的同类后台命令；另测超时清理无法确认的情况
- Given: 命令及后代在不受停止干预时持续运行，进程启动时刻可观察，宿主在超时测试期间保持运行
- When: 取得后台任务回执后继续其他工作，等待自启动满 1 秒并检查停止反馈，随后结束无超时命令的宿主
- Then: 后台与 timeout 组合被接受，回执早于超时且不取消或重置计时；满 1 秒开始停止对应任务及后代，确认清理后反馈超时而非通过，无法确认则保留任务和具体原因。不提供 timeout 的命令不因相同等待时长被自动停止，宿主结束时仍按归属清理
