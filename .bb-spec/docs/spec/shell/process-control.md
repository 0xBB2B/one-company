# 单个 Shell 停止控制

## 目的
让用户无需等待模型响应即可停止选定 Shell，同时防止停错任务和误报清理完成。

## 逻辑
Shell 列表中按 K 发起对选定任务的停止确认，确认页展示任务编号、宿主和命令，默认选择取消。
取消确认不发送停止请求；确认后只停止对应 Shell 及其后代，不停止宿主运行或其他 Shell；守护进程内的 Shell 由守护进程执行停止并回执。
发出请求后显示正在停止，确认进程清理后才显示停止成功；这不是命令执行成功。
命令自然退出或列表刷新不改变已确认的目标身份，不能将动作转移到相同行号的新任务。
无法读取状态或无法确认停止时显示具体原因，保留未确认任务，不当作成功从管理范围删除。
控制操作不依赖模型服务响应，不自动重新启动被停止的命令，也不回滚命令已经产生的文件。

## 约束
- C-1：当用户在 Shell 列表按 K 时，系统应展示选定任务的编号、宿主和命令并请求确认，默认选择取消；取消不影响进程，确认只停止该 Shell 及其后代，不停止宿主或其他任务，不回滚成果。
- C-2：当系统处理停止请求时，系统应先显示正在停止，确认清理后才报告停止成功，并将停止与执行成功区分；此控制不等待模型响应，也不自动重启命令。
- C-3：如果确认期间任务已结束、列表顺序变化、目标身份无法核对或清理失败，系统应保持原目标身份，显示已结束或具体错误及不确定原因，不把请求发送给新占据原行位置或复用进程编号的无关任务，不误报清理完成。

## 例子
用户发现测试卡住，在列表选中它并按 K；确认页注明实现子代理的具体身份。确认后仅停止该测试及其后代，开发服务和实现子代理本身不被一并终止。

## 验收
### AC-1 停止确认与精确范围 ← C-1
- 触发: 操作 在主 agent 和两个子运行均有 Shell 时，选中其中一个子运行的一条 Shell 按 K，先取消一次，再确认停止
- Given: 该 Shell 有后代，同一宿主还有另一条命令，且目标已经写入文件
- When: 查看确认页默认选择及两次操作后的活动
- Then: 确认页准确显示目标编号、宿主、命令并默认取消；取消无影响，确认后仅目标及后代停止，其他命令与宿主不被停止，原文件保留

### AC-2 停止反馈不依赖模型 ← C-2
- 触发: 操作 模型服务不可用时从列表确认停止一个可清理的 Shell
- Given: 命令正在运行且停止请求至清理确认之间可观察
- When: 查看停止过程及后续命令活动
- Then: 控制仍可执行，先显示正在停止，再于清理确认后报告停止而非命令通过，命令不会被控制功能自动重启

### AC-3 刷新和失败不能导致误停 ← C-3
- 触发: 操作 打开停止确认后让目标自然结束并刷新列表，另测试状态读取失败、身份不匹配及后代清理无法确认
- Given: 同一列表包含持续运行的无关命令，原目标编号已知
- When: 确认原目标停止并查看结果
- Then: 新占据同一行或无关进程编号的命令不被停止；已结束目标如实反馈，读取或清理失败显示具体原因，未确认任务没有被当作清理成功删除
