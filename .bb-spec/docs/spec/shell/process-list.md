# Shell 列表与停止

## 目的
让用户在输入栏位置查看本窗口主会话与本工作区守护进程内的具体 Shell 和宿主，并无需等待模型响应即可停止选定 Shell，同时防止停错任务和误报清理完成。

## 逻辑
/ps 是进入列表的唯一入口，像角色设置页一样临时替换输入栏，不采用居中浮层、全屏页面或在状态栏下展开。
列表一行代表一个 Shell 任务，显示任务编号、具体宿主（本窗口主会话，或守护进程内需求代理、角色及其运行身份）、状态、耗时和命令；任意窗口可对本工作区任一 Shell 请求停止，选中行蓝色突出且不附箭头。
同角色不同子运行通过独立身份区分，不能仅写角色名而让用户无法判断是哪次运行。
↑↓ 选择，Enter 查看详情，K 请求停止，Esc 关闭；停止确认及详情都在同一输入栏区域切换。
详情只显示任务身份、宿主、状态、完整命令、工作目录、进程编号、耗时和 Esc 返回列表，不提供输出查看、停止按钮或左右选择操作提示。
按 K 后的确认页展示任务编号、宿主和命令，默认选择取消；取消不发送停止请求；确认后只停止对应 Shell 及其后代，不停止宿主运行或其他 Shell；守护进程内的 Shell 由守护进程执行停止并回执。
发出请求后该行显示正在停止，确认进程清理后才显示已停止；已停止不是命令执行成功。控制操作不依赖模型服务响应，不自动重新启动被停止的命令，也不回滚命令已经产生的文件。
命令自然退出或列表刷新不改变已确认的目标身份，不能将动作转移到相同行号的新任务。
无法读取状态或无法确认停止时显示具体原因，未确认的任务保留在列表并标明不确定，不当作成功从管理范围删除。
列表超过可视容量时限高并滚动，关闭后恢复输入栏。空列表明确说明当前没有活动 Shell；读取失败显示具体原因，不以空列表替代错误。

## 约束
- C-1：当用户执行 /ps 时，系统应在输入栏位置打开管理页，保持原状态栏与 Agents 面板的相对顺序，不打开居中浮层、全屏页或在状态栏下展开；关闭后恢复输入栏。
- C-2：在 Shell 列表中，系统应一行展示一个任务及其编号、具体宿主、状态、耗时、命令，蓝色突出选中行且不附箭头；↑↓ 选择、Enter 进入详情、K 请求停止、Esc 关闭，按键不得同时操作 Agents 面板，详情或确认页不额外叠加弹窗。
- C-3：当用户查看 Shell 详情时，系统应只展示任务身份、宿主、状态、完整命令、目录、进程编号和耗时，并仅提示 Esc 返回列表；不显示查看输出或停止按钮，不显示左右选择及 Enter 执行提示。
- C-4：当列表超过可视容量或没有活动 Shell 时，系统应分别提供限高滚动或明确空态，列表增长不无限扩高；如果读取失败或选择期间目标结束，应显示具体错误或真实结束状态，不用其他任务的详情冒充原目标。
- C-5：当用户在列表按 K 时，系统应展示选定任务的编号、宿主和命令并请求确认，默认选择取消；取消不影响进程，确认只停止该 Shell 及其后代，不停止宿主或其他任务，不回滚成果。
- C-6：当系统处理停止请求时，系统应先显示正在停止，确认清理后才显示已停止，并将已停止与执行成功区分；此控制不等待模型响应，也不自动重启命令。
- C-7：如果确认期间任务已结束、列表顺序变化、目标身份无法核对或清理无法确认，系统应保持原目标身份，显示已结束或具体错误及不确定原因，不把请求发送给新占据原行位置或复用进程编号的无关任务；清理未确认的任务保留在列表并标明不确定，不误报清理完成。

## 例子
用户执行 /ps，看见同属实现角色的两个任务各有不同宿主标识；回车查看长命令的完整信息，再按 Esc 回到原列表，不出现输出查看按钮。发现测试卡住后选中它按 K，确认页注明该实现角色运行的具体身份；确认后仅停止该测试及其后代，开发服务和该角色运行本身不被终止，行上先显示正在停止、清理确认后显示已停止。

## 验收
### AC-1 输入栏位置的管理页 ← C-1
- 触发: 操作 执行 /ps 打开列表，再关闭
- Given: 当前主会话有 Shell 与 Agents 面板，原输入栏与状态栏位置可观察
- When: 对照页面位置和关闭后的焦点
- Then: 管理页仅临时替换输入栏，原底部内容相对顺序不变；没有居中浮层、全屏页或状态栏下展开，关闭恢复输入栏

### AC-2 每行归属可辨且按键不串界面 ← C-2
- 触发: 操作 在两个实现角色运行和主会话各有 Shell 时打开列表，选择各行、查看详情并发起再取消停止
- Given: 两个实现角色运行有不同运行身份，Agents 面板同时可见
- When: 查看行字段、选中效果和各层按键响应
- Then: 每个 Shell 恰占一行且字段齐全，两个运行的具体身份可区分；选中行蓝色且无箭头，按键只作用于 Shell 页面，详情与停止确认在输入栏区域切换，取消不停止进程

### AC-3 详情只读且无冗余操作 ← C-3
- 触发: 操作 选择带长命令的 Shell 后按 Enter，再按 Esc
- Given: 任务的宿主、目录、进程编号、命令和启动时间均已知
- When: 检查详情内容及按键提示
- Then: 身份与状态信息正确，完整命令可读，仅提示 Esc 返回列表；没有查看输出、停止按钮及左右操作、Enter 执行提示，Esc 返回列表

### AC-4 长列表空态与异常不冒充其他任务 ← C-4
- 触发: 操作 增加 Shell 直到超出可视容量并滚动到末项，另查看空列表、读取失败及详情目标自行结束的情况
- Given: 终端尺寸固定，目标任务身份已知
- When: 观察高度、末项可达性及三种边界反馈
- Then: 列表限高且末项可选择，空列表显示没有活动 Shell；读取失败显示具体错误，目标结束显示真实结束状态而不换成其他任务，终端高度不足时仍可返回

### AC-5 停止确认与精确范围 ← C-5
- 触发: 操作 在主会话和两个子运行均有 Shell 时，选中其中一个子运行的一条 Shell 按 K，先取消一次，再确认停止
- Given: 该 Shell 有后代，同一宿主还有另一条命令，且目标已经写入文件
- When: 查看确认页默认选择及两次操作后的活动
- Then: 确认页准确显示目标编号、宿主、命令并默认取消；取消无影响，确认后仅目标及后代停止，其他命令与宿主不被停止，原文件保留

### AC-6 停止反馈不依赖模型 ← C-6
- 触发: 操作 模型服务不可用时从列表确认停止一个可清理的 Shell
- Given: 命令正在运行且停止请求至清理确认之间可观察
- When: 查看停止过程及后续命令活动
- Then: 控制仍可执行，先显示正在停止，再于清理确认后显示已停止而非命令通过，命令不会被控制功能自动重启

### AC-7 刷新和失败不能导致误停 ← C-7
- 触发: 操作 打开停止确认后让目标自然结束并刷新列表，另测试状态读取失败、身份不匹配及后代清理无法确认
- Given: 同一列表包含持续运行的无关命令，原目标编号已知
- When: 确认原目标停止并查看结果
- Then: 新占据同一行或无关进程编号的命令不被停止；已结束目标如实反馈，读取或清理失败显示具体原因，清理未确认的任务仍在列表并标明不确定，没有被当作清理成功删除
