# Shell 状态汇总与入口

## 目的
让用户随时知道当前 Shell 数量和宿主分布，并从输入栏快速进入管理界面。

## 逻辑
Shell 汇总行位于输入栏及原状态栏下方、Agents 面板上方，原状态内容保持可见。
汇总以 shell：总数 · 主 agent：数量 · 角色：数量展示本窗口主会话与本工作区守护进程内需求代理及各角色的全部活动 Shell。
等待结果和后台运行都计入，按命令任务计数而不按后代进程或列表页数计数，同角色子运行在汇总中合计。
输入栏完全为空且无其他界面占用按键时，按 ↓ 先选中 Shell 汇总行，以蓝色整行突出但不打开页面。
在汇总行按 Enter 与 /ps 打开同一个输入栏替换式管理页，再按 ↓ 进入可见 Agents，Esc 返回输入栏。
停止不确定的任务与真实运行计数区分显示，读取失败明确报错，不把未知状态冒充零个任务。

## 约束
- C-1：当当前主会话有活动 Shell 时，系统应在原状态栏下方、Agents 上方显示 Shell 汇总行，统计本窗口主会话与本工作区守护进程内全部等待结果及后台运行任务，并按主 agent 与角色汇总；一个命令及其后代只计一个 Shell，工作区外和已确认结束的任务不计入。
- C-2：当输入栏完全为空且没有补全菜单、设置页或其他交互界面占用按键时，系统应让 ↓ 先选择可见 Shell 汇总行，蓝色整行突出且不附箭头、不立即打开；Enter 打开与 /ps 相同的管理页，↓ 进入可见 Agents，Esc 返回输入栏；输入非空或界面占用时不得抢按键。
- C-3：如果 Shell 状态读取失败或停止无法确认，系统应显示具体读取错误或单独的不确定数量，不将其显示为零活动或已清理；实际活动任务数量不受列表滚动、角色分组或重复刷新影响。

## 例子
主 agent 有一个开发服务，实现子代理有一条等待结果的测试和一个后台服务，汇总显示 shell：3 · 主 agent：1 · worker：2；空输入按 ↓ 选中整行，回车在输入栏位置打开管理页。

## 验收
### AC-1 所有活动 Shell 合计与布局 ← C-1
- 触发: 操作 主 agent 启动一个后台 Shell，两个 worker 各启动一个等待结果或后台 Shell，并在工作区外窗口启动额外命令
- Given: 其中一条命令包含多个后代，另有已经确认结束的命令；普通和全屏终端均可观察
- When: 查看底部布局和汇总，再使其中一个活动任务完全结束
- Then: 初始显示 shell：3 · 主 agent：1 · worker：2，汇总位于原状态栏与 Agents 之间且原状态内容可见；后代、工作区外窗口和已结束任务不多计，活动任务结束后按真实归属减去一个

### AC-2 空输入优先选择 Shell 入口 ← C-2
- 触发: 操作 在 Shell 与 Agents 均可见时从空输入按 ↓、Enter，再返回并测试 ↓ 进入 Agents 及 Esc 返回输入
- Given: 另可测试输入非空、补全菜单、设置页、Shell 管理页正在处理输入的情况
- When: 观察焦点与打开的界面，并与直接输入 /ps 对照
- Then: 合法空输入首次 ↓ 只蓝色选中 Shell 汇总行，不带箭头、不打开页面；Enter 与 /ps 效果相同，再 ↓ 才进入 Agents，Esc 返回输入；输入非空或其他界面占用时不抢按键、不同时操作 Agents

### AC-3 不确定与读取失败不伪造计数 ← C-3
- 触发: 操作 在两个真实运行任务之外制造一个停止不确定任务，再制造状态读取失败并滚动或刷新列表
- Given: 三个任务的实际状态可独立对照，列表容量小于全部任务数
- When: 查看汇总及错误反馈
- Then: 真实运行数为二，不确定另列而非当作第三个真实运行或清理成功；滚动刷新不改变总数，读取失败明确显示具体错误而不伪造零任务
