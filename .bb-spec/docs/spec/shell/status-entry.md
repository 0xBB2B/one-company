# Shell 状态汇总

## 目的
让用户随时知道当前活动 Shell 的数量和宿主分布，而不占用额外的界面行或按键。

## 逻辑
Shell 汇总是原状态栏内的一段纯文本，显示本窗口主会话与本工作区守护进程内需求代理及各角色的全部活动 Shell：总数，以及按主会话与各角色分列的数量；原状态栏其他内容保持可见。
等待结果和后台运行都计入，按命令任务计数而不按后代进程或列表页数计数，同角色的不同子运行在汇总中合计；工作区外和已确认结束的任务不计入。
汇总文本不可聚焦、不响应按键，也不拦截输入栏或其他界面的任何按键；查看与停止具体 Shell 的唯一入口是 /ps。
停止请求已发出但清理未确认的任务与真实运行计数区分显示；读取失败明确报错，不把未知状态冒充零个任务。

## 约束
- C-1：当本窗口主会话或本工作区守护进程内存在活动 Shell 时，系统应在原状态栏内以纯文本显示汇总，统计本窗口主会话与本工作区守护进程内全部等待结果及后台运行任务，并按主会话与各角色分列；一个命令及其后代只计一个 Shell，工作区外和已确认结束的任务不计入；没有活动 Shell 时不显示汇总。
- C-2：当用户在输入栏或任何界面按键时，系统应不让汇总文本获得焦点或拦截按键，按键按其所在界面的原有含义处理；进入 Shell 列表只经 /ps。
- C-3：如果 Shell 状态读取失败或停止清理无法确认，系统应显示具体读取错误或单独的不确定数量，不将其显示为零活动或已清理；实际活动任务数量不受列表滚动、角色分组或重复刷新影响。

## 例子
主会话有一个开发服务，实现角色有一条等待结果的测试和一个后台服务，状态栏内显示总数 3、主会话 1、实现角色 2；用户在空输入按 ↓ 不会选中这段文本，输入 /ps 才打开列表。

## 验收
### AC-1 所有活动 Shell 合计与位置 ← C-1
- 触发: 操作 主会话启动一个后台 Shell，两个实现角色运行各启动一个等待结果或后台 Shell，并在工作区外窗口启动额外命令
- Given: 其中一条命令包含多个后代，另有已经确认结束的命令；普通和全屏终端均可观察
- When: 查看状态栏与汇总，再使其中一个活动任务完全结束，最后让全部任务结束
- Then: 初始显示总数 3、主会话 1、实现角色 2，汇总位于原状态栏内且原状态内容可见；后代、工作区外窗口和已结束任务不多计，活动任务结束后按真实归属减一；全部结束后汇总消失

### AC-2 汇总不可聚焦不抢按键 ← C-2
- 触发: 操作 在汇总可见且 Agents 面板可见时从空输入按 ↓、Enter，再输入 /ps
- Given: 另可测试输入非空、补全菜单、设置页正在处理输入的情况
- When: 观察焦点与打开的界面
- Then: ↓ 与 Enter 均未选中或打开汇总，按键按各自界面原有含义生效；只有 /ps 打开 Shell 列表

### AC-3 不确定与读取失败不伪造计数 ← C-3
- 触发: 操作 在两个真实运行任务之外制造一个已发停止但清理未确认的任务，再制造状态读取失败并滚动或刷新列表
- Given: 三个任务的实际状态可独立对照，列表容量小于全部任务数
- When: 查看汇总及错误反馈
- Then: 真实运行数为二，不确定另列而非当作第三个真实运行或清理成功；滚动刷新不改变总数，读取失败明确显示具体错误而不伪造零任务
