# 可执行且精简的规划产物

## 目的
把规划时间用于行为、依赖和验证判断，减少重复文档生成与边写边推翻。

## 逻辑
规划角色在同一次运行中先确定任务骨架，再生成自包含任务正文。
任务骨架明确行为切片、文件归属、真实依赖、运行入口切换节点和验证边界。
骨架体现在任务索引与相应任务的协作说明中，不额外创建长期报告或增加用户确认轮次。
增量规划从变化范围及其直接依赖开始核实，发现真实影响再扩展读取，未受影响任务不重写。
规范原文仍须准确内联；机械规则使用固定检查入口，不临时开发任务生成器或检查器。
技术前提未核实或约束无法同时满足时如实报告，不以形式合格冒充可执行。

## 约束
- C-1：当规划角色生成任务时，系统应先核对包含行为、归属、依赖、切换节点及验证边界的任务骨架，再补正文；全部在同次规划内完成，不新增角色或确认轮次。
- C-2：当规划为增量时，系统应按变化及真实依赖确定读取和修改范围，保持未受影响任务的内容与运行字段不变，不默认重写整套任务。
- C-3：当规划角色检查产物时，系统应使用固定机械检查入口，并准确内联所需原文；不得为每次规划临时编写生成器、验收解析器或检查器。
- C-4：如果计划将提前移除当前仍在使用的执行入口，或关键接口、环境、文件约束未得到核实，系统应指出受影响任务和待验证条件，不报告规划已可执行。

## 例子
一个迁移计划会在替代入口可用前删除现用入口，规划者先报告切换顺序阻塞，而不是先生成全部任务后等实现者发现无法继续派工。

## 验收
### AC-1 骨架成立后产出局部计划 ← C-1, C-2, C-3
- 触发: 操作 对两个受影响任务和一个未受影响任务执行增量规划
- Given: 需求已确认，依赖和运行入口切换条件可核实，固定机械检查入口可用
- When: 规划角色完成任务产出
- Then: 同次运行先核对骨架再生成正文，产物含归属、真实依赖、切换条件和验证边界，所需原文准确内联，未受影响任务逐字不变，没有额外角色、确认轮次或临时检查器

### AC-2 不能以形式合格掩盖不可执行 ← C-4
- 触发: 操作 分别规划提前删除现用入口和关键验证环境缺失的任务
- Given: 候选任务满足文件数量和行数限制，但所述运行条件尚未成立
- When: 规划角色核对任务骨架
- Then: 报告具体受影响任务和未满足条件，不把任务宣布为可执行，也不未经授权改变接口或扩大范围
