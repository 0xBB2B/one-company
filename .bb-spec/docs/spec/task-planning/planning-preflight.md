# 规划启动前检查

## 目的
让规划角色只在需求与编辑条件就绪后启动，避免启动后才发现无法规划。

## 逻辑
需求代理在派工前核对需求确认状态、完整规划或增量规划类型、受影响任务的编辑状态以及范围占用。
增量规划提供已确认的变化摘要、相关位置和已知环境限制；摘要用于定位，不替代规划角色核实事实。
存在已完成任务需要重规划时，由需求代理先核对原运行和成果，再按获准变更调整受影响任务状态。
未知技术前提必须被明确列出；缺少本轮规划必需的条件时报告具体阻塞，不启动必然空跑的规划。
独立工作目录中的派工必须由具备对应目录权限的需求代理执行，不能借用其他目录的授权。

## 约束
- C-1：当需求代理准备规划派工时，系统应先核对已确认需求、规划类型、受影响任务编辑状态、范围占用及已知验证条件，再决定是否启动。
- C-2：如果需求未确认、待改任务尚未解除完成状态限制、原运行可能继续写入或派工目录不在授权范围内，系统应说明具体阻塞并不启动规划，不改写旧运行结果或绕过权限。
- C-3：当增量规划条件满足时，系统应向规划角色提供变化摘要、相关位置和已知前提，并要求其独立核实；不为未受影响任务重置运行状态。

## 例子
两个已完成任务中只有一个需要调整，需求代理核实其原运行已结束并更新受影响状态后再派工，另一个任务与成果保持不变。

## 验收
### AC-1 就绪后一次派工 ← C-1, C-3
- 触发: 操作 对已确认的局部变更启动增量规划
- Given: 两个任务中只有一个受影响，其原运行已停止且编辑状态已按授权调整，相关范围无占用
- When: 需求代理准备规划派工
- Then: 先完成前检再启动一次规划，输入含变化摘要、相关位置和环境限制，未受影响任务状态不变，摘要不被当作免核实证明

### AC-2 阻塞前提不触发空跑 ← C-1, C-2
- 触发: 操作 分别对未确认需求、仍标完成的待改任务、原运行可能写入的范围和无权限工作目录请求规划
- Given: 每个案例只有所述一项前提不满足，可观察派工次数及原记录
- When: 需求代理执行前检
- Then: 每个案例均显示具体阻塞且规划派工次数为零，没有伪改运行结果、占用证明或目录授权
