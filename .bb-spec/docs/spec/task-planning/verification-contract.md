# 任务验证约定

## 目的
让测试在实现前就明确要证明什么，避免测试通过却绕开实际需求。

## 逻辑
每个任务的验证方式包含紧凑的验证约定，不另外生成长篇测试设计文档。
约定说明公开入口及其真实契约、必须成立的行为、适用场景和测试替代边界。
涉及外部系统时核实使用版本、返回所代表的完成时机以及事件或数据的含义。
按任务选择正常、拒绝、重复、交错、超时、退出等场景，不适用项简要说明理由，不机械穷举组合。
涉及状态控制、安全边界、宿主接入或不可重复副作用的任务，由需求代理在实施前核对验证方案。
验证分为开发中目标测试、交付前受影响回归、全部任务完成后的集成验证，并明确环境与责任。
方案核对不是实际测试代码审查，也不替代完成后的统一审查与验收。

## 约束
- C-1：当规划角色描述任务验证时，系统应明确真实入口与契约、必须成立的行为、适用及不适用场景、允许模拟和必须真实贯通的边界。
- C-2：当任务涉及状态控制、安全边界、宿主接入或不可重复副作用时，系统应在实施前由需求代理核对验证方案，不增加测试角色、单任务审查派工或第二次实现派工。
- C-3：当规划验证责任时，系统应列出目标测试、受影响回归及集成验证的范围、执行条件和责任；无法自动观察的实机要求必须明确由谁在何处完成。
- C-4：如果真实契约或必需验证条件无法确认，系统应指出具体缺项并阻止把不完整方案视为实施就绪，不以模拟成功、模型自觉遵守提示或已有测试数量替代证明。

## 例子
暂停任务不仅验证一次暂停成功，还验证继续期间再次暂停、停止与暂停交错，以及模型忽略核对提示时不会重复未知写入。

## 验收
### AC-1 高风险验证方案覆盖真实行为 ← C-1, C-2, C-3
- 触发: 操作 规划一个具有暂停、继续和写入副作用的任务
- Given: 真实控制入口及执行条件可核实，存在受影响的已有测试
- When: 需求代理核对规划交付
- Then: 任务列明完成时机、不可重复写入要求、重复和交错场景及模拟边界，区分三层验证范围和责任，核对在实施前完成且没有新增角色或单任务审查

### AC-2 缺失前提不能用模拟通过替代 ← C-3, C-4
- 触发: 操作 提交仅安排模型主动核对的副作用测试方案，以及要求实机观察但未明确环境和责任的任务
- Given: 两个方案均声称已有目标测试可以通过
- When: 需求代理核对验证约定
- Then: 分别指出缺少系统阻止重放的证明和实机验证安排，不把两个方案判为实施就绪，测试数量不改变结论
