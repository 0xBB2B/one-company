# 运行信息工具更新

## 目的
让 AI 用小范围请求更新进度，由程序约束数据而不反复编辑整份文件。

## 逻辑
本包流程通过专用工具查询、初始化和修改运行信息。
请求明确指定需求、可选任务及更新内容，查询可限定任务或字段，不要求传入完整文档或整份状态。
普通字段更新与阶段推进分开校验，备注不能夹带阶段、定义正文或伪造完成证据。
查询返回可用于核对更新先后的状态版本，更新基于已读取版本；过期请求重新查询后再处理。
一次请求的字段全部通过检查才作为一个更新生效，不允许只写入其中一部分。
工具成功回执只含归属、变更字段、状态版本和必要提示，不重复整份定义、全部历史或运行证据。

## 约束
- C-1：当主会话查询或修改运行信息时，系统应通过专用工具提供定向查询和局部更新，不要求完整文档或整份运行信息作为输入。
- C-2：当工具处理更新时，系统应检查归属、字段白名单、类型和原有角色权限，并将普通字段更新与阶段推进分别验证；任一字段不合法时整个请求不得生效。
- C-3：当两个窗口根据同一状态版本更新同一需求时，系统应拒绝后到的过期更新，保留先前已成功内容，并提示重新读取，不静默覆盖。
- C-4：当更新成功时，系统应返回包含归属、变更字段和新状态版本的简短回执；如果保存未确认，应返回失败或结果不明，不伪报成功或盲目重复写入。

## 例子
AI 只提交任务编号、新备注和已读取的状态版本即可更新备注；另一窗口持旧版本更新时收到冲突提示，而不是覆盖新备注。

## 验收
### AC-1 局部请求与定向查询 ← C-1, C-4
- 触发: 操作 只查询一个任务的备注和状态，再仅提交该任务的新备注
- Given: 需求包含两个任务及较长的定义和历史记录
- When: 通过工具查询并更新
- Then: 无需重传文档或全部任务，另一任务不变，回执含归属、变更字段和版本且不包含完整定义或历史

### AC-2 非法字段不产生部分更新 ← C-2
- 触发: 操作 同一请求提交合法备注和未知字段，再以普通备注更新请求夹带完成阶段或越权修改
- Given: 已保存各请求前的运行信息
- When: 工具处理请求
- Then: 各请求均被拒绝，合法备注也未被部分写入，阶段和角色权限没有扩大

### AC-3 两窗口过期更新保护 ← C-3
- 触发: 操作 两个窗口读取同一版本，先后提交不同备注
- Given: 两次请求都带读取时的版本
- When: 第一窗口成功后第二窗口提交
- Then: 第二次收到版本冲突，第一窗口内容保留，重新读取可获得当前内容与版本

### AC-4 保存异常不虚报成功 ← C-4
- 触发: 操作 在保存过程中制造写入失败或结果无法确认
- Given: 有可查询的更新前内容及本次更新请求
- When: 观察工具回执并重新查询
- Then: 不返回已确认成功；可区分失败与结果不明，并提供核对依据而不盲目重放更新
