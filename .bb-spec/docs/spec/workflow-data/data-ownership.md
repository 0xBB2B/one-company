# 数据归属

## 目的
让需求和任务文档只因定义变化而更新，让流程数据在创建需求文档与独立工作目录之前即可记录，并在同仓库的不同工作目录中定位同一需求。

## 逻辑
需求名称、标题、创建日期、目标、非目标、规范变更及边界属于需求定义；任务编号、标题、依赖、文件范围、验收引用、验证命令和正文属于任务定义。
需求阶段、任务进度、子运行关联、完成提交、备注、运行描述、执行时间、返修轮次、阻塞原因和开发现场属于运行信息。
定义文档与完整验收报告保存在仓库；运行信息和决策只保存在本机用户数据区，专用工具是唯一写入途径，不设第二套可写来源。
运行信息和决策以仓库身份和需求身份归属，不以当前对话所在目录或分支名称代替身份；同仓库的多个 worktree 定位同一需求的数据，不同需求与不同仓库的数据分别保存。
首次合法记录请求即可建立归属记录，不要求需求文档、任务文档或验收报告已经存在；工作目录只是需求的开发现场，删除 worktree 或功能分支不删除流程数据。
流程数据仅保存在本机，不随 Git 提交、推送或克隆同步；普通运行字段更新不生成决策记录，也不改变验收报告。

## 约束
- C-1：当用户查询或修改需求及任务定义时，系统应以仓库文档为定义来源，不将目标、业务规则或验证方式移入运行描述。
- C-2：当需求阶段、任务运行字段或开发现场更新时，系统应只经专用工具更新本机用户数据区中的运行信息，不在需求和任务文档中保存或同步这些字段，不因普通进度更新追加决策；工具之外写入的内容不作为合法运行信息。
- C-3：当验收者交付报告时，系统应将完整报告保存在仓库中的指定位置并保持验收者唯一写入；运行信息更新不得转录、覆盖或回滚报告。
- C-4：当主会话首次记录已明确归属仓库与需求的流程数据时，系统应将其保存在本机用户数据区，并允许需求文档和计划中的 worktree 尚不存在。
- C-5：当用户从同仓库的不同 worktree 查询同一需求时，系统应定位同一份归属记录；不同仓库或不同需求不得因名称相同而混用数据。
- C-6：当本需求的 worktree 或功能分支被删除时，系统应保留已保存的流程数据；Git 提交、推送或克隆不得自动携带这些数据。
- C-7：如果仓库或需求身份缺失、冲突或无法核对，或请求试图用运行信息入口修改需求或任务定义，系统应拒绝写入并显示具体原因，保持定义、报告和其他归属的数据不变。

## 例子
用户在需求文档尚未建立时记录创建 worktree 的授权，得到本机记录回执；随后在新 worktree 中任务从进行中进入失败并记录原因，任务定义文档没有变化，验收者之后写出的完整验收报告仍能随代码审阅。

## 验收
### AC-1 定义内容由仓库保存 ← C-1
- 触发: 操作 创建需求及任务定义并通过正常文档编辑修改目标和验证方式
- Given: 定义与运行信息已分离
- When: 查询文档及本机运行信息
- Then: 仓库文档包含完整需求和任务定义，本机运行信息不替代这些定义

### AC-2 推进任务不改定义也不生成决定 ← C-2
- 触发: 操作 通过工具推进任务并更新运行备注、描述、提交关联及执行时间，再绕过工具向数据区写入一条运行字段
- Given: 已保存定义文档和决策记录的调用前内容，推进前提满足
- When: 完成更新并查询本机运行信息
- Then: 工具更新反映在查询中，需求和任务定义文档与调用前相同，决策记录未新增普通进度条目，绕过工具写入的内容不被当作合法运行信息

### AC-3 验收报告整体保留 ← C-3
- 触发: 操作 由验收者写入指定报告，再由主会话更新运行备注
- Given: 报告含结论、日期、逐项结果和正文
- When: 检查仓库报告与运行信息
- Then: 完整报告仍在指定位置且备注更新未改变报告，主会话没有另写一份报告

### AC-4 文档与 worktree 创建前记录 ← C-4
- 触发: 操作 在需求文档与计划工作目录都不存在时记录一条已授权决定
- Given: 当前仓库可识别，需求身份明确，本机用户数据区尚无该需求
- When: 通过决策工具提交合法决定
- Then: 返回可查询的记录回执，记录位于本机用户数据区，未创建需求文档或 worktree

### AC-5 同仓库共享且不同归属隔离 ← C-5
- 触发: 操作 从同仓库的两个 worktree 查询同一需求，再查询同名的另一仓库需求和同仓库另一需求
- Given: 第一个需求已有一条带唯一标记的记录
- When: 分别通过工具查询这四个归属
- Then: 前两个查询返回同一条记录，后两个不返回该记录

### AC-6 工作目录清理与 Git 不带走记录 ← C-6
- 触发: 操作 删除已完成需求的 worktree 和功能分支，再提交推送并克隆该仓库
- Given: 清理已获准且不存在活动写入，本机已有该需求流程数据
- When: 在本机查询原需求并检查 Git 交付内容
- Then: 原需求记录仍可查询，新增提交和克隆内容不含本机流程数据

### AC-7 身份不明与定义改写被拒绝 ← C-7
- 触发: 操作 在仓库身份不可确认或需求身份相互冲突时提交更新，再用运行信息更新请求提交新的任务目标
- Given: 已有一个名称相似但身份不同的需求，没有定义修改授权
- When: 工具处理两个请求
- Then: 两个请求均被拒绝并显示原因，相似需求及其他归属的数据、定义与验收报告均未改变
