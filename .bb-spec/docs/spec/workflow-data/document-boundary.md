# 文档与运行数据分离

## 目的
让需求和任务文档只因定义变化而更新，不因执行进度产生无意义改动。

## 逻辑
需求名称、标题、创建日期、目标、非目标、规范变更及边界属于需求定义。
任务编号、标题、依赖、文件范围、验收引用、并行声明、验证命令和正文属于任务定义。
需求阶段、任务进度、子运行关联、完成提交、备注、运行描述、执行时间、返修轮次、阻塞原因和开发现场属于运行信息。
定义文档与完整验收报告保存在仓库；运行信息和决策保存在本机用户数据区，不设置第二套可写来源。
验收报告的结论和日期与报告正文一起保存，需求阶段必须经过门禁才推进，不由报告中的一个词直接推断。
普通运行字段更新不生成决策记录，也不改变验收报告。

## 约束
- C-1：当用户查询或修改需求及任务定义时，系统应以仓库文档为定义来源，不将目标、业务规则或验证方式移入运行描述。
- C-2：当需求阶段、任务运行字段或开发现场更新时，系统应只更新本机运行信息，不在需求和任务文档中保存或同步这些字段，也不因普通进度更新追加决策。
- C-3：当验收者交付报告时，系统应将完整报告保存在仓库中的指定位置并保持验收者唯一写入；运行信息更新不得转录、覆盖或回滚报告。
- C-4：如果请求试图用运行信息入口修改需求或任务定义，或以报告结论代替需求完成门禁，系统应拒绝请求并保持定义、报告和需求阶段不变。

## 例子
任务从执行中进入失败并记录原因，任务定义文档没有变化；验收者之后写出的完整验收报告仍能随代码审阅。

## 验收
### AC-1 定义内容继续由仓库保存 ← C-1
- 触发: 操作 创建需求及任务定义并通过正常文档编辑修改目标和验证方式
- Given: 定义与运行信息已分离
- When: 查询文档及本机运行信息
- Then: 仓库文档包含完整需求和任务定义，本机运行信息不替代这些定义

### AC-2 推进任务不改定义也不生成决定 ← C-2
- 触发: 操作 通过工具推进任务并更新运行备注、描述、提交关联及执行时间
- Given: 已保存定义文档和决策记录的调用前内容，推进前提满足
- When: 完成更新并查询本机运行信息
- Then: 查询反映更新，需求和任务定义文档与调用前相同，决策记录未新增普通进度条目

### AC-3 验收报告整体保留 ← C-3
- 触发: 操作 由验收者写入指定报告，再由主会话更新运行备注
- Given: 报告含结论、日期、逐项结果和正文
- When: 检查仓库报告与运行信息
- Then: 完整报告仍在指定位置且备注更新未改变报告，主会话没有另写一份报告

### AC-4 定义改写及完成捷径被拒绝 ← C-4
- 触发: 操作 用运行信息更新请求提交新的任务目标，再仅凭报告结论请求完成需求
- Given: 没有定义修改授权，也没有满足完成门禁的运行证据
- When: 分别提交两个请求
- Then: 两个请求均被拒绝，定义、验收报告和需求阶段保持不变
