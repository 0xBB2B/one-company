# 流程数据安全迁移

## 目的
将当前项目已有决策和运行信息移到本机用户数据区，不丢失记录或让活动写入产生两套进度。

## 逻辑
迁移工具先只读预检目标仓库及其全部 worktree，覆盖进行中和已完成需求，不扫描其他项目。
正式迁移必须获准且确认全部相关写入方停止，并保证完成后不再使用迁移前的写入方式；工具不擅自停止其他窗口。
迁移保存需求和任务归属、运行字段及决策原始内容、编号和替代关系，重复来源不能造成重复记录。
同一身份的来源分叉、阶段冲突或保护证据不匹配时报告具体来源，不用时间戳、分支名或自动拼接选出胜者。
完整核对目标内容与全部源数据后，才移除仓库中的决策和运行字段；定义正文、验收报告及 Git 历史不被改写。
迁移状态可查询；失败或中断后先核对已有成果，不返回已完成、不盲目重放或重编号。

## 约束
- C-1：当用户请求迁移预检时，系统应只读列出目标仓库全部 worktree 中所有需求的来源、覆盖范围及问题，包括已完成需求，不检查未指定的其他仓库。
- C-2：当请求正式迁移时，系统应检查迁移授权、全部相关写入停止及切换写入方式的条件；任何条件未确认都应阻塞，不擅自暂停其他窗口，也不边写边迁。
- C-3：当迁移合法数据时，系统应保持决定内容、编号和引用以及任务运行信息的含义；相同记录只迁入一次；来源分叉、冲突或损坏时不得覆盖、猜测或重编号。
- C-4：当全部目标数据重新读取且与源数据核对成功时，系统应仅移除已迁出的决策和运行字段，并保留定义、验收报告及既有交付保护效力；完成后只有本机来源可写，不改写 Git 历史。
- C-5：如果迁移失败、中断或发现源数据发生变化，系统应报告未完成及已执行范围，校验完成前不得删除源数据；再次执行先核对迁移进度，不能重复追加、误删或虚报完成。

## 例子
三个 worktree 都有同一需求的记录，其中一个仍有窗口写入；预检能列出来源，但正式迁移被阻塞。停写后若记录出现分叉，仍需先处理分叉，不能挑更新时间较晚的一份覆盖。

## 验收
### AC-1 只读预检覆盖全部指定来源 ← C-1
- 触发: 操作 对含两个 worktree、进行中及已完成需求的仓库执行迁移预检
- Given: 本机另有未指定仓库，保存预检前各来源内容
- When: 查看预检结果并核对文件
- Then: 指定仓库全部来源均被列出且未改变，未指定仓库没有被扫描或迁移

### AC-2 活动写入阻塞正式迁移 ← C-2
- 触发: 操作 分别在未授权、仍有活动写入或尚不能停止旧写入方式时请求迁移
- Given: 其他窗口可能继续处理任务
- When: 工具检查迁移前提
- Then: 请求被阻塞并列明未满足条件，没有移动源数据或擅自停止其他窗口

### AC-3 保真与冲突保护 ← C-3
- 触发: 操作 迁移含重复相同记录的合法来源，再分别预检同编号不同内容、冲突任务阶段和损坏记录
- Given: 已记录各来源决定原文、编号、替代关系与运行字段
- When: 查询迁移或预检结果
- Then: 合法来源不重复且内容含义保持，其余场景列出冲突来源并阻塞，不覆盖、拼接或重编号

### AC-4 校验成功后只清除迁出内容 ← C-4
- 触发: 操作 在全部停写且来源一致时执行完整迁移
- Given: 迁移获准，定义、报告、运行数据和已完成交付保护证据可核对
- When: 核查目标、源文件和写入入口
- Then: 数据可从本机查询，仓库仅移除决策和运行字段，定义与报告保留且保护仍有效，旧写入方式不再可用，Git 历史未被改写

### AC-5 中断与来源变化不丢数据 ← C-5
- 触发: 操作 在目标写入、校验和清理阶段分别中断迁移，并模拟源数据改变后再次执行
- Given: 已保存源数据内容及每阶段已确认的迁移进度
- When: 查询迁移状态并重试
- Then: 明确未完成及已执行范围，校验前源数据不被删除；重试先核对进度，数据不重复、源变化不被覆盖、未完成不被报告为完成
