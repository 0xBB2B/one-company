# 需求与任务状态推进

## 目的
用程序阻止非法状态和跳过验证的阶段推进，使进度具有明确含义。

## 逻辑
需求阶段限于起草、已确认、已规划、执行中、审查中、验收中、已完成、已拒绝八种。
任务进度限于待办、进行中、已完成、失败四种；子运行状态独立存在，不代替任务进度。
正常需求顺序为起草、已确认、已规划、执行中、审查中、验收中、已完成，每一步都检查其前提；工作流形状声明包含某项阶段检查时才要求对应证据，形状跳过的阶段检查以确认形状时记录的用户决定作为该阶段检查的证据。
审查、验收与交付证据只以运行身份提供，工具自行读取该运行由守护进程写入的结构化结果并核对其绑定的需求、任务与版本。
任务先登记进行中，再关联子运行；子运行交付满足结构化阶段检查后，验证命令成功且有本次提交时已核对提交信息，才可完成任务。
已有实现满足需求且无改动时仍须通过对应的结构化证据与验证，不要求伪造新提交。
阶段回退限于审查中退回执行中、验收中退回执行中、已规划退回已确认，以及已完成需求的提交前白盒失败退回执行中，只由工具在阶段检查失败归因后触发，带理由与决定编号并留下原因记录；返修保留原运行与失败原因。
定义变更需要用户确认，已完成需求不原地重开；增加任务或重验不得沿用失效的完成结论；纯技术失败不自动将需求判为已拒绝。

## 约束
- C-1：当工具初始化或更新状态时，系统应只接受约定的需求八种阶段及任务四种进度，拒绝未知值和将子运行状态写成任务进度。
- C-2：当需求正常推进时，系统应逐阶段核对前提：已确认需用户确认回执，已规划需规划产物核验，执行中需调度就绪，审查中需全部任务完成，验收中需匹配版本的白盒审查通过结果，已完成需黑盒验收结构化结果与指定报告一致且全部通过；工作流形状声明包含该阶段检查时才要求对应证据，形状跳过的阶段检查以确认形状时记录的用户决定作为该阶段检查的证据。
- C-3：当推进需求阶段或完成任务需要审查、验收或交付证据时，系统应只接受运行身份，自行读取该运行由守护进程写入的结构化结果并核对其绑定的需求、任务与版本；调用方内联提供的证据对象应被拒绝，绑定不匹配的结果不作为证据。
- C-4：当任务开始或结束时，系统应先登记进行中再关联实际子运行；已完成必须具备合法交付与成功验证，有本次提交时还须核对提交信息，无改动时须有既有实现已满足要求的证据；失败应记录失败与具体原因；启动回执或子运行结束不得直接完成任务。
- C-5：当阶段检查失败经归因后需要回退时，系统应只由工具触发带理由与决定编号的阶段回退，回退限于审查中退回执行中、验收中退回执行中、已规划退回已确认，以及已完成需求的提交前白盒失败退回执行中；回退前核对受影响任务的原运行已停止与已授权范围；协调本次返修的需求代理可继续运行，自动返修使用 AI 归因决定，涉及产品选择或追加返修轮次时使用用户决定，回退后留下原因记录并保留原运行与失败原因；调用方直接请求的阶段回退应被拒绝。
- C-6：当发生产品变更或拒绝请求时，系统应只在产品裁决下将需求置为已拒绝；纯技术失败保持阻塞，已完成需求不得原地重开，定义变更须经用户确认后才生效。

## 例子
子代理正常结束但任务验证命令失败，任务被记录为失败，需求仍处于执行中，不能仅凭子运行结束进入审查中；白盒审查返回未通过并归因为实现缺陷后，工具把需求从审查中退回执行中并记录理由与决定编号。

## 验收
### AC-1 状态集合不可扩张 ← C-1
- 触发: 操作 提交未知需求阶段、未知任务进度及子运行的已暂停值作为任务进度
- Given: 已有合法需求阶段和任务进度
- When: 通过状态工具请求修改
- Then: 三类请求均被拒绝，原值不变，错误提示列明对应合法集合

### AC-2 阶段检查随形状逐项核对 ← C-2
- 触发: 操作 对包含白盒审查与黑盒验收的形状按正常顺序推进，对每一步分别移除必要前提后请求推进再补齐；另对声明跳过白盒审查的形状请求进入验收中
- Given: 每次失败测试使用该阶段合法起始状态，完成测试含匹配的结构化结果与指定报告，跳过形状已记录确认时的用户决定
- When: 通过工具推进已确认、已规划、执行中、审查中、验收中、已完成
- Then: 缺少前提时均保持原阶段并给出缺失原因，前提齐全才依序推进，直接从起草跳到已完成被拒绝；跳过白盒审查的形状以该用户决定作为审查证据进入验收中，未记录该决定时被拒绝

### AC-3 证据只按运行身份读取 ← C-3
- 触发: 操作 分别以合法运行身份、内联证据对象、绑定其他需求或旧版本的运行身份请求推进验收中与完成任务
- Given: 合法运行由守护进程写入了绑定当前需求、任务与版本的通过结果
- When: 工具处理三类请求
- Then: 合法运行身份的请求读取到结构化结果并推进；内联证据对象被拒绝且阶段不变；绑定不匹配的运行身份被拒绝并显示不匹配项

### AC-4 子运行与任务完成分离 ← C-4
- 触发: 操作 启动任务，依次测试只有启动回执、交付失败、验证失败、有提交但未核对、全部条件满足及无改动的合法交付
- Given: 各场景均有明确任务与子运行归属，无改动场景有既有实现证据和成功验证
- When: 查询任务并请求完成
- Then: 启动先显示进行中，前四种场景不得显示已完成，失败有具体原因，后两种满足阶段检查后完成任务，无改动场景不伪造提交

### AC-5 阶段回退带理由与决定编号 ← C-5
- 触发: 操作 分别在审查中、验收中的阶段检查失败归因后由工具触发回退，在已规划阶段因规划产物核验失败归因后触发回退；再由调用方直接请求回退、在原运行未停止时请求回退、请求没有提交前白盒失败证据的已完成退回执行中
- Given: 合法场景有归因结果、已授权范围与对应决定编号，其余场景分别缺少所需依据或不在允许的回退集合内
- When: 通过工具处理回退请求
- Then: 三种合法回退分别到达执行中、执行中、已确认，记录含理由、决定编号与原运行关联；其余请求被拒绝，阶段不变且不重复派工

### AC-6 拒绝与重开有依据 ← C-6
- 触发: 操作 以产品裁决请求置为已拒绝，再以纯技术失败请求置为已拒绝，并请求重开已完成需求与未经确认的定义变更
- Given: 产品裁决场景有对应决定，其余场景缺少产品裁决或用户确认
- When: 通过工具处理请求
- Then: 产品裁决请求成功置为已拒绝；纯技术失败保持阻塞而非已拒绝，已完成需求未被重开，未确认的定义变更未生效
