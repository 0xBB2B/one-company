# 版本关联与安全续接

## 目的
让同一窗口或另一窗口准确找到进度，而不把其他工作版本的完成记录当作当前结果。

## 逻辑
需求定位、规划检查、调度、修订和对账从本机流程数据获取运行阶段，不从定义文档推断阶段。
运行记录关联需求、任务、子运行以及适用的定义和代码版本，工作目录改变不改变需求身份。
同一需求在不同 worktree 的内容可能不同，数据能定位不代表当前版本已经验证通过。
续接先查询原运行接管的任务与工作现场，任务的停止状态以 Shell 登记表为准；仍有活动任务时不重复派工。
已验收交付的保护与实际文档内容相符才可继续关联操作，不因运行信息迁出而取消保护。
数据缺失、损坏或证据失效时明确说明，不从报告中的通过字样、分支名称或文件时间猜测完成。

## 约束
- C-1：当规划、调度、修订、对账或续接需要需求与任务进度时，系统应查询本机流程数据并返回明确归属；多个待续需求需用户选择，不能任取一个。
- C-2：当使用完成状态或审查验收证据时，系统应核对其对应的定义、代码与工作现场；版本改变或不匹配时应标明待重新核对并拒绝沿用旧通过结果。
- C-3：当续接涉及原任务执行时，系统应先核对原子运行接管的任务、写入范围和停止情况，任务的停止状态以 Shell 登记表为准；登记表仍有该运行的活动任务时不得重复派工，也不得自动回滚已有成果。
- C-4：如果本机状态或已完成交付保护证据缺失、损坏或不匹配，系统应显示具体阻塞并保留现有文件，不初始化为完成、不把查询失败解释为没有需求，也不自动根据当前内容重建通过证据。

## 例子
一个 worktree 的任务已经完成，但另一个 worktree 修改了同一任务的实现；查询能找到原记录，工具却拒绝把旧完成证据用于修改后的版本。

## 验收
### AC-1 流程从本机定位进度 ← C-1
- 触发: 操作 在定义文档不含运行字段的条件下依次执行规划检查、调度、修订、对账和续接
- Given: 本机分别存在一个或两个进行中需求，状态和文档归属明确
- When: 各入口读取进度
- Then: 使用本机记录得到正确阶段和任务；续接有两个候选时要求选择，不依赖文档中的运行字段

### AC-2 不同版本不共享通过结论 ← C-2
- 触发: 操作 在一个 worktree 取得任务完成及审查证据，再从内容已改变的另一 worktree 请求据此推进
- Given: 两个工作目录属于同仓库同需求，但当前定义或代码与证据版本不同
- When: 查询并尝试放行当前版本
- Then: 可以定位原记录，但明确提示版本不匹配，不能沿用已完成或通过结论放行，原证据没有被伪造为新证据

### AC-3 未停止不重派 ← C-3
- 触发: 操作 分别在 Shell 登记表仍有原运行活动任务时和登记表显示其任务全部停止后续接任务
- Given: 各场景都有原运行关联及已经产生的成果
- When: 执行续接核对
- Then: 仍有活动任务时不重复派工、保留成果并列出活动任务；全部停止后仍核对版本、范围和证据再决定续接位置

### AC-4 缺失和损坏不冒充完成 ← C-4
- 触发: 操作 分别移除本机状态、损坏状态、移除交付保护证据或改变已保护文档后查询和续接
- Given: 仓库仍有需求文档与含通过文字的报告
- When: 工具处理请求
- Then: 各场景报告对应阻塞，不将缺失状态默认设为完成或没有需求，不改写报告或自动重建通过证据
