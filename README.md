# pi-company

**让 pi 按需求完成规划、实现、代码审查和功能验收**

## 这是什么

pi-company 把开发分为三个层次：

- **主会话**：你在当前窗口中的对话，负责讨论需求、编写规范与需求文档，并取得你的确认。
- **需求代理**：负责一个需求的后台 AI 代理，保存相关上下文、安排任务并推进实现、审查和验收。
- **角色代理**：需求代理按需启动的助手，分别负责规划、编程、代码审查或功能验收。

代码审查检查实现是否合理，功能验收检查实际行为是否符合需求。每个阶段都有明确的检查条件，检查通过后才能进入下一阶段。需求代理运行在后台进程中，启动后可从同一仓库的其他窗口查看进度、补充说明、暂停或停止；关闭某个窗口不会结束它。

## 安装

```bash
pi install git:github.com/0xBB2B/pi-company
```

本地开发时使用 `pi install /absolute/path/to/pi-company`，并先在该目录执行 `pnpm install --frozen-lockfile` 安装锁定依赖。本框架使用 pnpm 11.7.0，运行及测试均使用 Node；运行 pi 的 Node 版本需 ≥ 22.19。角色代理随包提供，无需另装子代理系统。

## 卸载

```bash
pi remove git:github.com/0xBB2B/pi-company
```

卸载不会立即停止已启动的后台进程：它们会在空闲后自动退出，也可以手动停止。本机的需求状态、运行与对话记录会保留，重新安装后仍可读取。

## 快速开始

在 Git 仓库中打开 pi。本包的所有会话命令均以 `/pi-company:` 开头：

| 命令 | 用途 |
|---|---|
| `/pi-company:new <一句话需求>` | 开始处理新需求 |
| `/pi-company:resume` | 继续处理进行中的需求 |
| `/pi-company:revise <问题描述>` | 修复已有功能的问题 |
| `/pi-company:sync [功能领域 ...]` | 核对指定领域的规范与代码是否一致 |
| `/pi-company:setting` | 打开角色设置页 |
| `/pi-company:ps` | 查看和管理终端命令任务 |

例如执行 `/pi-company:new 给订单列表加导出功能`：主会话先讨论需求，写好规范与需求文档，再请你确认；确认后启动需求代理，由它规划任务、实现功能、安排代码审查和功能验收。如果需要补充信息，问题会显示在对话中，你的回答会交给需求代理。对话中断后，用 `/pi-company:resume` 读取保存的进度并继续。

## 守护进程

守护进程就是负责持续运行代理的后台进程。每个仓库一个守护进程；同一仓库通过 Git worktree 建立的多个工作目录共用这个进程。首次启动需求代理或提交前审查时会自动启动，不需要手动操作。

进程会在空闲后自动退出，空闲时限为 10 分钟；设备合盖睡眠的时间不计入。进程崩溃或电脑重启后，之前未结束的运行会被标记为中断，可在面板中选「续接」继续处理。网络短暂断开时，相关运行先暂停，网络恢复后自动继续。

## 面板与查看页

面板位于输入框下方，显示当前工作区中正在执行和最近结束的代理任务。输入框为空且没有补全菜单时，按 ↓ 进入面板。

每行都有暂停、继续、续接、停止、查看等按钮；按 ←→ 选择按钮，选中「查看」后按 Enter 打开对话记录。其他按钮也用 Enter 执行：「继续」用于暂停的运行，「续接」用于异常中断的运行。查看页只读展示实时记录，需要操作运行时返回面板。

运行结束后，该行会变灰（灰显），保留 20 秒后移出列表。操作失败的提示单独保留 20 秒后清除。

## 角色与设置

包内默认提供五个角色：规划者（planner）、实现者（worker）、审查者（reviewer）、验收者（acceptance）和需求代理（requirement-agent）。角色定义可以来自：

| 来源 | 目录 | 生效范围 |
|---|---|---|
| 包内默认 | `agents/` | 随包提供 |
| 用户设置 | `~/.pi/agent/agents/` | 当前用户的项目 |
| 项目设置 | 仓库内 `.pi/agents/` | 当前项目 |

同名角色优先使用项目定义，其次是用户定义，最后是包内默认。项目定义只有在 pi 中将项目设为受信任后才会加载。

执行 `/pi-company:setting` 打开设置页：按 ←→ 切换角色、↑↓ 选择字段、Tab 切换全局或项目设置、Enter 修改。全局设置适用于该用户的项目，项目设置只影响当前项目。

可配置字段包括模型、思考强度，以及外部工具服务 MCP。字段旁会显示当前设置来自哪里，这个来源标签只读；要改变设置，先切换到对应范围再编辑。MCP 需要另外安装适配器扩展，未安装时没有可选服务。

## Shell 管理

通过终端执行的命令称为 Shell 任务。本窗口主会话与本工作区守护进程启动的任务统一登记，列表显示它们属于哪个窗口或代理，以及是否仍在运行；工作区外不计入。状态栏显示任务总数和各类来源的数量。

执行 `/pi-company:ps` 打开管理页，选择任务后按 `K` 停止。如果系统无法确认进程是否已结束，页面会要求你核对；确认后可将它标记为已停止。

代理调用命令时可以设置 `background: true` 在后台执行，用户手动输入的命令保持等待执行结果。后台任务仍有超时限制，到期后停止命令及其子进程。

命令目前通过 macOS 系统沙箱执行，只能写入获准范围，不能访问其他仓库或直接读写本机流程数据库。其他平台没有可用的隔离方式时，会拒绝执行并说明原因。

普通命令可以查看 Git 状态和差异，不能直接修改共享的提交记录、分支或暂存区，也不能切换分支、重置工作目录或重写历史。需要提交时，明确列出本次文件，代理通过专用提交工具完成；其他文件的暂存与未暂存内容会保留。重命名文件时须同时选择新旧路径。

多个提交同时进行而遇到 Git 锁时，工具会报告失败，重新核对状态后可以重试。仓库若要求运行提交检查脚本（hook）、内容转换程序（filter）或签名程序，可能因隔离限制而无法提交，工具不会跳过这些检查。提交失败时，本次文件可能已暂存，应先查看状态。

## 本机数据

数据根目录默认为 `~/.pi/agent/pi-company/`；设置 `PI_CODING_AGENT_DIR` 时，使用该目录下的 `pi-company/`。本机运行数据不随 Git 同步，主要存放位置如下：

| 位置（相对于数据根目录） | 内容 |
|---|---|
| `repos/<仓库身份>/data.sqlite` | 需求状态、运行、对话、决策、消息、窗口、文件占用和错误详情 |
| `global.sqlite` | 全局角色设置与主会话 Shell 任务登记 |
| `repos/<仓库身份>/logs/<启动 UUIDv7>.log` | 每次后台进程启动产生的运行日志 |
| `sock/` | 窗口与后台进程通信所需的文件，位于数据根目录一级 |

业务数据使用 SQLite 保存，每条数据库记录以 UUIDv7 作为唯一主键。同一仓库的多个 worktree 共用仓库数据库；数据库文件只允许当前用户读写。

普通日志使用 `.log` 文件，记录后台进程的正常输出和错误输出，不写入 SQLite。每次启动使用独立文件，权限为 `0600`（仅当前用户可读写）；启动失败时只查看本次日志末尾。关闭窗口后，后台进程仍可继续写日志。

仓库内的 `.pi-company/` 保存规范与需求文档，例如 `spec/` 下的规则文件和 `requirements/<需求身份>/requirements.md`。这些文件与验收报告一起纳入 Git 版本管理。

## 多窗口与工作区

工作区按启动目录划分：在仓库内启动窗口时，工作区通常只有该仓库；从包含多个仓库的父目录启动时，可以管理其中发现的多个仓库。

同一仓库的不同 worktree 共用仓库身份和后台进程，从这些工作目录打开的窗口能看到同一批需求与运行。涉及多个仓库的接口或数据格式时，先在各仓库规范中写清约定，确认后再分别建立需求文档并启动需求代理。

同一文件或代码范围同时只允许一个任务写入；其他任务等待它停止写入并释放使用权后再接手，不同文件的任务可以并行。

## 常见问题

**无法连接后台进程时会怎样？**
启动代理、查询状态等操作会显示连接失败，不会假装成功。重新打开面板或窗口通常能让后台进程重新启动。

**为什么一个任务的问题也出现在另一个窗口？**
需求代理属于仓库的后台进程。提问、失败提示等消息会发送到仍连接该仓库的窗口，所以其他窗口也可能看到同一次运行的动态。

**为什么面板看不到别的项目？**
面板只显示当前工作区中发现的仓库，与窗口的启动目录有关。

**如何添加自定义角色？**
在用户角色目录 `~/.pi/agent/agents/` 或项目角色目录 `.pi/agents/` 下新增角色定义文件，然后在 `/pi-company:setting` 中查看。同名角色优先使用项目定义；项目定义需要该项目在 pi 中受信任。

**提交前审查失败后会发生什么？**
主会话先记录失败原因和处理决定，再让需求代理修复问题。修复后重新进行验收和提交前审查，并核对所审查的代码版本与内容；审查通过后才能推送。

## 开发

内部语法解析入口 `runtime/syntax-parser.ts` 使用随包分发的 TS/TSX、JS/JSX、Go 语法 WASM 和固定版本 `web-tree-sitter` 运行时。安装后可离线解析，不需要 CodeGraph 或现场编译；资源缺失、损坏或版本不兼容时明确失败。该入口只解析调用方提供的源码字符串，不包含项目扫描、索引或新业务工具。资源来源、许可证和使用边界见 [解析资源说明](resources/tree-sitter/README.md)。

```bash
pnpm install --frozen-lockfile
pnpm test
pnpm run test:installation
pi install /absolute/path/to/pi-company
```
