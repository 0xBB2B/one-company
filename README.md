## 这是什么

pi-company 把开发分为三个层次：

- **主会话**：你在当前窗口中的对话，负责讨论需求、编写规范与需求文档，并取得你的确认。
- **需求代理**：负责一个需求的后台 AI 代理，保存相关上下文、安排任务并推进实现、审查和验收。
- **角色代理**：需求代理按需启动的助手，分别负责规划、编程、代码审查或功能验收。

代码审查检查实现是否合理，功能验收检查实际行为是否符合需求。每个阶段都有明确的检查条件，检查通过后才能进入下一阶段。需求代理运行在后台进程中，启动后可从同一仓库的其他窗口查看进度、补充说明、暂停或停止；关闭某个窗口不会结束它。

> 当前框架提供协议、生命周期、数据库、需求正文存储与持久项目索引；已接入持续文件同步、需求事件与项目快照门槛。当前 M3 功能与阶段验证已完成，验证范围、证据与限制详见 [M3 报告](M3-IMPLEMENTATION-REPORT.md)。下面原有命令仍运行旧工作流，不处理新 UUID 需求的授权与生命周期。M4—M9 的完整查询、自然语言需求、专用写入、QA/关闭通知、PM、Git 外置和总体验收尚未完成；当前公开的新业务工具只有 `pi_company_requirement_manage` 和 `pi_company_project_manage`，不表示计划中的 11 个核心工具已经全部上线。

## 安装

```bash
pi install git:github.com/0xBB2B/pi-company
```

本地开发时使用 `pi install /absolute/path/to/pi-company`，并先在该目录执行 `pnpm install --frozen-lockfile` 安装锁定依赖。本框架使用 pnpm 11.7.0，运行及测试均使用 Node；运行 pi 的 Node 版本需 ≥ 22.19。角色代理随包提供，无需另装子代理系统。

## 卸载

```bash
pi remove git:github.com/0xBB2B/pi-company
```

卸载不会立即停止已启动的后台进程：它们会在空闲后自动退出，也可以手动停止。本机的需求状态、运行与对话记录会保留，重新安装后仍可读取。

## 快速开始

在 Git 仓库中打开 pi。本包的所有会话命令均以 `/pi-company:` 开头：

| 命令 | 用途 |
|---|---|
| `/pi-company:new <一句话需求>` | 开始处理新需求 |
| `/pi-company:resume` | 继续处理进行中的需求 |
| `/pi-company:revise <问题描述>` | 修复已有功能的问题 |
| `/pi-company:sync [功能领域 ...]` | 核对指定领域的规范与代码是否一致 |
| `/pi-company:setting` | 打开角色设置页 |
| `/pi-company:ps` | 查看和管理终端命令任务 |

例如执行 `/pi-company:new 给订单列表加导出功能`：主会话先讨论需求，写好规范与需求文档，再请你确认；确认后启动需求代理，由它规划任务、实现功能、安排代码审查和功能验收。如果需要补充信息，问题会显示在对话中，你的回答会交给需求代理。对话中断后，用 `/pi-company:resume` 读取保存的进度并继续。

### 当前项目索引

已接入仓库可由代理调用 `pi_company_project_manage`。公开参数只有：

```json
{ "action": "init", "repoId": "<当前 lifecycle 中的 64 位仓库身份>", "preview": true }
```

- `action` 只接受 `init`、`status`、`refresh`；`preview` 只允许用于 `init`。设为 `true` 时，经真实宿主 UI 确认后仅单次枚举路径元数据，不读取文件正文、不创建 `index.db` 或启动监听；预览许可不能升级为初始化或持续扫描批准。
- `init`（非预览）或 `refresh` 经当前真实宿主 UI 确认扫描范围后，默认在已有仓库守护进程中持续同步；许可绑定仍存活的 session、窗口、仓库根与分支。同一 session 重连时重新核对身份、重签连接许可并对账，不沿用旧连接令牌；新 session 不继承批准。窗口/session 关闭先撤销该会话许可，再等待在途操作和资源收尾。
- `status` 不扫描文件，不授予持续同步权限，也不代表缓存已经做过当前性核对。
- 初始化和刷新会索引当前代码、配置、普通文档与 `docs/spec`，提取 TS/TSX、JS/JSX、Go 的结构和可证明的同文件直接调用；其他语言只保留文件级记录。语法错误返回 `partial`，无效 spec 返回 `invalid`，不会回退旧正文。
- `.git`、依赖、构建/缓存/日志、本机数据库、敏感凭据、链接文件、多链接文件、嵌套仓库和 `docs/prod` 正文都不进入索引。归档需求只登记合法 UUID 文件路径，状态固定为 `unknown`，不产生活动需求授权。
- 默认预算为单文件 2 MiB、文本集合 20 MiB、20,000 个目录条目、64 层深度。发布前会再次读取并核对 hash，因此一次完整构建最多读取两倍文本集合预算。工具输出最多 32 KiB、100 项；截断、预算耗尽、跳过项和必要阻塞状态会明确返回。

索引写入仓库外的 `index.db`，未变文件按内容 hash 和解析器版本跨刷新、跨进程复用。同一仓库的多个窗口复用守护进程；不同 worktree/分支分别维护索引、队列与代次，同一现场不为每个窗口重复启动监听。这不授予代理创建或切换分支/worktree 的权限。

文件新增、修改、删除、改名及本地 pull 会先标记待同步，再合并连续事件并对账；启动/重连、监听失败或溢出、低频检查、手动 `refresh` 和受管理基线读取前都会补核对。当前性依据包含内容 hash，不仅依赖大小和修改时间。`docs/prod` 始终只处理路径元数据；发现归档与本机旧活动需求对应时，先阻止续接并标记待核对，不读取归档正文，不凭归档将需求改成 `completed`。可信关闭原因保持不变，归档删除或 Git 回退不会恢复授权。当前还没有 M4 `knowledge_query`。

### 模型请求与结果的项目依据

已接入持续索引的主会话和后台角色在模型请求前核对当前允许输入的快照，绑定工作区、分支、文件指纹、观察事件和连接权限。生成期间发现变化或失联，会标明回答属于旧快照，拒绝据此继续受管理写入或交付；模型已生成的推理不会瞬间更新。写入、Shell、提交及角色结果保留原请求依据并在实际操作边界复核，不能靠填入新 hash 把旧结果变成当前通过。受管理后台命令或写入尚未确认结束时，不能封存交付结果。

未初始化的现场保留原有工作流限制；已经受管理的现场失联、撤权或基线不可核对时明确阻塞，不降级为未管理路径。源码与配置说明当前实现，`docs/spec` 说明当前规则，获授权的已确认 prod 说明本次目标，实际验证记录说明检查结果；索引或模型回答不能互相替代这些依据。

这些检查不是不可变文件副本，也不能锁住任意外部编辑器。已观察到的外部变化会使旧依据失效；若监听漏事件且文件发生 A→B→A（改动后又恢复），前后 hash 可能无法发现。通用读取旁路以及主会话已有消息/摘要的限制仍适用，不保证模型自动遗忘旧内容。

## 守护进程

守护进程就是负责持续运行代理的后台进程。每个仓库一个守护进程；同一仓库通过 Git worktree 建立的多个工作目录共用这个进程。首次启动需求代理或提交前审查时会自动启动，不需要手动操作。

进程会在空闲后自动退出，空闲时限为 10 分钟；设备合盖睡眠的时间不计入。进程崩溃或电脑重启后，之前未结束的运行会被标记为中断，可在面板中选「续接」继续处理。网络短暂断开时，相关运行先暂停，网络恢复后自动继续。

## 面板与查看页

面板位于输入框下方，显示当前工作区中正在执行和最近结束的代理任务。输入框为空且没有补全菜单时，按 ↓ 进入面板。

每行都有暂停、继续、续接、停止、查看等按钮；按 ←→ 选择按钮，选中「查看」后按 Enter 打开对话记录。其他按钮也用 Enter 执行：「继续」用于暂停的运行，「续接」用于异常中断的运行。查看页只读展示实时记录，需要操作运行时返回面板。

运行结束后，该行会变灰（灰显），保留 20 秒后移出列表。操作失败的提示单独保留 20 秒后清除。

## 角色与设置

包内默认提供五个角色：规划者（planner）、实现者（worker）、审查者（reviewer）、验收者（acceptance）和需求代理（requirement-agent）。角色定义可以来自：

| 来源 | 目录 | 生效范围 |
|---|---|---|
| 包内默认 | `agents/` | 随包提供 |
| 用户设置 | `~/.pi/agent/agents/` | 当前用户的项目 |
| 项目设置 | 仓库内 `.pi/agents/` | 当前项目 |

同名角色优先使用项目定义，其次是用户定义，最后是包内默认。项目定义只有在 pi 中将项目设为受信任后才会加载。

执行 `/pi-company:setting` 打开设置页：按 ←→ 切换角色、↑↓ 选择字段、Tab 切换全局或项目设置、Enter 修改。全局设置适用于该用户的项目，项目设置只影响当前项目。

可配置字段包括模型、思考强度，以及外部工具服务 MCP。字段旁会显示当前设置来自哪里，这个来源标签只读；要改变设置，先切换到对应范围再编辑。MCP 需要另外安装适配器扩展，未安装时没有可选服务。

## Shell 管理

通过终端执行的命令称为 Shell 任务。本窗口主会话与本工作区守护进程启动的任务统一登记，列表显示它们属于哪个窗口或代理，以及是否仍在运行；工作区外不计入。状态栏显示任务总数和各类来源的数量。

执行 `/pi-company:ps` 打开管理页，选择任务后按 `K` 停止。如果系统无法确认进程是否已结束，页面会要求你核对；确认后可将它标记为已停止。

代理调用命令时可以设置 `background: true` 在后台执行，用户手动输入的命令保持等待执行结果。后台任务仍有超时限制，到期后停止命令及其子进程。

命令目前通过 macOS 系统沙箱执行，只能写入获准范围，不能访问其他仓库或直接读写本机流程数据库。其他平台没有可用的隔离方式时，会拒绝执行并说明原因。

普通命令可以查看 Git 状态和差异，不能直接修改共享的提交记录、分支或暂存区，也不能切换分支、重置工作目录或重写历史。需要提交时，明确列出本次文件，代理通过专用提交工具完成；其他文件的暂存与未暂存内容会保留。重命名文件时须同时选择新旧路径。

多个提交同时进行而遇到 Git 锁时，工具会报告失败，重新核对状态后可以重试。仓库若要求运行提交检查脚本（hook）、内容转换程序（filter）或签名程序，可能因隔离限制而无法提交，工具不会跳过这些检查。提交失败时，本次文件可能已暂存，应先查看状态。

## 本机数据

数据根目录默认为 `~/.pi/agent/pi-company/`；设置 `PI_CODING_AGENT_DIR` 时，使用该目录下的 `pi-company/`。本机运行数据不随 Git 同步，主要存放位置如下：

| 位置（相对于数据根目录） | 内容 |
|---|---|
| `repos/<仓库身份>/data.db` | 需求状态、运行、对话、决策、消息、窗口、文件占用和错误详情 |
| `repos/<仓库身份>/index.db` | 当前代码、`docs/spec`、普通资料、结构关系与全文搜索片段的可重建持久索引；经宿主批准持续同步，公开 action 为初始化、状态和刷新 |
| `repos/<仓库身份>/requirements/<UUIDv7>/` | 需求的 `prod.md` 和只跟踪该正文的独立本机 Git 仓库 |
| `global.db` | 全局角色设置与主会话 Shell 任务登记 |
| `repos/<仓库身份>/logs/<启动 UUIDv7>.log` | 每次后台进程启动产生的运行日志 |
| `sock/` | 窗口与后台进程通信所需的文件，位于数据根目录一级 |

业务数据使用 SQLite 保存，每条数据库记录以 UUIDv7 作为唯一主键。同一仓库的多个 worktree 共用仓库数据库；数据库文件及 WAL/SHM 附属文件只允许当前用户读写。数据根必须与该仓库全部 worktree 分离，初始化会核对真实路径。

检测到旧 `data.sqlite`、`global.sqlite` 或其 WAL/SHM 残留时不会新建替代空库。M1 内部存储服务已提供受控迁移、完整一致性备份和隔离恢复：操作先登记并核对授权与写入者停止状态，恢复副本默认 `needs_review`；旧备份中的 `active` 永不自动获得执行权限，较新的可信 closing/closed 元数据不会被旧状态覆盖。较新终态元数据可以保留，但旧备份不包含备份之后尚未纳入快照的新正文。

M1 的 `requirement_manage` 已接通真实宿主 lifecycle、输入结构和 UI 交互授权，提供 create、updateDraft、confirmUpdate、read、diff 与 metadata。保存 draft 只保存正文版本，不批准目标；确认目标也不自动授予规划或实施权限。正文存储内部只提供 create、save、readVersion、diffVersions、verifyVersion 五个固定接口：每个需求使用 UUIDv7 身份和独立本机 Git，只提交 `prod.md`，完成归档名固定为 `<UUIDv7>.<需求描述>.md`。closing/closed 或未知、冲突状态拒绝专用正文读取，现有项目快照入口在读取内容前排除 `docs/prod`。内部状态职责见 [需求状态基础](runtime/requirement-state.md)。

需求事件服务按已批准的准确提交对和 hash 即时提供差异，持久保存事件元数据及 PM 消费位置，不在 SQLite/outbox 保存正文或 patch；草稿及外部未确认修改不产生批准通知。专用服务在读取与交付正文时复核生命周期和访问代次，进入 `closing` 后先撤权，不等待普通索引或积压通知。这些基础能力不表示完整 PM 调度、最终 QA 和完成关闭流程已经上线。普通 read、Shell、Git 历史、MCP 等通用旁路没有全面正文拦截；主会话已有消息或摘要也不会自动清空。

普通日志使用 `.log` 文件，记录后台进程的正常输出和错误输出，不写入 SQLite。每次启动使用独立文件，权限为 `0600`（仅当前用户可读写）；启动失败时只查看本次日志末尾。关闭窗口后，后台进程仍可继续写日志。

原有工作流仍在仓库内的 `.pi-company/` 保存规范与需求文档，例如 `spec/` 下的规则文件和 `requirements/<需求身份>/requirements.md`，并将它们纳入 Git。该目录不属于M1的新UUID需求存储与授权协议；新需求正文位于上表的数据根目录中，不进入业务仓库。

## 多窗口与工作区

工作区按启动目录划分：在仓库内启动窗口时，工作区通常只有该仓库；从包含多个仓库的父目录启动时，可以管理其中发现的多个仓库。

同一仓库的不同 worktree 共用仓库身份和后台进程，从这些工作目录打开的窗口能看到同一批需求与运行。涉及多个仓库的接口或数据格式时，先在各仓库规范中写清约定，确认后再分别建立需求文档并启动需求代理。

同一文件或代码范围同时只允许一个任务写入；其他任务等待它停止写入并释放使用权后再接手，不同文件的任务可以并行。

## 常见问题

**无法连接后台进程时会怎样？**
启动代理、查询状态等操作会显示连接失败，不会假装成功。重新打开面板或窗口通常能让后台进程重新启动。

**为什么一个任务的问题也出现在另一个窗口？**
需求代理属于仓库的后台进程。提问、失败提示等消息会发送到仍连接该仓库的窗口，所以其他窗口也可能看到同一次运行的动态。

**为什么面板看不到别的项目？**
面板只显示当前工作区中发现的仓库，与窗口的启动目录有关。

**如何添加自定义角色？**
在用户角色目录 `~/.pi/agent/agents/` 或项目角色目录 `.pi/agents/` 下新增角色定义文件，然后在 `/pi-company:setting` 中查看。同名角色优先使用项目定义；项目定义需要该项目在 pi 中受信任。

**提交前审查失败后会发生什么？**
主会话先记录失败原因和处理决定，再让需求代理修复问题。修复后重新进行验收和提交前审查，并核对所审查的代码版本与内容；审查通过后才能推送。

## 开发

内部语法解析入口 `runtime/syntax-parser.ts` 使用随包分发的 TS/TSX、JS/JSX、Go 语法 WASM 和固定版本 `web-tree-sitter` 运行时。安装后可离线解析，不需要 CodeGraph 或现场编译；资源缺失、损坏或版本不兼容时明确失败。该低层入口只解析调用方提供的源码字符串；项目扫描、结构提取、持久化和宿主授权分别由 `runtime/project-index-policy.ts`、`runtime/code-extractor.ts`、`runtime/index-store.ts`、`runtime/project-index-service.ts` 和 `runtime/project-manage-tool.ts` 负责。资源来源、许可证和使用边界见 [解析资源说明](resources/tree-sitter/README.md)。

内部规则校验入口 `runtime/spec-format.ts` 检查当前规则 JSON 的字段、重复键、大小和引用，返回内容指纹与待审查信息；项目索引服务会把有效的当前规则写入索引，无效集合则发布 `invalid` 并清掉旧规则正文。它仍不发布业务规则，也不以格式通过代替语义审查。共享 schema 的分发源与计数说明见 [规则格式说明](resources/spec/README.md)。

```bash
pnpm install --frozen-lockfile
pnpm test
pnpm run test:installation
pi install /absolute/path/to/pi-company
```
