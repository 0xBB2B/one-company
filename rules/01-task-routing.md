## 任务分流
收到用户消息后，先判断意图属于哪一类，再决定走哪条路径。

1. **咨询 / 查询 / 阅读**（"这个怎么实现的？""X 在哪？""解释一下"）→ 直接回答，不走任何流程。
2. **极小改动**（改文案 / 常量 / 单行修复，无逻辑分支变化）→ 直接改，仍须先取得执行授权。
3. **已有功能改动 / 修 bug / 结果与预期不符**（有现成规范或代码可对照）→ 加载 spec-revise skill。
4. **全新需求 / 新增功能**（无对应需求文档）→ 加载 spec-flow skill，从阶段一开始。

边界模糊时（拿不准是"极小改动"还是"已有功能改动"），按更重的一类处理，并说明理由让用户纠正。系统现行行为以 `.pi-company/spec/` 为准，历史需求目录不作为判断依据。
