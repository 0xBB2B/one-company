# 审查失败统一归因与返修规则

需求代理内部派出的角色（reviewer、acceptance 等）返回 FAIL 时，归因职责归需求代理：需求代理保持审查角色只读，自行逐条归因、区分产品决策与可自动解决的问题并安排返修，不上报主会话代为归因。

主会话只在两类情况介入：需求代理转发提问时向用户展示选项并作答；需求代理判断问题超出已授权目标、范围或验收标准，需要产品决策时，由主会话向用户呈现具体选项，用户选择后经 `decision_record` 记录，再调用 `pi_company_workflow retreat`（参数写明 `stage` 回退目标阶段、`version` 需求当前版本号、`reason` 回退理由、`decisionId` 该决定编号）把需求回退到执行阶段，随后重新派出需求代理接手。用户未形成选择时保持现状不变，不记录、不回退。
