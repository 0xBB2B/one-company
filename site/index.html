一个需求怎么走完How a requirement gets done

标出来的三步只有你能做。其余由代理完成，程序逐步核对。The three marked steps are yours alone. Agents do the rest, and the program checks each one.

  1. 01 · 主代理Main agent理清需求Clarify和你理清目标、不做什么、约束；涉及界面时先出 HTML 原型。Pins down goals, non-goals and constraints. UI work gets an HTML prototype first.
  2. 02 · 你You批准Approve在程序弹出的窗口里选"确认"才生效。Takes effect only when you confirm in the program’s window.
  3. 03 · PM规划Plan读批准的需求，写计划、拆任务、派工。Reads the approved requirement, writes the plan, assigns tasks.
  4. 04 · worker实现Build在需求自己的分支里，按技术栈写代码。Writes code by stack, on the requirement’s own branch.
  5. 05 · reviewer审查Review通用审查和专项审查同时跑，全部通过才算过。General and stack reviewers run together. All must pass.
  6. 06 · QA · 你QA · You验收VerifyQA 黑盒验收后交给你，你通过需求才关闭。QA tests the behavior, then you accept it to close the requirement.
  7. 07 · 你You交付Deliver选合并方式，开 PR 或合进本地分支。Pick a merge method, then open a PR or merge locally.

模型说的不算，程序核对的才算A model saying so isn’t enough. The program checks.

代理写代码很快，也很会说"做完了"。OneCompany 把关键判断交给程序和你。Agents write code fast, and they are quick to say “done”. OneCompany leaves the key calls to the program and to you.

只有你能批准Only you can approve

批准和裁决只认你的原话和你在程序窗口里的选择。代理说"用户同意了"不算数，代理之间也不能互相批准。Approvals count only from your own words or your choice in a program window. An agent saying “the user agreed” does not count, and agents can’t approve each other.

自称完成不算完成Claiming done isn’t done

各角色的权限、版本和阶段门槛都由程序核对。代理说"通过了"不能代替实际检查。The program checks every role’s permissions, versions and stage gates. An agent saying “passed” never replaces the actual check.

改动不出范围Changes stay in scope

worker 改了本需求任务范围外的文件，结果被拒收。写入范围重叠的任务不会同时派出。A worker that edits files outside the requirement’s task scopes gets its result rejected. Tasks with overlapping write scopes are never dispatched at the same time.

每处改动查得回需求Every change traces back

提交带需求编号，需求完成时正文和原型归档进分支。以后能从代码查到当初为什么这样做。Commits carry the requirement ID, and the requirement and prototypes are archived in the branch when it completes. You can always find why the code looks the way it does.

一支随包附带的团队A team that ships with the package

你只和主代理说话，其他角色都在后台运行。不用另装子代理系统。You talk only to the main agent. Every other role runs in the background, with no separate subagent system to install.

也能换成你们的规矩Bring your own rules

三步开始Start in three steps

  1. 1准备Prepare

    装好 pi（Node ≥ 22.19）和 Git ≥ 2.38，给主窗口的模型配好凭据。Install pi (Node ≥ 22.19) and Git ≥ 2.38, and set up credentials for your model.

  2. 2安装Install

    在终端运行上面那条安装命令。角色代理随包提供。Run the install command above. Role agents ship with the package.

  3. 3开工Build

    在 Git 仓库里打开 pi，直接说需求，比如"登录页加上验证码登录"。Open pi inside a Git repo and say what you want, like “add code login to the sign-in page”.
