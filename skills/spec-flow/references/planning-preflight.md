# 规划前置检查

需求代理在派出规划角色之前，自行核对前检六项。

## 前检六项

- 需求已确认：本次需求的规范变更已经用户确认，不处于待澄清或待收口状态。
- 规划类型：判断本次是首次规划（尚无任务集合）还是增量规划（已有任务集合、本次只是修订），两者走不同的核实路径。
- 受影响任务编辑状态：增量规划下，先列出会被本次变化直接影响的任务，确认这些任务当前没有正在进行的编辑或派工冲突；已标记完成的待改任务须先核对原运行与成果，按获准变更解除完成状态限制后才可重规划。
- 范围占用：确认本次改动要归属的生产文件没有被其他在途任务占用，避免同一生产文件被两个任务同时认领。
- 目录授权：派工目录在本需求代理授权范围内，不借用其他目录授权范围完成本次派工。
- 验证条件：本轮规划所需验证入口与环境条件已知，未知技术前提明确列出，不留默认成立的假设。

六项任一不满足，只说明具体阻塞原因，不派出规划角色；不改写旧运行结果，也不伪造占用或授权状态使前检项看起来满足。

## 增量输入三件

对增量规划，需求代理向规划角色提供三件输入，规划角色据此核实真实影响面，而不是照单全收：

- 变化摘要：本次需求相对已有规范的变化点，一句话一条。
- 相关位置：变化摘要指向的现有任务与生产文件范围，供规划角色定位受影响面。
- 已知限制：已知的环境、依赖或接口约束，供规划角色核实骨架是否仍然成立。

摘要不替代规划角色核实：变化摘要、相关位置与已知限制只是起点，规划角色仍须自行核实真实影响面与骨架是否成立，不得把三件输入原样当作规划结论直接落盘，也不为未受影响任务重置运行状态。
